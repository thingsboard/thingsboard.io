ThingsBoard 4.4 introduces Remote Agents for centralized deployment management, faster integration processing, a redesigned user interface, Java 25, expanded Reporting capabilities, and new options across APIs and dashboards.

This release also marks an important milestone: Community Edition and Professional Edition are now unified into a single ThingsBoard platform. Features that were previously exclusive to Professional Edition, such as integrations and Reporting, are now available in every deployment. We covered this transition and the updated licensing model in our dedicated [One ThingsBoard](/blog/one-thingsboard-source-available/) post.

## Remote Agents: manage remote deployments from one place

Manage your remote hosts from the ThingsBoard UI, without connecting over SSH for routine deployment tasks.

You can deploy and manage ThingsBoard Edge, IoT Gateway, and other Docker Compose apps, even on many hosts at once. Reusable application profiles keep configurations consistent, and backup and rollback make upgrades safer.

Install a Remote Agent on each host you want to manage. The agent deploys and manages apps there, sends host and container metrics to ThingsBoard, and shows live container logs.

## Faster integration processing

Integration data now reaches the Rule Engine faster, and TB Core has less work to do.

Before, the Integration Executor sent data to TB Core, which converted it and found the right device. Now, the Integration Executor does this work itself and keeps device and profile data in memory. It then sends messages straight to the Rule Engine.

**The processing path changes from:**

## Run ThingsBoard on Java 25

ThingsBoard 4.4 runs on Java 25. The runtime, Docker images, and installation packages are all updated. Docker images already include Java 25. On Linux or Windows installations without Docker, install JDK 25 and make it the default Java version before upgrading.

## Reporting improvements

Your customers can now work with reports on their own: customer users get report templates, schedules, and generated reports for their own data.

**Public report download links** make sharing easier, and **dynamic Y-axis configuration** makes report charts more flexible.

## API and integration improvements

<BlogGrid tight>
	<BlogIconCard title="API keys for WebSocket" icon="key" family="blue">

	</BlogIconCard>
	<BlogIconCard title="Alarm Rules API" icon="bell" family="yellow">
Manage alarm rules programmatically through a dedicated API. Create and configure alarm rules directly from your systems and scripts.
	</BlogIconCard>
	<BlogIconCard title="Request body templates" icon="braces" family="purple">
Control exactly what your rule chains send to other services. The REST API Call rule node now supports request body templates.
	</BlogIconCard>
	<BlogIconCard title="OAuth 2.0 for Kafka" icon="lock" family="grey">
Connect to Kafka clusters that require OAuth 2.0, using the new `OAUTHBEARER` authentication support in Kafka integrations.
	</BlogIconCard>
</BlogGrid>

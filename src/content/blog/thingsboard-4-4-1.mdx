For years, a ThingsBoard dashboard has been a grid of widgets. When people build dashboards by hand, ready-made widgets are the fastest way to get one working. A custom page in HTML, CSS, and JavaScript can look and behave exactly the way you want, but writing one by hand takes much longer. With AI, it takes seconds. ThingsBoard 4.4.1 adds an HTML Page layout for dashboard states, and AI Solution Creator and the AI Assistant can now build these pages from a design you attach. The release also closes 84 known vulnerabilities in third-party libraries and adds an SBOM to every build.

## From widget grids to HTML pages

Widgets were made for people. You pick a chart, a value card, or a table, bind it to your data, and drag it into place. No code, and a working dashboard is ready in minutes. When a person does the configuring, that speed matters most.

The grid has limits, though. Some screens don’t fit it: a branded start page, a plant overview drawn as a floor plan, a kiosk view for the control room. Until now, they took a custom widget, a pile of CSS overrides, or a compromise.

AI shifts the balance. An assistant writes a full page of HTML, CSS, and JavaScript as fast as it fills in widget settings, so the flexibility of code no longer costs you time. The result is also easier to control: one page, in code you can read, review, and change. We think this is where dashboard building is heading, and 4.4.1 is the first step.

The new HTML Page layout turns a dashboard state into one custom page. The page has the same capabilities as widgets: the widget context API for your data, navigation between dashboard states, actions, and JS and CSS resources.

Moving to a page doesn’t mean giving up widgets. You can embed existing widgets right into the page. We recommend it for the most powerful ones, such as maps, charts, and tables, and any other widget can be reused wherever it fits. The page sets the layout and the look; the widgets you already trust do the heavy lifting.

To use it, open **Manage layouts** and set the state’s layout type to **HTML Page**. In edit mode, **Edit HTML page** opens the same editor the HTML Container widget uses, in plain HTML or Angular mode, with HTML, CSS, JavaScript, resources, and actions in one place. The page fills the full height of the layout on desktop and mobile.

## AI builds the page from your design

You can write HTML pages by hand, but you no longer have to. AI Solution Creator and the AI Assistant now accept files with your message: images, PDFs, text files, and Word, Excel, or PowerPoint documents. Instead of describing a dashboard in a long prompt, attach a design and ask the assistant to make your dashboard look like it. To attach a file, drag it into the chat or paste a copied image.

The design doesn’t have to follow ThingsBoard’s own style. To show that, we took two free designs from Figma Community and applied them to two ThingsBoard dashboards.

### AI behind NAT and firewalls

AI features no longer need a public base URL. Your ThingsBoard instance now opens an outbound WebSocket connection to the AI service, and the AI service never connects back into your network. On-premises installations behind NAT or a firewall can use AI Solution Creator and the assistants without extra network setup, and your users’ access tokens stay inside your instance.

Learn more about [AI Solution Creator](/blog/ai-solution-creator/).

## Finding vulnerabilities with AI, before attackers do

AI has changed security work on both sides. The tools that help build dashboards also find vulnerabilities faster than ever, and attackers have them too. So we put significant resources into using AI first: we analyze ThingsBoard’s own code and every dependency we manage with AI tools, and scan every supported release line for vulnerable libraries. Independent penetration tests and security researchers who report issues to us responsibly catch what automated tools miss.

Here is what that work brings in 4.4.1:

- **84 CVEs closed in third-party libraries.** We updated Tomcat, Jackson, Bouncy Castle, and front-end npm packages, among others. Several of the fixed CVEs were rated critical. The same dependency fixes go into our supported LTS releases.
- **Fixes in ThingsBoard itself.** The OAuth2 login flow now encrypts and authenticates its authorization request cookie with AES-256-GCM. We closed a gap in the TBEL script sandbox that allowed writing to the server’s file system, and tightened permission checks for device claiming and user activation links.
- **An SBOM with every build.** Every ThingsBoard jar, installation package (`.deb`, `.rpm`, Windows `.zip`), and Docker image now comes with a CycloneDX SBOM. Point your scanner at it to see exactly which components and versions you run, without unpacking anything.

Found a vulnerability? Write to [security@thingsboard.io](mailto:security@thingsboard.io). Read more about how we handle security in our [Trust Center](/trust-center/).

## Final thoughts

ThingsBoard dashboards started as widget grids configured by hand. With 4.4.1, a dashboard state can also be an HTML page, built by AI from a design you attach, in code you can read and change, with your maps, charts, and tables embedded where you need them. The same AI that speeds up building also helps us find vulnerabilities: 4.4.1 closes 84 CVEs and adds an SBOM to every build.

Next, we’re working on agents that tidy up generated dashboards. They will refactor the code, move custom widgets into reusable bundles, and keep each dashboard small. Less code means faster AI edits and dashboards that are easier to manage as they grow.

The [release notes](/docs/pe/releases/releases-table/v4-4-x/) list every change, and the [upgrade instructions](/docs/pe/installation/upgrade-instructions/) take you to 4.4.1.

ThingsBoard Community Edition and Professional Edition are now [one platform](/blog/one-thingsboard-source-available/), and the mobile app follows. **ThingsBoard App 2.0** is one open-source app for ThingsBoard 4.4 and ThingsBoard Cloud, built with Flutter for iOS and Android. Use it as is, or as the base of your own branded [IoT mobile app](/products/mobile/).

Version 2.0 keeps every feature of the former Professional Edition app, protects user data and sessions better, and fixes dozens of issues across sign-in, navigation, dashboards, languages and screen layouts. It is also lighter: about a quarter smaller on Android.

Want to see it on your phone? The ThingsBoard Cloud app, built on ThingsBoard App 2.0, is available on [Google Play](https://play.google.com/store/apps/details?id=org.thingsboard.cloud) and the [App Store](https://apps.apple.com/us/app/thingsboard-cloud/id6499209395).

ThingsBoard App 2.0 continues the former Professional Edition app and keeps all of its history. Everything that app had is now available to every ThingsBoard user: white-labeling, OAuth 2.0, self-registration, push notifications, QR code login and device provisioning.

For teams that build their own branded app, there is now one codebase to start from, [flutter_thingsboard_app](https://github.com/thingsboard/flutter_thingsboard_app), under the BSD 3-Clause license. Every new fix and feature lands in one place.

The app runs on [thingsboard_client](https://pub.dev/packages/thingsboard_client) 5.0, which now replaces the separate Community and Professional Edition Dart clients as well. It is generated from the ThingsBoard API specification, so it covers the whole API of ThingsBoard 4.4 and stays in step with the server. See the [Dart API Client](/docs/pe/reference/dart-client/) reference.

## Safer sign-in and sessions

Some of these changes come from the app itself, others from [thingsboard_client](https://pub.dev/packages/thingsboard_client) 5.0, the Dart client the app is built on. Your own Dart code gets the client's protections too.

<BlogGrid tight>
	<BlogIconCard title="Secure storage" icon="shield-lock" family="blue">
App data now lives in the device's secure storage: Keychain on iOS and Keystore-encrypted storage on Android.
	</BlogIconCard>
	<BlogIconCard title="Compatible servers only" icon="server" family="purple">
The app checks the server version at start-up and on every sign-in. On a server older than 4.4, it asks for a server update and keeps no session.
	</BlogIconCard>
	<BlogIconCard title="Clearer two-factor authentication" icon="2fa" family="teal">
Each method is explained, the authenticator app opens in one tap, backup codes are suggested after setup, and a rejected code always says why.
	</BlogIconCard>
	<BlogIconCard title="Expired sessions handled cleanly" icon="lock" family="grey">
When a session is revoked elsewhere, for example after a password change, the app shows one clear "Session has expired" message and returns to the login page.
	</BlogIconCard>
	<BlogIconCard title="Safer QR codes" icon="qrcode" family="yellow">
A QR code that points to a server that doesn't answer or isn't ThingsBoard no longer switches the app to it. The app explains why and stays on the current server.
	</BlogIconCard>
	<BlogIconCard title="Fewer outside requests" icon="world" family="green">
The app font ships with the app instead of being downloaded from Google at run time.
	</BlogIconCard>
	<BlogIconCard title="No stale sessions" icon="key" family="pink">
A token refresh that finishes after logout or a new login is dropped, so an old session can't overwrite the current one. A replaced client stops writing to the app storage.
	</BlogIconCard>
	<BlogIconCard title="Credentials masked in logs" icon="eye-off" family="grey">
With debug logging on, the client hides authorization headers, QR login secrets, and any password, token or secret in requests.
	</BlogIconCard>
</BlogGrid>

## What's fixed

App 2.0 fixes dozens of issues, including regressions from version 1.9. In short:

<BlogGrid tight>
	<BlogIconCard title="Lists and alarms" icon="list-details" family="blue">
Entity lists sort again, alarm details link to their dashboard, and alarm status updates without a pull to refresh.
	</BlogIconCard>
	<BlogIconCard title="Dashboards and notifications" icon="layout-dashboard" family="teal">
The default dashboard opens after sign-in, dashboards reopen after the app returns from the background, and push notifications open the right dashboard.
	</BlogIconCard>
	<BlogIconCard title="Navigation" icon="arrow-back-up" family="grey">
Back returns where you expect, pages opened from the menu have a way back, and iOS supports the edge swipe.
	</BlogIconCard>
	<BlogIconCard title="Languages" icon="language" family="yellow">
The profile language applies across the whole app, Arabic gets a fully mirrored layout, and screens that were left in English are translated.
	</BlogIconCard>
	<BlogIconCard title="Every screen size" icon="device-mobile-rotated" family="green">
Pages scroll in landscape and on foldable cover screens, stay clear of the camera cutout, and handle large text.
	</BlogIconCard>
	<BlogIconCard title="Sign-up and errors" icon="user-check" family="purple">
Self-registration works with reCAPTCHA, device claiming reports success again, and errors are clear and translated.
	</BlogIconCard>
</BlogGrid>

See the [GitHub release notes](https://github.com/thingsboard/flutter_thingsboard_app/releases/tag/v2.0.0) for the full list.

## Before you upgrade

- **Server version.** App 2.0 needs ThingsBoard 4.4.0 or later. For an older server, use the 1.x app version from the [compatibility matrix](/docs/mobile/pe/compatibility/).
- **One more sign-in.** Because app data moved to secure storage, users sign in once more and choose their region or server again after updating from 1.x.

This guide describes how to deploy Trendz Analytics on a Kubernetes cluster.

## Prerequisites

<Prerequisites product={Products.TRENDZ} />
- A running Kubernetes cluster with `kubectl` configured to communicate with it. If you don't have Minikube installed, follow <a href="https://kubernetes.io/docs/setup/learning-environment/minikube/" target="_blank">these instructions</a>.

**Node requirements:** Designate a node for the Trendz instance and label it with a custom label. Use affinity settings to deploy Trendz on that node. The typical resource usage is **4 CPU and 8 GB RAM** per instance — configure your limits to meet or exceed these recommendations.

## Installation steps

Trendz Analytics can be installed in two ways:

- **Run alongside ThingsBoard** — recommended. Trendz is deployed as part of the ThingsBoard Kubernetes cluster, sharing the same infrastructure and database.
- **Standalone** — Trendz runs independently on its own Kubernetes deployment. Use this if you are not running ThingsBoard on the same cluster or prefer an isolated setup.

### Step 1. Clone Trendz Kubernetes scripts

```bash
git clone https://github.com/thingsboard/trendz-k8s.git --depth 1
cd trendz-k8s
```

### Step 2. Configure the deployment

Set up an external PostgreSQL instance with an empty database named `trendz`. This can be hosted on a managed service (e.g. AWS RDS) or as a stateful deployment in your cluster.

Put its connection in `trendz-db-app-secret.yml`:

```bash
nano trendz-db-app-secret.yml
```

```yaml
SPRING_DATASOURCE_URL: jdbc:postgresql://trendz-db-service:5432/trendz
SPRING_DATASOURCE_USERNAME: postgres
SPRING_DATASOURCE_PASSWORD: postgres
```

Then edit the other files:

- `trendz-python-executor-secret.yml`: replace `placeholder` with a long random value, for example from `openssl rand -hex 32`. Trendz and the Python Executor read the same Secret.
- `trendz-app-deployment.yml`: set `TB_API_URL` to the ThingsBoard service as seen from the `trendz` namespace, and fill in the license values.
- `trendz-app-shared-pvc.yml`: set `storageClassName` to a ReadWriteMany storage class of your cluster (NFS, EFS, Azure Files, CephFS). All Trendz pods share this volume, so a ReadWriteOnce volume does not work.

### Step 3. Deploy to Kubernetes

```bash
kubectl apply -f trendz-namespace.yml
kubectl apply -f trendz-db-app-secret.yml -f trendz-python-executor-secret.yml
kubectl apply -f trendz-app-env-config.yml -f trendz-app-files-config.yml
kubectl apply -f trendz-python-executor-env-config.yml -f trendz-python-executor-files-config.yml
kubectl apply -f trendz-app-shared-pvc.yml
kubectl apply -f trendz-cache-deployment.yml
kubectl apply -f trendz-python-executor-deployment.yml -f trendz-python-executor-network-policy.yml
kubectl apply -f trendz-app-deployment.yml
```

<Aside type="note">
The Python Executor is deployed automatically as part of this step — no separate installation is required.
</Aside>

### Step 4. Check the logs

Verify the instance started successfully. Get the pod name and stream its logs:

```bash
kubectl logs -f [trendz-pod-name]
```

Look for the following line:

```text
Started TrendzApplication in 5.654 seconds (JVM running for 6.229)
```

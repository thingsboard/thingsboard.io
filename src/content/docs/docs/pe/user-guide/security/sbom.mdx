A software bill of materials (SBOM) lists every component inside a piece of software: its name, version, license and where it comes from. Use it to check ThingsBoard against vulnerability databases, to review licenses, or to meet a compliance requirement.

ThingsBoard publishes SBOMs starting with version {SBOM_FROM_VER}. Each SBOM is a [CycloneDX](https://cyclonedx.org/) 1.6 JSON file. The SBOM of a package names the SHA-256 hash of the package, and the SBOM of an image names the image digest, so you can tell exactly which artifact it describes.

## Where to find the SBOMs

| Artifact | Where its SBOM is | What it covers |
| --- | --- | --- |
| `.deb`, `.rpm` and Windows `.zip` packages | Next to the package on the GitHub release page, as `<package file>.cdx.json` | The application with its libraries, and the third-party files shipped in the package. Java is not listed, because the package does not include it |
| Docker images | Attached to the image in the registry | The operating system packages, the Java or Node.js runtime and the application |
| Java application jars | Inside the jar, at `META-INF/sbom/application.cdx.json` | The jar only |

## Installation packages

Download the SBOM from the [release page](https://github.com/thingsboard/thingsboard/releases) the same way as the package:

<Code lang="bash" code={`wget ${PE_RELEASE_URL}/thingsboard-${PE_PKG_VER}.deb.cdx.json`} />

To check that an SBOM belongs to the package you have, compare the hash it records with the hash of your file:

<Code lang="bash" code={`sha256sum thingsboard-${PE_PKG_VER}.deb
jq -r '.metadata.component.hashes[] | select(.alg == "SHA-256") | .content' thingsboard-${PE_PKG_VER}.deb.cdx.json`} />

## Docker images

The SBOM of an image is stored in the registry and linked to the image, so the image itself stays unchanged. Each architecture (`linux/amd64`, `linux/arm64`) has its own SBOM.

You need the [ORAS](https://oras.land/docs/installation) command-line tool to download it.

<Steps>

1. Find the SBOM attached to the image for your architecture:

   <Code lang="bash" code={`oras discover --platform linux/amd64 \\
  --artifact-type application/vnd.cyclonedx+json \\
  docker.io/thingsboard/tb-node:${PE_FULL_VER}`} />

   The output shows the image digest and, below it, the digest of the SBOM:

   ```text
   docker.io/thingsboard/tb-node@sha256:2a84…
   └── application/vnd.cyclonedx+json
       └── sha256:64f8…
           └── [annotations]
               └── org.opencontainers.image.created: "2026-11-10T10:10:07Z"
   ```

2. Download the SBOM by its digest:

   ```bash
   oras pull docker.io/thingsboard/tb-node@<SBOM digest from step 1>
   ```

   ORAS saves the file to the current directory as `thingsboard_tb-node_<version>_<architecture>_<first 12 characters of the image digest>.cdx.json`.

</Steps>

Use the same commands for the other images, for example `thingsboard/tb-mqtt-transport` or `thingsboard/tb-web-ui`.

<Aside type="caution">
  Most ways of copying an image leave the SBOM behind: `docker pull` followed by `docker push`, `skopeo copy`, `crane copy`, and `oras cp` or `regctl image copy` without extra options. If you mirror ThingsBoard images to your own registry, either download the SBOM first, or copy with `oras cp -r` or `regctl image copy --referrers`, which keep it.
</Aside>

## Java application jars

Read the SBOM of a jar from an installed system, without a download:

```bash
unzip -p /usr/share/thingsboard/bin/thingsboard.jar META-INF/sbom/application.cdx.json > thingsboard.cdx.json
```

## Use an SBOM

To scan an SBOM for known vulnerabilities:

<Code lang="bash" code={`trivy sbom thingsboard-${PE_PKG_VER}.deb.cdx.json
grype sbom:thingsboard-${PE_PKG_VER}.deb.cdx.json`} />

You can also upload the file to [Dependency-Track](https://dependencytrack.org/) to follow new vulnerabilities over time.

<Aside type="note">
  A scanner report is a list of candidates, not of confirmed problems: a vulnerable function in a library may never be called by ThingsBoard. If you find something that looks exploitable, report it as described in the [Trust Center](/trust-center/report-vulnerability/).
</Aside>

This guide walks you through setting up ThingsBoard in cluster mode using Docker Compose with microservices architecture. Licensing is free and requires no credit card. Docker container images are available on <a href="https://hub.docker.com/search?q=thingsboard&type=image&image_filter=store" target="_blank">Docker Hub</a>.

For a simpler single-node installation, see <DocLink product={Products.PE} path="installation/docker" target="_blank">Docker (Linux, macOS)</DocLink>.

## Prerequisites

Install Docker:
- <a href="https://docs.docker.com/engine/install/ubuntu/" target="_blank">Docker for Ubuntu</a>
- <a href="https://docs.docker.com/engine/install/centos/" target="_blank">Docker for CentOS</a>
- <a href="https://docs.docker.com/desktop/setup/install/mac-install/" target="_blank">Docker Desktop for macOS</a>

A server with at least **8 GB of RAM** (16 GB recommended for production cluster deployments).

You'll also need outbound internet access to pull Docker images and to reach the ThingsBoard License Portal during activation.

<Aside type="caution">
On Linux, add your user to the `docker` group so you can run commands without `sudo`.
See <a href="https://docs.docker.com/engine/install/linux-postinstall/#manage-docker-as-a-non-root-user" target="_blank">Manage Docker as a non-root user</a>.
</Aside>

<Aside type="note">
Deploying Rule Engine as a separate service requires an additional separate license key.
</Aside>

## Step 3. Configure Deployment Type

The docker compose scripts support three deployment modes. Edit the `.env` file:

```bash
nano .env
```

Set the `TB_SETUP` variable to one of the following:

| Mode | Description |
|---|---|
| `basic` **(recommended, default)** | ThingsBoard Core and Rule Engine run in one JVM (requires 1 license). MQTT, CoAP, and HTTP transports run in separate containers. |
| `monolith` | ThingsBoard Core, Rule Engine, and all transports run in one JVM (requires 1 license). Minimizes memory footprint. |
| `advanced` | ThingsBoard Core and Rule Engine run in separate replicated containers (requires a license for 4 deployments). |

All deployment modes support separate JS executors, Redis, and different queue services.

<Aside type="tip">
Already have a license key? In the same `.env` file, uncomment the `TB_LICENSE_SECRET` line and replace `PUT_YOUR_LICENSE_SECRET_HERE` with your key. Otherwise, leave the line commented out and activate your instance from the web UI in [Step 9](#step-9-license-and-activate-your-instance).
</Aside>

## Step 4. Configure Database

Edit the `.env` file to set the database type:

```bash
nano .env
```

Set the `DATABASE` variable to one of:

| Value | Description |
|---|---|
| `postgres` | Use PostgreSQL for all data |
| `hybrid` | Use PostgreSQL for entities and Cassandra for time-series data |

<Aside type="note">
The corresponding Docker services are defined in `docker-compose.postgres.yml` and `docker-compose.hybrid.yml`.
</Aside>

## Step 5. Choose Queue Service

ThingsBoard cluster deployments require an external message broker. In Memory queue is **not** suitable for cluster mode.

- **Kafka** — recommended for production. Used on most ThingsBoard production environments. Works for on-prem and private cloud deployments.
- **Confluent Cloud** — fully managed streaming platform based on Kafka. Useful for cloud-agnostic deployments.

<Tabs>
<TabItem label="Kafka (recommended)">

<a href="https://kafka.apache.org/" target="_blank">Apache Kafka</a> is an open-source stream-processing platform.

Edit the `.env` file:

```bash
nano .env
```

Verify the following line:

```bash
TB_QUEUE_TYPE=kafka
```

## [Optional] Configure HTTPS

Serving ThingsBoard over HTTPS encrypts the traffic between browsers and the server and prevents browser security warnings. HTTPS is handled by HAProxy: it accepts incoming traffic on ports 80 (HTTP) and 443 (HTTPS), terminates TLS with a trusted certificate from Let's Encrypt, and forwards requests to ThingsBoard.

Before you start, make sure that:

- a domain name is assigned to your server, and its DNS record points to the server's IP address;
- ports 80 and 443 are reachable from the internet.

The deployment already includes HAProxy as the `haproxy-certbot` container, so you only need to request the certificate. Replace `YOUR_DOMAIN` and `YOUR_EMAIL` with your values, then request the certificate and reload HAProxy to apply it:

```bash
docker exec haproxy-certbot certbot-certonly --domain YOUR_DOMAIN --email YOUR_EMAIL
docker exec haproxy-certbot haproxy-refresh
```

<Aside type="note">
A valid certificate is used only when you access the Web UI by domain name. If you use an IP address, a self-signed certificate is used.
</Aside>

## Inspect Logs and Control Containers

Run these commands from the repository root. Pick the tab that matches the `TB_SETUP` value in your `.env` file:

<Tabs>
<TabItem label="basic">

Stream ThingsBoard node logs:

```bash
docker compose --env-file .env -f basic/docker-compose.yml logs -f tb-monolith | grep --line-buffered --color=always -E 'Started ThingsboardServerApplication|$'
```

View the state of all containers:

```bash
docker compose --env-file .env -f basic/docker-compose.yml ps
```

Stream logs of all services:

```bash
docker compose --env-file .env -f basic/docker-compose.yml logs -f
```

</TabItem>
<TabItem label="monolith">

```bash

```

View the state of all containers:

```bash
docker compose --env-file .env -f monolith/docker-compose.yml ps
```

Stream logs of all services:

```bash
docker compose --env-file .env -f monolith/docker-compose.yml logs -f
```

</TabItem>
<TabItem label="advanced">

Stream ThingsBoard node logs:

```bash
docker compose --env-file .env -f advanced/docker-compose.yml logs -f tb-core1 tb-core2 tb-rule-engine1 tb-rule-engine2
```

View the state of all containers:

```bash
docker compose --env-file .env -f advanced/docker-compose.yml ps
```

Stream logs of all services:

```bash
docker compose --env-file .env -f advanced/docker-compose.yml logs -f
```

</TabItem>
</Tabs>

Stop all services:

```bash
./docker-stop-services.sh
```

Remove all deployed containers:

```bash
./docker-remove-services.sh
```

Update specific services (pull newer image and rebuild container):

```bash
./docker-update-service.sh [SERVICE...]
```

If `[SERVICE...]` is omitted, all services are updated.

Starting with ThingsBoard 4.4, Community Edition and Professional Edition are unified into a single ThingsBoard platform.

This guide explains how to upgrade an existing ThingsBoard Community Edition deployment to ThingsBoard 4.4.

## Before You Begin

Complete these steps on your current Community Edition deployment:

1. **Upgrade to the latest 4.3 LTS patch release.**
   See <DocLink product={Products.CE} path="installation/upgrade-instructions" target="_blank">CE upgrade instructions</DocLink>.
2. **Get a license key.**
   <DocLink product={Products.PE} path="installation/register-community-grant" target="_blank">Register in the **Community Grant Program**</DocLink> for a free perpetual key, or buy one in the <a href="https://license.thingsboard.io/" target="_blank" rel="noopener noreferrer"><strong>License Portal</strong></a>.
   Registration runs on ThingsBoard 4.3, so do it before the upgrade.
   The license sets how many devices and assets the deployment can have. Check that your current counts fit within it.
3. **Back up the database and configuration files.**
   After the database upgrade you can't roll back to Community Edition without this backup.

<Aside type="caution">
Don't start the upgrade until you have a license key. You can't register in the Community Grant Program once the deployment is on ThingsBoard 4.4.
</Aside>

## Ubuntu

Use these instructions to upgrade an existing ThingsBoard Community Edition deployment installed from the `.deb` package on Ubuntu to ThingsBoard 4.4.

<PrerequisitesNote />

### Step 1. Install Java 25

ThingsBoard 4.4 requires **Java 25**, while ThingsBoard Community Edition 4.3 runs on Java 17.
Install OpenJDK 25 and make it the default Java version:

```bash
sudo apt update && sudo apt install -y openjdk-25-jdk-headless
sudo update-alternatives --set java /usr/lib/jvm/java-25-openjdk-$(dpkg --print-architecture)/bin/java
```

Verify the installation:

```bash
java -version
```

The reported version must be 25.

### Step 2. Install Font Libraries

ThingsBoard 4.4 requires font libraries for its built-in reporting component. Community Edition doesn't use them, so install them before the upgrade:

```bash
sudo apt update && sudo apt install -y libharfbuzz0b fontconfig fonts-dejavu-core
```

### Step 3. Download ThingsBoard Package

Download the ThingsBoard {PE_FULL_VER} package:

<Code code={ubuntuDownloadCmd} lang="bash" />

Run the next steps from this directory so that the package file can be found.

### Step 4. Stop ThingsBoard

Stop the ThingsBoard service so that the database isn't in use during the upgrade:

```bash
sudo systemctl stop thingsboard
```

ThingsBoard stays unavailable until it starts again in Step 7, so plan the upgrade for a maintenance window.

### Step 5. Install ThingsBoard Package

Install the ThingsBoard {PE_FULL_VER} package over the existing Community Edition installation:

<Code code={ubuntuInstallCmd} lang="bash" />

<Aside type="caution" title="Configuration files">
`dpkg` asks how to handle a configuration file (`[Y/I/N/O/D/Z]`) only if you modified that file and the new package contains a different version.

If no prompt appears, your existing configuration is preserved and no additional action is required.

If prompted, use the new package configuration as the base:

1. Press **Y** to install the package maintainer's version. Your previous file is kept with the `.dpkg-old` suffix.
2. Copy your custom settings from the `.dpkg-old` file into the new configuration.

**Important:** complete the configuration update before running the database upgrade. The upgrade script uses this configuration to connect to the database.
</Aside>

### Step 6. Upgrade the Database

Run the upgrade script. It migrates the database schema and data from Community Edition to ThingsBoard 4.4:

```bash
sudo /usr/share/thingsboard/bin/install/upgrade.sh --fromVersion=CE
```

On large databases the script can take a long time. Don't interrupt it.

### Step 7. Start ThingsBoard

Start the ThingsBoard service:

```bash
sudo systemctl start thingsboard
```

The first startup after the upgrade can take a few minutes. To follow its progress, watch the log, and press **Ctrl+C** to stop watching:

```bash
tail -f /var/log/thingsboard/thingsboard.log
```

### Step 8. Verify the Upgrade

<VerifyUpgrade guidePath="installation/ubuntu#step-8-license-and-activate-your-instance" guideLabel="Ubuntu installation guide" />

### [Optional] Install the WebReport Component

The WebReport component is a separate service that renders dashboards into PDF and PNG reports.
If you need scheduled or on-demand dashboard reports, install it as described in the <DocLink product={Products.PE} path="installation/ubuntu#optional-install-thingsboard-webreport-component" target="_blank">Ubuntu installation guide</DocLink>.

## Windows

Use these instructions to upgrade an existing ThingsBoard Community Edition deployment on Windows to ThingsBoard 4.4.

<PrerequisitesNote />

### Step 1. Install Java 25

ThingsBoard 4.4 requires **Java 25**, while ThingsBoard Community Edition 4.3 runs on Java 17.
Download and install JDK 25 (for example, <a href="https://adoptium.net/temurin/releases/?version=25" target="_blank" rel="noopener noreferrer">Eclipse Temurin 25</a>) and make it the system's default Java version.

Verify the installation:

```text
java -version
```

The reported version must be 25.

### Step 2. Download ThingsBoard Package

Download the ThingsBoard installation archive for Windows: <a href={windowsDownloadUrl} target="_blank" rel="noopener noreferrer">{windowsDownloadText}</a>.

### Step 3. Stop ThingsBoard

Open **Command Prompt as Administrator** and stop the ThingsBoard service:

```text
net stop thingsboard
```

### Step 4. Back Up the Current Configuration

Before replacing the installation files, make a copy of your current ThingsBoard configuration directory located in `<ThingsBoard install dir>\conf` (e.g. `C:\thingsboard\conf`).

Keep this backup until the upgrade is complete.

### Step 5. Update ThingsBoard Files

1. The <code>{windowsDownloadText}</code> archive contains a top-level `thingsboard` folder. Extract it to the parent of your installation directory (e.g. `C:\`) so that it replaces `C:\thingsboard`, and choose to replace all existing files.
   Check that `upgrade.bat` is located directly in `C:\thingsboard`, not in a nested `C:\thingsboard\thingsboard` folder.
2. Open the new `conf\thingsboard.yml` and copy your custom settings into it from the backup you made in Step 4: database connection, ports, queue settings, and any other values you changed.
   Use the new file as the base, the same as on Linux, so new 4.4 settings are kept.

<Aside type="caution">
Complete the configuration update before running the database upgrade in Step 6. The upgrade script uses this configuration to connect to the database.
</Aside>

### Step 6. Upgrade the Database

1. Open **Command Prompt as Administrator** and go to the ThingsBoard installation directory (e.g. `C:\thingsboard`):

   ```text
   cd C:\thingsboard
   ```

2. Run the upgrade script:

   ```text
   upgrade.bat --fromVersion=CE
   ```

### Step 7. Start ThingsBoard

Start the ThingsBoard service:

```text
net start thingsboard
```

### Step 8. Verify the Upgrade

## Docker

Use these instructions to upgrade an existing single-node ThingsBoard Community Edition deployment that runs in Docker to ThingsBoard 4.4.

<PrerequisitesNote />

### Step 1. Download ThingsBoard Images

Pull the ThingsBoard {PE_FULL_VER} and WebReport images:

<Code code={dockerPullCmd} lang="bash" />

### Step 2. Upgrade ThingsBoard

Stop and remove the ThingsBoard CE service:

```bash
docker compose stop thingsboard-ce
docker compose rm -f thingsboard-ce
```

Update your `docker-compose.yml` according to the <DocLink product={Products.PE} path="installation/docker" target="_blank">Docker installation guide</DocLink>. Make sure to change the image tag to <code>{PE_FULL_VER}</code>, define the required volumes, and add the WebReport service.

Run the upgrade and start the services:

```bash
docker compose run --rm -e UPGRADE_TB=true -e FROM_VERSION="CE" thingsboard
docker compose up -d
```

## Minikube

Use these instructions to upgrade an existing ThingsBoard Community Edition deployment on a Minikube Kubernetes cluster to ThingsBoard 4.4.

<PrerequisitesNote />

For AWS EKS, Azure AKS, or GCP GKE refer to the corresponding <DocLink product={Products.PE} path="installation" target="_blank">installation guides</DocLink>.

### Step 1. Stop ThingsBoard CE Resources

Delete the CE resources from the cluster:

```bash
./k8s-delete-resources.sh
```

### Step 2. Switch to Kubernetes Scripts

ThingsBoard uses a separate repository of Kubernetes scripts with additional components. Clone it into a separate directory:

<Code code={cloneCmd} lang="bash" />

Copy your custom settings from the CE configuration (database type, hosts, environment variables, volumes) into the corresponding files of the new scripts.

### Step 3. Run the Database Upgrade

Upgrade the Community Edition database:

```bash
./k8s-upgrade-tb.sh --fromVersion=CE
```

<Aside type="note">
The upgrade script creates a temporary `tb-db-setup` pod using the image from `database-setup.yml`. All third-party services (Zookeeper, Kafka, Valkey, PostgreSQL, and Cassandra if using the `hybrid` database mode) must be in `Running` state before executing this command. Check pod status with:

```bash
kubectl get pods -n thingsboard
```
</Aside>

### Step 4. Deploy ThingsBoard Resources

Deploy the ThingsBoard resources:

```bash
./k8s-deploy-resources.sh
```

### Step 5. Verify the Upgrade

Wait until all pods are running:

```bash
kubectl get pods -n thingsboard
```

The ThingsBoard URL is `http://{your-cluster-ip}`. Get the cluster IP with `minikube ip`.

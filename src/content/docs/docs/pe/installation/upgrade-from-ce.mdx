## Ubuntu

<Aside type="note" title="Before you start">

1. **Upgrade to the latest Community Edition version.** The steps below assume you are already on it. <DocLink product={Products.CE} path="installation/upgrade-instructions" target="_blank">How to upgrade</DocLink>
2. **Get a license key.** <DocLink product={Products.PE} path="installation/register-community-grant" target="_blank">Register in the Community Grant Program</DocLink> for a free perpetual key, or buy one in the <a href="https://license.thingsboard.io/" target="_blank" rel="noopener noreferrer">License Portal</a>. Do this before you upgrade: the key is what licenses {SOURCE_AVAILABLE_FROM_VER}.

</Aside>

### Install Java 25

ThingsBoard 4.4 requires **Java 25**, while ThingsBoard CE runs on Java 17. Install OpenJDK 25 and make it the default Java version **before** upgrading:

```bash
sudo apt update && sudo apt install -y openjdk-25-jdk-headless
sudo update-alternatives --set java /usr/lib/jvm/java-25-openjdk-$(dpkg --print-architecture)/bin/java
```

Verify the installation:

```bash
java -version
```

The reported version must be 25.

### ThingsBoard Package Download

Download the ThingsBoard {PE_FULL_VER} package:

<Code code={ubuntuDownloadCmd} lang="bash" />

### ThingsBoard Service Upgrade

Stop ThingsBoard service if it is running:

```bash
sudo systemctl stop thingsboard
```

Install the ThingsBoard {PE_FULL_VER} package:

<Code code={ubuntuInstallCmd} lang="bash" />

<ConfigFileNote platform="ubuntu" />

Execute the upgrade script:

```bash
sudo /usr/share/thingsboard/bin/install/upgrade.sh --fromVersion=CE
```

### Start the Service

Start ThingsBoard:

```bash
sudo systemctl start thingsboard
```

### Activate the License

If you registered in the <DocLink product={Products.PE} path="installation/register-community-grant" target="_blank">Community Grant Program</DocLink>, your instance is licensed and activated as soon as it starts — nothing to do here. If you bought a license instead, after ThingsBoard starts, open it in your browser and activate your license as described in <DocLink product={Products.PE} path="installation/ubuntu#step-8-license-and-activate-your-instance" target="_blank">Step 8 of the Ubuntu installation guide</DocLink>.

### [Optional] Install the Web Report Component

The Web Report component renders dashboards into PDF and PNG reports. If you need scheduled or on-demand dashboard reports, install it as described in the <DocLink product={Products.PE} path="installation/ubuntu#optional-install-thingsboard-webreport-component" target="_blank">Ubuntu installation guide</DocLink>.

```text

```

<Aside type="note">
Scripts listed below should be executed using Administrator Role.
</Aside>

```text

```

### ThingsBoard Service Upgrade

Stop and remove the ThingsBoard CE service:

```bash
docker compose stop thingsboard-ce
docker compose rm -f thingsboard-ce
```

Update your `docker-compose.yml` according to the <DocLink product={Products.PE} path="installation/docker" target="_blank">Docker installation guide</DocLink>. Make sure to change the image tag to <code>{PE_FULL_VER}</code>, define the required volumes, and add the Web Report service.

Run the upgrade and start the services:

```bash
docker compose run --rm -e UPGRADE_TB=true -e FROM_VERSION="CE" thingsboard
docker compose up -d
```

### Stop ThingsBoard CE Resources

Delete the CE resources from the cluster:

```bash
./k8s-delete-resources.sh
```

### Switch to Kubernetes Scripts

ThingsBoard uses a separate repository of Kubernetes scripts with additional components. Clone it into a separate directory:

<Code code={cloneCmd} lang="bash" />

Copy your custom settings from the CE configuration (database type, hosts, environment variables, volumes) into the corresponding files of the new scripts.

### Run the Database Upgrade

Upgrade the Community Edition database:

```bash
./k8s-upgrade-tb.sh --fromVersion=CE
```

<Aside type="note">
The upgrade script creates a temporary `tb-db-setup` pod using the image from `database-setup.yml`. All third-party services (Zookeeper, Kafka, Valkey, PostgreSQL, and Cassandra if using the `hybrid` database mode) must be in `Running` state before executing this command. Check pod status with:

```bash
kubectl get pods -n thingsboard
```
</Aside>

### Deploy ThingsBoard Resources

Deploy the ThingsBoard resources:

```bash
./k8s-deploy-resources.sh
```

### Verify the Upgrade

Wait until all pods are running:

```bash
kubectl get pods -n thingsboard
```

### Activate the License

If you registered in the <DocLink product={Products.PE} path="installation/register-community-grant" target="_blank">Community Grant Program</DocLink>, your instance is licensed and activated as soon as it starts — nothing to do here. If you bought a license instead, once all pods are running, open `http://{your-cluster-ip}` in your browser (get the IP with `minikube ip`) and activate your license as described in <DocLink product={Products.PE} path="installation/minikube-cluster-setup#step-5-license-and-activate-your-instance" target="_blank">Step 5 of the Minikube cluster setup guide</DocLink>.

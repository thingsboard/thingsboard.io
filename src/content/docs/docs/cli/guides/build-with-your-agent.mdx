You can use ThingsBoard CLI in two ways. You can <DocLink product={Products.CLI} path="reference/commands">run the commands yourself</DocLink>, or you can tell an AI agent what you need. The agent then runs the commands for you. This page is about the agent.

The CLI supports two agents: <a href="https://docs.anthropic.com/en/docs/claude-code/overview" target="_blank" rel="noopener noreferrer nofollow"><strong>Claude Code</strong></a> and <a href="https://antigravity.google/docs/cli/overview" target="_blank" rel="noopener noreferrer nofollow"><strong>Antigravity</strong></a>. If you did not set up the CLI yet, start with the <DocLink product={Products.CLI} path="quickstart">ThingsBoard CLI quickstart</DocLink>.

`tb init` adds the ThingsBoard skills to your project folder. The skills tell the agent how to create devices, dashboards, alarm rules, calculated fields, and demo data. Start the agent in the project folder. The agent then loads the skills.

<Aside>
The CLI writes the agent kit again when it starts: `.claude/` for Claude Code, or `.agents/` and `AGENTS.md` for Antigravity. Do not edit these files. The CLI replaces your changes.
</Aside>

<Aside type="tip">
Did you run `tb init` while the agent was running? Restart the agent to load the skills. In Claude Code, type `/exit`, then run `claude --continue`.
</Aside>

## What you can ask the agent

Write what you need in your own words. You do not write JSON. These are four frequent types of requests.

- **Create a single entity.** Ask for one or a few items, like a calculated field on one device. For a small change like this, the agent can ask "Just these items, or full solution treatment?".

  **Starting point:** the device `Pump-42` is on your tenant. It sends `flowRate`, `powerConsumption`, `pressure`, `rpm`, `temperature`, and `vibration`.

  ```text wrap
  For Pump-42, I want to know the average pressure over the last 5 minutes.
  ```

- **Build something new.** Ask for a full solution: devices and their hierarchy, dashboards, alarm rules, calculated fields, customers, and users. The agent also adds demo data, so the dashboards show values at once.

  **Starting point:** an empty tenant.

  ```text wrap
  I want a dashboard to monitor telemetry for my logistics company. I have several fleets; each fleet contains vans, and every van reports rpm, speed, fuelConsumption, and fuelLevel.

  I'd like an alternative design. On the main page, show my vans in two switchable views: grid and list. When I drill down into a van, give me a button to set a threshold for each telemetry key. The full focus should be the van view: a route map, a SCADA symbol of the van, and value cards right on the widget.

  Aim for a very smart design.
  ```

- **Change a solution.** Add devices, change a threshold, add a dashboard element, or add a new sensor type. The agent changes only the affected items. All other items stay the same.

  **Starting point:** a waste management solution that you made earlier in the ThingsBoard UI.

  ```text wrap
  In my waste management solution I want to be able to set the alarm level for each bin separately, right from the dashboard. Right now every bin alarms at the same fill level, but some bins fill up faster than others, so I need to set a different threshold for each one. Let me click on a bin and type in its own threshold, and the alarm should use that number for that specific bin.
  ```

- **Fix a problem.** Tell the agent which entity does not work, like a calculated field without values or an alarm that does not fire. The agent finds the cause and proposes a fix.

  **Starting point:** a building asset and its temperature sensors are on your tenant. A calculated field that you added in the UI shows no values.

  ```text wrap
  My calculated field "Building Average Temperature" isn't producing any values. The building should show the average temperature across all its temperature sensors, but avgTemperature is just empty. Can you look into why and tell me what's going on?
  ```

You can ask for other results too. Give more details for a better first result: the entities, their hierarchy, who sees what, and the important thresholds.

## Quick builds and full solutions

The agent selects the flow from your request:

- **Quick build.** Your request describes one or two types of devices. It names no customers, users, roles, sites, or hierarchy. The agent builds the result at once, with no questions and no approval stops. It creates one dashboard for you as the tenant administrator. The agent tells you "Quick build: …".
- **Full solution.** Your request names customers, roles, sites, or a hierarchy. The agent asks questions, shows the design, and builds the solution step by step. To get this flow for a small request, add "full solution" to your request.

You can grow a quick build later. Ask the agent to add a customer, a user group, or a role. The agent then adds the role design. Your existing dashboard becomes the dashboard of the new administrator role. Each other role gets its own dashboard.

## Deploy the result

At the end of each flow, the agent asks one question: "Deploy to ThingsBoard and stream live demo data for 5 minutes?". Select one option:

- **Deploy and stream live data.** The agent runs `tb push <solution> --run-tasks`. Then it starts `tb emulator run` in the background. You get the links to the dashboards.
- **Deploy only.** The agent runs `tb push <solution> --run-tasks` and gives you the links.
- **Not now.** The agent shows the command to deploy later.

If your request already says "deploy it" or "show it on a dashboard", the agent deploys without the question. The agent always uses the active profile.

To deploy the same solution to a different ThingsBoard environment, push it with a different profile:

```bash
tb push <solution> --profile staging --run-tasks
```

For profiles, see <DocLink product={Products.CLI} path="reference/configuration">Configuration</DocLink>.

## What the CLI does for you

- **Custom dashboards.** On ThingsBoard 4.4.0.1 and later, the agent writes each dashboard screen as a custom HTML page. Maps and the alarm table stay standard widgets in the page. On older servers, the agent uses grids of standard widgets. For the widget type, see <DocLink product={Products.PAAS} path="reference/widgets/html-widgets/html-container">HTML container widget</DocLink>.
- **Git history for each step.** The agent makes a git commit after each step. You can go back to an earlier version of the solution at any time.
- **The same files for each environment.** You push the same solution files to dev, staging, and production. Each environment has its own profile.
- **Push does not make duplicates.** The CLI finds entities on the server by the IDs in the files. When you push again, the CLI updates the entities. It does not create copies.

## Build and update a solution

<Aside type="tip">
- Give the domain, hierarchy, roles, and important alarms in your first prompt. The first design is then closer to what you need.
- Did someone change entities in the ThingsBoard UI? Run `tb pull` before the next change. Otherwise, the next `tb push` overwrites the UI changes.
- If the result is not correct, tell the agent what to change. The agent handles it as a new change.
</Aside>

Some time after a deployment, the agent can ask "Did you achieve the result you expected?". To send feedback at any time, run `tb feedback`.

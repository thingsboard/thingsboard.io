Build and release the ThingsBoard app version 1.7 or later for iOS and Android.

<Aside type="note">
  For versions earlier than 1.7, see the pre-1.7 release <DocLink product={Products.MOBILE_PE} path="release-before-v1.7">guide</DocLink>.
</Aside>

## Before you start

This guide assumes you have already:

- Cloned the app source code and created an app bundle in **Mobile apps**, as described in the <DocLink product={Products.MOBILE_PE} path="getting-started" bold={false}>Getting started</DocLink> guide.
- Placed the downloaded `configs.json` file in the project root.
- Installed the Flutter version that matches your app version. It is listed in the <DocLink product={Products.MOBILE_PE} path="compatibility" bold={false}>compatibility matrix</DocLink> and in the `.fvmrc` file in the project root.

If you need to change any settings, update them in **Mobile apps**, re-download `configs.json`, and replace the file in your project.

<Aside type="caution">
  Do not edit <code>configs.json</code> manually. Always manage settings in <strong>Mobile apps</strong> to keep all environments in sync and avoid misconfigurations.
</Aside>

To re-download the file:

<Steps>

1. Go to **Mobile apps** → **Bundles** in the left main menu.
2. Click the **Configuration app** button in the row of the target bundle.
3. In the **Configuration dialog**, click **Download file** to get `configs.json`.
4. Replace the existing `configs.json` in your project root, next to `pubspec.yaml`, and rebuild the app.

</Steps>

### App ID, name and version

You don't need to rename the app in the source code. The build reads the app ID and name from `configs.json`:

| Platform | App ID | App name |
|----------|--------|----------|
| Android | `androidApplicationId` (the application ID) | `androidApplicationName` |
| iOS | `iosApplicationId` (the bundle ID) | `iosApplicationName` |

These values come from the application you added to the bundle in **Mobile apps**. Without `--dart-define-from-file configs.json`, the build falls back to the default app ID `org.thingsboard.app`, which you can't publish under your account.

<Aside type="caution">
Starting with version 2.0.0, the default app ID is `org.thingsboard.app` (it was `org.thingsboard.pe.app`). An app that sets its own `androidApplicationId` and `iosApplicationId` in `configs.json` keeps them. A build that relied on the old default gets a new ID, which App Store and Google Play treat as a different app: existing users don't receive it as an update.
</Aside>

The version shown in the stores comes from the `version` field in `pubspec.yaml` (for example, `2.0.0+17` is version `2.0.0`, build `17`). App Store Connect and Google Play reject an upload whose build number was already used, so raise it for every upload, either in `pubspec.yaml` or with the `--build-name` and `--build-number` build options.

## iOS — build and release

Follow the official <a href="https://docs.flutter.dev/deployment/ios" target="_blank" rel="noopener noreferrer">Build and release an iOS app</a> guide to prepare your app for the <a href="https://developer.apple.com/app-store/submitting/" target="_blank" rel="noopener noreferrer">App Store</a> and <a href="https://developer.apple.com/testflight/" target="_blank" rel="noopener noreferrer">TestFlight</a>.

### Configure signing

Starting with version 1.9.1, the iOS project has two targets that are signed and shipped together:

- **Runner** — the app itself.
- **NotificationServiceExtension** — a notification service extension that adds the icon configured in the notification template to push notifications. Its bundle ID is set automatically to `<iosApplicationId>.NotificationServiceExtension`. Don't change it: Apple requires an extension's bundle ID to start with the app's bundle ID.

<Steps>
1. Run any iOS build once, for example `flutter build ios --no-codesign --no-tree-shake-icons --dart-define-from-file configs.json`. It generates `ios/Flutter/AppConfig.xcconfig` with the bundle ID from `configs.json`, so Xcode shows your bundle ID instead of the default one.
2. Open `ios/Runner.xcworkspace` in Xcode (not `Runner.xcodeproj`).
3. Select the **Runner** target, open the **Signing & Capabilities** tab, and select your **Team**.
4. Select the **NotificationServiceExtension** target and select the same **Team**. Both targets come with the ThingsBoard team selected, so the build fails until you change it in both.
5. With **automatic signing**, Xcode registers both App IDs and creates their provisioning profiles. With **manual signing**, also create an App ID and an App Store provisioning profile for `<iosApplicationId>.NotificationServiceExtension`, and select that profile for the extension target.
</Steps>

<Aside type="tip">
  The extension doesn't need its own Firebase configuration, push notification capability or App Group. `GoogleService-Info.plist` stays in the **Runner** target only.
</Aside>

### Build the archive

<Aside type="caution">
  When producing a build archive, you must include both <code>--no-tree-shake-icons</code> and <code>--dart-define-from-file</code> in your build command.
</Aside>

```bash
flutter build ipa --no-tree-shake-icons --dart-define-from-file configs.json
```

The `.ipa` file is written to `build/ios/ipa/`. Upload it to App Store Connect with the <a href="https://apps.apple.com/app/transporter/id1450874784" target="_blank" rel="noopener noreferrer">Transporter</a> app, or open the archive from `build/ios/archive/` in Xcode and click **Distribute App**.

## Android — build and release

Follow the official <a href="https://docs.flutter.dev/deployment/android" target="_blank" rel="noopener noreferrer">Build and release an Android app</a> guide to prepare your app for <a href="https://support.google.com/googleplay/android-developer/answer/9859152" target="_blank" rel="noopener noreferrer">Google Play</a>.

<Aside type="caution">
  Out of the box, the release build in `android/app/build.gradle` is signed with the debug key, so `flutter run --release` works without setup. Google Play rejects apps signed with a debug key. Before the first upload, create an upload keystore and add a release signing config, as described in the <a href="https://docs.flutter.dev/deployment/android#sign-the-app" target="_blank" rel="noopener noreferrer">Sign the app</a> section of the Flutter guide.
</Aside>

<Aside type="caution">
  When producing a build archive, you must include both <code>--no-tree-shake-icons</code> and <code>--dart-define-from-file</code> in your build command.
</Aside>

```bash
flutter build appbundle --no-tree-shake-icons --dart-define-from-file configs.json
```

The app bundle is written to `build/app/outputs/bundle/release/app-release.aab`. Upload it to the Google Play Console.

After the first upload, copy the **SHA-256 certificate fingerprint** of the app signing key from the Google Play Console (**Release → Setup → App Integrity → App Signing**) to the Android application in your Mobile apps bundle. App links and <DocLink product={Products.MOBILE_PE} path="qr-code-settings" bold={false}>QR code login</DocLink> need it.

## Build flags

**`--no-tree-shake-icons`** — prevents Flutter from removing icons that the code doesn't reference directly. The app picks some icons at runtime by name: the icons set in the Mobile apps layout and in notification templates. The iOS notification service extension draws push notification icons from the same icon fonts. Without this flag, those icons are missing or shown as empty boxes.

**`--dart-define-from-file configs.json`** — loads the mobile app configuration from the JSON file downloaded from **Mobile apps**: the server address, app ID and name, app secrets and app links settings. Without it, the build uses the default ThingsBoard settings.

## Troubleshooting

### Signing fails for NotificationServiceExtension

An error such as `Signing for "NotificationServiceExtension" requires a development team` or `No profiles for '…NotificationServiceExtension' were found` means the extension target isn't signed with your team. Complete [Configure signing](#configure-signing) for both targets.

<span id="extension-bundle-id-not-prefixed"></span>

### Embedded binary's bundle identifier is not prefixed with the parent app's bundle identifier

The extension's bundle ID was changed by hand. In the **NotificationServiceExtension** target, set **Bundle Identifier** back to `$(IOSAPPLICATIONID).NotificationServiceExtension` and build again with `--dart-define-from-file configs.json`.

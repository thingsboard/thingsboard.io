The **ThingsBoard License Server** keeps track of every ThingsBoard instance (server process) that runs with your license.

## How Instances Are Registered

When you start ThingsBoard with a license key, the instance registers itself with the License Server and receives an **instance ID**. From then on, the instance periodically sends license check requests to confirm that the license is valid. See <DocLink product={Products.LICENSE} path="what-is-license-server/#architecture" bold={false} target="_blank">Architecture</DocLink> for details.

The **Subscriptions** and **Perpetual licenses** pages of the License Portal show how many production and development instances each license uses.

## Cluster Setup

A single license key can be used by all nodes of a ThingsBoard cluster. You don't need a separate key per node, so adding or removing nodes requires no extra license management.

Each running node counts as one production instance. To run a cluster or a high availability (HA) setup, make sure your license includes enough production instances — you can add them when you create a <DocLink product={Products.LICENSE} path="subscription/" bold={false} target="_blank">subscription</DocLink> or a <DocLink product={Products.LICENSE} path="perpetual/" bold={false} target="_blank">perpetual license</DocLink>.

## Floating Mode

In <a href="https://en.wikipedia.org/wiki/Floating_licensing" target="_blank" rel="noopener noreferrer">floating mode</a>, instances are not tied to specific hardware. You can use the license key on Node 1, then deactivate that node and apply the same key on Node 2.

<Aside type="caution">
Do not run more instances with the same license key than your license allows. If the License Server detects more instances than the license covers, ThingsBoard shuts down the instances.
</Aside>

The Request Connector polls external HTTP(S) API endpoints on a configurable schedule, extracts
device data from the responses, and forwards it to ThingsBoard as attributes and telemetry.
It can also push data to external HTTP(S) APIs in response to shared attribute updates and
RPC commands from ThingsBoard.

To enable this connector, add it to the `connectors` list in `tb_gateway.json` — see the
<DocLink product={props.product} path="config/general">General Configuration</DocLink> reference.

## Section "server"

| Parameter | Default | Description |
|-----------|---------|-------------|
| `host` | `http://127.0.0.1:5000` | Base URL of the external HTTP(S) server |
| `SSLVerify` | `true` | Verify the server's SSL certificate |

## Section "security"

Global authorization credentials sent with every request to the external server. Supported types: `basic`, `oauth2`,
and `anonymous`.

<Tabs>
<TabItem label="Basic">

The connector sends an `Authorization: Basic <base64(username:password)>` header with every request.

| Parameter | Default | Description |
|-----------|---------|-------------|
| `type` | `basic` | Authorization type |
| `username` | `username` | Username |
| `password` | `password` | Password |

```json
{
  "security": {
    "type": "basic",
    "username": "username",
    "password": "password"
  }
}
```

Since ThingsBoard IoT Gateway version 3.8.3, environment variables can be specified for username and password fields. 
This allows you to avoid hardcoding sensitive information in the configuration file and provide it securely at runtime.

To use ENV variables for username and password, you can set them in your environment or define them in your `docker-compose.yml` file.

The following ENV variables are used for Basic authentication configuration:

- `REQUEST_BASIC_USERNAME`
- `REQUEST_BASIC_PASSWORD`

Make attention that if you specify ENV variables for username and password, the values from the configuration file 
will be ignored, and the connector will use the values from the ENV variables instead.

</TabItem>
<TabItem label="OAuth2">

<Aside type="note">
  OAuth2 is available in ThingsBoard IoT Gateway v.3.8.7 and later.
</Aside>

The connector obtains an OAuth 2.0 access token from the authorization server using the client credentials grant and
sends it in the `Authorization: Bearer <token>` header with every request. The token is renewed automatically before
it expires, so the connector keeps working with APIs that issue short-lived tokens.

| Parameter | Default | Description |
|-----------|---------|-------------|
| `type` | `oauth2` | Authorization type |
| `tokenUrl` | | URL for obtaining the access token. The token request uses the `SSLVerify` setting of the connector |
| `clientId` | | Client ID from the API provider |
| `clientSecret` | | Client secret from the API provider |
| `scope` | | *(Optional)* Scopes to request, separated by spaces |
| `clientAuthentication` | `header` | *(Optional)* How the client ID and secret are sent to `tokenUrl`: `header` — in an `Authorization: Basic` header; `body` — as `client_id` and `client_secret` form fields |
| `tokenPrefix` | `Bearer` | *(Optional)* Word placed before the token in the `Authorization` header. To send the token without a prefix, set it to `""` |
| `tokenRefreshRatio` | `0.75` | *(Optional)* Part of the token lifetime after which the token is renewed, a number from `0` to `1` |
| `tokenRequestTimeout` | `10` | *(Optional)* Token request timeout in seconds |
| `tokenRetryDelay` | `10` | *(Optional)* Seconds to wait after a failed token request before the next attempt |
| `defaultExpiresIn` | | *(Optional)* Token lifetime in seconds, used when the token response has no `expires_in` field |

<Aside type="note">
  If the token response has no `expires_in` field and `defaultExpiresIn` is not set, the token is renewed only after
  the server rejects a request with code `401`.
</Aside>

```json
{
  "security": {
    "type": "oauth2",
    "tokenUrl": "http://127.0.0.1:5000/oauth2/token",
    "clientId": "client_id",
    "clientSecret": "client_secret",
    "scope": "read write"
  }
}
```

The `clientId` and `clientSecret` parameters support placeholders in the `${VARIABLE_NAME}` format. This allows you to
keep the credentials out of the configuration file and provide them as environment variables according to your
system's setup:

```json
{
  "security": {
    "type": "oauth2",
    "tokenUrl": "http://127.0.0.1:5000/oauth2/token",
    "clientId": "${API_CLIENT_ID}",
    "clientSecret": "${API_CLIENT_SECRET}"
  }
}
```

<Aside type="note">
  Hardcoded and placeholder values can be mixed in the same parameter. Placeholder names are case-sensitive and must
  exactly match the environment variable names. See
  <DocLink product={props.product} path="config/general/#environment-variables">Environment Variables</DocLink>
  for how to set them. If a variable is not set, the connector does not start and logs an error with the variable name.
</Aside>

</TabItem>
<TabItem label="Anonymous">

No authorization header is sent. Useful for public APIs or testing.

| Parameter | Default | Description |
|-----------|---------|-------------|
| `type` | `anonymous` | Authorization type |

```json
{
  "security": {
    "type": "anonymous"
  }
}
```

</TabItem>
</Tabs>

## Section "mapping"

An array of endpoint configurations. Each entry defines a URL to poll, the HTTP method and
headers, how often to poll, and how to convert the response into ThingsBoard device data.

| Parameter | Default | Description |
|-----------|---------|-------------|
| `url` | `getdata` | URL path appended to `host` for the request |
| `httpMethod` | `GET` | HTTP method (`GET`, `POST`, etc.) |
| `httpHeaders` | `{"ACCEPT": "application/json"}` | Additional HTTP headers |
| `allowRedirects` | `true` | Follow HTTP redirects |
| `timeout` | `0.5` | Request timeout in seconds |
| `scanPeriod` | `5` | Polling interval in seconds |

<Aside type="note">
  You can add multiple objects to the `mapping` array to poll as many endpoints as needed.
</Aside>

### Subsection "converter"

Defines how the HTTP response body is converted into ThingsBoard device data.

<Tabs>
<TabItem label="json">

The default converter. Parses a JSON response body and maps fields to a device name, type,
attributes, and telemetry.

| Parameter | Default | Description |
|-----------|---------|-------------|
| `type` | `json` | Converter type |
| `deviceNameJsonExpression` | `SD8500` | JSON expression to extract the device name; a plain string is used as-is |
| `deviceTypeJsonExpression` | `SD` | JSON expression to extract the device type; a plain string is used as-is |
| `timeout` | `60000` | Milliseconds before a "Device Disconnected" event is triggered |
| `attributes[].type` | `string` | Data type of the attribute value |
| `attributes[].key` | `serialNumber` | Attribute key name in ThingsBoard |
| `attributes[].value` | `${serial}` | JSON-path expression to extract the value from the response |
| `telemetry[].type` | `string` / `integer` | Data type of the telemetry value |
| `telemetry[].key` | `Maintainer` | Telemetry key name in ThingsBoard |
| `telemetry[].value` | `${Developer}` | JSON-path expression to extract the value from the response |
| `telemetry[].tsField` | | *(Optional)* JSON-path expression for a field carrying a datetime string used as the telemetry timestamp |
| `telemetry[].dayfirst` | `false` | *(Optional)* Treat the first number in `tsField` as the day (`true`) or month (`false`) |
| `telemetry[].yearfirst` | `false` | *(Optional)* Treat the first number in `tsField` as the year |

<Aside type="note">
  The `tsField` example below (for the `Pressure` key) illustrates how to supply a custom
  timestamp. If `tsField` is omitted, the `ts` or `timestamp` field from the response is
  used, or the current server time if neither is present.
</Aside>

**Full mapping example:**

```json
{
  "url": "getdata",
  "httpMethod": "GET",
  "httpHeaders": {
    "ACCEPT": "application/json"
  },
  "allowRedirects": true,
  "timeout": 0.5,
  "scanPeriod": 5,
  "converter": {
    "type": "json",
    "deviceNameJsonExpression": "SD8500",
    "deviceTypeJsonExpression": "SD",
    "attributes": [
      {
        "key": "serialNumber",
        "type": "string",
        "value": "${serial}"
      }
    ],
    "telemetry": [
      {
        "key": "Maintainer",
        "type": "string",
        "value": "${Developer}"
      },
      {
        "key": "Pressure",
        "type": "integer",
        "value": "${press}",
        "tsField": "${timestampField}",
        "dayfirst": true
      }
    ]
  }
}
```

You can also combine multiple response fields into a single value using expressions:

```json
{ "key": "combine", "type": "string", "value": "${hum}:${temp}" }
```

</TabItem>
<TabItem label="custom">

| Parameter | Default | Description |

## Section "attributeUpdates"

Optional. When a ThingsBoard shared attribute changes, the gateway sends an HTTP request
to an external URL on the device.

| Parameter | Default | Description |
|-----------|---------|-------------|
| `httpMethod` | `GET` | HTTP method for the outgoing request |
| `httpHeaders` | `{"CONTENT-TYPE": "application/json"}` | Additional HTTP headers |
| `timeout` | `0.5` | Request timeout in seconds |
| `allowRedirects` | `true` | Follow HTTP redirects |
| `deviceNameFilter` | `SD.*` | Regex filter on device name |
| `attributeFilter` | `send_data` | Regex filter on attribute name |
| `requestUrlExpression` | `sensor/${deviceName}/${attributeKey}` | Expression to build the request path appended to `host` |
| `requestValueExpression` | `{"${attributeKey}":"${attributeValue}"}` | Expression to build the request body |

<Aside type="note">
  The connector appends `requestUrlExpression` to `host` to form the request URL. A value that starts with
  `http://` or `https://` is used as the full URL instead.
</Aside>

```json
"attributeUpdates": [
  {
    "httpMethod": "POST",
    "httpHeaders": {
      "CONTENT-TYPE": "application/json"
    },
    "timeout": 0.5,
    "allowRedirects": true,
    "deviceNameFilter": "SD.*",
    "attributeFilter": "send_data",
    "requestUrlExpression": "sensor/${deviceName}/${attributeKey}",
    "requestValueExpression": "{\"${attributeKey}\":\"${attributeValue}\"}"
  }
]
```

## Section "serverSideRpc"

Optional. Maps ThingsBoard RPC commands to outgoing HTTP requests sent to the device.

| Parameter | Default | Description |
|-----------|---------|-------------|
| `deviceNameFilter` | `.*` | Regex filter on device name |
| `methodFilter` | `echo` | Regex filter on RPC method name |
| `requestUrlExpression` | `sensor/${deviceName}/request/${methodName}/${requestId}` | Expression to build the request path appended to `host` |
| `responseTimeout` | `1` | Seconds to wait for a response |
| `httpMethod` | `GET` | HTTP method for the outgoing request |
| `requestValueExpression` | `${params}` | Expression to build the request body |
| `responseValueExpression` | | *(Optional)* Expression that extracts the value to return from a JSON response, for example `${temp}`. Without it, the whole response body is returned |
| `timeout` | `0.5` | Request timeout in seconds |
| `httpHeaders` | `{"CONTENT-TYPE": "application/json"}` | Additional HTTP headers |

<Aside type="note">
  The connector appends `requestUrlExpression` to `host` to form the request URL. A value that starts with
  `http://` or `https://` is used as the full URL instead.
</Aside>

The gateway always waits for the HTTP response and replies to ThingsBoard: `{"result": <response body>}` on success
or `{"error": "<message>"}` on failure.

<Aside type="note">
  With `oauth2` security, set `responseTimeout` with a margin for obtaining a new token. Otherwise, ThingsBoard may
  receive the `Rpc timeout` error even though the request is still sent to the server later.
</Aside>

```json
"serverSideRpc": [
  {
    "deviceNameFilter": ".*",
    "methodFilter": "echo",
    "requestUrlExpression": "sensor/${deviceName}/request/${methodName}/${requestId}",
    "responseTimeout": 1,
    "httpMethod": "GET",
    "requestValueExpression": "${params}",
    "timeout": 0.5,
    "httpHeaders": {
      "Content-Type": "application/json"
    }
  },
  {
    "deviceNameFilter": ".*",
    "methodFilter": "no-reply",
    "requestUrlExpression": "sensor/${deviceName}/request/${methodName}/${requestId}",
    "httpMethod": "POST",
    "requestValueExpression": "${params.hum}",
    "httpHeaders": {
      "Content-Type": "application/json"
    }
  }
]
```

The connector also has built-in `get` and `set` RPC methods that send an HTTP request without configuration. See the
<DocLink product={props.product} path="features/reserved-rpc">Reserved RPC methods</DocLink> guide for details.

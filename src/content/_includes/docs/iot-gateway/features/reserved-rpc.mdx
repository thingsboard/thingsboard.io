Built-in GET/SET RPC methods let you read and write telemetry and attribute values on connected devices
without any additional connector configuration. The method name and parameter string are sent as the
RPC payload from the ThingsBoard RPC debug terminal on the gateway dashboard.

The following connectors support built-in GET/SET RPC methods:

<Tabs>
  <TabItem label="OPC-UA">
    The built-in **GET** and **SET** methods read and write any node by its node ID, for example the one in the `value`
    of a telemetry entry in the connector configuration.

    For example, given a timeseries entry:

    ```json
    {
      "timeseries": [
        {
          "key": "temperature",
          "type": "identifier",
          "value": "${ns=3;i=1001}"
        }
      ]
    }
    ```

    #### GET

    Read the current value of a node by its OPC-UA node ID:

    ```bash
    get ns=3;i=1001;
    ```

    Response:

    ```json
    {"result": {"value": 25.34}}
    ```

  <TabItem label="Modbus">
    #### GET

    Read the value of a Modbus slave register:

    ```bash
    get type=<type>;functionCode=<functionCode>;objectsCount=<objectsCount>;address=<address>;
    ```

    | Parameter | Description |
    |-----------|-------------|
    | `type` | Data type of the value to read |
    | `functionCode` | Modbus function code |
    | `objectsCount` | Number of objects to read |
    | `address` | Register address |

    Example — read a 16-bit integer from register 1 (outdoor temperature):

    ```bash
    get type=16int;functionCode=3;objectsCount=1;address=1;
    ```

    Response:

    ```json
    {"result": 13}
    ```

    <ImageGallery images={[
      {
        src: '/src/assets/images/gateway/get-set-connector-rpc/modbus-get-set-rpc-1.png',
        alt: 'Modbus GET RPC result showing register value',
        caption: 'Modbus GET — reading the outdoor temperature register.',
      },
    ]} />

    #### SET

    Write a value to a Modbus slave register:

    ```bash
    set type=<type>;functionCode=<functionCode>;objectsCount=<objectsCount>;address=<address>;value=<value>;
    ```

    |-----------|-------------|
    | `type` | Data type of the value to write |
    | `functionCode` | Modbus function code |
    | `objectsCount` | Number of objects to write |
    | `address` | Register address |
    | `value` | Value to write |

    Example — write 80 to register 2 (room light level):

    ```bash
    set type=16int;functionCode=6;objectsCount=1;address=2;value=80;
    ```

  <TabItem label="S7">
    Reserved GET/SET RPC methods work differently depending on the PLC family. S7 PLCs support both
    `data` and `tag` addressing, while Siemens Logo! PLCs are addressed using `vmAddress`.

    <Tabs>
      <TabItem label="PLC">
        #### GET

        ##### `data` type addressing

        Read a value from an S7 PLC using `data` type addressing:

        ```bash
        get type=data;dbNumber=<dbNumber>;start=<start>;dataType=<dataType>;size=<size>;bit=<bit>;
        ```

        | Parameter | Description |
        |-----------|-------------|
        | `dbNumber` | DB number for S7 PLCs |
        | `start` | Start address for S7 PLCs |
        | `dataType` | Data type of the value to read |
        | `size` | Size of the parameter in bytes for S7 PLCs |
        | `bit` | Bit number for S7 PLCs. **Only for boolean values** |

        Example — read a boolean status flag from DB1, byte 0, bit 1:

        ```bash
        get type=data;dbNumber=1;start=0;dataType=bool;size=1;bit=1;
        ```

        Response:

        ```json
        {"result": true}
        ```

        <ImageGallery images={[
          {
            src: '/src/assets/images/gateway/get-set-connector-rpc/s7-plc-get-set-rpc-1.png',
            alt: 'S7 PLC GET RPC result showing the status flag value',
            caption: 'S7 PLC GET — reading the current status flag value.',
          },
        ]} />

        ##### `tag` type addressing

        Read a value from an S7 PLC using `tag` type addressing:

        ```bash
        get type=tag;tag=<tag>;
        ```

        | Parameter | Description |
        |-----------|-------------|
        | `tag` | Tag address for S7 PLCs |

        Example:

        ```bash
        get type=tag;tag=DB1.DBD104:REAL;
        ```

        #### SET

        ##### `data` type addressing

        Write a value to an S7 PLC using `data` type addressing:

        ```bash
        set type=data;dbNumber=<dbNumber>;start=<start>;dataType=<dataType>;size=<size>;bit=<bit>;value=<value>;
        ```

        | Parameter | Description |
        |-----------|-------------|
        | `dbNumber` | DB number for S7 PLCs |
        | `start` | Start address for S7 PLCs |
        | `dataType` | Data type of the value to write |
        | `size` | Size of the parameter in bytes for S7 PLCs (optional) |
        | `bit` | Bit number for S7 PLCs. **Only for boolean values** |
        | `value` | Value that will be written to the device|

        Example — set a boolean status flag at DB1, byte 0, bit 1 to `false`:

        ```bash
        set type=data;dbNumber=1;start=0;dataType=bool;size=1;bit=1;value=false;
        ```

    | `variable` | OCPP variable name to read |
    | `variableInstance` | Instance name, if the variable has multiple instances (optional) |
    | `timeout` | Seconds to wait for the Charge Point's response (optional, default 5) |

  <TabItem label="CAN">
    The CAN connector supports only the **SET** method: sending a message to the CAN bus. A `get` request
    returns an error.

    #### SET

    Send a CAN message:

    ```bash
    set nodeId=<id>;type=<type>;byteorder=<byteorder>;isExtendedId=<isExtendedId>;value=<value>;
    ```

    | Parameter | Description |
    |-----------|-------------|
    | `nodeId` | CAN arbitration ID, decimal (`291`) or hexadecimal with the `0x` prefix (`0x123`) |
    | `type` | How to encode `value`: `hex`, `string`, `bool`, `8int`, `8uint`, `16int`, `16uint`, `32int`, `32uint`, `64int`, `64uint`, or `32float` |
    | `byteorder` | Byte order for numeric types: `big` or `little` (optional, default `big`) |
    | `isExtendedId` | `true` for a 29-bit extended ID, `false` for an 11-bit standard ID (optional, default `false`) |
    | `value` | Value to send |

    With `type=hex`, `value` is the message payload as hex digits, for example `0A1B`. With `type=string`, the
    value is sent as ASCII text. Integer types take as many bytes as their size: `16int` takes 2 bytes, and so on.

    Example — send the light level 80 as one unsigned byte to node `0x400`:

    ```bash
    set nodeId=0x400;type=8uint;value=80;
    ```

    Response:

    ```json
    {"result": {"success": true}}
    ```

  <TabItem label="ODBC">
    `get` and `set` work the same way: both run an SQL query or call a stored procedure.

    ```bash
    get query=<query>;value=<arg1>,<arg2>;with_result=<true|false>;
    get procedure_name=<name>;value=<arg1>,<arg2>;with_result=<true|false>;
    ```

    | Parameter | Description |
    |-----------|-------------|
    | `query` | SQL query to run. Use `?` placeholders for arguments. Either `query` or `procedure_name` is required |
    | `procedure_name` | Name of the stored procedure to call |
    | `value` | Comma-separated arguments for the `?` placeholders or the procedure (optional) |
    | `with_result` | `true` to return the first row of the result set (optional, default `false`) |

    <Aside type="note">
      The parameters must be in the order shown above. The query and the arguments cannot contain `;`.
    </Aside>

    With `with_result=true`, the response contains the first row of the result set as an object with column
    names as keys, or `null` if the query returns no rows. A statement that returns no result set, such as `UPDATE`,
    gives an error with `with_result=true`. Without it, the response is `{"result": {"success": true}}`.

    Example — read the latest value of a column:

    ```bash
    get query=SELECT temperature FROM telemetry WHERE device = ? ORDER BY ts DESC LIMIT 1;value=thermostat-1;with_result=true;
    ```

    Response, for example:

    ```json
    {"result": {"temperature": 18.04}}
    ```

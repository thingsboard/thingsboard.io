Install and manage ThingsBoard IoT Gateway remotely with **ThingsBoard Agent**: a Docker container that runs on the target machine, connects to your ThingsBoard server, and deploys the Gateway on its behalf. No SSH access or manual Docker commands are required on the machine.

<Banner variant="pe">ThingsBoard Agent is a <b>ThingsBoard Professional Edition</b> feature. The server side requires ThingsBoard PE or ThingsBoard Cloud; the Gateway itself is open-source.</Banner>

The agent adds remote lifecycle management on top of the Gateway installation:

- **Remote installation:** Deploy the Gateway from the ThingsBoard UI.
- **Upgrades from the cloud:** Push new Gateway versions without touching the machine.
- **Restart and recovery:** Restart the Gateway remotely; the agent restores it if a deployment fails.
- **Monitoring:** Container states, CPU, memory, and live logs in the ThingsBoard UI.
- **Fleet operations:** Update all gateways of a fleet at once with <DocLink product={Products.PE} path='user-guide/agents/bulk-actions'>bulk actions</DocLink>.

## Prerequisites

- ThingsBoard Professional Edition server or a ThingsBoard Cloud tenant.
- Docker installed on the target machine (Linux, amd64 or arm64).
- Outbound network access from the target machine to the ThingsBoard gRPC port (default `7070`).

## Installation

<Steps>
  <ol>
    <li>
      In ThingsBoard, go to **Entities** > **Gateways** and click the **+** icon in the upper-right corner. Enter a name, select the device profile, and click **Create**.
    </li>
    <li>
      In the **Launch command** window, select the **ThingsBoard Agent** option and click **Deploy with Agent**.
    </li>
    <li>
      Select the agent that runs on the target machine. If the machine has no agent yet, create one and run the generated `docker run` command on the target machine first; see <DocLink product={Products.PE} path='user-guide/agents/installation'>Install ThingsBoard Agent</DocLink>.
    </li>
    <li>
      Review the deployment configuration and confirm. The agent pulls the Gateway image, creates the container, and starts it; the **Event progress** dialog shows every step.
    </li>
    <li>
      Verify the result. The Gateway connects to ThingsBoard and appears as active on the Gateways dashboard.
    </li>
  </ol>
</Steps>

## Manage the Gateway

The Gateway runs as an agent-managed <DocLink product={Products.PE} path='user-guide/agents/applications'>application</DocLink>. From the ThingsBoard UI you can:

- Restart or delete the deployment, and view live container logs.
- <DocLink product={Products.PE} path='user-guide/agents/upgrades'>Upgrade</DocLink> to a new Gateway version, with automatic rollback on failure.
- Roll out gateways to many machines with <DocLink product={Products.PE} path='user-guide/agents/agent-profiles'>agent auto-provisioning</DocLink> and the **Gateway** preset.

Gateway configuration works the same as with any other installation: use the <DocLink product={props.product} path='features/remote-configuration'>remote configuration</DocLink> feature or the Gateways dashboard.

<Aside type="note">
To install the Gateway without an agent, use the manual <DocLink product={props.product} path='installation/docker-installation'>Docker Compose installation</DocLink>.
</Aside>

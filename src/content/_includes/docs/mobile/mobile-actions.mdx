Mobile actions are a special subtype of <a href={props.product === Products.MOBILE_PE ? '/docs/pe/user-guide/actions/' : '/docs/user-guide/actions/'}>widget actions</a> that let you trigger native device functions — take a photo, scan a QR code, get the phone's location, make a phone call, and more. The result of each action is passed to a JavaScript function you configure, so you can process it further — for example, save a photo as an entity attribute or use a scanned QR code to claim a device.

## Action types

### Take picture from gallery

Opens the device image gallery so you can select a photo. Returns the selected image as a base64 data URL.

Configure the **processImage** function to handle the result — for example, store the image as an entity attribute to display it later in widgets.

### Take photo

Opens the device camera to capture a photo. Returns the captured image as a base64 data URL.

Configure the **processImage** function to handle the result.

### Open map directions

Takes a location in latitude/longitude format and opens the available maps app to show directions to that location.

Configure the **getLocation** function to extract latitude/longitude from entity attributes — for example, to direct you to a field device's location.

### Open map location

Takes a location in latitude/longitude format and opens the available maps app to display that location on the map.

Configure the **getLocation** function to extract coordinates from entity attributes.

### Scan QR code

Opens the QR code scanner. Returns the scanned value.

Configure the **processQrCode** function to process the result. A common use case is device claiming — the QR code encodes the **device name** and **secret key**, which are then used to claim the device. For details, see <a href={props.product === Products.MOBILE_PE ? '/docs/pe/user-guide/claiming/' : '/docs/user-guide/claiming/'}>Claiming devices</a>.

### Make phone call

Takes a phone number and opens the appropriate app to initiate a call.

Configure the **getPhoneNumber** function to extract the number from entity attributes.

### Get phone location

Reads the current device location from location services. Returns a latitude/longitude pair.

Configure the **processLocation** function to handle the result — for example, save the coordinates as entity attributes to update the entity's position on a map widget.

<ShowFor product={props.product} show={[Products.MOBILE_PE]}>

Turn on **Save location to entity** to have the platform write the coordinates for you, instead of doing it yourself in the function. You then pick a target entity and the data keys to save under, and the function still runs afterwards — with the name of the entity the location was saved to. See <a href="/docs/pe/user-guide/location-tracking/" target="_blank"><b>Location tracking</b></a>.

<ConditionalHeading level={3} id="start-live-location-tracking" showFor="mobile-pe">Start live location tracking</ConditionalHeading>

Starts a background GPS tracking session. Unlike **Get phone location**, which reads one position and finishes, a session keeps streaming fixes and saving each one to the target entity until it is stopped.

The dashboard resolves the target entity, the data keys and the session limits up front, so the app has everything it needs and never looks anything up mid-session. A tracking bar appears across the app while the session runs.

Configure the target entity, the saved keys, the accuracy and the session limits in the widget action — see <a href="/docs/pe/user-guide/location-tracking/#start-live-location-tracking" target="_blank"><b>Location tracking</b></a>. For what the session looks like on the phone, see <DocLink product={props.product} path="live-location-tracking">Live location tracking</DocLink>.

<ConditionalHeading level={3} id="stop-live-location-tracking" showFor="mobile-pe">Stop live location tracking</ConditionalHeading>

Ends the tracking session currently running in the app. It has no configuration of its own — the session already knows where it writes.

A session can also be stopped from the app's tracking bar or tracking page, so a stop action on the dashboard is a convenience rather than a requirement.

</ShowFor>

### Take screenshot

Captures the current phone screen. Returns the image as a base64 data URL.

Configure the **processImage** function to handle the result — for example, store the screenshot as an entity attribute.

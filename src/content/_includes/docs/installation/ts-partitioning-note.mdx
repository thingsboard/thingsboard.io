<Aside type="caution" title="Do not use INDEFINITE time-series partitioning in production">
  <p>With <code>INDEFINITE</code> all time-series data lands in a single partition. On PostgreSQL that turns cleanup from a cheap partition drop into row-by-row deletes: the table bloats, and only <code>VACUUM FULL</code> returns the disk space.</p>
  {!props.postgresOnly && (
    <p>On Cassandra data still expires by native TTL, but every key's whole history becomes one unbounded partition, which degrades reads and compaction.</p>
  )}
  <p>Keep the default <code>MONTHS</code>, or match your write volume — <code>DAYS</code> when it is high, <code>YEARS</code> when it is low. The setting is <code>SQL&#95;POSTGRES&#95;TS&#95;KV&#95;PARTITIONING</code>{!props.postgresOnly && (<> for PostgreSQL and <code>TS&#95;KV&#95;PARTITIONING</code> for Cassandra</>)}.</p>
  <p>Decide before production: existing data is never repartitioned.{!props.postgresOnly && ' On Cassandra, switching away later also hides earlier history — those rows keep partition 0, which queries no longer look up.

`EdgeEventController` exposes REST endpoints for querying edge events: the downlink queue that the **ThingsBoard server** keeps for each Edge, like entity assignments, rule chain pushes, and RPC calls. Call it on the server: it backs the **Downlinks** tab of the Edge. On an Edge node, this log stays empty.

## Endpoints

Base path: `/api/edge/{edgeId}/events`

| Method | Path | Description |
|--------|------|-------------|
| GET | `/api/edge/{edgeId}/events` | Returns a paginated list of edge events. Supports `pageSize`, `page`, `textSearch`, `sortProperty`, `sortOrder`, `startTime`, and `endTime`. Requires `TENANT_ADMIN` or `CUSTOMER_USER` authority. |

## Cloud events vs. edge events

Two event logs help diagnose synchronization:

- **Cloud events** at `/api/edge/events`: Outbound messages queued on Edge waiting to be sent upstream to the server, like telemetry, alarms, and entity changes. Accessible via `EdgeController`.
- **Edge events** at `/api/edge/{edgeId}/events` on the **server**: downlink messages the server sends to the Edge, like entity assignments, rule chain pushes, and RPC calls. Accessible via `EdgeEventController`.

Both queues use the same pagination interface and are useful for diagnosing synchronization issues. If the cloud events queue grows without draining, check the gRPC connection status via <DocLink product={Products.EDGE_PE} path="user-guide/edge-status-events" target="_blank">Edge status & events</DocLink> and <DocLink product={Products.EDGE_PE} path="user-guide/message-statistics" target="_blank">message statistics</DocLink>.

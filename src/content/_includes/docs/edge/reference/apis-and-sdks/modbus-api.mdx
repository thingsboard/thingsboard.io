ThingsBoard Edge acts as a Modbus client (master): it polls the registers and coils of Modbus devices on the local network or on a serial line, and writes values to them. Devices do not initiate connections to Edge.

Available since ThingsBoard Edge **4.4.2**. The Modbus transport is enabled on Edge by default. To turn it off, set the `MODBUS_ENABLED` environment variable to `false`.

**Default port:** 502 TCP (Edge connects to devices on this port)

## Device profile

Modbus devices require a **device profile** with the **Modbus** transport type. The profile defines the request timeout, the number of retries, the poll period, the byte and word order, and the mappings. To create it, go to **Device profiles**, add a device profile, and select **Modbus** as the transport type.

## Device connection

The connection settings are set per device, in the transport configuration of the device:

| Connection | Fields |
|------------|--------|
| TCP | Host, port, framing (Modbus TCP or RTU over TCP), and unit id |
| Serial port | Serial port, baud rate, parity, stop bits, unit id, and optional RS-485 direction control |

The host is resolved and the serial port is opened **on the Edge machine**. For a serial port, use a path that does not change after a reboot, like `/dev/serial/by-id/...`, and give the Edge service access to it. On Linux, add the user to the `dialout` group. In Docker, pass the port to the container with the `--device` option.

## Mappings

Map registers and coils to ThingsBoard keys in the Modbus section of the device profile:

| List | Direction | Result |
|------|-----------|--------|
| Timeseries | Read every poll period | Telemetry |
| Client attributes | Read every poll period or attributes poll period | Client attributes |
| Shared attribute updates | Written when the shared attribute changes | Value in the device |
| RPC | Read or written on an RPC command | RPC response |

Each mapping has a key, a data type, a function code, a 0-based address, and optionally a count, a bit, and a multiplier.

Edge reads the mapped values at each poll period and publishes them as telemetry or attributes. Values are stored locally and synced to the ThingsBoard server over gRPC.

## Polling interval

The poll period is configured in the device profile and can be replaced per device. A period below 100 ms is raised to 100 ms. To change this bound, set `MODBUS_MIN_POLL_PERIOD_MS`.

## RPC commands

The RPC method name selects a mapping of the **RPC** list by its key. A mapping with a read function code returns the value:

```json
{
  "method": "getSetpoint",
  "params": {}
}
```

```json
{"value": 42}
```

A mapping with a write function code writes the value from the params and returns `{"result": "ok"}`:

```json
{
  "method": "setSetpoint",
  "params": 42
}
```

A failed command returns `{"error": "..."}` with the reason, like `Device did not respond in time`.

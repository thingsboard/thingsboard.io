  -v ~/.tb-pe-tcp-udp-integration-logs:/var/log/tb-tcp-udp-integration \\
  -e "RPC_HOST=mytbedge" \\
  -e "RPC_PORT=9090" \\

  --name my-tb-pe-tcp-udp-integration \\
  --network NETWORK_NAME \\
  --restart always \\
  thingsboard/tb-tcp-udp-integration:${PE_FULL_VER}`;

**UDP Integration** receives data from devices that send it over UDP and converts the payload into ThingsBoard telemetry and attributes. It also supports downlink: the Edge can send a message back through the same UDP socket.

<Aside type="caution">
  UDP Integration runs only as a **remote integration**. It is a separate service that you start on the same machine as the Edge, or on another machine that can reach the Edge over the network.
</Aside>

## Prerequisites

- A ThingsBoard server with tenant administrator access. The templates are created there.
- A ThingsBoard Edge PE instance connected to the server.
- Docker on the machine that will run the UDP integration service. UDP port **11560** must be open for incoming packets there.
- The `echo` command and `netcat` (`nc`) to simulate a device.

The example device **SN-001** sends temperature and humidity readings to port **11560**. Pick the payload format that matches your device:

<Tabs>
  <TabItem label="Text">
    ```text
    SN-001,default,temperature,25.7,humidity,69
    ```
  </TabItem>
  <TabItem label="JSON">
    ```json
    [{"deviceName": "SN-001", "deviceType": "default", "temperature": 25.7, "humidity": 69}]
    ```
  </TabItem>
  <TabItem label="Binary">
    ```text
    \x53\x4e\x2d\x30\x30\x31\x64\x65\x66\x61\x75\x6c\x74\x32\x35\x2e\x37\x36\x39
    ```

    | Bytes | Hex | Value | Description |
    |---|---|---|---|
    | 0-5 | `\x53\x4e\x2d\x30\x30\x31` | `SN-001` | Device name |
    | 6-12 | `\x64\x65\x66\x61\x75\x6c\x74` | `default` | Device type |
    | 13-16 | `\x32\x35\x2e\x37` | `25.7` | Temperature |
    | 17-18 | `\x36\x39` | `69` | Humidity |
  </TabItem>
  <TabItem label="Hex">
    ```text
    534e2d30303164656661756c7432352e373639
    ```

    Each pair of hex digits is one byte:

    | Bytes | Hex | Value | Description |
    |---|---|---|---|
    | 0-5 | `534e2d303031` | `SN-001` | Device name |
    | 6-12 | `64656661756c74` | `default` | Device type |
    | 13-16 | `32352e37` | `25.7` | Temperature |
    | 17-18 | `3639` | `69` | Humidity |
  </TabItem>
</Tabs>

## Create converter templates

Converter templates are created on the server. The uplink converter decodes the UDP payload into telemetry and attributes. The downlink converter encodes messages from the rule engine, for example shared attribute updates, into the message sent back to the device.

### Uplink converter

<Steps>

1. On the server, go to **Edge management > Templates** and open the **Converter** tab. Click **Add data converter** and select **Create new converter**.

2. Set **Converter type** to **Uplink**, select **UDP** as the **Integration type**, and enter the name `UDP uplink converter`.

3. In **Main decoding configuration**, select **JS**, paste the script for your payload format, and click **Add**.

   <Tabs>
     <TabItem label="Text">
       ```js maxLines=10 collapsible
       /** Decoder **/

       // decode payload to string
       var strArray = decodeToString(payload);
       var payloadArray = strArray.replace(/\"/g, "").replace(/\s/g, "").replace(/\\n/g, "").split(',');

       var telemetryPayload = {};
       for (var i = 2; i < payloadArray.length; i = i + 2) {
           var telemetryKey = payloadArray[i];
           var telemetryValue = parseFloat(payloadArray[i + 1]);
           telemetryPayload[telemetryKey] = telemetryValue;
       }

       // Result object with device attributes/telemetry data
       var result = {
           deviceName: payloadArray[0],
           deviceType: payloadArray[1],
           telemetry: telemetryPayload,
           attributes: {}
       };

       function decodeToString(payload) {
          return String.fromCharCode.apply(String, payload);
       }

       return result;
       ```
     </TabItem>
     <TabItem label="JSON">
       ```js maxLines=10 collapsible
       /** Decoder **/

       // decode payload to JSON
       var data = decodeToJson(payload);

       var result = {
          deviceName: data.deviceName,
          deviceType: data.deviceType,
          attributes: {},
          telemetry: {
              temperature: data.temperature,
              humidity: data.humidity
          }
       };

       function decodeToString(payload) {
          return String.fromCharCode.apply(String, payload);
       }

       function decodeToJson(payload) {
          var str = decodeToString(payload);
          return JSON.parse(str);
       }

       return result;
       ```
     </TabItem>
     <TabItem label="Binary">
       ```js maxLines=10 collapsible
       /** Decoder **/

       // decode payload to string
       var payloadStr = decodeToString(payload);

       var deviceName = payloadStr.substring(0, 6);
       var deviceType = payloadStr.substring(6, 13);

       var result = {
          deviceName: deviceName,
          deviceType: deviceType,
          attributes: {},
          telemetry: {
              temperature: parseFloat(payloadStr.substring(13, 17)),
              humidity: parseFloat(payloadStr.substring(17, 19))
          }
       };

       function decodeToString(payload) {
          return String.fromCharCode.apply(String, payload);
       }

       return result;
       ```
     </TabItem>
     <TabItem label="Hex">
       ```js maxLines=10 collapsible
       /** Decoder **/

       // decode payload to JSON — HEX handler wraps the hex string in a reports structure
       var data = decodeToJson(payload).reports[0].value;

       var result = {
           deviceName: hexToString(data.substring(0, 12)),
           deviceType: hexToString(data.substring(12, 26)),
           telemetry: {
               temperature: parseFloat(hexToString(data.substring(26, 34))),
               humidity: parseFloat(hexToString(data.substring(34, 38))),
           }
       };

       function decodeToString(payload) {
           return String.fromCharCode.apply(String, payload);
       }

       function hexToString(hex) {
           var str = '';
           for (var i = 0; i < hex.length; i += 2) {
               var notNullValue = parseInt(hex.substr(i, 2), 16);
               if (notNullValue) {
                   str += String.fromCharCode(notNullValue);
               }
           }
           return str;
       }

       function decodeToJson(payload) {
           var str = decodeToString(payload);
           return JSON.parse(str);
       }

       return result;
       ```
     </TabItem>
   </Tabs>

</Steps>

<Aside type="note">
  To see every processed message on the **Events** tab while you test, click the debug button in the dialog (it shows **Failures** by default) and select **All messages (15 min)**.
</Aside>

To change a converter later, open it on the **Converter** tab, click the pencil icon, edit the script, and click the checkmark icon. The change is pushed to every Edge that uses it.

### Downlink converter

<Steps>

1. On the **Converter** tab, click **Add data converter** and select **Create new converter**.

2. Set **Converter type** to **Downlink**, select **UDP** as the **Integration type**, and enter the name `UDP downlink converter`.

3. In **Main encoding configuration**, select **JS**, paste the following script, and click **Add**:

   ```js maxLines=10 collapsible
   // Encode downlink data from incoming Rule Engine message

   // msg - JSON message payload
   // msgType - e.g. 'ATTRIBUTES_UPDATED', 'POST_TELEMETRY_REQUEST'
   // metadata - key/value pairs with message metadata
   // integrationMetadata - key/value pairs defined in the Integration

   var result = {
       // downlink data content type: JSON, TEXT or BINARY (base64 format)
       contentType: "JSON",

       // downlink data
       data: JSON.stringify(msg),

       // Optional metadata object presented in key/value format
       metadata: {}
   };

   return result;
   ```

</Steps>

## Create integration template

<Steps>

1. On the server, go to **Edge management > Templates**, open the **Integration** tab, and click **Add integration**.

2. On the **Basic settings** step, select **UDP** as the **Integration type**. Keep the name `UDP integration` or enter your own. Click **Next**.

3. On the **Uplink data converter** step, select **Select existing**, choose `UDP uplink converter`, and click **Next**.

4. On the **Downlink data converter** step, select **Select existing**, choose `UDP downlink converter`, and click **Next**.

5. On the **Connection** step, keep **Port** at `11560` (or enter another free port). Under **Handler Configuration**, select the handler for your payload format:

   <Tabs>
     <TabItem label="Text">
       | Field | Value |
       |---|---|
       | **Handler Configuration** | **TEXT** |
       | **Charset Name** | `UTF-8` (the default) |
     </TabItem>
     <TabItem label="JSON">
       | Field | Value |
       |---|---|
       | **Handler Configuration** | **JSON** |
     </TabItem>
     <TabItem label="Binary">
       | Field | Value |
       |---|---|
       | **Handler Configuration** | **BINARY** (the default) |
     </TabItem>
     <TabItem label="Hex">
       | Field | Value |
       |---|---|
       | **Handler Configuration** | **HEX** |
     </TabItem>
   </Tabs>

6. **Execute remotely** is enabled and cannot be turned off, because UDP Integration runs only as a remote service. Copy the **Integration key** and **Integration secret** shown under it. You need them to start the service.

7. Click **Add**.

</Steps>

The other settings on the **Connection** step keep their defaults:

| Setting | Description |
|---|---|
| **Size of the buffer for inbound socket (in KB)** | Socket receive buffer size. |
| **Cache Size** | Maximum number of cached UDP sessions. |
| **Cache time to live in minutes** | How long a UDP session stays in the cache. |
| **Enable broadcast - integration will accepts broadcast address packets** | Accepts packets sent to the broadcast address. |

<Aside type="note">
  The debug button on the **Basic settings** step is set to **15 min** by default, so the **Events** tab of the integration shows all messages for the first 15 minutes. After that, only failures are stored. You can copy the key and secret later as well: open the template and expand **Execute remotely**.
</Aside>

## Assign the integration to the Edge

<Steps>

1. On the server, go to **Edge management > Edges**, open the Edge, and go to its **Assignments** tab.

2. In **Integrations**, click **Assign integration to this edge**, select `UDP integration`, and click **Assign**.

3. Log in to the Edge and go to **Integrations > Integrations**. The UDP integration is listed there.

</Steps>

## Install and run the remote UDP integration

The remote service connects to the Edge through the integration RPC port, **9090** by default (`INTEGRATIONS_RPC_PORT` in `tb-edge.yml`), and identifies itself with the **Integration key** and **Integration secret** of the template. See also <DocLink product={props.product} path="user-guide/integrations/remote-integrations">Remote integrations</DocLink>.

<Tabs>
  <TabItem label="Docker (Linux / Mac)">
    <Steps>

    1. Pull the image:

       <Code lang="bash" code={`docker pull thingsboard/tb-tcp-udp-integration:${PE_FULL_VER}`} />

    2. Create a directory for the logs:

       ```bash
       mkdir -p ~/.tb-pe-tcp-udp-integration-logs && sudo chown -R 799:799 ~/.tb-pe-tcp-udp-integration-logs
       ```

    3. Start the service. Replace the placeholders with your values:

       <Code lang="bash" code={udpDockerRun} />

       | Parameter | Description |
       |---|---|
       | `mytbedge` | Hostname of the Edge service |
       | `9090` | Integration RPC port of the Edge |
       | `-p 11560:11560/udp` | Publishes UDP port 11560 of the container on the host |
       | `YOUR_ROUTING_KEY` | **Integration key** of the template |
       | `YOUR_SECRET` | **Integration secret** of the template |
       | `NETWORK_NAME` | Docker network of the Edge container. Find it with `docker network ls`. |

    </Steps>

    To detach from the container without stopping it, press **Ctrl+p** then **Ctrl+q**. Useful commands:

    ```bash
    docker attach my-tb-pe-tcp-udp-integration  # reattach to the logs
    docker stop my-tb-pe-tcp-udp-integration
    docker start my-tb-pe-tcp-udp-integration
    ```
  </TabItem>
</Tabs>

Once the service is running, it listens on UDP port **11560**.

## Send an uplink message

<Steps>

1. Send a test message with `echo` and `nc`. Pick the command for your payload format:

   <Tabs>
     <TabItem label="Text">
       ```bash
       echo -e 'SN-001,default,temperature,25.7,humidity,69' | nc -w5 -u 127.0.0.1 11560
       ```
     </TabItem>
     <TabItem label="JSON">
       ```bash
       echo -e -n '{"deviceName": "SN-001", "deviceType": "default", "temperature": 25.7, "humidity": 69}' | nc -w60 -u 127.0.0.1 11560
       ```
     </TabItem>
     <TabItem label="Binary">
       ```bash
       echo -e -n '\x53\x4e\x2d\x30\x30\x31\x64\x65\x66\x61\x75\x6c\x74\x32\x35\x2e\x37\x36\x39' | nc -w5 -u 127.0.0.1 11560
       ```
     </TabItem>
     <TabItem label="Hex">
       ```bash
       echo -e -n '534e2d30303164656661756c7432352e373639' | xxd -r -p | nc -w5 -u 127.0.0.1 11560
       ```
     </TabItem>
   </Tabs>

2. On the Edge, go to **Integrations > Integrations**, open the UDP integration, and select the **Events** tab. An **Uplink** event with status **OK** appears.

3. The device **SN-001** is created automatically. On the Edge, go to **Devices & assets > Devices**, open it, and select the **Latest telemetry** tab to see the received values.

4. To see how the converter processed the message, go to **Integrations > Data converters**, open `UDP uplink converter`, and select the **Events** tab. Click the three dots in the **In** column to see the raw payload, or in the **Out** column to see the decoded result.

</Steps>

## Configure the rule chain for downlinks

To send messages from the rule engine to the integration, add an **integration downlink** node to the root rule chain of the Edge.

<Aside type="note">
  On Edge versions before 4.0, rule chains cannot be edited on the Edge. Edit the **Edge Root Rule Chain** template on the server instead (**Edge management > Templates**, **Rule chain** tab). The change is pushed to the Edge.
</Aside>

<Steps>

1. On the Edge, go to **Data processing > Rule chains** and open **Edge Root Rule Chain**.

2. In the node search field, type `integration downlink` and drag the **integration downlink** node onto the canvas.

3. Enter a name, select `UDP integration` in the **Integration** field, and click **Add**.

4. Connect the **message type switch** node to the new node and select the **Attributes Updated** link label.

5. Click the checkmark icon to save the rule chain.

</Steps>

## Send a downlink message

The integration sends the downlink to the address the device last sent a packet from, as long as its UDP session is still cached. In the test below, `nc` sends the uplink and then waits 120 seconds for the response.

<Steps>

1. Send an uplink message with `-q120`, so that `nc` keeps waiting for the response:

   <Tabs>
     <TabItem label="Text">
       ```bash
       echo -e 'SN-001,default,temperature,25.7,humidity,69' | nc -q120 -u 127.0.0.1 11560
       ```
     </TabItem>
     <TabItem label="JSON">
       ```bash
       echo -e -n '{"deviceName": "SN-001", "deviceType": "default", "temperature": 25.7, "humidity": 69}' | nc -q120 -u 127.0.0.1 11560
       ```
     </TabItem>
     <TabItem label="Binary">
       ```bash
       echo -e -n '\x53\x4e\x2d\x30\x30\x31\x64\x65\x66\x61\x75\x6c\x74\x32\x35\x2e\x37\x36\x39' | nc -q120 -u 127.0.0.1 11560
       ```
     </TabItem>
     <TabItem label="Hex">
       ```bash
       echo -e -n '534e2d30303164656661756c7432352e373639' | xxd -r -p | nc -q120 -u 127.0.0.1 11560
       ```
     </TabItem>
   </Tabs>

2. Within these 120 seconds, on the Edge, go to **Devices & assets > Devices**, open **SN-001**, and select the **Attributes** tab. Select the **Shared attributes** scope, click **+**, enter the key `firmware` and the value `v1.0`, and click **Add**.

3. Open the **Events** tab of the integration. A **Downlink** event with status **OK** appears.

4. The terminal prints the response from the Edge:

   ```json
   {"firmware":"v1.0"}
   ```

</Steps>

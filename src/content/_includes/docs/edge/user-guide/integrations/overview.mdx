Edge integrations connect ThingsBoard Edge to external brokers and servers, such as MQTT, HTTP, CoAP, OPC-UA, TCP, and UDP. Incoming data is processed on the Edge before it is synchronized with the server.

They work like integrations on the ThingsBoard server, with one key difference: you do not create the integration on the Edge. You create **integration templates** and **converter templates** on the server and assign them to one or more Edges. Each Edge receives a copy and runs it.

## Deployment options

Each integration can run in one of two modes.

### Embedded integrations

An embedded integration runs inside the main ThingsBoard Edge process.

<ImageGallery images={[
  {
    src: '/src/assets/images/docs/edge/user-guide/integrations/edge-integrations.svg',
    alt: 'Embedded integration architecture: external data source connects directly to ThingsBoard Edge, which forwards data to the ThingsBoard Server',
  },
]} />

**Advantages:**
- No extra packages to install. The integration is deployed in a few clicks from the UI.
- Minimal message delivery latency.

**Trade-offs:**
- Shares CPU, memory, and network connections with the Edge process.
- Lower isolation from the main Edge process.

### Remote integrations

A remote integration runs as a separate process on the local network and streams data to the Edge over the network.

<ImageGallery images={[
  {
    src: '/src/assets/images/docs/edge/user-guide/integrations/remote-integrations.svg',
    alt: 'Remote integration architecture: external data source connects to a remote integration process on the local network, which streams data to ThingsBoard Edge, which forwards to ThingsBoard Server',
  },
]} />

This is useful when the broker or server, for example a local MQTT broker or an OPC-UA server, has no external IP address and cannot be reached by the Edge directly. The remote integration is deployed on the same local network as the broker, pulls data from it, and streams it to the Edge whenever a connection is available. See <DocLink product={props.product} path="user-guide/integrations/remote-integrations">Remote integrations</DocLink>.

**Advantages:**
- Works with servers that have no external IP address.
- Fully isolated from the Edge process.

**Trade-offs:**
- Requires installing and maintaining a separate package.

## Converter templates

A converter template transforms data. An **uplink** converter decodes the raw integration payload into ThingsBoard telemetry and attributes. A **downlink** converter encodes messages from the rule engine into the format the device expects. A tenant administrator creates converter templates on the server:

<Steps>
1. Go to **Edge management > Templates** and open the **Converter** tab.
2. Click **Add data converter** and select **Create new converter**.
3. Set **Converter type** to **Uplink** or **Downlink**, select the **Integration type** the converter is made for, and enter a **Name**.
4. In **Main decoding configuration** (uplink) or **Main encoding configuration** (downlink), select the script language, **TBEL** or **JS**, and enter the decoder or encoder function. For uplink converters, **Advanced decoding parameters** holds optional settings such as **Update only keys list**.
5. Click **Add**.
</Steps>

<Aside type="note">
  To see every processed message on the **Events** tab while you set things up, click the debug button in the dialog (it shows **Failures** by default) and select **All messages (15 min)**. After 15 minutes, only failures are stored again.
</Aside>

You do not assign converter templates to an Edge. When an integration template is assigned to an Edge, its uplink and downlink converters are sent with it.

## Integration templates

When the converter templates are ready, create the integration template. Go to **Edge management > Templates**, open the **Integration** tab, click **Add integration**, and follow the wizard:

| Step | What to do |
|---|---|
| **Basic settings** | Select the **Integration type** and enter a name. |
| **Uplink data converter** | **Create new** creates a converter template in place. **Select existing** links a converter template of this integration type. For some types, such as HTTP and ChirpStack, **Library** offers ready-made converters. |
| **Downlink data converter** | The same options plus **Skip**, which is selected by default. CoAP has no downlink step. |
| **Connection** | The connection fields of the integration type, the **Execute remotely** toggle, and **Advanced settings**. Click **Add**. |

Integration templates do not run on the server. They run on the Edges they are assigned to.

### Assign a template to an Edge

<Steps>
1. Go to **Edge management > Edges**, open the Edge, and go to its **Assignments** tab.
2. In **Integrations**, click **Assign integration to this edge**, select the template, and click **Assign**.
</Steps>

For more details, see <DocLink product={props.product} path="user-guide/edge-management#assign-entities-to-one-edge">Assign entities to an Edge</DocLink>.

On the Edge, the assigned integrations and converters appear under **Integrations > Integrations** and **Integrations > Data converters**. They are read-only there. To change an integration or converter, edit the template on the server. The change is pushed to every Edge that has the template assigned.

### Configuration placeholders

If the same integration template is used on several Edges, but each Edge needs a different value for a field (for example a host address or a base URL), use **placeholders**.

Add a **server attribute** to the Edge and reference it in the template as `${{attributeKey}}`. When the server sends the integration to that Edge, it replaces the placeholder with the attribute value. The template on the server keeps the placeholder; only the copy on the Edge holds the value. If you change the attribute later, the server sends the integration to the Edge again with the new value. This also works when the integration comes from an edge profile: each Edge on the profile fills in the placeholder from its own attribute.

For example, an HTTP integration needs a different **Base URL** on every Edge:

<Steps>
1. On the server, go to **Edge management > Edges**, click the Edge, and open the **Attributes** tab. With the **Server attributes** scope selected, click **+**, enter the key `ipAddress` and the address of this Edge as the value, and click **Add**.
2. On the **Integration** tab of **Edge management > Templates**, open the template and set **Base URL** to `http://${{ipAddress}}`.
3. If the template is not assigned to the Edge yet, assign it as described above.
4. On the Edge, go to **Integrations > Integrations** and open the integration. **Base URL** shows the attribute value.
</Steps>

If an Edge does not have the attribute, ThingsBoard warns you when you save an integration template that is assigned to Edges. The dialog **Edge(s) have missing attribute(s)** lists the Edges and the attributes that are missing.

Add the missing attribute to each listed Edge. Until then, the Edge copy keeps the literal placeholder.

## Edge limitations

The Edge cannot create customers or entity groups. This affects how an uplink converter result is applied on the Edge:

- If the device type referenced in the converter does not exist on the Edge, the `default` device type is used.
- If the target customer is not available on the Edge, the device is assigned to the tenant.
- If the target entity group does not exist on the Edge, the `All` group is used.

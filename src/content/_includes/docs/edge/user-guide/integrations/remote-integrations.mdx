Any ThingsBoard integration can run **remotely**, as a separate service outside the ThingsBoard Edge process. The service runs on the same machine as the Edge or on another machine that can reach the Edge over the network. This guide sets up a remote HTTP integration as an example.

## Prerequisites

- A ThingsBoard server with tenant administrator access. The templates are created there.
- A ThingsBoard Edge PE instance connected to the server.
- A machine for the remote integration service with Docker, or with Ubuntu or CentOS/RHEL for the package install. Port **8082**, the default port of the remote HTTP integration, must be open there.
- `curl` to simulate a device.

## Configure the ThingsBoard server

### Step 1. Create the uplink converter

The uplink converter decodes incoming device data into ThingsBoard telemetry and attributes.

<Steps>

1. On the server, go to **Edge management > Templates** and open the **Converter** tab. Click **Add data converter** and select **Create new converter**.

2. Set **Converter type** to **Uplink**, select **HTTP** as the **Integration type**, and enter the name `HTTP remote uplink converter`.

3. In **Main decoding configuration**, select **JS**, paste the following script, and click **Add**:

   ```js maxLines=10 collapsible
   // decode payload to JSON
   var data = decodeToJson(payload);
   var deviceName = data.deviceName;

   var result = {
     deviceName: deviceName,
     deviceType: 'default',
     attributes: {
       model: data.model,
     },
     telemetry: {
       temperature: data.temperature
     }
   };

   function decodeToString(payload) {
     return String.fromCharCode.apply(String, payload);
   }

   function decodeToJson(payload) {
     var str = decodeToString(payload);
     return JSON.parse(str);
   }

   return result;
   ```

</Steps>

<Aside type="note">
  To see every processed message on the **Events** tab while you test, click the debug button in the dialog (it shows **Failures** by default) and select **All messages (15 min)**. After 15 minutes, only failures are stored again.
</Aside>

### Step 2. Create the remote integration template

<Steps>

1. On the server, go to **Edge management > Templates**, open the **Integration** tab, and click **Add integration**.

2. On the **Basic settings** step, select **HTTP** as the **Integration type** and enter the name `HTTP Demo Remote`. Click **Next**.

3. On the **Uplink data converter** step, select **Select existing**, choose `HTTP remote uplink converter`, and click **Next**. You can also create the converter here with **Create new**.

4. On the **Downlink data converter** step, keep **Skip** selected and click **Skip**.

5. On the **Connection** step, set **Base URL** to `${{remoteHttpIntegrationUrl}}` and turn on **Execute remotely**. ThingsBoard shows the generated **Integration key** and **Integration secret**. Click **Add**.

</Steps>

The `${{remoteHttpIntegrationUrl}}` placeholder is replaced with the value of the Edge server attribute of the same name when the integration is sent to the Edge. See <DocLink product={props.product} path="user-guide/integrations/overview#configuration-placeholders">Configuration placeholders</DocLink>.

### Step 3. Save the integration credentials

The remote service identifies itself with the **Integration key** and **Integration secret** of the template.

<Steps>

1. On the **Integration** tab of **Edge management > Templates**, open the integration you created.
2. Expand **Execute remotely** and copy the **Integration key** and the **Integration secret** with the copy buttons next to them.

</Steps>

### Step 4. Assign the integration to the Edge

Add the `remoteHttpIntegrationUrl` attribute first. It holds the address of the machine where the remote HTTP integration service will run. Without it, the assignment dialog warns **Edge has missing attribute(s)** and the Edge receives the literal placeholder.

<Steps>

1. On the server, go to **Edge management > Edges** and click the Edge.

2. On the **Attributes** tab, with the **Server attributes** scope selected, click **+**.

3. In the **Add attribute** dialog, enter `remoteHttpIntegrationUrl` as the key and `http://IP:8082` as the value, where `IP` is the address of the remote integration machine. Click **Add**.

4. On the **Details** tab, click **Manage integrations**, then **Assign to edge** (+). Select `HTTP Demo Remote` and click **Assign**.

5. Log in to the Edge and go to **Integrations > Integrations**. Open **HTTP Demo Remote**. **Base URL** shows the attribute value instead of the placeholder.

</Steps>

## Install the remote integration service

The service connects to the Edge through the integration RPC port, **9090** by default (`INTEGRATIONS_RPC_PORT` in `tb-edge.yml`), and uses the **Integration key** and **Integration secret** from [Step 3](#step-3-save-the-integration-credentials). Pick the install method and then the integration type.

## Send an uplink message

<Steps>

1. On the Edge, go to **Integrations > Integrations**, open **HTTP Demo Remote**, and copy the **HTTP endpoint URL**. It has the form `http://IP:8082/api/v1/integrations/http/<Integration key>` and points to the remote integration machine, so that machine must be reachable from your client and port **8082** must not be blocked by a firewall.

2. Send a test message. Replace `$YOUR_HTTP_ENDPOINT_URL` with the copied URL:

   ```bash
   curl -v -X POST \
     -d '{"deviceName":"SN-001","temperature":33,"model":"test"}' \
     $YOUR_HTTP_ENDPOINT_URL \
     -H "Content-Type:application/json"
   ```

3. On the Edge, open the **Events** tab of the integration. An **Uplink** event with status **OK** appears.

4. The device **SN-001** is created automatically. Go to **Devices & assets > Devices** on the Edge, open it, and select the **Latest telemetry** tab. The `temperature` key shows `33`.

</Steps>

## Troubleshooting

Check the log files of the service:

- **Docker:** `~/.tb-pe-{type}-integration-logs/`
- **Ubuntu / CentOS:** `/var/log/tb-{type}-integration/`

Look for `INFO` messages that show the latest integration configuration received from the Edge. If there are none, check `RPC_HOST`, `RPC_PORT`, the key, and the secret.

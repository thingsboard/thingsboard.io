<a href="https://www.chirpstack.io/" target="_blank" rel="noopener noreferrer">ChirpStack</a> is an open-source LoRaWAN network server. **ChirpStack Integration** receives the uplink messages ChirpStack forwards over HTTP, decodes them on the Edge, and lets you process and visualize LoRaWAN device data locally, with low latency and without a permanent connection to the server.

<Aside type="note">
  The Edge ChirpStack integration works the same way as the ChirpStack integration on the ThingsBoard server. Only the way it is created and deployed differs. For the full list of settings, see <DocLink product={Products.PE} path="user-guide/integrations/chirpstack" target="_blank">ChirpStack Integration</DocLink>.
</Aside>

## Prerequisites

- A ThingsBoard server with tenant administrator access. The templates are created there.
- A ThingsBoard Edge PE instance connected to the server.
- A ChirpStack network server, installed with <a href="https://www.chirpstack.io/project/guides/docker-compose/" target="_blank" rel="noopener noreferrer">Docker Compose</a> or on <a href="https://www.chirpstack.io/project/guides/debian-ubuntu/" target="_blank" rel="noopener noreferrer">Debian/Ubuntu</a>, that can reach the Edge over HTTP.
- A LoRaWAN device connected to ChirpStack. See <a href="https://www.chirpstack.io/project/guides/connect-device/" target="_blank" rel="noopener noreferrer">Connect a device</a> in the ChirpStack docs.

## Create converter template

The uplink converter decodes the ChirpStack payload into ThingsBoard telemetry and attributes. It is created on the server.

<Steps>

1. On the server, go to **Edge management > Templates** and open the **Converter** tab. Click **Add data converter** and select **Create new converter**.

2. Set **Converter type** to **Uplink**, select **ChirpStack** as the **Integration type**, and enter the name `ChirpStack uplink converter`.

3. Decide how to get the decoder:

   - **Create new**: write or paste your own decoder (next steps).
   - **Library**: select a **Vendor** and a device **Model**. ThingsBoard fills in a ready-made decoder for that device.

4. In **Main decoding configuration**, keep **Entity type** at **Device** and set **Device name**, for example `Chirp Device $eui`. The `$eui` placeholder is replaced by the device EUI from the ChirpStack payload, so the test device in this guide becomes `Chirp Device 24e124538b223213`.

5. Select **TBEL** or **JS** and paste the decoder script into the `function payloadDecoder(payload, metadata)` editor. `payload` is the raw LoRaWAN payload (the base64-decoded `data` field) as a byte array. `metadata` holds the other ChirpStack fields, such as `eui`, `deviceName`, `rssi`, `snr`, and `ts` (the message time in milliseconds). The example decodes a payload with battery, PIR, and daylight channels.

   <Tabs>
     <TabItem label="TBEL (recommended)">
       ```js maxLines=10 collapsible
       // payload  - raw LoRaWAN payload as bytes (the base64-decoded "data" field)
       // metadata - the other ChirpStack fields, for example eui, deviceName, rssi, snr, ts

       function decodePayload(input) {
           var result = { attributes: {}, telemetry: {} };
           var values = { HEX_bytes: bytesToHex(input) };

           var i = 0;
           while (i + 1 < input.length) {
               var channelId = input[i++];
               var channelType = input[i++];
               if (channelId == 0x01 && channelType == 0x75) {
                   values.battery = input[i++];
               } else if (channelId == 0x03 && channelType == 0x00) {
                   values.pir = input[i++] == 0 ? "normal" : "trigger";
               } else if (channelId == 0x04 && channelType == 0x00) {
                   values.daylight = input[i++] == 0 ? "dark" : "light";
               } else {
                   break;
               }
           }

           result.telemetry = { ts: metadata.ts, values: values };
           return result;
       }

       var result = decodePayload(payload);
       return result;
       ```
     </TabItem>
     <TabItem label="JavaScript">
       ```js maxLines=10 collapsible
       // payload  - raw LoRaWAN payload as bytes (the base64-decoded "data" field)
       // metadata - the other ChirpStack fields, for example eui, deviceName, rssi, snr, ts

       function decodePayload(input) {
           var result = { attributes: {}, telemetry: {} };
           var values = { HEX_bytes: bytesToHex(input) };

           var i = 0;
           while (i + 1 < input.length) {
               var channelId = input[i++];
               var channelType = input[i++];
               if (channelId == 0x01 && channelType == 0x75) {
                   values.battery = input[i++];
               } else if (channelId == 0x03 && channelType == 0x00) {
                   values.pir = input[i++] == 0 ? "normal" : "trigger";
               } else if (channelId == 0x04 && channelType == 0x00) {
                   values.daylight = input[i++] == 0 ? "dark" : "light";
               } else {
                   break;
               }
           }

           result.telemetry = { ts: metadata.ts, values: values };
           return result;
       }

       function bytesToHex(bytes) {
           var hex = '';
           for (var j = 0; j < bytes.length; j++) {
               hex += ('0' + (bytes[j] & 0xFF).toString(16)).slice(-2);
           }
           return hex;
       }

       var result = decodePayload(payload);
       return result;
       ```
     </TabItem>
   </Tabs>

6. Optionally expand **Advanced decoding parameters**. **Device profile name**, **Device label**, **Customer name**, and **Device group name** accept the same `$`-placeholders as the device name. The **Telemetry** and **Attributes** lists choose which keys of the ChirpStack payload are saved. **Update only keys list** saves a key only when its value changed.

7. Click **Add**.

</Steps>

<Aside type="note">
  To see every processed message on the **Events** tab while you test, click the debug button in the dialog (it shows **Failures** by default) and select **All messages (15 min)**.
</Aside>

## Create integration template

<Steps>

1. On the server, go to **Edge management > Templates**, open the **Integration** tab, and click **Add integration**.

2. On the **Basic settings** step, select **ChirpStack** as the **Integration type**. Keep the name `ChirpStack integration` or enter your own. Click **Next**.

3. On the **Uplink data converter** step, select **Select existing**, choose `ChirpStack uplink converter`, and click **Next**.

4. On the **Downlink data converter** step, keep **Skip** selected and click **Skip**. This guide does not send downlinks.

5. On the **Connection** step, fill in the fields:

   | Field | Value |
   |---|---|
   | **Base URL** | The URL of the Edge, for example `http://10.7.3.0:8080`. The default is the server URL, so replace it. |
   | **HTTP endpoint URL** | Built from the Base URL. Copy it; ChirpStack posts the uplinks to this URL. |
   | **Use API for ChirpStack 4+** | Keep enabled for ChirpStack v4. |
   | **Allow downlink** | Keep disabled. Enable it only if you want to send downlinks; it unlocks **Application server URL** (the ChirpStack REST API, for example `http://chirpstack-server-ip:8090`) and **Application server API Token** (an API key from **Tenant > API Keys** in the ChirpStack UI). |

6. Click **Add**.

</Steps>

<Aside type="note">
  If the Edges use different addresses, set **Base URL** to a placeholder such as `${{baseUrl}}` and add a `baseUrl` server attribute to each Edge. See <DocLink product={props.product} path="user-guide/integrations/overview#configuration-placeholders">Configuration placeholders</DocLink>. The debug button on the **Basic settings** step is set to **15 min** by default, so the **Events** tab shows all messages for the first 15 minutes; after that, only failures are stored.
</Aside>

## Assign the integration to the Edge

<Steps>

1. On the server, go to **Edge management > Edges** and click the Edge. On the **Details** tab, click **Manage integrations**.

2. Click **Assign to edge** (+), select `ChirpStack integration`, and click **Assign**.

3. Log in to the Edge and go to **Integrations > Integrations**. The ChirpStack integration is listed there. Open it to copy the **HTTP endpoint URL** if you have not done so yet.

</Steps>

## Configure the ChirpStack application

Log in to the ChirpStack UI at `http://chirpstack-server-ip:8080`. The default user name and password are `admin` / `admin`.

### Add a device profile

<Steps>

1. Go to **Tenant > Device Profiles** and click **Add device profile**.

2. On the **General** tab, fill in the required fields:

   | Field | Description |
   |---|---|
   | **Name** | Device profile name |
   | **Region** | LoRaWAN regional parameters |
   | **MAC Version** | LoRaWAN MAC version the device uses |
   | **Regional parameters revision** | Parameter set version for your region |
   | **ADR Algorithm** | Adaptive data rate logic |
   | **Expect uplink interval (secs)** | Expected interval between uplink messages |

3. Click **Submit**.

</Steps>

### Add the HTTP integration

<Steps>

1. Go to **Tenant > Applications**, click **Add application**, enter a name, and click **Submit**.

2. Open the **Integrations** tab of the application. Find **HTTP** in the list and click **+**.

3. Keep **Payload encoding** at **JSON**. Paste the **HTTP endpoint URL** of the ThingsBoard integration into **Event endpoint URL(s)** and click **Submit**.

</Steps>

### Add the device

<Steps>

1. Open the **Devices** tab of the application and click **Add device**.

2. On the **Device** tab, fill in the required fields:

   | Field | Description |
   |---|---|
   | **Name** | Device name |
   | **Device EUI (EUI64)** | Unique 64-bit identifier of the LoRaWAN device |
   | **Byte order** | Byte order of the DevEUI (MSB or LSB) |
   | **Device profile** | The device profile created above |

3. Click **Submit**.

</Steps>

### Add the gateway (optional)

For a test setup you can skip this. To add a gateway, go to **Tenant > Gateways**, click **Add gateway**, fill in **Name**, **Gateway ID (EUI64)**, and **Stats interval (secs)**, and click **Submit**.

## Send an uplink message

In production, ChirpStack forwards every uplink of the device to the integration. For a test, use the <a href="https://github.com/brocaar/chirpstack-simulator" target="_blank" rel="noopener noreferrer">ChirpStack device simulator</a>, or post a message in the ChirpStack format to the integration endpoint yourself:

```bash maxLines=10 collapsible
curl -v -X POST -d '{
    "deduplicationId": "7658d04d-7f1c-4eb6-900b-d948f3061a9d",
    "time": "2025-06-13T12:44:52.653+00:00",
    "deviceInfo": {
        "tenantId": "6e073e9a-6b4f-4747-b22c-7507568debfb",
        "tenantName": "ChirpStack",
        "applicationId": "c3f2c4aa-07c8-4d6c-8a86-7ea2d4a31dca",
        "applicationName": "Sample Application",
        "deviceProfileId": "d8ee6c09-414c-4b2e-888a-8e8f86e3187a",
        "deviceProfileName": "Default device profile",
        "deviceName": "chirp device",
        "devEui": "24e124538b223213",
        "deviceClassEnabled": "CLASS_A",
        "tags": {}
    },
    "devAddr": "01a44c4c",
    "adr": true,
    "dr": 5,
    "fCnt": 153,
    "fPort": 84,
    "confirmed": false,
    "data": "AXU9AwABBAAB",
    "rxInfo": [{
        "gatewayId": "e4e124dadef64eee",
        "uplinkId": 25127,
        "gwTime": "2025-06-13T12:44:52.653481+00:00",
        "nsTime": "2025-06-13T12:44:52.670509207+00:00",
        "timeSinceGpsEpoch": "1433853910.653s",
        "rssi": -68,
        "snr": 13.2,
        "channel": 4,
        "location": {},
        "context": "Hw9+zQ==",
        "crcStatus": "CRC_OK"
    }],
    "txInfo": {
        "frequency": 867300000,
        "modulation": {
            "lora": {
                "bandwidth": 125000,
                "spreadingFactor": 7,
                "codeRate": "CR_4_5"
            }
        }
    },
    "regionConfigId": "eu868"
}'  $YOUR_HTTP_ENDPOINT_URL -H "Content-Type:application/json"
```

Replace these values with your own:

| Value | Description |
|---|---|
| `deduplicationId` | Any UUID v4 |
| `tenantId` | Your ChirpStack tenant ID |
| `applicationId`, `applicationName` | ChirpStack application ID and name |
| `deviceProfileId`, `deviceProfileName` | ChirpStack device profile ID and name |
| `devEui` | Device EUI of the ChirpStack device |
| `gatewayId` | ChirpStack gateway ID |
| `$YOUR_HTTP_ENDPOINT_URL` | **HTTP endpoint URL** of the ThingsBoard integration |

Then check the result on the Edge:

<Steps>

1. Go to **Integrations > Integrations**, open the ChirpStack integration, and select the **Events** tab. An **Uplink** event with status **OK** appears. Click the three dots in the **Message** column to see the raw payload.

2. The device **Chirp Device 24e124538b223213** is created automatically (`$eui` is replaced by the `devEui` of the payload). Go to **Devices & assets > Devices**, open it, and select the **Latest telemetry** tab. The test payload decodes to `battery` `61`, `pir` `trigger`, and `daylight` `light`. The keys from the **Telemetry** list, such as `rssi` and `snr`, are saved as well.

3. To see how the converter processed the message, go to **Integrations > Data converters**, open `ChirpStack uplink converter`, and select the **Events** tab. The **In** column shows the raw payload, the **Out** column the decoded telemetry and attributes.

</Steps>

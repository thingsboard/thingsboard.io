The Edge status and cloud events pages are diagnostic tools available on the Edge instance itself, not on the server. Use them on-site during installation or when troubleshooting data delivery issues.

## Edge status page

The **Status** page confirms whether the Edge is connected to the server and displays the configuration used during installation. Use it on-site to verify the routing key or check when the Edge last connected.

Log in to the Edge and go to **Edge > Status**. The page shows the following fields:

## Cloud events

The **Cloud events** page shows all events that Edge has pushed to the server. Use it to check that telemetry, alarms, and other data reach the server, especially when data is missing on the server. Events with a **Pending** status indicate a backlog that has not yet been delivered.

Log in to the Edge and go to **Edge > Cloud events**. Each row in the table contains:

| Column | Description |
|--------|-------------|
| **Created time** | When the event was created, for example `2026-10-06 09:55:42` |
| **Action** | What the Edge sent: a change, for example **Added**, **Updated**, **Deleted**, **Attributes Updated**, **Timeseries Updated**, **RPC Call**, **Alarm Ack**, or **Alarm Clear**; or a request for data from the server, for example **Attributes Request**, **Relation Request**, or **Credentials Request** |
| **Entity type** | The type of entity that generated the event |
| **Entity ID** | Unique identifier of the entity |
| **Status** | **Deployed:** The event was pushed to the server. **Pending:** The event is stored locally and will be pushed when connectivity is restored. |
| **Data** | Click **Details** (…) to view the full payload. Not available for **Added** and **Deleted** events |

By default, the page shows the events of the last day. To change the range, click the time window button at the top of the page (it shows the current range, for example **last 1 day**).

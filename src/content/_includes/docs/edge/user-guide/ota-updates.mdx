OTA updates on ThingsBoard Edge follow the same model as on the ThingsBoard server. Firmware and software packages are created on the server, automatically propagated to each connected Edge instance, and then assigned to devices or device profiles on the Edge.

<DocImage src="/src/assets/images/docs/edge/user-guide/ota-updates.svg" alt="OTA update flow: firmware package created on the ThingsBoard server is auto-propagated to the Edge instance, then assigned to a device or device profile to trigger the update" width="800px" />

<Aside type="caution">
OTA update packages can only be created, modified, or deleted on the ThingsBoard server. The **OTA updates** page on the Edge has no option to add a package.
</Aside>

For a general overview of how OTA updates work, see <DocLink product={props.product} path="user-guide/ota-updates" target="_blank">OTA updates</DocLink>.

## Create an OTA update package

<Steps>
1. Log in to your ThingsBoard server and go to **Devices & assets > OTA updates**.

2. Click **Add package** and fill in the fields:
   - **Title:** The package name.
   - **Version:** The package version number.
   - **Version tag:** Populated automatically. Enter a custom value only if it must match the version string reported by the device.
   - **Device profile:** The target device profile.
   - **Package type:** **Firmware** or **Software**.
   - **Source:** **Upload binary file** to upload a file from your computer, or **Use external URL** and enter the **Direct URL** of the package.

3. Click **Add**. The package appears in the list.

   Once uploaded, the title, version, device profile, and package type cannot be modified.
</Steps>

## Verify the package on Edge

After the package is created on the server, ThingsBoard automatically propagates it to all connected Edge instances.

<Steps>
1. Log in to the Edge and go to **Devices & assets > OTA updates**.

2. Confirm the package appears in the list.

   If the package is missing, check the <DocLink product={props.product} path="user-guide/edge-status-events" target="_blank">Cloud events</DocLink> page on the Edge for sync errors.
</Steps>

## Deploy the package to devices

After the package is available on Edge, assign it to devices. You can assign it to a single device or to a device profile. Any device using that profile, including devices added later, receives the update automatically.

### By device

<Steps>
1. Go to **Devices & assets > Devices** and open the target device.

2. On the **Details** tab, click the pencil icon (**Toggle edit mode**) and find the **Assigned firmware** or **Assigned software** field, depending on the package type.

3. Select the package from the dropdown and click **Apply changes**.

   ThingsBoard Edge sends the update to the device. Monitor the update progress in the device's **Attributes**. The `fw_state` or `sw_state` attribute changes from `DOWNLOADING` through `UPDATING` to `UPDATED` once the device confirms the new version.
</Steps>

### By device profile

<Steps>
1. Go to **Devices & assets > Device profiles** and open the target profile.

2. On the **Details** tab, click the pencil icon (**Toggle edit mode**) and find the **Assigned firmware** and **Assigned software** fields.

3. Select the firmware and/or software package and click **Apply changes**.

   All current and future devices using this profile receive the update notification.
</Steps>

<Aside type="note">
The device must implement the ThingsBoard OTA update protocol to receive and apply packages. This includes reporting its current firmware version as a device attribute and responding to update notifications over MQTT. For implementation details, see <DocLink product={props.product} path="user-guide/ota-updates" target="_blank">OTA updates</DocLink>.
</Aside>

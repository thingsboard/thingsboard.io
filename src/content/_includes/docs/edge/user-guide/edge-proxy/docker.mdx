Running ThingsBoard Edge behind a <a href="https://en.wikipedia.org/wiki/Proxy_server" target="_blank" rel="noopener noreferrer">proxy server</a> means that its gRPC connection to the ThingsBoard server (port 7070 by default, set by `CLOUD_RPC_PORT`) is routed through the proxy instead of going directly to the internet. Edge opens this connection through the proxy with an HTTP `CONNECT` tunnel. Only this connection uses the proxy: devices, the Edge UI, and the local database are not affected, so there is no bypass list to configure.

This setup is common in restricted network environments where direct internet access is deliberately blocked. Proxies also add a security layer by filtering and monitoring outbound traffic, and can cache resources to reduce bandwidth usage.

## Prerequisites

- An HTTP proxy server that allows `CONNECT` to the ThingsBoard server's gRPC port, with its host, port, and credentials if required.
- ThingsBoard Edge must be installed and running via Docker Compose.
- <a href="https://docs.docker.com/engine/install/" target="_blank" rel="noopener noreferrer">Docker</a> and <a href="https://docs.docker.com/compose/install/" target="_blank" rel="noopener noreferrer">Docker Compose</a> must be installed.

<Aside type="note">
Run all commands from the directory that contains your `docker-compose.yml` file.
</Aside>

## Step 1. Stop the container

```bash
docker compose stop
```

## Step 2. Update `docker-compose.yml`

Open the file:

```bash
sudo nano docker-compose.yml
```

Add the following lines to the `environment` block of the `mytbedge` service:

```yaml
      CLOUD_RPC_PROXY_ENABLED: "true"
      CLOUD_RPC_PROXY_HOST: "proxy_host"
      CLOUD_RPC_PROXY_PORT: "proxy_port"
      CLOUD_RPC_PROXY_USERNAME: "proxy_user"
      CLOUD_RPC_PROXY_PASSWORD: "proxy_password"
```

Replace `proxy_host` and `proxy_port` with your proxy's hostname and port. If your proxy does not require authentication, omit the `CLOUD_RPC_PROXY_USERNAME` and `CLOUD_RPC_PROXY_PASSWORD` lines.

<Aside type="caution">
  The standard `HTTP_PROXY`, `HTTPS_PROXY`, and `NO_PROXY` variables have no effect on the Edge connection to the server. Use the `CLOUD_RPC_PROXY_*` variables.
</Aside>

## Step 3. Restart the containers

```bash
docker compose up -d && docker compose logs -f mytbedge
```

`mytbedge` is the default Edge service name in `docker-compose.yml`. If you renamed the service, replace it in the command.

Once started, open the Edge UI at <a href="http://localhost:8080" target="_blank" rel="noopener noreferrer">http://localhost:8080</a> and log in with your tenant credentials. Go to **Edge → Status** and confirm the **Status** field shows **Connected** — this confirms Edge is reaching the server through the proxy.

<Aside type="note">
If the Edge HTTP port was changed to **18080** during installation, access Edge at <a href="http://localhost:18080" target="_blank" rel="noopener noreferrer">http://localhost:18080</a> instead.
</Aside>

## Troubleshooting

Check that the proxy variables reached the Edge container:

```bash
docker compose exec mytbedge printenv | grep CLOUD_RPC_PROXY
```

Test connectivity to ThingsBoard Cloud through the proxy:

```bash
curl -x http://proxy_host:proxy_port https://your_tb_cloud_url
```

Check container logs for proxy-related errors:

```bash
docker compose logs mytbedge | grep -iE "proxy|UNAVAILABLE"
```

**Edge management** is the part of the ThingsBoard server where you create Edge instances, choose what each Edge receives, and check what was sent to it. Everything on this page is done on the server, under **Edge management > Edges** and **Edge management > Profiles**, not on the Edge itself.

An Edge receives its entities from two places:

- **Its edge profile:** a shared configuration for a group of Edges. This is the main way to configure Edges.
- **Its own assignments:** entities assigned to this Edge only, for what no other Edge needs.

Most entities can also be created on the Edge. Customers are the exception: you create them on the server. An Edge receives the customer that owns it and the users of the user groups assigned to it. See <DocLink product={props.product} path="user-guide/provision-customers-and-users">Customers and users</DocLink>.

## Create an Edge

<Steps>
1. Go to **Edge management > Edges**, click **Add edge**, and select **Add new edge**.
2. Enter a name. The **Edge profile** field shows the [default profile](#default-profile). Keep it or pick another one, then click **Add**. The new Edge receives everything on its profile, including the root rule chain.
3. A dialog with install instructions opens. The commands in it already contain the key and secret of this Edge. To copy the key and secret later, open the Edge and click **Copy Edge key** and **Copy Edge secret**.
</Steps>

For installation instructions, see <DocLink product={props.product} path="installation" target="_blank">Edge installation</DocLink>.

## Edge profiles

Each Edge has one **edge profile**. The profile defines the root rule chain its Edges run and the entity groups, rule chains, integrations, and scheduler events that every Edge on the profile receives. You configure the profile once, and every Edge on it gets the same set, including Edges created later.

<Aside type="tip">
**Example:** a `Factory Edge Profile` holds the factory's device and dashboard groups and the `Factory Root` rule chain. Every Edge placed on it starts with the same devices, dashboards, and processing logic, with nothing to set up per Edge.
</Aside>

### Create a profile

Go to **Edge management > Profiles > Edge profiles**, click **Add edge profile**, enter a name, and click **Add**.

A new profile starts empty. Add a root rule chain to it before you use it, because ThingsBoard does not let you create or move an Edge onto a profile without a root.

### Configure the profile

Open the profile and go to the **Assignments** tab. It has two sections:

- **Entity groups:** device, asset, entity view, dashboard, and user groups.
- **Logic & processing:** rule chains, integrations, and scheduler events.

Each section has its own add button, for example **Add device group**. For an entity group, select the **Owner** first, and the list shows only the groups of that owner. To remove a row, click its **×** icon.

There is nothing to save. Every change applies to all Edges on the profile right away, and the banner at the top shows how many Edges use the profile.

<Aside type="caution">
Removing an entity group from a profile unassigns it from every Edge on the profile. Each Edge deletes the group, its entities, and their local telemetry. An entity is kept only if it is also in another group the Edge receives. Data already synchronized to the server is kept.
</Aside>

### Root rule chain of the profile

One rule chain of the profile is its **root**, which receives all incoming messages first. The **Root** column of the **Rule chains** section marks it. To change it, click **Set root** on another rule chain of the profile. All Edges on the profile switch to the new root, except Edges that run a [root of their own](#root-rule-chain-of-an-edge).

### Which Edges receive a row

One profile can serve Edges of several customers, because a row reaches only the Edges whose owner can see it:

| Row owned by | Reaches |
|--------------|---------|
| The tenant | Every Edge on the profile |
| A customer (device, asset, entity view, or dashboard group) | Edges owned by the tenant, by that customer, or by a customer above it |
| A customer (user group or scheduler event) | Edges owned by that customer only |

To change the owner of an Edge, use **Manage owner and groups** on its **Details** tab.

### Re-apply a profile

Re-apply sends the whole profile to its Edges again. Use it when an Edge is out of sync with its profile, for example when it is missing a device group that the profile has.

Click the **Re-apply** icon of the profile in the list and confirm. Every Edge on the profile receives all rows of the profile again, including the ones it was missing. Rows that an Edge can no longer receive are removed.

Assignments made directly on an Edge stay as they are, and so does a root rule chain that an Edge already runs. Re-apply runs in the background, and the Edges receive their changes within seconds.

### Default profile

One profile of the tenant is the **default**, marked in the **Default** column. New Edges start on it. It is selected by default in the **Add edge** dialog, and Edges created through the REST API without an edge profile or a type are placed on it.

To change the default, click **Make edge profile default** on another profile. That profile must have a root rule chain.

You cannot delete the default profile, or any profile that Edges still use. Move those Edges to another profile first.

<Aside type="note">
An Edge created through the REST API with an Edge **type** but no edge profile is placed on the profile named after its type. If there is no such profile, ThingsBoard creates it with the rule chains and the root of the default profile.
</Aside>

### Edges created by Remote Agents

Edges that ThingsBoard creates for <DocLink product={Products.PE} path='user-guide/agents'>Remote Agents</DocLink> take their edge profile from the <DocLink product={Products.PE} path='user-guide/agents/application-profiles'>application profile</DocLink>. Select it on the **Edge Setup** step of the application profile wizard. The field shows the current default profile at first. If you clear it, new Edges always use the current tenant default, even after the default changes.

Changing the edge profile of an application profile affects only Edges created afterwards. Existing Edges keep their profile.

## Assign entities to one Edge

An Edge can receive entities that are not on its profile, for example a dashboard group for one site. Open the Edge and go to its **Assignments** tab. It lists everything the Edge receives, and the **Source** column shows where each row comes from:

- **From profile:** the row comes from the Edge's profile and is locked here. To change it, go to the profile with **Open profile** in the banner.
- **This edge:** the row was assigned to this Edge only. You add these rows with the button of each section, for example **Assign device group to this edge**, and remove them here.

The add buttons list only what this Edge can receive: entity groups of its owner and of the owners above it, and scheduler events of the tenant or of the Edge's own customer. Use the **All / From profile / This edge** filter to show one kind of row.

Each assignment is sent to the Edge as a [downlink](#downlinks), a message from the server to the Edge. If the Edge is connected, it receives the entities right away. If it is offline, it receives them once the connection is restored.

To remove only one entity from the Edge, remove it from its group on the server instead. The Edge deletes the entity unless it is also in another group the Edge receives.

### Root rule chain of an Edge

An Edge can run its own root rule chain instead of the profile root. In the **Rule chains** section of the Edge, click **Set as root for this edge** on any of its rule chains. The banner then shows that the Edge uses its own root.

A root set on the Edge is kept when the profile root changes and when the profile is re-applied, and replaced only when the Edge moves to another profile.

## Move an Edge to another profile

Open the Edge, click the pencil icon (**Toggle edit mode**), select another profile in the **Edge profile** field, and apply the changes. ThingsBoard asks you to confirm, because the move changes what the Edge holds:

- Rows of the old profile that the new profile does not have are unassigned, and the Edge deletes those groups' entities and their local telemetry.
- The Edge receives every row of the new profile.
- The root rule chain of the new profile replaces the Edge's root, even a root set on the Edge itself.
- Assignments made directly on the Edge are kept.

## Edge details

Click an Edge in **Edge management > Edges** to open its details. The **Details** tab has the following actions:

| Action | Description |
|--------|-------------|
| **Open details page** | Opens the Edge on its own full page instead of a side panel. |
| **Manage owner and groups** | Changes the owner of the Edge, for example to give it to a customer, and the groups it belongs to. |
| **Delete edge** | Deletes the Edge. See [Delete an Edge](#delete-an-edge). |
| **Copy Edge Id** | Copies the ID of the Edge. |
| **Copy Edge key** | Copies the Edge key. You need it to install the Edge. |
| **Copy Edge secret** | Copies the Edge secret. You need it to install the Edge. |
| **Sync Edge** | Sends everything the Edge receives to it again. See [Force synchronization](#force-synchronization). |
| **Install & Connect Instructions** | Shows the commands to install the Edge and connect it to the server. If a newer Edge version is available, this button is replaced by **Upgrade Instructions**. |

The other tabs of the details panel are:

| Tab | Contents |
|-----|----------|
| **Assignments** | Everything the Edge receives, from its profile and from [this Edge only](#assign-entities-to-one-edge) |
| **Attributes** | The latest attributes of the Edge. The server attribute `active` is `true` while the Edge is connected; `lastConnectTime` and `lastDisconnectTime` show when it last connected and disconnected. |
| **Latest telemetry** | The most recent telemetry of the Edge |
| **Alarms** | Alarms raised for the Edge itself |
| **Events** | Lifecycle and system events of the Edge |
| **Downlinks** | Messages the server sent to the Edge. See [Downlinks](#downlinks). |
| **Relations** | Entities related to the Edge |
| **Audit logs** | Actions users performed on the Edge |

## Downlinks

Downlinks are messages from the server to the Edge, such as entity assignments, configuration changes, and rule chain updates. When an Edge is missing something it should have, open its **Downlinks** tab to see whether the server sent it and whether the Edge received it.

Each row of the table contains:

| Column | Description |
|--------|-------------|
| **Event time** | When the downlink was created |
| **Type** | The type of entity the message is about, for example a device, an asset, or a rule chain |
| **Event action** | What happened to the entity, for example **Added**, **Updated**, or **Deleted** |
| **Entity ID** | The ID of the entity |
| **Status** | **Deployed:** the Edge received the message. **Pending:** the message waits in the queue until the Edge is connected. |
| **Data** | Click to see the full message |

## Force synchronization

When the Edge reconnects, it synchronizes on its own. If something is still missing after that, for example after a long outage, start the synchronization manually: open the Edge and click **Sync Edge** on its **Details** tab.

To make all Edges of a profile match it again at once, [re-apply the profile](#re-apply-a-profile) instead.

## Delete an Edge

<Aside type="danger">
Deleting an Edge removes it from the server permanently, together with its downlink history. This cannot be undone. The entities that were assigned to the Edge, and the data they already synchronized to the server, stay on the server.
</Aside>

Open the Edge, click **Delete edge** on its **Details** tab, and confirm.

## Upgrade from an earlier version

On upgrade to a version with edge profiles, ThingsBoard creates edge profiles from your existing setup, and Edges keep working as before:

- Each Edge **type** gets a profile named after it, and all Edges of that type are placed on it. The `default` profile becomes the default profile.
- The `default` profile takes the rule chain that was the edge **Template root**, so new Edges still start on the same root. Every other profile takes the root that most of its Edges run.
- An Edge that ran a different root than its profile keeps it as its own root.
- Rule chains set to **Assign rule chain to edge(s) on creation** are added to every profile, so all Edges receive them, not only new ones.
- Entities assigned to an Edge before the upgrade stay assigned to it as [assignments of that Edge](#assign-entities-to-one-edge).

**Edge management** is the part of the ThingsBoard server where you create Edge instances, choose what each Edge receives, and check what was sent to it. Everything on this page is done on the server, under **Edge management > Edges**, not on the Edge itself.

Most entities can also be created on the Edge. Customers are the exception: you create them on the server. An Edge receives the customer that owns it and the users of the user groups assigned to it. See <DocLink product={props.product} path="user-guide/provision-customers-and-users">Customers and users</DocLink>.

## Create an Edge

<Steps>
1. Go to **Edge management > Edges**, click **Add edge**, and select **Add new edge**.
2. Enter a name and click **Add**. A dialog with install instructions opens. The commands in it already contain the key and secret of this Edge.
3. To copy the key and secret later, open the Edge and click **Copy Edge key** and **Copy Edge secret**. You need them to install the Edge.
</Steps>

The new Edge automatically receives the rule chains that are marked for new Edges. See [Rule chains of new Edges](#rule-chains-of-new-edges).

For installation instructions, see <DocLink product={props.product} path="installation" target="_blank">Edge installation</DocLink>.

## Assign entities to an Edge

An Edge receives only what you assign to it. Click the Edge in the list to open its **Details** tab. The **Manage …** buttons on this tab assign entity groups, rule chains, integrations, and scheduler events. Each button opens the list of what the Edge already has:

| Button | Description |
|--------|-------------|
| **Manage user groups** | User groups. Their users can log in to the Edge. |
| **Manage asset groups** | Asset groups |
| **Manage device groups** | Device groups |
| **Manage entity view groups** | Entity view groups |
| **Manage dashboard groups** | Dashboard groups |
| **Manage scheduler events** | <DocLink product={Products.PE} path="user-guide/scheduler" target="_blank">Scheduler events</DocLink> |
| **Manage rule chains** | Rule chain templates. See <DocLink product={props.product} path="user-guide/rule-chain-templates">Rule chain templates</DocLink>. |
| **Manage integrations** | Integration templates. See <DocLink product={Products.EDGE_PE} path="user-guide/integrations/overview">Integrations</DocLink>. |

To assign a device group, for example:

<Steps>
1. Go to **Edge management > Edges** and click the Edge.
2. On the **Details** tab, click **Manage device groups**.
3. Click **Assign to edge** (+), select one or more groups, and click **Assign**.
</Steps>

The other buttons work the same way. Each assignment is sent to the Edge as a [downlink](#downlinks), a message from the server to the Edge. If the Edge is connected, it receives the entities right away. If it is offline, it receives them once the connection is restored.

### Unassign entities

Open the same list, for example with **Manage device groups**. In the row of the group, click **Unassign entity group from edge** and confirm. For rule chains, integrations, and scheduler events, the row action is **Unassign from edge**.

<Aside type="caution">
When you unassign an entity group, the Edge deletes the group. It also deletes the entities of the group and their local telemetry. An entity is kept only if it is also in another group assigned to the Edge. Data already synchronized to the server is kept.
</Aside>

To remove only one entity from the Edge, remove it from the group on the server instead. The same rule applies: the Edge deletes the entity unless it is also in another group assigned to the Edge.

## Rule chains of an Edge

Every Edge runs one **root** rule chain, which receives all incoming messages first. A new Edge starts with the [template root](#rule-chains-of-new-edges). To change the root rule chain of one Edge:

<Steps>
1. Open the Edge and click **Manage rule chains** on its **Details** tab.
2. In the row of a rule chain that is already assigned to the Edge, click **Make rule chain root**.
</Steps>

This changes only this Edge. The root rule chain cannot be unassigned. To remove it, make another rule chain the root first.

### Rule chains of new Edges

Go to **Edge management > Templates** and open the **Rule chain** tab. Two row actions there control what every new Edge starts with:

- **Make rule chain as edge template root:** every new Edge receives this rule chain as its root. The **Template root** column marks it.
- **Assign rule chain to edge(s) on creation:** every new Edge also receives this rule chain. The **Assign to edge** column marks these rule chains. To turn this off, click **Do not assign rule chain to edge(s) on creation** in the same row.

## Edge details

Click an Edge in **Edge management > Edges** to open its details. Besides the **Manage …** buttons, the **Details** tab has the following actions:

| Action | Description |
|--------|-------------|
| **Open details page** | Opens the Edge on its own full page instead of a side panel. |
| **Manage owner and groups** | Changes the owner of the Edge, for example to give it to a customer, and the groups it belongs to. |
| **Delete edge** | Deletes the Edge. See [Delete an Edge](#delete-an-edge). |
| **Copy Edge Id** | Copies the ID of the Edge. |
| **Copy Edge key** | Copies the Edge key. You need it to install the Edge. |
| **Copy Edge secret** | Copies the Edge secret. You need it to install the Edge. |
| **Sync Edge** | Sends all assigned entities to the Edge again. See [Force synchronization](#force-synchronization). |
| **Install & Connect Instructions** | Shows the commands to install the Edge and connect it to the server. If a newer Edge version is available, this button is replaced by **Upgrade Instructions**. |

The other tabs of the details panel are:

| Tab | Contents |
|-----|----------|
| **Attributes** | The latest attributes of the Edge. The server attribute `active` is `true` while the Edge is connected; `lastConnectTime` and `lastDisconnectTime` show when it last connected and disconnected. |
| **Latest telemetry** | The most recent telemetry of the Edge |
| **Alarms** | Alarms raised for the Edge itself |
| **Events** | Lifecycle and system events of the Edge |
| **Downlinks** | Messages the server sent to the Edge. See [Downlinks](#downlinks). |
| **Relations** | Entities related to the Edge |
| **Audit logs** | Actions users performed on the Edge |

## Downlinks

Downlinks are messages from the server to the Edge, such as entity assignments, configuration changes, and rule chain updates. When an Edge is missing something it should have, open its **Downlinks** tab to see whether the server sent it and whether the Edge received it.

Each row of the table contains:

| Column | Description |
|--------|-------------|
| **Event time** | When the downlink was created |
| **Type** | The type of entity the message is about, for example a device, an asset, or a rule chain |
| **Event action** | What happened to the entity, for example **Added**, **Updated**, or **Deleted** |
| **Entity ID** | The ID of the entity |
| **Status** | **Deployed:** the Edge received the message. **Pending:** the message waits in the queue until the Edge is connected. |
| **Data** | Click to see the full message |

## Force synchronization

When the Edge reconnects, it synchronizes on its own. If something is still missing after that, for example after a long outage, start the synchronization manually: open the Edge and click **Sync Edge** on its **Details** tab.

## Delete an Edge

<Aside type="danger">
Deleting an Edge removes it from the server permanently, together with its downlink history. This cannot be undone. The entities that were assigned to the Edge, and the data they already synchronized to the server, stay on the server.
</Aside>

Open the Edge, click **Delete edge** on its **Details** tab, and confirm.

Edge management covers the server-side tools for provisioning Edge instances, assigning entities, monitoring connectivity, and inspecting synchronization state. Edge always operates in conjunction with a ThingsBoard server — the server provisions it, pushes configuration, and receives synchronized data.

## Provisioning Edge instances

Before installing Edge, you must create an Edge instance on the server. This generates the **Edge key** and **Edge secret** used during installation to bind the Edge to the server.

<Steps>
1. On the server, go to **Edge management → Instances** and click **Add Edge** (+).
2. Open the instance and copy the **Edge key** and **Edge secret** from the **Details** tab. These credentials are required when running the Edge installation.
</Steps>

For installation instructions, see <DocLink product={props.product === Products.EDGE_PE ? Products.EDGE_PE : Products.EDGE} path="installation" target="_blank">Edge installation</DocLink>.

## Edge details page

The **Edge Details** page is the primary place to manage a specific Edge instance from the server. Use it to retrieve credentials during installation, assign entities, trigger force synchronization, or inspect connectivity and event history when troubleshooting.

<Steps>
1. On the server, go to **Edge management → Instances** and click the Edge.
</Steps>

The following tabs are available:
- **Details:** Contains general information such as Edge ID, Edge key, and Edge secret. You can also assign entities and trigger force synchronization from this tab.
- **Attributes:** Displays the latest attributes published to the server.
- **Latest telemetry:** Displays the most recent telemetry records from the Edge.
- **Alarms:** Displays the list of alarms.
- **Events:** Displays various events related to the Edge.
- **Downlinks:** Displays messages transferred from the server to the Edge.
- **Relations:** Displays other entities connected to the Edge.
- **Audit logs:** Displays audit records tracking user actions.

## Force synchronization

When connectivity is restored, Edge synchronizes automatically. If synchronization does not complete — for example, after a prolonged outage or a configuration mismatch — you can trigger it manually.

<Steps>
1. On the server, go to **Edge management → Instances**, click the Edge, then click **Sync Edge**.
</Steps>

## Cloud events

The **Cloud Events** page shows all events that Edge has pushed to the server. Use it to verify that telemetry, alarms, and other data are reaching the server — particularly when data that should appear on the server is missing. Events with a **Pending** status indicate a backlog that has not yet been delivered.

<Steps>
1. Log in to the Edge and go to **Edge → Cloud events**.
</Steps>

Each row in the table contains:

| Column | Description |
|--------|-------------|
| **Created time** | Date and time the event was created and pushed, in `YYYY-MM-DD H:Min:Sec` format |
| **Action** | The operation pushed to the server: Added, Deleted, Updated, Attributes Updated, Attributes Deleted, Timeseries Deleted, Timeseries Updated, RPC Call, Credentials Updated, Relation Add or Update, Relation Deleted, Relations Deleted, Alarm Ack, Alarm Clear, Attributes Request, Rule Chain Metadata Request, Relation Request, Credential Request |
| **Entity type** | The type of entity that generated the event |
| **Entity ID** | Identification code of the entity |
| **Status** | **Deployed:** The event was pushed to the server. **Pending:** The event is stored locally and will be pushed when connectivity is restored. |
| **Data** | Click to view the full payload that was pushed |

By default, events are displayed for the last day. Click **Time window** at the top of the page to set a different time range.

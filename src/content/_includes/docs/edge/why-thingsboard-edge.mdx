ThingsBoard Edge brings the full IoT platform to the network edge: factories, remote sites, vehicles, and field installations. It runs the complete ThingsBoard stack locally, processes data on-site, and syncs with the cloud only when needed.

If you need local processing, offline operation, or reduced bandwidth costs without sacrificing ThingsBoard's features, Edge is the right choice.

---

## Core problems Edge solves

### Unreliable connectivity

Remote industrial sites, moving assets, and developing regions often lack stable internet. Edge continues operating during outages, storing data locally and syncing when connectivity returns. Operators access dashboards and receive alarms regardless of cloud connection.

**Use cases:**
- Oil rigs with satellite uplinks
- Farms in areas with spotty cellular coverage
- Ships and autonomous vehicles
- Remote substations and installations

### Latency-critical operations

Cloud round-trips take 50-500 ms depending on location and network quality. For industrial automation, predictive maintenance, and safety systems, this delay is unacceptable. Edge processes telemetry and triggers actions locally with sub-second response times.

**Use cases:**
- Factory automation requiring immediate shutdowns
- Autonomous vehicles (5-20 TB data per day, cannot wait for cloud)
- Medical devices needing instant alarms
- Smart building HVAC responding to occupancy changes

### Bandwidth and cloud costs

High-frequency sensors, video streams, and machine data generate massive volumes. Autonomous vehicles produce 5-20 TB per day. Edge filters, aggregates, and compresses data before sending it to the cloud, typically reducing traffic by 80-95%.

**Use cases:**
- Industrial facilities with hundreds of high-frequency sensors
- Video surveillance systems
- Vibration and acoustic monitoring
- Environmental sensor networks

### Data sovereignty

Regulations (GDPR, HIPAA), contracts, or security policies may require data to stay on-premises. Edge keeps raw telemetry local while enabling cloud-based analytics on aggregated or anonymized data.

**Use cases:**
- Healthcare (patient data cannot leave facility)
- Smart homes (privacy-sensitive user behavior)
- Government and defense installations
- Financial institutions

## What Edge provides

### Full ThingsBoard stack locally

Run the complete platform on-site:
- Connect devices via MQTT, CoAP, HTTP, LwM2M, SNMP
- Process telemetry with the Rule Engine
- Store data in local PostgreSQL or Cassandra
- Display real-time dashboards
- Trigger local alarms and notifications
- Execute server-side RPC commands

### Automatic cloud synchronization

Edge syncs bidirectionally with ThingsBoard Cloud or your on-premise server:
- **Upstream:** Push device data (filtered, aggregated, or complete).
- **Downstream:** Pull configuration updates, dashboards, rule chains, firmware.
- **Offline resilience:** Data queues during outages and syncs when connectivity returns.

### Traffic control

Configure precisely what reaches the cloud:
- Send only alarms and critical events
- Aggregate raw telemetry (hourly averages instead of per-second readings)
- Sample at lower frequency (1/minute instead of 10/second)
- Push diagnostics on-demand

### Batch management

Update thousands of Edge instances from the cloud:
- Deploy new dashboards and rule chains
- Configure device profiles and attributes
- Manage firmware rollouts
- Monitor Edge health and connectivity

## Design principles

### Autonomous operation

Edge is not a thin client. It runs the full ThingsBoard platform locally. If cloud connectivity fails:
- Devices continue sending data
- Rule Engine processes locally
- Alarms trigger normally
- Dashboards remain accessible
- Data persists in local database

When connectivity returns, Edge automatically syncs.

### Feature parity

Edge inherits all ThingsBoard {props.product === Products.EDGE_PE ? 'PE' : 'CE'} features. The same APIs, the same Rule Engine nodes, the same dashboard widgets. Deploy and test in the cloud, then push configurations to Edge with zero code changes.

### Deployment flexibility

Run Edge on any infrastructure:
- **Industrial PCs** at factory sites
- **Raspberry Pi** for pilot deployments
- **Docker** containers for rapid provisioning
- **Ubuntu/CentOS/Windows** for standard enterprise servers

## When to use Edge

### Use Edge when you need

- **Offline operation:** Sites with intermittent connectivity like ships, mines, and remote installations
- **Low latency:** Sub-second response times for industrial control or safety systems
- **Bandwidth reduction:** High-volume sensors where cloud storage is prohibitively expensive
- **Local dashboards:** Operators who need real-time visibility without internet dependency
- **Data residency:** Regulatory or contractual requirements to keep data on-premises
- **Distributed architecture:** Hundreds of remote sites needing local processing with central reporting

### Avoid Edge when

- Devices have reliable, low-latency connectivity to the cloud.
- Cloud round-trip delay (50-500 ms) is acceptable.
- Data volumes are low and cloud bandwidth cost is negligible.
- All data can be stored in the cloud without regulatory concerns.
- You have a single centralized site.

---

## Architecture options

- **Edge with ThingsBoard Cloud:** Simplest deployment. Edge instances sync with ThingsBoard Cloud. No server infrastructure to manage.
- **Edge with self-hosted ThingsBoard:** Run ThingsBoard server on-premise or in your own cloud. Full control over infrastructure and data.
- **Edge standalone:** Run Edge without cloud connection. Suitable for fully isolated sites or air-gapped environments.
- **Hybrid (multi-site):** Deploy Edge at every remote location (factories, stores, substations). Aggregate data in the cloud for enterprise-wide analytics.

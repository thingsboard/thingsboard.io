**Remote Agent** installs, upgrades, and monitors ThingsBoard Edge remotely from the cloud: no manual Docker commands and no maintenance access to the target machine. The agent is a small Docker container that runs next to Edge on the same host, connects to your ThingsBoard server, and executes deployments on its behalf. This page covers the Edge-specific flows; for the full feature — agents, profiles, application actions, and bulk operations — see the <DocLink product={props.product} useTbDocs path='user-guide/agents'>Remote Agent documentation</DocLink>.

Compared to a manual Docker installation, the agent adds:

- **Remote installation:** Deploy Edge from the ThingsBoard UI to any host where the agent runs.
- **Managed upgrades:** Push new Edge versions from the cloud, with volume backups, automatic database migration, and rollback on failure.
- **Monitoring:** Host and container metrics, container states, and live logs in the ThingsBoard UI.
- **Fleet operations:** Upgrade or restart all Edge instances of a fleet with <DocLink product={props.product} useTbDocs path='user-guide/agents/bulk-actions'>bulk actions</DocLink>.

## Prerequisites

- ThingsBoard Professional Edition server or a ThingsBoard Cloud tenant.
- Docker installed on the target machine (Linux, amd64 or arm64).
- Outbound network access from the target machine to the ThingsBoard gRPC port (default `7070`).

## Auto-provision Edge instances

Full guide: <DocLink product={props.product} useTbDocs path='user-guide/agents/agent-profiles#auto-provision-an-agent'>Auto-provision an agent</DocLink>.

Auto-provisioning covers hosts that have never run an agent: nothing needs to be deployed or created up front, neither the agent nor the Edge entity. Generate one provisioning command bound to an <DocLink product={props.product} useTbDocs path='user-guide/agents/agent-profiles'>agent profile</DocLink> and run it on the target machine: the command starts the agent, and ThingsBoard registers it and creates the Edge entity tied to it automatically, configured from the application profile assigned to the agent profile. It is also the fastest way to roll out a fleet: every machine that runs the same command receives its own agent and Edge instance.

<Steps>
  <ol>
    <li>
      Go to **Edge management > Edges**, open the **Add edge** (+) menu, and click **Auto-provision**.
    </li>
    <li>
      Pick an agent profile that has an Edge application profile assigned, or create one: the **Edge** and **Edge + Gateway** presets create the agent profile with the latest Edge application profile already assigned. The dialog shows **Ready to provision** once the selected profile qualifies.
    </li>
    <li>
      Click **Next** and copy the provisioning script.
    </li>
    <li>
      Run the script on every target machine. Each run registers a new agent that installs Edge on its host; the new Edge instance appears in the **Edge instances** table.
    </li>
  </ol>
</Steps>

## Install Edge with an agent

Full guide: <DocLink product={props.product} useTbDocs path='user-guide/agents/applications#deploy-an-application'>Deploy an application</DocLink>.

<Steps>
  <ol>
    <li>
      Create an Edge instance in ThingsBoard — go to **Edge management > Edges**, click **Add edge**, enter a name, and click **Add** — or open an existing one.
    </li>
    <li>
      In the Edge details, click **Upgrade Instructions** and select the **Agent** tab. The four-step wizard opens.
    </li>
    <li>
      On **Select Agent**, pick the agent that runs on the target machine: only online agents can install. If the machine has no agent yet, create one and run the generated command on the machine first; see <DocLink product={props.product} useTbDocs path='user-guide/agents/installation'>Install Remote Agent</DocLink>.
    </li>
    <li>
      On **Review & Customize**, select the <DocLink product={props.product} useTbDocs path='user-guide/agents/application-profiles'>application profile</DocLink> that supplies the Docker Compose configuration — one of your profiles or a predefined profile shipped with the platform — then enter the application name, adjust the image pull policy, and review the resulting Compose configuration. The related entity is the Edge itself: its credentials are wired into the configuration automatically.
    </li>
    <li>
      On **Save Application**, check the summary and click **Save**. The agent downloads the images and starts the containers.
    </li>
    <li>
      The **Install** step confirms that your agent is online and links to the created deployment: open **Agent application** and check its **Events** tab to verify that the install finished.
    </li>
  </ol>
</Steps>

## Update the deployment

Full guide: <DocLink product={props.product} useTbDocs path='user-guide/agents/application-actions#update-an-application'>Update an application</DocLink>.

To change the configuration of a deployed instance, click **Update** on the application details page. For a profile-managed application, the configuration panes in the update dialog are read-only: edit the configuration through the profile with **Update profile**. In the profile editor, the template stays read-only on the left, and your Compose on the right is what gets saved. Back in the update dialog, the comparison shows exactly what the updated profile changes; confirm with **Update**, and the agent re-deploys the application with the new configuration and the Edge credentials merged in. The finished update appears on the **Events** tab.

## Upgrade Edge remotely

Full guide: <DocLink product={props.product} useTbDocs path='user-guide/agents/application-actions#upgrade-an-application'>Upgrade an application</DocLink>.

Agent-managed Edge instances upgrade from the ThingsBoard UI: the agent stops the instance, backs up the selected volumes, migrates the database when needed, and starts the new version. A failed upgrade rolls back automatically, using the backed-up volumes.

<Steps>
  <ol>
    <li>
      When a newer template version exists, the **Upgrade available** button appears in the Edge details. Click it: the **Upgrade Application** wizard opens.
    </li>
    <li>
      If the application is linked to a profile that still points to the previous template version, the wizard starts with the **Upgrade Profile** step: review the new template next to the profile's current Compose with the new image auto-merged in, and click **Upgrade Profile** so the application can adopt the new configuration.
    </li>
    <li>
      On **Review & Customize**, select the volumes to back up before the upgrade and the image pull policy, then click **Next**.
    </li>
    <li>
      On **Save Application**, confirm the target version and the volumes to back up, and click **Upgrade**.
    </li>
    <li>
      Wait in the **Event progress** dialog until every stage reports **Completed**. **View in events** opens the agent's event log.
    </li>
  </ol>
</Steps>

<Aside type="tip">
The Edge details show the upgrade of one instance. To see every application eligible for an upgrade on a host at once, open the agent's <DocLink product={props.product} useTbDocs path='user-guide/agents/applications#applications-table'>Applications table</DocLink>: it lists each application with its template version and the **Upgrade available** mark.
</Aside>

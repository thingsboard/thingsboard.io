ThingsBoard Edge stores telemetry and attributes locally and synchronizes them to the ThingsBoard Server through **Push to cloud** rule nodes in the Edge rule chain. This recipe covers the default behavior and how to forward only part of the data.

## Default behavior

The built-in Edge root rule chain already forwards device data to the server through **Push to cloud** nodes. Unless you have modified the root rule chain:

- **Post telemetry** messages go through **Save Timeseries** to **Push to cloud**.
- **Post attributes** messages (client-side attributes published by devices) go through **Save Client Attributes** to **Push to cloud**.
- **Attributes Updated** and **Attributes Deleted** messages go straight to **Push to cloud**.

<Aside type="note">
  The **Push to cloud** node queues messages when the Edge-to-Server gRPC connection is unavailable and resumes delivery once connectivity is restored.
</Aside>

To change the attribute scope that **Push to cloud** sends, see <DocLink product={props.product} path='user-guide/attribute-sync' target="_blank">Attribute synchronization</DocLink>. To push attribute changes from the server to the Edge, see <DocLink product={props.product} path='user-guide/attributes#syncing-attribute-updates' target="_blank">Attributes</DocLink>.

## Push only a subset of data

To forward only specific message types or device groups to the server:

<Steps>
1. Add a filter node, for example **script** or **device profile switch**, before the **Push to cloud** node.
2. Route only matching messages to **Push to cloud**; let everything else pass through without forwarding.
3. Click **Apply changes**.
</Steps>

For the full configuration reference and available node settings, see <DocLink product={props.product} path='user-guide/telemetry-synchronization' target="_blank">Telemetry synchronization</DocLink>.

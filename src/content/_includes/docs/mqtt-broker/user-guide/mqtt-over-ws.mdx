MQTT is a lightweight protocol designed for efficient message delivery — but web browsers cannot use MQTT natively over a raw TCP socket.
**MQTT over WebSocket** bridges this gap, allowing MQTT messages to be sent and received directly through browsers and Node.js applications, combining the reliability of MQTT with the web compatibility of WebSocket.

## What is WebSocket?

WebSocket is a communication protocol that enables real-time, bi-directional communication between a client and a server over a single, long-lived TCP connection.
Unlike the traditional HTTP request/response model, WebSocket allows continuous data exchange with low latency.
It supports both unencrypted (`ws://`) and encrypted (`wss://`) connections.

## Benefits of MQTT over WebSocket

- **Efficient resource utilization** — MQTT's lightweight design minimizes bandwidth and device resource usage in web applications.
- **Real-time communication** — WebSocket's persistent connection enables low-latency data exchange.
- **Bi-directional communication** — full-duplex support, combined with MQTT's publish/subscribe model, enables interactive communication scenarios.
- **Web compatibility** — MQTT over WebSocket integrates with the browser security model without plugins or special configuration.
- **Full MQTT feature support** — retained messages, Last Will and Testament, QoS levels, and persistent sessions all work over WebSocket.

## WebSocket listeners in TBMQ

TBMQ provides two WebSocket listeners:

- **WS** (WebSocket) — unencrypted, typically on port `8084`.
- **WSS** (WebSocket Secure) — TLS-encrypted, typically on port `8085`.

For configuration details, see the <DocLink product={props.product} path="install/config/#mqtt-listeners-parameters">TBMQ configuration reference</DocLink> (`LISTENER_WS_ENABLED` and related variables).

## Getting started with MQTT.js

This example demonstrates how to connect to TBMQ over WebSocket, subscribe to a topic, and exchange messages using the <a href="https://github.com/mqttjs/MQTT.js" target="_blank" rel="noopener noreferrer">MQTT.js</a> library in Node.js.

### Prerequisites

Ensure TBMQ is installed. See <DocLink product={props.product} path="install/installation-options">Installation options</DocLink>.

### Install MQTT.js

Install <a href="https://nodejs.org/en/learn/getting-started/how-to-install-nodejs" target="_blank" rel="noopener noreferrer">Node.js</a> first, then:

```bash
npm install mqtt --save
```

### Connect over WebSocket

<Aside type="note">
  The username `tbmq_websockets_username` is the default MQTT client credential built into TBMQ for WebSocket client connections.
</Aside>

```javascript
const mqtt = require('mqtt');

const url = 'ws://localhost:8084/mqtt';
const topic = 'sensors/temperature';
const message = 'Hello World';

const options = {
    clean: true,
    clientId: 'tbmq_websockets_client_id',
    username: 'tbmq_websockets_username',
    password: null
};

console.log('Connecting client...');

const client = mqtt.connect(url, options);

client.on('connect', function () {
    console.log('Client connected!');
    client.subscribe(topic, function (error) {
        if (!error) {
            client.publish(topic, message);
        }
    });
});

client.on('message', (topic, message) => {
    console.log(`Received message. Payload: ${message.toString()}. Topic: ${topic}`);
    client.end();
});

client.on('error', (error) => {
    console.log('Error: ', error?.message);
});

client.on('reconnect', () => {
    console.log('Reconnecting...');
});

client.on('close', () => {
    console.log('Closing client...');
});
```

Save the code to `ws_example.js` and run it:

```bash
node ws_example.js
```

The client connects to TBMQ, subscribes to `sensors/temperature`, publishes a message to that topic, receives it, and disconnects.

You can also use the built-in <DocLink product={props.product} path="user-guide/ui/websocket-client">WebSocket client</DocLink> in the TBMQ UI to subscribe and verify messages.

### Connection URL breakdown

The URL `ws://localhost:8084/mqtt` consists of:

| Component | Description |
|---|---|
| `ws://` | WebSocket protocol scheme. Use `wss://` for encrypted connections. |
| `localhost` | Hostname or DNS of the machine running TBMQ. |
| `8084` | Port on which the WebSocket listener accepts connections. |
| `/mqtt` | Required path for MQTT over WebSocket, as defined in the MQTT specification. |

## WebSocket Secure (WSS)

MQTT over WebSocket Secure (WSS) encrypts communication between clients and the broker, protecting data from unauthorized access.

### Certificate types

- **CA-signed certificates** — issued by a trusted Certificate Authority; widely recognized by browsers. Recommended for production and public-facing deployments.
- **Self-signed certificates** — suitable for development or private networks. Browsers will display a security warning unless the certificate is manually added to the browser's trust store.

<Aside type="note">
  If you are using a self-signed certificate, add it to the browser's trust store to enable the <DocLink product={props.product} path="user-guide/ui/websocket-client">WebSocket client</DocLink> to connect without errors.
</Aside>

### Two-way authentication (mTLS) with WSS

Standard browser WebSocket connections only support one-way TLS, where the server presents its certificate to the client. Browsers do not universally support client-side certificates for WebSocket connections, so mutual TLS (mTLS) is **not feasible in browser environments**.

In non-browser environments (Node.js, Python, Java), mTLS is fully supported and remains an effective security measure.

The following example shows a Node.js client connecting to TBMQ over WSS with mutual TLS. Make sure the WSS listener is <DocLink product={props.product} path="security/listeners/#wss-listener">enabled and configured</DocLink>, and that MQTT client credentials of type **X.509 Certificate Chain** have been created with the client certificate CN specified. See <DocLink product={props.product} path="user-guide/ui/mqtt-client-credentials/#ssl-credentials">SSL credentials</DocLink>.

Replace `example.com` with your DNS hostname and update the certificate file paths accordingly.

```javascript
const mqtt = require('mqtt');
const fs = require('fs');

const url = 'wss://example.com:8085/mqtt';
const topic = 'sensors/temperature';
const message = 'Hello World';

const keyFile  = '/path/to/your/client/key/file.pem';
const certFile = '/path/to/your/client/cert/file.pem';
const caFile   = '/path/to/your/ca/cert/file.pem';

const options = {
  clean: true,
  clientId: 'tbmq_websockets_client_id',
  username: null,
  password: null
};

try {
  options.key  = fs.readFileSync(keyFile);
  options.cert = fs.readFileSync(certFile);
  options.ca   = fs.readFileSync(caFile);
  options.rejectUnauthorized = true;

  console.log('Connecting client...');

  const client = mqtt.connect(url, options);

  client.on('connect', function () {
    console.log('Client connected!');
    client.subscribe(topic, function (error) {
      if (!error) {
        client.publish(topic, message);
      }
    });
  });

  client.on('message', (topic, message) => {
    console.log(`Received message. Payload: ${message.toString()}. Topic: ${topic}`);
    client.end();
  });

  client.on('error', (error) => {
    console.log('Error: ', error?.message);
  });

  client.on('reconnect', () => {
    console.log('Reconnecting...');
  });

  client.on('close', () => {
    console.log('Closing client...');
  });

} catch (err) {
  console.error('Error reading certificate file:', err);
}
```

Save to `wss_example.js` and run:

```bash
node wss_example.js
```

<Aside type="note">
  To use Basic credentials (one-way authentication) instead of mTLS, set `options.username = 'tbmq_websockets_username'` and remove the `options.key`, `options.cert`, and `options.ca` lines.
</Aside>

A **Widget** is a dashboard element that displays a specific type of data or provides specific functionality. Widgets enable visualization of device data, remote device control, alarm management, and display of custom HTML content.

Widgets are organized into [**widget bundles**](#widget-bundles), which group related widgets by functionality or use case.

<IoTHubBanner href="/iot-hub/widgets/">
  Looking for a specific visualization? Browse pre-built <strong>Widget</strong> templates in the <strong>ThingsBoard IoT Hub</strong>, find one that fits your visualization needs, and drop it into your dashboard in just a few clicks.
</IoTHubBanner>

## Add Widget to Dashboard

<Steps>
1. Open a dashboard and click **Edit mode**.
2. Click **+ Add widget** in the toolbar, or, on an empty dashboard, the **+ Add new widget** placeholder.
3. On the **Installed** tab, select a **widget bundle**, then choose the specific widget. Switch to the **IoT Hub** tab to browse widgets from the ThingsBoard IoT Hub instead.
4. Configure the **datasource** — select an <DocLink product={props.product} path="user-guide/aliases" bold={true} target="_blank">entity alias</DocLink> (recommended) or select entities directly and add the required data keys.
5. Adjust **appearance** and **behavior** (title, units, colors, thresholds, actions, etc.) using the **Basic** or **Advanced** toggle in the dialog header.
6. Optionally click **Preview**, then click **Add**.
7. Drag to the desired position and resize on the grid.
8. Click **Save** to persist changes and exit edit mode.
</Steps>

<Aside type="tip">
  Instead of adding widgets manually, click **Configure with AI** to describe the dashboard you want in plain language. See <DocLink product={props.product} path="user-guide/dashboards/#configure-dashboard-with-ai" bold={true} target="_blank">Configure Dashboard with AI</DocLink>.
</Aside>

## Configure Widgets

Available configuration tabs depend on the widget type:

| Widget type | Time window | Datasources | Appearance | Widget card | Actions |
|---|:---:|:---:|:---:|:---:|:---:|
| Time series | ✓ | ✓ | ✓ | ✓ | ✓ |
| Latest values | ◑ | ✓ | ✓ | ✓ | ✓ |
| Control | — | ✓ | ✓ | ✓ | ✓ |
| Alarm | ✓ | ✓ | ✓ | ✓ | ✓ |
| Static | — | — | — | ✓ | ✓ |

*◑ — available when aggregation is enabled on a data key.*

**Layout** settings (position and size on the dashboard grid) are available for all widget types.

### Basic and Advanced Settings

The widget configuration dialog offers two modes. Switch between them using the toggle in the dialog header.

- **Basic mode** — shows only the most essential settings: datasource, key label, and a small set of appearance options. Best for quick setup.
- **Advanced mode** — exposes the full configuration across all tabs (data, appearance, widget card, actions, layout).

### Widget Time Window

<Aside type="note">
  Applies to **Time series** and **Alarm** widgets, and to **Latest values** widgets when aggregation is enabled on a data key.
</Aside>

The time window defines the time interval and aggregation/grouping rules applied to telemetry and alarm data. A widget can use either its **own time window** or inherit the <DocLink product={props.product} path="user-guide/dashboards/#dashboard-time-window" target="_blank">dashboard time window</DocLink>.

See <DocLink product={props.product} path="user-guide/time-window" target="_blank">time window</DocLink> for complete details.

### Datasources

A datasource defines where a widget gets its data — which entities to query and which keys to read. Most widgets have one or more datasources; **Static** widgets have none. Each datasource specifies a **type**, an **entity scope** (a single device or an alias-resolved set), optional **filters**, and a list of **data keys**.

<Aside type="note">
  For **Control** widgets, the datasource does not read data — it identifies the **target device** to which RPC commands are sent. The data key list is replaced by RPC command configuration specific to each control widget.
</Aside>

#### Datasource Types

**Device** — reads data from a single explicitly selected device. Use when the widget always shows data for the same device, regardless of dashboard context.

**Entity** — reads data from one or more entities resolved by an <DocLink product={props.product} path="user-guide/aliases" bold={true} target="_blank">entity alias</DocLink>. The alias can target a single entity (e.g., the device currently in dashboard context) or a dynamic list (e.g., all devices of a given type, assets in a group). Use for context-aware and multi-entity widgets.

**Function** — generates synthetic values using a JavaScript function (e.g., random numbers, sine waves). Use to configure and preview widget appearance during development without requiring live device data.

**Entities count** — returns the number of entities matched by an alias and optional filters as a single numeric value. Use with value card widgets to display metrics such as "Total devices" or "Active gateways".  
The dedicated <DocLink product={props.product} path='reference/widgets/count-widgets/entity-count' target="_blank">Entity count</DocLink> widget is built around this datasource type.

**Alarms count** — returns the number of alarms matched by the selected entity scope and alarm filters (severity, status, type, assignee) as a single numeric value. Use with value card widgets to display metrics such as "Active critical alarms".  
The dedicated <DocLink product={props.product} path='reference/widgets/count-widgets/alarm-count' target="_blank">Alarm count</DocLink> widget is built around this datasource type.

#### Data Keys

A data key identifies the telemetry, attribute, or entity field a widget reads from its datasource. Each datasource can have multiple data keys.

**Key source types:**
- <DocLink product={props.product} path="user-guide/digital-twins/time-series-data/" bold={true} target="_blank">Time series</DocLink> — telemetry keys reported by devices or written via the Rule Engine/REST API.
- <DocLink product={props.product} path="user-guide/digital-twins/attributes/" bold={true} target="_blank">Attributes</DocLink> — Client, Server, and Shared attributes of the selected entity.
- **Entity fields** — metadata fields available for the entity type (e.g., name, type, label, created time).

Available sources depend on the widget type:

| Widget type | Time series | Attributes | Entity fields | Alarm fields |
|---|:---:|:---:|:---:|:---:|
| Time series | ✓ | — | — | — |
| Latest values | ✓ | ✓ | ✓ | — |
| Alarm | ✓ | ✓ | ✓ | ✓ |
| Control, Static | — | — | — | — |

<h5>Add Key</h5>

Click the **key input field** and select from the dropdown of **available keys**.

To add a key not yet reported by the device, type the name manually and choose its source type — the widget will display data once values arrive.

<h5>Basic Key Configuration</h5>

Each key row provides inline access to **Label**, **Units**, and **Decimal places** without opening the full dialog. Available fields may vary by widget type.

<h5>Advanced Key Configuration</h5>

Click the **pencil** icon on a key row to open the full key configuration dialog.

**Key** — The telemetry key the widget reads. Changing this remaps the widget to a different key without removing and re-adding the datasource.

**Label** — Display name shown in the widget legend and tooltip. Defaults to the key name if left empty.

**Units** — Symbol appended to displayed values (e.g., `°C`, `%`, `kWh`).

**Decimal places** — Number of decimal digits shown for numeric values.

**Color** — Series color used in charts and legends.

**Aggregation** — *available for Latest values widgets only.* Enables a time window and reduces the key's time series data to a single aggregated value per interval.  
Configurable per key individually.  
Supported functions: **Min**, **Max**, **Average**, **Sum**, **Count**.

**Delta calculation** — Compares the current aggregated value against a historical reference period. Requires aggregation to be enabled.  
The result can be shown as the **Previous value**, an **Absolute delta** (current − previous), or a **Percentage delta** (relative difference).  
Available comparison periods: Previous interval, Day ago, Week ago, Month ago, Year ago, Custom.

**Data post-processing function** — JavaScript function applied to each data point after it is received from the server and before the resulting value is used by the widget.

Use this function when the value needs additional client-side transformation without modifying the original telemetry or attribute stored in ThingsBoard. Typical use cases include unit conversion, rounding, filtering unwanted values, formatting timestamps or strings, calculating differences between consecutive data points, or deriving another value from the original data.

**Signature:** `function(time, value, prevValue, timePrev, prevOrigValue): any`

| Parameter | Description |
|-----------|-------------|
| `time` | Timestamp of the current data point, in milliseconds. |
| `value` | Original value of the current data point. |
| `prevValue` | Post-processed value of the previous data point. |
| `timePrev` | Timestamp of the previous data point, in milliseconds. |
| `prevOrigValue` | Original, unprocessed value of the previous data point. |

For example, the following function converts every incoming value by multiplying it by 10:

```js
return value * 10;
```

The transformation affects only the value used by the widget. It does not change the telemetry or attribute stored in ThingsBoard.

For time-series data, returning `null` can be used to exclude a data point from the visualization. For example, in a line chart, the following function creates a gap whenever the value is 0:

```js
if (value === 0) {
  return null;
}
return value;
```

#### Data Filters

Filters narrow which data a widget retrieves from its data sources. Build a filter by adding keys and defining conditions on those keys — multiple keys and conditions can be combined.

See <DocLink product={props.product} path="user-guide/filters/" target="_blank">Filters</DocLink> for details.

#### Alarm Filters

Alarm widgets use a dedicated filter panel instead of a data key list. Use these filters to control which alarms appear in the widget — by status, severity, type, assignee, or entity scope.

- **Alarm status list** — show only alarms in the selected statuses: *Active*, *Cleared*, *Acknowledged*, *Unacknowledged*. Multiple statuses can be combined.
- **Alarm severity list** — show only alarms at the selected severities: *Critical*, *Major*, *Minor*, *Warning*, *Indeterminate*. Multiple severities can be combined.
- **Alarm type list** — restrict to specific alarm type names (e.g., `HighTemperature`). Leave empty to show all types.
- **Assignee** — filter by the user the alarm is assigned to, or leave as *All*.
- **Search propagated alarms** — when enabled, the widget includes alarms that originated on **child entities** and were propagated up to the parent. Useful when the datasource resolves an asset or group and you want to see alarms from all devices within it, not just direct alarms on the asset itself.

### Appearance

The Appearance tab controls the visual presentation, layout structure, and display behavior of a widget — how data is rendered and formatted — without affecting datasources, queries, or processing logic.

Available options depend on the widget type:

- **Value formatting** — default units, decimal precision, date format, and the "No data" message displayed when no data is available for the selected time window.
- **Layout structure** — layout type, auto scale, element visibility (label, icon, value, date), and icon sizing.
- **Chart rendering** — axes configuration (position, min/max, units), additional Y-axes, thresholds, grid lines, stacking, zoom, legend behavior, tooltip configuration, and aggregation display.
- **Table presentation** — header visibility, search, column management, actions column, pagination, tabs, and row styling.
- **Styling and theming** — background color, blur, padding, color palette, icon/value/label colors, and custom CSS.
- **Animation and visual states** — animation enablement, state-based styling, and dynamic effects.
- **Domain-specific visuals** (e.g., SCADA widgets) — symbol selection, flow direction, presence indicators, and animation speed.

### Widget Card

The widget card is the outer frame wrapping every widget on a dashboard. It provides a title bar, card-level visual styling, and optional header buttons available to end-users.

<h4>Card Title</h4>

- **Display widget title** — toggle that shows or hides the title bar entirely.
- **Title** — label displayed in the header. Supports dynamic patterns such as `${entityName}` or `${entityLabel}`.
- **Title tooltip** — tooltip text shown when hovering over the title.
- **Display title icon** — toggle that adds an icon before the title text. When enabled, configure the icon, its size, alignment, and color.
- **Advanced title style** — expandable section for fine-grained font and text styling (size, weight, color, decoration).

<h4>Card Style</h4>

Applies visual styling to the entire widget container.

- **Text color** — default text color inside the widget.
- **Background color** — fill color of the card.
- **Padding** — inner spacing between the card edge and its content.
- **Margin** — outer spacing around the card.
- **Border radius** — corner rounding of the card.
- **Drop shadow** — toggle that adds a drop-shadow effect around the card.
- **Advanced widget style** — expandable section for custom CSS applied to the widget container.

<h4>Card Buttons</h4>

Controls which action icons appear in the widget header.

- **Enable fullscreen** — shows an expand button in the widget header. Clicking it opens the widget in a full-screen overlay. The default depends on the widget type.
- **Enable data export** — shows a download button in the widget header. Clicking it lets users export the widget's current dataset (based on the active time window) as **CSV**, **XLS**, or **XLSX**. The default depends on the widget type. See <DocLink product={props.product} path="user-guide/csv-xls-data-export" target="_blank">CSV/XLS data export</DocLink> for details.

### Widget Actions

Actions connect user interactions to navigation or device control operations. Each action is defined by an **action source** (what triggers it) and an **action type** (what it does).

<h4>Action Sources</h4>

Action sources vary by widget type.

| Source | Widgets |
|---|---|
| **Widget header button** — a custom button in the widget title bar | All |
| **On row click** — clicking a table row | Tables |
| **On row double click** — double-clicking a table row | Tables |
| **Action cell button** — a custom button column in a table | Tables |
| **On HTML element click** — a tagged `id`-marked HTML element | HTML widgets |
| **On map element click** — markers and polygons | Map widgets |

<h4>Action Types</h4>

Action types are the same for all widgets.

| Type | Description |
|---|---|
| **Navigate to new dashboard state** | Open a named state in the current dashboard |
| **Update current dashboard state** | Update the entity context of the current state |
| **Navigate to other dashboard** | Open a different dashboard |
| **Open URL** | Open a web URL |
| **Custom action** | Execute a custom JavaScript function |
| **Custom action (with HTML template)** | Execute a function inside an HTML popup |
| **Mobile action** | Trigger a mobile device function (camera, QR scan, location) |
| **Place map item** | Create and place a new entity on the map *(map widgets only)* |

<h4>Add Action</h4>

**In basic mode** — scroll to **Actions** in the widget settings, click **Add action**, configure the source and type, then click **Add** and **Save**.

**In advanced mode** — open the **Actions** tab, click **+**, configure the source and type, then click **Add** and **Apply**.

See <DocLink product={props.product} path="user-guide/actions">Widget actions</DocLink> for complete examples of every source and type.

### Widget Layout Settings

The **Layout** tab controls how the widget behaves on the dashboard grid and on mobile screens.

<h4>Resize Options</h4>

- **Resizable** — when enabled, the widget can be resized by dragging its edges or corners in edit mode. Disable to lock the widget to its current size.
- **Preserve aspect ratio** — when enabled, resizing maintains the original width-to-height ratio.

<h4>Mobile</h4>

Controls widget visibility and sizing on mobile screens:

- **Hide widget in mobile mode** — removes the widget from the mobile layout while keeping it on desktop.
- **Hide widget in desktop mode** — removes the widget from the desktop layout while keeping it on mobile.
- **Order** — position of the widget in the mobile layout stack. Widgets stack vertically on mobile; lower values appear first.
- **Height** — widget height in the mobile grid (in grid units). Overrides the desktop height for mobile screens.

## Import and Export Widget

Widgets can be exported as self-contained JSON files and imported into any dashboard or ThingsBoard instance. The exported file contains the full widget definition — type, configuration, appearance, and actions — but not the entity data itself.

### Export Widget

In the widget header, click the **Export widget** icon to download its configuration as a `.json` file.

### Import Widget

<Steps>
1. Open a dashboard and click **Edit mode**.
2. Click **+ Add widget**, then click the **Import widget** icon in the dialog header.
3. Drag and drop the `.json` file, or click **Browse file**, then click **Import**. The widget is added to the dashboard.
4. Open the widget's settings and reconfigure the **datasource** — the widget retains its original entity references, which must be updated for the target dashboard.
5. Click **Save**.
</Steps>

## Duplicate Widget

Duplicating a widget allows you to reuse an existing configuration instead of creating a new widget from scratch. This is useful when multiple widgets share the same layout, style, or behavior but use different data.

<h4>Create a Full Copy</h4>

A full copy creates an independent duplicate with all settings preserved.

<Steps>
  1. Open the dashboard in <strong>edit mode</strong>.
  2. Right-click the widget and select <strong>Copy</strong> (or press <strong>Ctrl+C</strong>).
  3. Open the target dashboard (if needed).
  4. Right-click an empty area of the canvas and select <strong>Paste</strong> (or press <strong>Ctrl+V</strong>).
  5. Reposition the widget and <strong>save dashboard</strong>.
</Steps>

A full copy can be pasted into the same dashboard or into a different dashboard. After duplication, the new widget is independent and can be modified without affecting the original.

<h4>Create Referenced Copy</h4>

If you are working with multiple dashboard states or layouts (<DocLink product={props.product} path="user-guide/layouts/#breakpoints" bold={true} target="_blank">breakpoints</DocLink>) and want configuration changes to sync across all of them, use widget references.
A referenced copy shares the same configuration as the original widget. Any changes made to one instance are automatically reflected in the other.

<Steps>
  1. Right-click the widget and select <strong>Copy reference</strong> (or press <strong>Ctrl+R</strong>).
  2. In the same dashboard, switch to another state.
  3. Right-click the canvas and select <strong>Paste reference</strong> (or press <strong>Ctrl+I</strong>).
  4. Reposition the widget and <strong>save dashboard</strong>.
</Steps>

A pasted reference displays a **Reference** badge on the widget. Click the badge to replace the reference with an independent copy.

Referenced copies can only be used within the same dashboard, typically across different states. They cannot be pasted into another dashboard.

## Delete Widget

To delete a widget, switch to dashboard **edit mode**, then click the **✕** icon on the widget header, or right-click the widget and select **Delete** (or press **Ctrl+X**). Confirm the removal in the dialog that appears.
Click **Save** to persist the change, or **Cancel** to discard it and restore the widget.

## Widget Bundles

Widgets are grouped into bundles according to their purpose. System-level bundles are managed by the System Administrator; tenant-level bundles can be created by individual tenants.

### Add Widget Bundle

<Steps>
  1. Navigate to **Resources &#8702; Widgets**, then open the **Widgets bundles** tab.
  2. Click **+ Add widgets bundle**, then select **Create new widgets bundle**.
  3. Enter the bundle title and, optionally, a description and an image.
  4. Click **Add**.
  5. The new bundle appears in the list.
</Steps>

---

### Export Widget Bundle

Click the **Export** icon on the bundle to download it as a JSON file. In the dialog, toggle **Include bundle widgets in exported data** to embed the full widget definitions, or disable it to export only the referenced widget FQNs.

---

### Import Widget Bundle

<Steps>
  1. Navigate to **Resources &#8702; Widgets**, then open the **Widgets bundles** tab.
  2. Click **+ Add widgets bundle**, then select **Import widgets bundle**.
  3. Drag and drop the JSON file, or click **Browse file**, then click **Import**.
  4. The bundle is imported.
</Steps>

---

### Delete Widget Bundle

Delete a widget bundle using the trash icon, or select multiple bundles using the checkboxes for bulk deletion, then confirm the deletion in the dialog that appears.

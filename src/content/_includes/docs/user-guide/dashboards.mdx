**Dashboards** are configurable pages for visualizing and interacting with your IoT data. They are built from widgets — charts, tables, maps, controls, and more — and can display data from any combination of devices, assets, or other entities.

Before getting started, review the <DocLink product={props.product} path="user-guide/data-visualization" target="_blank">key concepts</DocLink> — states, aliases, layouts, actions, and time windows — that make up every dashboard.

</IoTHubBanner>

<Steps>

</Steps>

## Configure Dashboard with AI

**Configure with AI** lets you set up or modify a dashboard by describing what you want in plain language, instead of manually configuring aliases, time window, states, and widgets one by one. 
See the <DocLink product={props.product} path="user-guide/ai-assistant" bold={true} target="_blank">AI Assistant</DocLink> guide for how the Assistant works more generally and what else it can configure.

It's useful whenever you know what you want to see but don't want to build it widget-by-widget — for example:
- Creating a first set of widgets for a device or a fleet of devices
- Restructuring an existing dashboard's layout
- Adding a visualization for specific telemetry or attributes
- Updating dashboard configuration — aliases, time window, or states — to match a new requirement

<Aside type="note">
  AI Assistant is available to **Tenant Administrators only**.
  Customer-level users do not have access to this feature.
</Aside>

<h3>Workflow</h3>

<Steps>
1. Click **Configure with AI** to open the AI Assistant panel — from the **Monitor &#8702; Dashboards** page to start a new dashboard, or from within an existing dashboard's toolbar to modify it.
2. Describe the change you want in the chat — what data to show and how, e.g. *"Show SN-001 device's latest telemetry as value cards, a trend chart, and a table of its active alarms."* Use the suggested prompts if you're not sure where to start.
3. The Assistant explains its plan, then proposes each change — such as adding an entity alias, updating dashboard settings, adding <DocLink product={props.product} path="user-guide/widgets" target="_blank">widgets</DocLink>, or renaming a <DocLink product={props.product} path="user-guide/dashboards/#states">state</DocLink> — as an approval card describing exactly what will happen.
4. Click **Approve** on each proposal to apply it, **Deny** to skip it, or **Approve all further actions** to apply the rest of the plan without confirming each step individually.
5. Keep the conversation open to refine the result — reply with follow-up instructions (add a widget, change a chart type, rename a state) instead of starting over.
</Steps>

<h3>Best Practices</h3>

- Describe the outcome and the data you want to see — let the Assistant choose the widgets and layout.
- Name the device, asset, or fleet clearly so the Assistant sets up the right <DocLink product={props.product} path="user-guide/dashboards/#entity-aliases">entity alias</DocLink>.
- For complex dashboards, build them up with a few focused prompts instead of one long request.
- Review each proposed change before approving, especially before using **Approve all further actions**.

<h3>Limitations</h3>

- Changes are proposed, not applied silently: each one needs your approval, unless you choose to approve all further actions in that chat.
- The Assistant may rename existing resources as part of its plan, such as a dashboard state — review the plan if you want to keep the original names.

## Add a New Widget

In edit mode, click **+ Add widget** in the toolbar to open the widget library, then pick a widget to add it to the current layout.

ThingsBoard provides a wide range of customizable widgets — charts, tables, maps, controls, alarms, and more — organized into bundles by category. The widget library's **Installed** tab lists bundles already available on your instance; switch to the **IoT Hub** tab to browse and add widget bundles from the <a href="/iot-hub/widgets/" target="_blank" rel="noopener noreferrer"><strong>ThingsBoard IoT Hub</strong></a>. Each widget offers settings to tailor its appearance and behavior to your use case.

Explore the available widgets and their configuration options in the <DocLink product={props.product} path="user-guide/widgets" target="_blank">Widgets</DocLink> documentation.

## Filters

Filters narrow which data appears on the dashboard. 

Multiple key filters are combined with `and`; within a single key, complex expressions with `and`/`or` like `(A > 0 and A < 20) or (A = 50 or A = 60)` are supported.

Each filter checks one or more key conditions against an attribute or telemetry key — for example, show only devices where `model = "DHT22"` and `battery < 20`.

<Steps>
1. In edit mode, click **Filters** in the toolbar, then click **Add filter**.
2. Enter a **Filter name**. Toggle **Editable** to allow end users to modify the filter in view mode.
3. Click **Add key filter**, then set the **Key type**, **Key name**, and **Value type** for the condition. In the filters table below, choose an **Operation** and enter a **Value**, then click **Add**.
4. Repeat to add more key filters — use the **And**/**Or** toggle to control how they combine. The **Filter preview** shows the resulting expression as you build it.
5. Click **Add** to save the filter, then **Save** in the Filters dialog to apply it to the dashboard.
</Steps>

See <DocLink product={props.product} path="user-guide/filters/" target="_blank">Filters</DocLink> for more details.

## Dashboard Settings

Click the **gear** icon (**Settings**) in the edit mode toolbar to open the **Settings** dialog and configure dashboard appearance and behavior: state controller, title, logo, toolbar visibility, layout, and advanced CSS.

<h4>State Controller</h4>

Determines how <DocLink product={props.product} path="user-guide/dashboards/#states">dashboard states</DocLink> are driven. Default: **entity** — state is bound to the currently selected entity context.

<h4>Title</h4>

In **Title settings**, enable **Title** to show the dashboard title in the top-left corner. Adjust color and transparency with the color picker.

<h4>Logo</h4>

In **Dashboard logo settings**, enable **Display logo in dashboard fullscreen mode** and upload an image. The logo appears in the top-left corner when the dashboard is in fullscreen.

<h4>Toolbar Settings</h4>

Each toggle in **Toolbar settings** controls the visibility of a toolbar option.

| Toggle | Description |
|--------|-------------|
| **Hide toolbar** | Entirely hides the toolbar; only the **Enter edit mode** (pencil) icon is displayed in the top-right corner. |
| **Keep toolbar opened** | Keeps the toolbar always expanded; when off, it collapses into a three-dots menu. |
| **Display dashboards selection** | Shows or hides the dashboards selector in the toolbar. |
| **Display entities selection** | Shows or hides the entities selector in the toolbar. |
| **Display filters** | Shows or hides the filters button (only if filters are defined). |
| **Display time window** | Shows or hides the time window control. |
| **Display export** | Shows or hides the export button. |
| **Display update dashboard image** | Shows or hides the update dashboard image button. |

<h4>Advanced Settings</h4>

**Dashboard CSS** — apply custom CSS scoped to the dashboard.

<h4>Layout Settings</h4>

Configure the default layout grid and appearance. See <DocLink product={props.product} path="user-guide/dashboards/#layouts">Layouts</DocLink> for layout types and breakpoints.

- **Columns count** — number of columns in the dashboard grid (default: 24).
- **Minimum layout width** — minimum width in columns before the layout scrolls horizontally.
- **Margin between widgets** — spacing between widgets in pixels.
- **Apply margin to the sides of the layout** — adds outer padding around the widget grid.
- **Auto fill layout height** — stretches the layout to fill the full page height.
- **Background color** — sets a solid background color for the dashboard.
- **Background image** — sets a background image (browse from gallery or set a link); configure **Background size mode** (e.g. Fit width).

<h4>Mobile Layout Settings</h4>

- **Auto fill layout height** — applies auto-fill to the mobile layout.
- **Mobile row height** — height of each row in the mobile layout (default: 70 px).

## Dashboard Time Window

A **time window** sets the time range — and, for historical data, the aggregation — applied to the data shown on a dashboard, for example "last 1 hour" or a fixed date range. See <DocLink product={props.product} path="user-guide/time-window/" target="_blank">Time Window</DocLink> for the difference between real-time and history time windows and when to use each.

The **dashboard-level time window**, set from the toolbar, applies to all time series and alarm widgets unless a widget has its own time window configured.

## Entity Aliases

An **Entity alias** is a named reference that tells a widget which entity, or entities, to pull data from — for example, "all thermometers" or "the device selected in the current state". See <DocLink product={props.product} path="user-guide/aliases" bold={true} target="_blank">Entity Aliases</DocLink> for the difference between static and dynamic aliases and when to use each.

Manage a dashboard's aliases from the toolbar: click **Entity aliases** in edit mode to open the aliases dialog, then add, edit, or delete the aliases used by the dashboard's widgets.

<Steps>
1. In edit mode, click **Entity aliases** in the toolbar, then click **Add alias**.
2. Enter an **Alias name**. Toggle **Resolve as multiple entities** to render data from every matching entity at once — when off, the widget uses only one (e.g. the entity selected in the current state).
3. Select a **Filter type** — such as *Device type*, *Asset type*, *Entity from dashboard state*, or *Owner of entity from dashboard state* — then complete the fields it adds. For *Device type*, select one or more **Device types** and, optionally, a **Device name expression**.
4. Click **Add**, then **Save** in the Entity aliases dialog to apply the alias to the dashboard.
</Steps>

## States

A **state** is a named view within a dashboard — for example, a root state listing all devices and a detail state showing data for one selected device. 

Navigating between states is done using customizable actions in widgets (see <DocLink product={props.product} path="user-guide/dashboards/#navigate-between-states">Navigate Between States</DocLink> below).

To manage states, in edit mode click **States** in the toolbar to open the **Manage dashboard states** dialog, which lists every state with its Name, State Id, and Root state flag.

### Add a State

<Steps>
1. In edit mode, click **States** in the toolbar to open the **Manage dashboard states** dialog.
2. Click the **+** icon (**Add dashboard state**) next to **Dashboard states**.
3. Enter a state **Name** — the **State Id** is generated from it automatically, but editable. Use `${entityName}` for dynamic naming.
4. Click **Add**, then **Save** in the Manage dashboard states dialog.
</Steps>

Once added, switch between states using the state dropdown next to **States** in the toolbar.

**Root state**

Every dashboard has one root state, and it can't be deleted while set as root. To change it, click the **pencil** icon (**Edit dashboard state**) next to a state, enable the **Root state** checkbox, and click **Save**.

### Navigate Between States

To move between states, attach a <DocLink product={props.product} path='user-guide/actions/#navigate-to-new-dashboard-state' bold={true} target="_blank">Navigate to new dashboard state</DocLink> action to any widget. When the action is triggered — for example, by clicking a row in a table or a button in the widget header — the dashboard switches to the target state.

Before configuring the action, make sure you have already **[added the target state](#add-a-state)**.

<Steps>
1. Open the dashboard in **Edit mode**.
2. Click the **pencil** icon on the widget to open its settings.
3. Go to the **Actions** tab and click **+ Add action**.
4. Set **Action source** (e.g., *Widget header button* or *On row click*), enter a **Name**, and set **Action type** to *Navigate to new dashboard state*.
5. Select the **Target state** from the dropdown and click **Add**.
6. Click **Apply**, then **Save** the dashboard.
</Steps>

## Manage Owner and Groups

Reassign a dashboard to a different <strong>owner</strong> (the tenant or a customer) and organize it into a <strong>dashboard group</strong>. Grouping matters because dashboards are shared or made public as a group, not individually — see <DocLink product={props.product} path="user-guide/dashboards/#share-dashboard-with-customers">Share Dashboard with Customers</DocLink> and <DocLink product={props.product} path="user-guide/dashboards/#make-dashboard-public">Make Dashboard Public</DocLink>.

Typically used by a <strong>Tenant Administrator</strong> managing who owns and can access a dashboard.

  <Steps>
    <ol>
      <li>Go to the <strong>Monitor &#8702; Dashboards</strong> page.</li>
      <li>Click the <strong>pencil</strong> icon (<strong>Dashboard details</strong>) next to the desired dashboard, then click <strong>Manage owner and groups</strong>.</li>
      <li>In the <strong>Owner</strong> field, select a new owner from the dropdown.</li>
      <li>Optionally, select an existing dashboard group or add a new one in <strong>Groups</strong>.</li>
      <li>Click <strong>Update</strong>.</li>
    </ol>
  </Steps>

  <Aside type="note">
    A Tenant Administrator always has the right to reassign or revoke dashboard ownership.
  </Aside>

  <Aside type="tip" title="Include customer entities">
    This option controls whether customer-owned dashboards are displayed in the list.<br/>
    <ul>
      <li><strong>Enabled (default):</strong> shows all dashboards, including customer-owned.</li>
      <li><strong>Disabled:</strong> shows only your own dashboards.</li>
    </ul>
  </Aside>

## Share Dashboard with Customers

<strong>Share Dashboard with Customers</strong> grants one or more customers secure, login-required access to every dashboard in a group.

Use it when the customer should log in to see only their own data. You can also grant write access, not just read-only. For access that doesn't require a login — public monitoring screens, partners, embedded views — use <DocLink product={props.product} path="user-guide/dashboards/#make-dashboard-public">Make Dashboard Public</DocLink> instead.

Dashboards are shared as part of a <strong>dashboard group</strong>, not individually — see <DocLink product={props.product} path="user-guide/dashboards/#manage-owner-and-groups">Manage Owner and Groups</DocLink> to add a dashboard to a group.

Typically used by a <strong>Tenant Administrator</strong> onboarding a customer, or a <strong>Customer Administrator</strong> granting access to their own sub-customers or users. See <DocLink product={props.product} path="user-guide/customers">Customers</DocLink> for how customer accounts work.

By default, sharing applies to <strong>All users</strong> of the selected customer; uncheck it to scope access to a specific <strong>user group</strong> instead (e.g. Customer Administrators or Customer Users).

When sharing, choose a permission level:

- <strong>Read</strong> — the customer can view the dashboards but cannot modify them.
- <strong>Write</strong> — the customer can view and edit the dashboards.
- <strong>Other</strong> — apply one or more previously created <strong>Roles</strong> with fine-grained permissions.

<Aside type="tip">
  A <strong>Role</strong> is a named set of permissions (e.g. read, write, delete) that can be reused across multiple entity groups. See <DocLink product={props.product} path="user-guide/roles">Role-Based Access Control</DocLink> for details.
</Aside>

<Steps>
  <ol>
    <li>Go to <strong>Monitor &#8702; Dashboards &#8702; Groups</strong>.</li>
    <li>Click the <strong>Share</strong> icon next to the dashboard group to open the <strong>Share entity group</strong> dialog.</li>
    <li>Select the <strong>Customer</strong> to share with.</li>
    <li>Set the <strong>Permissions</strong>: <strong>Read</strong>, <strong>Write</strong>, or <strong>Other</strong> to select one or more <strong>Roles</strong>.</li>
    <li>Click <strong>Share</strong>.</li>
  </ol>
</Steps>

<Aside type="note">
  Sharing grants access to the dashboard only — not to the data it displays. The customer must also have access to the associated devices or entities for widgets to show data.
</Aside>

## Make Dashboard Public

A <strong>public dashboard</strong> is a dashboard anyone can open with a link — no ThingsBoard account or login required. Making a dashboard group public turns every dashboard in that group into a public dashboard.

This is different from <DocLink product={props.product} path="user-guide/dashboards/#share-dashboard-with-customers">sharing a dashboard group with a customer</DocLink>:

<table>
  <thead>
    <tr><th></th><th>Public dashboard</th><th>Shared with a customer</th></tr>
  </thead>
  <tbody>
    <tr><td><strong>Login required</strong></td><td>No — anyone with the link</td><td>Yes — the customer's own account</td></tr>
    <tr><td><strong>Access level</strong></td><td>Always read-only</td><td>Read, Write, or a custom Role</td></tr>
    <tr><td><strong>Best for</strong></td><td>External viewers with no account</td><td>Ongoing access for a specific customer</td></tr>
  </tbody>
</table>

<strong>Common scenarios for public dashboards:</strong>

- <strong>Sharing dashboards with customers or partners</strong> who don't need (or shouldn't get) a login
- <strong>Embedding a dashboard</strong> in an external website or customer portal, e.g. in an iframe
- <strong>Public monitoring pages</strong> — lobby screens, kiosks, status pages
- Quick demos or one-off links where setting up a customer account isn't worth it

A public dashboard is always <strong>read-only</strong>: visitors can view widgets, change the time window, and switch dashboard states, but cannot edit the dashboard, and cannot see any other dashboards, tenant data, or ThingsBoard UI.

<Steps>
  1. Go to <strong>Monitor &#8702; Dashboards &#8702; Groups</strong>.
  2. Click the <strong>Make public</strong> icon next to the dashboard group.
  3. Confirm making the group public.
</Steps>

<Aside type="note">
  The first time you make a group public, ThingsBoard creates a built-in system customer named <strong>Public</strong>, used to manage anonymous access to public dashboards and other publicly shared resources.
</Aside>

Share a link to an individual public dashboard.

<Steps> 
  1. Open the now-public group and click the <strong>Public dashboard link</strong> icon next to the desired dashboard.
  2. In the <strong>Public dashboard link</strong> dialog, click the <strong>copy</strong> icon (<strong>Copy public link</strong>) to copy it, or share it directly via the Facebook, X, LinkedIn, or Reddit buttons.
</Steps>

<Aside type="note">
  A public dashboard only shows data if its underlying device or asset groups are <strong>also</strong> public — the dashboard and the data behind it are made public separately. See <DocLink product={props.product} path="user-guide/groups/#make-group-public-or-private">Make Group Public or Private</DocLink>.
</Aside>

To revoke public access, click the <strong>Make private</strong> icon next to the dashboard group and confirm — this immediately disables every public link for that group.

## Export and Import Dashboard

### Export Dashboard

Export a dashboard's **configuration** as a **JSON** file. This captures the dashboard structure, widget settings, and layout — not a visual snapshot of the data.

Use this for:
- **Backup** — save a copy of a dashboard configuration
- **Migration** — move dashboards between ThingsBoard instances or environments
- **Reuse** — copy or duplicate an existing dashboard as a starting point for a new one
- **Version control** — store dashboard configurations alongside your project code (for automatic, ongoing versioning instead, see <DocLink product={props.product} path="user-guide/dashboards/#dashboard-version-control">Dashboard Version Control</DocLink> below)

Two ways to export:
- On the **Monitor &#8702; Dashboards** page, click the **Export dashboard** icon next to a dashboard. In the **Export dashboard** dialog, optionally toggle **Embed dashboard images and resources** (on by default), then click **Export**.
- Inside a dashboard, click the **Export dashboard** button in the toolbar and select **Export JSON configuration**.

### Export as PDF, PNG, or JPEG

Export a visual snapshot of the current dashboard — a pixel-accurate capture of all widgets, charts, and data as displayed on screen at the time of export. Unlike the JSON export above, this captures how the dashboard <em>looks</em>, not how it is configured.

- <strong>Formats:</strong> PDF, PNG, JPEG
- <strong>Best for:</strong> sharing reports with stakeholders, printing dashboards, archiving a point-in-time view

Click the <strong>Export dashboard</strong> button on the right side of the toolbar, then select the desired format: <strong>PDF</strong>, <strong>PNG</strong>, or <strong>JPEG</strong>.

The snapshot is generated and automatically downloaded to your device.

<Aside type="note">
  To automate report distribution to stakeholders, use the <strong>Reporting</strong> feature. See <DocLink product={props.product} path="user-guide/reporting/dashboards/" bold={true} target="_blank">Reporting</DocLink> for details.
</Aside>

### Import Dashboard

Import a dashboard from a JSON configuration file.

<Steps>
  1. Go to **Monitor &#8702; Dashboards**.
  2. Click **+ Add dashboard &#8702; Import dashboard**.
  3. Upload the `.json` configuration file and click **Import**.
</Steps>

### Dashboard Version Control

Dashboard configurations can be exported to a remote Git repository, versioned, and restored at any point in time — enabling backup, rollback to a previous state, and collaborative management of dashboard changes across teams. Unlike a one-off JSON export, this keeps a full, ongoing history automatically.

See <DocLink product={props.product} path='user-guide/version-control' target="_blank">Version Control</DocLink> for full details.

## Home Dashboard

The **Home dashboard** is the dashboard that opens when a user clicks **Home** in the left-hand navigation. If none is configured, ThingsBoard falls back to a built-in default Home page for that role.

A Home dashboard can be set at three levels, resolved in this order — the first one found is used:

1. **User** — set individually per user account.
2. **Customer** — set once for a Customer; applies to that customer's users who haven't set their own.
3. **Tenant** — set once for a Tenant; applies tenant-wide to Tenant Administrators and, when neither a user-level nor customer-level Home dashboard is set, to customer users too.

### Setting a User's Home Dashboard

See <DocLink product={props.product} path="user-guide/users/#user-details">User Details</DocLink> — the **Home dashboard** field is set individually per user from their user profile.

### Setting the Tenant or Customer Home Dashboard

A Tenant Administrator or Customer Administrator can replace the default Home page for their entire tenant or customer:

<Steps>
1. Build a Dashboard with the widgets/information you want to show, or <DocLink product={props.product} path="user-guide/dashboards/#import-dashboard">import one</DocLink>.
2. Go to **Platform &#8702; Settings &#8702; Home**.
3. Select the dashboard in the **Home dashboard** field.
4. Optionally enable **Hide home dashboard toolbar** to hide the toolbar when this dashboard is open.
5. Click **Save**.
</Steps>

Once saved, that dashboard replaces the default Home page for every user of that tenant (or customer) who doesn't have their own Home dashboard set individually.

<ShowFor product={props.product} show={[Products.PE]}>
Setting this requires **White Labeling** write permission — if the field is read-only, the current user's role doesn't grant it.
</ShowFor>

## Troubleshooting

| Symptom | Cause | Fix |
|---------|-------|-----|
| Widget shows no data | Its entity alias doesn't resolve to any entity, or a filter excludes it | Check the alias in <DocLink product={props.product} path="user-guide/dashboards/#entity-aliases">Entity Aliases</DocLink>, and any <DocLink product={props.product} path="user-guide/dashboards/#filters">filters</DocLink> applied to the dashboard |
| Widget shows no data for a specific time range | The dashboard or widget time window doesn't cover the period with data | Check the <DocLink product={props.product} path="user-guide/dashboards/#dashboard-time-window">dashboard time window</DocLink> and any widget-level override |
| Public dashboard link opens but widgets are blank | The devices or assets behind the widgets aren't public — only the dashboard was made public | Make the underlying entities public too — see <DocLink product={props.product} path="user-guide/groups/#make-group-public-or-private">Make Group Public or Private</DocLink> |
| Customer can't see a shared dashboard's data | The customer has access to the dashboard but not to the devices or assets it displays | Grant the customer access to the associated entities — see <DocLink product={props.product} path="user-guide/dashboards/#share-dashboard-with-customers">Share Dashboard with Customers</DocLink> |
| Import fails or the dashboard opens empty | The uploaded file isn't a valid dashboard JSON export, or it was edited by hand | Re-export the original dashboard and import that file unmodified |
| Home page still shows the built-in default widgets (e.g. "Getting started") | No Home dashboard has been configured for the user, customer, or tenant | Set one via <DocLink product={props.product} path="user-guide/dashboards/#home-dashboard">Home Dashboard</DocLink> |

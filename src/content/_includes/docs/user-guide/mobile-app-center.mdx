The **Mobile apps** page (Mobile App Center) is a hub for building, configuring, and managing mobile apps in ThingsBoard. Whether you are starting from scratch or publishing the {props.product === Products.CE ? 'ThingsBoard mobile app' : 'ThingsBoard app'} to Google Play or the App Store, this tool guides you through every step.

The page is divided into tabs:

- **[Bundle](#bundle)** — manage settings for mobile applications included in the bundle: authentication methods, layout, and self-registration.
- <DocLink product={props.product} path="user-guide/mobile-app-center/applications">Applications</DocLink> — add, edit, or remove mobile applications.
- <DocLink product={props.product} path="user-guide/mobile-app-center/qr-code-widget">QR code widget</DocLink> — set up a QR code widget on the Home page for easy mobile app access.

## Bundle

A **Bundle** groups OAuth 2.0 settings, layout design, and self-registration for one or more mobile apps — letting you manage Android and iOS versions in one place.

The bundle wizard includes the following steps:

<ul>
  <li><strong>Basic settings</strong> — define the bundle name and link your apps. You can also create a new app directly.</li>
  <li><strong>OAuth 2.0</strong> — enable Single Sign-On (SSO) via third-party identity providers that support OAuth 2.0.</li>
  <li><strong>Layout</strong> — customize the app's navigation menu to match your use cases.</li>
  <li><strong>Self registration</strong> — set up a registration form for new mobile users.</li>
</ul>

### Adding a New Bundle

<Steps>
1. Go to the **Mobile apps** page.
2. On the **Bundles** tab, click **+ Add bundle** in the upper-right corner.
</Steps>

The bundle configuration wizard opens.

### Basic Settings

The first step of the wizard has four fields:

- **Title** — the bundle name.
- **Android Application** and **iOS Application** — pick an existing application for each platform, or click **Create new** next to the field to [create one](#creating-an-application) without leaving the wizard. A bundle can hold one application per platform, and either platform can stay empty.
- **Description** — optional notes about the bundle.

<Aside type="tip">
  You can add applications even after the bundle is created.
</Aside>

#### Creating an Application

<Steps>
1. Click **Create new** in the corresponding section (Android Application or iOS Application).
2. Enter the **Application package** name and, optionally, an **Application title**.
3. An **Application Secret** is generated automatically — copy and store it, or replace it with your own value.
4. Set the **Status**:
   - **Draft** — for applications still in development. Store information can be added later.
   - **Published** — for applications ready to be launched and used by end users.
   - **Deprecated** — for older applications that are no longer actively supported but still available.
   - **Suspended** — for applications that are temporarily disabled or restricted.
5. (Optional) Specify minimum/latest app versions and release notes.
6. Add **store information**:
   - **Android**: **Google Play link** and **SHA256 certificate fingerprints**.
   - **iOS**: **App Store link** and **App Site Association ID**.
7. Click **Add** to save the application.
</Steps>

Click **Next**.

### OAuth 2.0

Enable authentication through an external provider that supports the <DocLink product={props.product} path="user-guide/security/oauth-2-support" target="_blank">OAuth 2.0</DocLink> protocol.
Select an existing OAuth 2.0 client or <DocLink product={props.product} path="user-guide/security/oauth-2-support/#oauth-20-client" target="_blank">configure a new one</DocLink>.

You can also disable OAuth 2.0 for mobile devices.

To change this later, go to **Mobile apps** → **Bundles**, click the bundle, and open the **OAuth 2.0** tab.

When OAuth 2.0 is enabled, the login screen of the app shows a sign-in button for each selected client above the email and password fields.

To add a new menu item:

<Steps>
1. Click **+ Add specific page** at the bottom of the page or between existing menu items.
2. Enter the **Page name**.
3. Select the **Page type**:
   - **Dashboard** — link to a ThingsBoard dashboard.
   - **Web view** — link to an external webpage.
   - **Custom** — a built-in app page addressed by its path.
4. Depending on the selected page type, select a dashboard, enter the external **URL**, or enter the **Path** of the built-in page.
5. Click **Add**.
</Steps>

### Self registration

The <strong>self-registration</strong> feature lets tenants set up a public sign-up page where clients can register and access ThingsBoard with predefined roles and permissions.

To configure it later, go to **Mobile apps** → **Bundles**, click the bundle, and open the **Self registration** tab.

Configure the self-registration form:

<strong>Basic settings:</strong>

- **Page title** — the header displayed at the top of the registration page.
- **Notification recipient** — recipients who receive notifications about new user registrations. Learn more about <DocLink product={props.product} path="user-guide/notifications" target="_blank">notifications</DocLink>.
- **Redirect settings**:
  - **Application URL scheme** — the custom URL scheme for redirecting users after registration (e.g., `tbscheme`).
  - **Application URL hostname** — the hostname used in redirection (e.g., `app.pe.thingsboard.org`).

<strong>Registration form fields:</strong>

The mandatory fields are email, password, and repeat password. Additional fields can be added as needed.

<strong>Captcha properties:</strong>

Captcha prevents automated creation of fake accounts.

To generate Captcha keys, navigate to the <a href="https://www.google.com/recaptcha/intro/v3.html" target="_blank">Google reCAPTCHA admin console</a>:

<Steps>
  <ol>
    <li>Select the reCAPTCHA version (v2, v3, or Enterprise).</li>
    <li>Specify the domain name of your ThingsBoard instance.</li>
    <li>Copy and securely store the site key and secret key.</li>
  </ol>
</Steps>

### Configuration Dialog

After the bundle is created, the **Configuration dialog** opens with the steps to get the {props.product === Products.CE ? 'ThingsBoard mobile app' : 'ThingsBoard app'} running against this bundle. Follow them to set up your app, or click **Close** if you already have one configured.

The dialog has four sections:

- **Prepare development environment** — a **Documentation** link to the Flutter SDK setup.
- **Get app source code** — the `git clone` command for the app repository.
- **Configure app settings** — a **Download file** button for the bundle's `configs.json`, which goes into the root directory of the cloned project.
- **Run the app** — the `flutter run` command that builds the app with that file.

The **Getting Started** button at the bottom links to a Flutter getting-started guide. For the ThingsBoard walkthrough, see the <a href={props.product === Products.CE ? '/docs/mobile/getting-started/' : '/docs/mobile/pe/getting-started/'}>Getting started</a> guide. Turn on **Do not show again** to stop the dialog from opening after each new bundle.

To open the dialog again, go to **Mobile apps** → **Bundles** and click the **Configuration app** button in the row of the bundle.

The bundle is created. Applications included in the bundle now use the configured settings.

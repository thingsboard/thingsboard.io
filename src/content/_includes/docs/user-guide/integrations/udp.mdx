UDP Integration lets devices that use their own text or binary protocol send data to ThingsBoard as UDP datagrams. An **uplink data converter** transforms each datagram into device or asset data, including telemetry and attributes. ThingsBoard can also send a **downlink** datagram back to the device's source address. UDP Integration runs only as a <DocLink product={props.product} path="user-guide/integrations/remote/" target="_blank">remote integration</DocLink>: a standalone process that binds the UDP port and connects to ThingsBoard over gRPC.

Use UDP Integration when:
- Devices send a custom text or binary protocol over raw UDP.
- Firmware sends fire-and-forget datagrams to a fixed host and port and cannot be changed.
- Low transport overhead matters more than delivery guarantees, for example for battery-powered sensors or high-frequency telemetry.

## Architecture

1. **Receive data.** A device sends a datagram to the configured port (default `11560`) on the remote integration host. The handler turns it into the converter payload: text, JSON, raw bytes, or a hex envelope.
2. **Decode the payload.** The uplink converter identifies the device or asset and extracts attributes and telemetry.
3. **Process the message.** ThingsBoard processes the converted data through the Rule Engine. If **Allow create devices or assets** is enabled, ThingsBoard can create an entity that does not exist yet.
4. **Send downlink data (optional).** The integration remembers each device's source address. The downlink converter encodes the Rule Engine message, and the integration sends it as a datagram to that address.

### Create the Uplink Data Converter

The uplink converter reads the payload prepared by the **[handler](#handler-configuration)** and maps it to ThingsBoard entities and data. UDP Integration uses the **Generic** converter: you write the decoder in TBEL or JavaScript. For converter types and the full decoder reference, see <DocLink product={props.product} path="user-guide/integrations/uplink-data-converter/#converter-types" target="_blank">Uplink data converter</DocLink>.

   - If telemetry keys are fixed rather than embedded in the payload, replace the loop with explicit assignments: `telemetryPayload['temperature'] = parseFloat(payloadArray[2]);`.
   - To report device properties instead of measurements, move fields from the `telemetry` map to the `attributes` map.

   ```js maxLines=35 collapsible
   var result = {
       deviceName: hexToString(data.substring(0, 12)),
       deviceType: hexToString(data.substring(12, 26)),
       telemetry: {
           temperature: parseFloat(hexToString(data.substring(26, 34))),
           humidity: parseFloat(hexToString(data.substring(34, 38)))
       }
   };

   /** Helper functions **/

   function decodeToString(payload) {
       return String.fromCharCode.apply(String, payload);
   }

   // Hexadecimal string to string
   function hexToString(hex) {
       var str = '';
       for (var i = 0; i < hex.length; i += 2) {
           var notNullValue = parseInt(hex.substr(i, 2), 16);
           if (notNullValue) {
               str += String.fromCharCode(notNullValue);
           }
       }
       return str;
   }

   function decodeToJson(payload) {
       var str = decodeToString(payload);
       var data = JSON.parse(str);
       return data;
   }

   return result;
   ```

   The decoder reads the hex string from `reports[0].value` of the handler's JSON envelope and converts each segment back to ASCII.

   **To adapt:**

   - Adjust the `substring(start, end)` offsets to match your device's hex-encoded field layout (each ASCII character encodes to 2 hex digits, so a 6-character name occupies 12 hex characters).
   - For numeric fields not represented as ASCII digits, use `parseInt(hexToString(data.substring(start, end)), 16)` to decode a raw integer.
   - If your device sends a flat hex string rather than a JSON envelope, replace `decodeToJson(payload).reports[0].value` with `decodeToString(payload)` and adjust offsets accordingly.

<h4 id="decoder-inputs">Decoder Inputs</h4>

The decoder signature is `function decoder(payload, metadata): object | object[]`.

| Variable | Type | Content |
|----------|------|---------|
| `payload` | byte array | The datagram, prepared by the handler type (see the table below). |
| `metadata` | `{[key: string]: string}` | `integrationName` and the key–value pairs from the integration's **Metadata** field. The sender's IP address and port are not included. |

What reaches `payload` for each handler type:

| Handler type | `payload` content |
|--------------|-------------------|
| **Text** | The datagram decoded with **Charset Name** and serialized as a JSON string, so the text arrives in double quotes. The Text decoder template strips them. Empty datagrams are ignored. |
| **JSON** | The datagram bytes, unchanged. |
| **Binary** | The datagram bytes, unchanged. Empty datagrams are ignored. |
| **Hex** | A JSON envelope with the datagram as a lowercase hex string: `{"reports":[{"value":"534e2d..."}]}`. The Hex decoder template reads `reports[0].value`. |

Built-in helpers include `decodeToString(payload)`, `decodeToJson(payload)`, and, in TBEL, `hexToBytes`, `bytesToString`, and `parseBytesToInt`. For other patterns, see <DocLink product={props.product} path="user-guide/integrations/uplink-data-converter/#common-scripting-patterns" target="_blank">Common scripting patterns</DocLink>.

#### Connection Settings

| Parameter | Description |
|-----------|-------------|
| **Port** | UDP port the integration listens on. Default: `11560`. Must be free on the remote integration host. |
| **Size of the buffer for inbound socket (in KB)** | Receive buffer of the UDP socket. Default: `64`. Increase it if datagrams are dropped under load. |
| **Enable broadcast** | Accepts datagrams sent to a broadcast address. On by default. |
| **Execute remotely** | Always on for UDP. ThingsBoard generates the **Integration key** and **Integration secret** for the remote process. |
| **Cache Size** | Shown only when a downlink converter is assigned. Maximum number of device addresses remembered for downlink delivery. Default: `1000`. When the cache is full, older entries are evicted. |
| **Cache time to live in minutes** | Shown only when a downlink converter is assigned. How long a device address stays valid after its last uplink. Default: `1440` (24 hours); range `0`–`525600`. |
| **Metadata** | In **Advanced settings**. Key–value pairs added to the `metadata` of every message from this integration. |

## Configure Downlink

The integration sends downlinks as datagrams to the source IP address and port of the device's latest uplink. It learns that address only from uplinks, so a device must send at least one uplink first.

- If the device's address is cached, the downlink is sent immediately.
- Otherwise, the downlink waits until the next uplink from that device.
- After each downlink payload, the integration sends a second datagram with the line separator of the remote host's OS (`\n` on Linux and macOS, `\r\n` on Windows). Device-side parsers must ignore it.

To receive downlinks, the device must listen on the same port it sends from. A one-shot `echo ... | nc -u` uses a random source port that closes right after sending.

The downlink converter turns a <DocLink product={props.product} path="user-guide/rule-engine" target="_blank">Rule Engine</DocLink> message into the datagram bytes. For the full encoder reference, see <DocLink product={props.product} path="user-guide/integrations/downlink-data-converter" target="_blank">Downlink data converter</DocLink>.

### Create and Assign the Downlink Converter

<Steps>
1. Open the integration in **Integrations &#8702; Integrations** and click **Toggle edit mode** (pencil icon).

3. Enter a name, for example `UDP Downlink Converter`.

Encoder used in this guide:

```js
/** Encoder **/

// Encode downlink data from the incoming Rule Engine message.
// msg: JSON message payload.
// msgType: message type, e.g. 'ATTRIBUTES_UPDATED', 'POST_TELEMETRY_REQUEST', etc.
// metadata: key-value pairs containing additional message data.
// integrationMetadata: key-value pairs configured in the integration.

var result = {
    // Specify the response body format: JSON, TEXT, or BINARY.
    contentType: "JSON",

    // Serialize the incoming message and use it as the UDP payload.
    data: JSON.stringify(msg),

    // Add optional metadata when required by the integration.
    metadata: {}
};

return result;
```

The integration sends the encoded `data` bytes as the datagram.

## Troubleshooting

| Symptom | Cause | Fix |
|---------|-------|-----|
| No events in the integration | The remote process is not running, or the datagram did not reach the port. | Check that the remote process is running and connected. Open the UDP port in the firewall. Check the target host and port. |
| Remote process cannot connect to ThingsBoard | Wrong host, port, key, or secret. | Check the connection settings and **Integration key** / **Integration secret** in `tb-remote-integration.yml`. Make sure the gRPC port (`9090` by default) is reachable. |
| Port already in use | Another process or integration uses the port. | Pick another **Port**. The integration retries binding every 5 seconds until the port is free. |
| Decoded values are wrong | The **Handler Type** does not match the decoder template. | Use the same format for the handler and the template. Capture raw datagrams to compare, for example `tcpdump -i any udp port 11560 -X`. |
| Device not created | `deviceName` is empty or undefined. | Check **Out** in the converter events. Make sure the decoder extracts `deviceName`. |
| Converter error | The decoder threw an exception. | Open the converter's **Events** tab, read the **Error** field, and reproduce it with **Test decoder function**. |
| Telemetry not saved | The decoder returns `{}`, `[]`, or empty telemetry. | Make sure `telemetry` holds at least one key. |
| Wrong timestamp | The device sends `ts` in seconds. | Convert it: `ts: data.ts * 1000`. |
| Device does not receive downlinks | The device sends from a changing source port, or its cached address expired. | Send and listen on a fixed source port, for example with `nc -p`. Increase **Cache time to live in minutes** if needed. |

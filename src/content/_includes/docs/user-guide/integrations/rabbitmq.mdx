RabbitMQ Integration connects ThingsBoard to a <a href="https://www.rabbitmq.com/" target="_blank" rel="noopener noreferrer"><strong>RabbitMQ</strong></a> broker over AMQP 0-9-1. It reads messages from one or more queues, and an **uplink data converter** transforms each message into device or asset data, including telemetry and attributes. ThingsBoard can also publish **downlink** messages to a RabbitMQ exchange.

Use RabbitMQ Integration when:
- Devices, gateways, or backend services already publish data to RabbitMQ.
- One queue carries data for many devices: the converter sets the target device for each message.
- An application must receive ThingsBoard data or commands from a RabbitMQ queue.

## Architecture

<ImageGallery images={[
  {
    src: '/src/assets/images/user-guide/integrations/rabbitmq-integration-architecture.svg',

    caption: 'RabbitMQ integration architecture. The integration polls the uplink queue and publishes downlinks to the exchange, which routes them to a separate downlink queue.',
  },
]} />

1. **Receive data.** A producer publishes a message to an exchange, which routes it to a queue. The integration polls the queue and acknowledges each message as soon as it reads it.
2. **Decode the payload.** The uplink converter identifies the device or asset and extracts attributes and telemetry.
3. **Process the message.** ThingsBoard processes the converted data through the Rule Engine. If **Allow create devices or assets** is enabled, ThingsBoard can create an entity that does not exist yet.
4. **Send downlink data (optional).** The Rule Engine passes a message to the integration. The downlink converter encodes it, and the integration publishes it to an exchange with the **Downlink topic** as the routing key.

<Aside type="caution">
  Because the integration acknowledges a message before it decodes it, a message that fails conversion is lost. Test the converter before you connect a production queue.
</Aside>

## Prerequisites

- Access to {props.product !== Products.PAAS && props.product !== Products.PAAS_EU && <><DocLink product={Products.PE} path="installation/" target="_blank">ThingsBoard</DocLink> or </>}<a href="/installations/?product=thingsboard-cloud" target="_blank"><strong>ThingsBoard Cloud</strong></a> with integrations enabled for your tenant.
- Permission to create integrations and data converters, and to edit rule chains for downlink.
- A RabbitMQ broker that ThingsBoard reaches on a plain AMQP port, `5672` by default. The integration does not support AMQP over TLS. ThingsBoard Cloud accepts only a public broker address.
- A broker user with configure, read, and write permissions on the queue's virtual host.

### Create the Uplink Data Converter

The uplink converter reads the message body and maps it to ThingsBoard entities and data. RabbitMQ Integration uses the **Generic** converter: the decoder is a TBEL or JavaScript script. For converter types and the full decoder reference, see <DocLink product={props.product} path="user-guide/integrations/uplink-data-converter/#converter-types" target="_blank">Uplink data converter</DocLink>.

<Steps>
1. Go to **Integrations &#8702; Data converters** and click **+ Add data converter &#8702; Create new converter**.
2. **Converter type** — keep **Uplink**.
3. **Integration type** — select **RabbitMQ**.
4. **Name** — enter a name, for example `RabbitMQ Uplink Converter`.
5. **Main decoding configuration** — the editor opens with the default decoder below. Keep it for JSON messages: it takes the device name and type from `deviceName` and `deviceType`, stores `serialNumber` as an attribute, and stores the other fields as telemetry. The timestamp comes from `ts` (Unix milliseconds) or `timestamp` (ISO 8601); without them, the decoder uses the server time. The editor opens in TBEL; use the **TBEL / JS** toggle to switch to JavaScript.
   <Aside type="tip" title="TBEL">
     Use <DocLink product={props.product} path="user-guide/tbel" target="_blank">TBEL</DocLink> for converter scripts — it runs much faster than JavaScript inside ThingsBoard.
   </Aside>
   <Tabs>
     <TabItem label="TBEL (Recommended)">
       ```js maxLines=15 collapsible
       // Decode an uplink message from a buffer
       // payload - array of bytes
       // metadata - key/value object

       /** Decoder **/

       // decode payload to JSON
       var data = decodeToJson(payload);

       // --- Device name and type ---
       var deviceName = data.deviceName != null ? data.deviceName : 'Unknown Device';
       var deviceType = data.deviceType != null ? data.deviceType : 'default';
       // var customerName = 'Customer C';
       // var groupName = 'thermostat devices';

       // use assetName and assetType instead of deviceName and deviceType
       // to automatically create assets instead of devices.
       // var assetName = 'Asset A';
       // var assetType = 'building';

       // --- Timestamp parsing ---
       var timestamp = -1;
       if (data.ts != null) {
           timestamp = data.ts;
       } else if (data.timestamp != null) {
           timestamp = new Date(data.timestamp).getTime();
       }
       if (timestamp == -1) {
           timestamp = Date.now();
       }

       // --- Telemetry and attributes ---
       var telemetry = {};

       // Keys from the payload that should be stored as attributes instead of telemetry
       var attributeKeyList = ["serialNumber"];

       // Add the payload keys that match the attribute key list to attributes
       var attributes = {};
       for (var i = 0; i < attributeKeyList.size(); i++) {
           var attributeKey = attributeKeyList[i];
           if (data[attributeKey] != null) {
               attributes[attributeKey] = data[attributeKey];
           }
       }

       // Keys to exclude from telemetry (device info, attributes and non-telemetry fields)
       var excludeFromTelemetryList = ["deviceName", "deviceType", "ts", "timestamp"];
       excludeFromTelemetryList.addAll(attributeKeyList);

       // Parse all remaining JSON fields as telemetry
       telemetry.putAll(toFlatMap(data, excludeFromTelemetryList, true));

       // Result object with device attributes/telemetry data
       var result = {
          deviceName: deviceName,
          deviceType: deviceType,
       // customerName: customerName,
       // groupName: groupName,
       // assetName: assetName,
       // assetType: assetType,
       };

       // Add attributes to the result only if at least one matching key was found
       if (attributes.size() > 0) {
          result.put("attributes", attributes);
       }

       result.put("telemetry", {
          ts: timestamp,
          values: telemetry
       });

       /** Helper functions 'decodeToString', 'decodeToJson' and 'toFlatMap' are already built-in **/

       return result;

       // Decode an uplink message from a buffer
       // payload - array of bytes
       // metadata - key/value object

       /** Decoder **/

       // decode payload to JSON
       var data = decodeToJson(payload);

       // --- Device name and type ---
       var deviceName = data.deviceName != null ? data.deviceName : 'Unknown Device';
       var deviceType = data.deviceType != null ? data.deviceType : 'default';

       // --- Timestamp parsing ---
       var timestamp = -1;
       if (data.ts != null) {

       }
       if (timestamp == -1) {
           timestamp = Date.now();
       }

       // --- Telemetry and attributes ---
       var telemetry = {};

       // Keys from the payload that should be stored as attributes instead of telemetry
       var attributeKeyList = ["serialNumber"];

       // Add the payload keys that match the attribute key list to attributes
       var attributes = {};
       for (var i = 0; i < attributeKeyList.length; i++) {
           var attributeKey = attributeKeyList[i];
           if (data[attributeKey] != null) {
               attributes[attributeKey] = data[attributeKey];
           }
       }

       // Keys to exclude from telemetry (device info, attributes and non-telemetry fields)
       var excludeFromTelemetryList = ["deviceName", "deviceType", "ts", "timestamp"].concat(attributeKeyList);

       // Parse all remaining JSON fields as telemetry
       toFlatMap(data, telemetry, excludeFromTelemetryList);

       // Result object with device attributes/telemetry data
       var result = {
          deviceName: deviceName,
          deviceType: deviceType,
       // customerName: customerName,
       // groupName: groupName,
       // assetName: assetName,
       // assetType: assetType,
       };

       // Add attributes to the result only if at least one matching key was found
       if (Object.keys(attributes).length > 0) {
          result.attributes = attributes;
       }

       result.telemetry = {
          ts: timestamp,
          values: telemetry
       };

       /** Helper functions **/

       function decodeToString(payload) {
          return String.fromCharCode.apply(String, payload);
       }

       function decodeToJson(payload) {
          var str = decodeToString(payload);
          return JSON.parse(str);
       }

       function toFlatMap(obj, result, excludeList, prefix) {
           prefix = prefix || '';
           for (var key in obj) {
               if (excludeList.indexOf(key) !== -1) continue;
               var value = obj[key];
               var fullKey = prefix ? prefix + '.' + key : key;
               if (typeof value === 'object' && value !== null && !Array.isArray(value)) {
                   toFlatMap(value, result, excludeList, fullKey);
               } else {
                   result[fullKey] = value;
               }
           }
       }

       return result;
       ```

   **To adapt:**
   - **Device name in another field** — replace `data.deviceName`, for example with `data.id`.
   - **Other attributes** — add keys to `attributeKeyList`, for example `"firmwareVersion"`.

   - **Customer or group** — uncomment `customerName` or `groupName` and add it to the result.
   - **Plain-text payload** — read it with `decodeToString(payload)` and parse the text instead of calling `decodeToJson`.

<h4>Decoder Inputs</h4>

The decoder signature is `function decoder(payload, metadata): object | object[]`.

| Variable | Type | Content |
|----------|------|---------|
| `payload` | byte array | The message body. The integration reads it as UTF-8 text, so send JSON or text: binary data does not arrive intact. |
| `metadata` | `{[key: string]: string}` | `integrationName` and the key–value pairs from the integration's **Metadata** field. Message headers, properties, and the routing key are not passed. |

Built-in helpers:

| Function | Result |
|----------|--------|
| `decodeToJson(payload)` | Parses the bytes as JSON and returns an object. |
| `decodeToString(payload)` | Converts the bytes to a UTF-8 string. |
| `toFlatMap(obj, excludeKeys, flatNested)` | TBEL only. Returns a flat key–value map of `obj`, skipping `excludeKeys`. With `flatNested` set to `true`, nested objects become dot-separated keys. The JavaScript template defines its own `toFlatMap(obj, result, excludeList)`, which writes into `result`. |

For field renaming, nested values, and non-JSON payloads, see <DocLink product={props.product} path="user-guide/integrations/uplink-data-converter/#common-scripting-patterns" target="_blank">Common scripting patterns</DocLink>.

### Create the Integration

<Steps>
1. Go to **Integrations &#8702; Integrations** and click **+ Add integration**.
2. **Basic settings:**
   - **Integration type** — select **RabbitMQ**.
   - **Name** — keep the default `RabbitMQ integration` or enter your own.
   - **Enable integration** and **Allow create devices or assets** — keep both on, so the device is created on its first uplink.
   - Click **Next**.
3. **Uplink data converter:**
   - Click **Select existing** and choose `RabbitMQ Uplink Converter`.
   - Alternatively, click **Create new** to write a decoder here.
   - Click **Next**.
4. **Downlink data converter:**
   - Click **Skip**. Add a downlink converter later if you need to **[publish data to RabbitMQ](#configure-downlink)**.
5. **Connection:**
   - **Host** — enter the CloudAMQP **Cluster** hostname, for example `hawk.rmq.cloudamqp.com`.
   - **Port** — keep `5672`.
   - **Queue** — set **Name** to `tb-uplink`. Turn **Durable** on, and turn **Exclusive** and **Auto delete** off, to match the queue you created.
   - **Advanced settings** — expand it and enter the **Username**, **Password**, and **Virtual host** from the instance **Overview** page (see **[Create a CloudAMQP Instance](#create-a-cloudamqp-instance)**).
   - Leave the other parameters at their defaults. See **[Connection Settings](#connection-settings)** for details.
6. Optionally, click **Check connection**. ThingsBoard connects to the broker and shows the result. The check covers the host, port, credentials, and virtual host, not the queue.
7. Click **Add**.
</Steps>

<Aside type="caution" title="Queue flags">
  The integration declares each queue with the **Durable**, **Exclusive**, and **Auto delete** flags when it starts. The defaults (**Durable** off, **Exclusive** and **Auto delete** on) create a temporary queue that RabbitMQ deletes when the integration disconnects. If the queue already exists with other flags, the integration does not start and reports `Failed to bind queue: [tb-uplink]`.
</Aside>

#### Connection Settings

| Parameter | Default | Description |
|-----------|---------|-------------|
| **Host** | — | Broker hostname or IP address. ThingsBoard Cloud accepts only a public address. |
| **Port** | `5672` | Plain AMQP port. The integration does not use TLS. |
| **Queue &#8702; Name** | `my-queue` | Queue to read from. To read several queues, separate their names with commas and no spaces, for example `tb-uplink,tb-status`. |
| **Queue &#8702; Durable** | Off | The queue survives a broker restart. |
| **Queue &#8702; Exclusive** | On | The queue belongs to the integration's connection, and RabbitMQ deletes it when the connection closes. |
| **Queue &#8702; Auto delete** | On | RabbitMQ deletes the queue after its last consumer unsubscribes. |
| **Execute remotely** | Off | Runs the integration as a separate process outside the ThingsBoard cluster, for example next to a broker in a private network. ThingsBoard generates an **Integration key** and **Integration secret** for it. See <DocLink product={props.product} path="user-guide/integrations/remote" target="_blank">Remote Integration</DocLink>. |

**Advanced settings**

| Parameter | Default | Description |
|-----------|---------|-------------|
| **Username** | — | Broker user. If empty, the client uses `guest`, which RabbitMQ accepts only from `localhost`. |
| **Password** | — | Password of the broker user. |
| **Downlink topic** | — | Routing key of downlink messages. See **[Configure Downlink](#configure-downlink)**. |
| **Exchange name** | — | Exchange that receives downlink messages. If empty, ThingsBoard uses the default exchange, which routes each message to the queue named by the routing key. |
| **Virtual host** | — | Virtual host of the queue. If empty, the broker uses `/`. |
| **Connection timeout, ms** | `60000` | Time to establish the TCP connection. |
| **Handshake timeout, ms** | `10000` | Time to complete the AMQP handshake. |
| **Poll interval, ms** | `5000` | Pause before the next poll after the integration finds its queues empty. While messages are available, it reads them without a pause. Values below `200` count as `200`. |
| **Description** | — | Free-text description. |
| **Metadata** | — | Key–value pairs added to the `metadata` of every message from this integration. |

After a network failure, the integration reconnects to the broker automatically.

## Configure Downlink

ThingsBoard publishes a downlink when the Rule Engine routes a message to the integration — for example, after a shared attribute update. The integration publishes the encoder's `data` to the **Exchange name** exchange with the **Downlink topic** as the routing key. With an empty **Exchange name**, the default exchange delivers the message to the queue whose name equals the **Downlink topic**.

The message carries no properties: no headers, no content type, and transient delivery. The integration ignores the encoder's `metadata`.

The downlink converter turns a <DocLink product={props.product} path="user-guide/rule-engine" target="_blank">Rule Engine</DocLink> message into the published payload. For the full encoder reference, see <DocLink product={props.product} path="user-guide/integrations/downlink-data-converter" target="_blank">Downlink data converter</DocLink>.

<Aside type="caution">
  Publish downlinks to a separate queue. If the **Downlink topic** routes to a queue that the integration reads, it consumes its own downlinks as uplinks.
</Aside>

### Create and Assign the Downlink Converter

Add a downlink converter to the integration and set the **Downlink topic**, the queue that receives downlinks.

<Steps>
1. Open the integration in **Integrations &#8702; Integrations** and click **Toggle edit mode** (pencil icon).
2. In the **Downlink data converter** field, click **Create new**. The **Downlink** converter type and **RabbitMQ** integration type are preselected.
3. Enter a name, for example `RabbitMQ Downlink Converter`.
4. In **Main encoding configuration**, replace the default encoder with the encoder below.
5. To record downlink events, click the debug icon next to the name, select **All messages**, and click **Apply**.
6. Click **Add**.
7. **Advanced settings** — expand it and set the downlink queue:
   - **Downlink topic** — enter `tb-downlink`. The field is empty by default, and with an empty value RabbitMQ drops every downlink without an error.
   - **Exchange name** — leave empty.
8. Click **Apply changes**.
</Steps>

Encoder used in this guide (TBEL and JavaScript):

```js
/** Encoder **/

// Publish the message data as is.
var result = {
    // Payload content type: JSON, TEXT, or BINARY (Base64).
    contentType: "JSON",
    data: JSON.stringify(msg),
    // The integration does not use the downlink metadata.
    metadata: {}
};

return result;
```

**To adapt:**
- **Selected fields** — build `data` from the fields you need, for example `JSON.stringify({ interval: msg.temperatureUploadFrequency })`.
- **Binary payload** — set `contentType` to `BINARY` and return the bytes in `data` as a Base64 string.
- **Other message types** — branch on `msgType`, for example `RPC_CALL_FROM_SERVER_TO_DEVICE`. See <DocLink product={props.product} path="reference/rule-engine/message-types" target="_blank">Rule Engine message types</DocLink>.

### Configure the Root Rule Chain

<Steps>
1. Go to **Data processing &#8702; Rule chains** and open the **Root Rule Chain**.
2. From the **Action** section, drag an **integration downlink** node onto the canvas.
3. Enter a **Name** (for example, `Downlink to RabbitMQ`), select your RabbitMQ integration, and click **Add**.
4. Connect the **message type switch** node to the **integration downlink** node with the **Attributes Updated** relation.
5. Click **Apply changes**.
</Steps>

## Troubleshooting

| Symptom | Cause | Fix |
|---------|-------|-----|
| Integration does not start; **Check connection** fails | Wrong **Host** or **Port**, or the broker is unreachable. | Check that ThingsBoard reaches `host:5672`. A TLS-only port such as `5671` does not work. |
| Same, after the TCP connection | Wrong **Username**, **Password**, or **Virtual host**. | Copy them from the broker again. On CloudAMQP, the virtual host equals the username. |
| `Host must be in the public network.` | The host is a private address, and ThingsBoard Cloud blocks it. | Use a public broker, or run the integration with **Execute remotely**. |
| `Failed to bind queue: [...]` | The queue exists with other **Durable**, **Exclusive**, or **Auto delete** flags, or the user lacks the configure permission. | Match the flags to the queue in the management UI, or grant the permission. |
| Queue disappears after a restart | **Exclusive** or **Auto delete** is on. | Turn both off and turn **Durable** on. |
| No uplinks arrive | The producer routes messages to another queue, or a queue name contains a space. | Check the bindings in the management UI. Separate queue names with commas only. |
| Converter error; the message is gone | The body is not valid JSON, or the decoder fails on it. The integration has already acknowledged the message. | Check **In** and **Error** in the converter events, fix the decoder, and publish again. |
| Device not created | `deviceName` is empty, or **Allow create devices or assets** is off. | Check **Out** in the converter events and the integration settings. |
| Downlink event is **OK**, but the queue is empty | **Downlink topic** is empty, or it does not match a queue name or binding. | With an empty **Exchange name**, set **Downlink topic** to the queue name. |
| No downlink event | No downlink converter is assigned, or the rule chain does not reach the **integration downlink** node. | Check the integration settings and the **Attributes Updated** relation. |

To read debug events, open the integration or converter, click **Events**, and select an event: **In** is the received data, **Out** is the converter result, and **Error** holds the error text.

Pub/Sub Integration connects ThingsBoard to <a href="https://cloud.google.com/pubsub" target="_blank" rel="noopener noreferrer"><strong>Google Cloud Pub/Sub</strong></a> as a subscriber. It receives messages from a pull subscription, and an **uplink data converter** transforms each message into device or asset data, including telemetry and attributes.

Use Pub/Sub Integration when:
- Devices or backend services publish data to a Pub/Sub topic.
- One subscription carries data for many devices: the converter sets the target device for each message.
- Message attributes identify the device or describe the data: the converter receives them as metadata.

<Aside type="note">
  The integration is uplink-only. To publish ThingsBoard data to a Pub/Sub topic, use the <DocLink product={props.product} path="reference/rule-engine/nodes/external/gcp-pubsub" target="_blank">GCP Pub/Sub node</DocLink>. See **[Configure Downlink](#configure-downlink)**.
</Aside>

## Architecture

<ImageGallery images={[
  { src: '/src/assets/images/user-guide/integrations/pub-sub-integration-architecture.svg', alt: 'Google Cloud Pub/Sub integration architecture showing message flow from a Pub/Sub subscription to ThingsBoard', caption: 'Pub/Sub integration architecture. Messages are received from a Pub/Sub subscription, converted by the uplink data converter, and forwarded to the ThingsBoard Core Service.' },
]} />

1. **Receive data.** A publisher sends a message to a topic. Pub/Sub delivers it to the pull subscription, and the integration receives it over a streaming pull connection.
2. **Decode the payload.** The uplink converter identifies the device or asset and extracts attributes and telemetry.
3. **Process the message.** ThingsBoard processes the converted data through the Rule Engine. If **Allow create devices or assets** is enabled, ThingsBoard can create an entity that does not exist yet.
4. **Acknowledge the message.** The integration acknowledges each message after processing, including a message that fails conversion. Pub/Sub does not deliver it again.

## Set Up Pub/Sub Integration

### Create the Uplink Data Converter

The uplink converter reads the message data and maps it to ThingsBoard entities and data. Pub/Sub Integration uses the **Generic** converter: you write the decoder in TBEL or JavaScript. For converter types and the full decoder reference, see <DocLink product={props.product} path="user-guide/integrations/uplink-data-converter/#converter-types" target="_blank">Uplink data converter</DocLink>.

<Steps>
1. Go to **Integrations &#8702; Data converters** and click **+ Add data converter &#8702; Create new converter**.
2. **Converter type** — keep **Uplink**.
3. **Integration type** — select **Pub/Sub**.
4. **Name** — enter a name, for example `Pub/Sub Uplink Converter`.
5. **Main decoding configuration** — the editor opens with the default decoder below. Keep it for JSON messages: it takes the device name and type from `deviceName` and `deviceType`, stores `serialNumber` as an attribute, and stores the other fields as telemetry. The timestamp comes from `ts` (Unix milliseconds) or `timestamp` (ISO 8601); without them, the decoder uses the server time. The editor opens in TBEL; use the **TBEL / JS** toggle to switch to JavaScript.
   <Aside type="tip" title="TBEL">
     Use <DocLink product={props.product} path="user-guide/tbel" target="_blank">TBEL</DocLink> for converter scripts — it runs much faster than JavaScript inside ThingsBoard.
   </Aside>
   <Tabs>
     <TabItem label="TBEL (Recommended)">
       ```js maxLines=15 collapsible
       // Decode an uplink message from a buffer
       // payload - array of bytes
       // metadata - key/value object

       /** Decoder **/

       // decode payload to JSON
       var data = decodeToJson(payload);

       // --- Device name and type ---
       var deviceName = data.deviceName != null ? data.deviceName : 'Unknown Device';
       var deviceType = data.deviceType != null ? data.deviceType : 'default';
       // var customerName = 'Customer C';
       // var groupName = 'thermostat devices';

       // use assetName and assetType instead of deviceName and deviceType
       // to automatically create assets instead of devices.
       // var assetName = 'Asset A';
       // var assetType = 'building';

       // --- Timestamp parsing ---
       var timestamp = -1;
       if (data.ts != null) {
           timestamp = data.ts;
       } else if (data.timestamp != null) {
           timestamp = new Date(data.timestamp).getTime();
       }
       if (timestamp == -1) {
           timestamp = Date.now();
       }

       // --- Telemetry and attributes ---
       var telemetry = {};

       // Keys from the payload that should be stored as attributes instead of telemetry
       var attributeKeyList = ["serialNumber"];

       // Add the payload keys that match the attribute key list to attributes
       var attributes = {};
       for (var i = 0; i < attributeKeyList.size(); i++) {
           var attributeKey = attributeKeyList[i];
           if (data[attributeKey] != null) {
               attributes[attributeKey] = data[attributeKey];
           }
       }

       // Keys to exclude from telemetry (device info, attributes and non-telemetry fields)
       var excludeFromTelemetryList = ["deviceName", "deviceType", "ts", "timestamp"];
       excludeFromTelemetryList.addAll(attributeKeyList);

       // Parse all remaining JSON fields as telemetry
       telemetry.putAll(toFlatMap(data, excludeFromTelemetryList, true));

       // Result object with device attributes/telemetry data
       var result = {
          deviceName: deviceName,
          deviceType: deviceType,
       // customerName: customerName,
       // groupName: groupName,
       // assetName: assetName,
       // assetType: assetType,
       };

       // Add attributes to the result only if at least one matching key was found
       if (attributes.size() > 0) {
          result.put("attributes", attributes);
       }

       result.put("telemetry", {
          ts: timestamp,
          values: telemetry
       });

       /** Helper functions 'decodeToString', 'decodeToJson' and 'toFlatMap' are already built-in **/

       return result;
       ```
     </TabItem>
     <TabItem label="JavaScript">
       ```js maxLines=15 collapsible
       // Decode an uplink message from a buffer
       // payload - array of bytes
       // metadata - key/value object

       /** Decoder **/

       // decode payload to JSON
       var data = decodeToJson(payload);

       // --- Device name and type ---
       var deviceName = data.deviceName != null ? data.deviceName : 'Unknown Device';
       var deviceType = data.deviceType != null ? data.deviceType : 'default';
       // var customerName = 'Customer C';
       // var groupName = 'thermostat devices';

       // use assetName and assetType instead of deviceName and deviceType
       // to automatically create assets instead of devices.
       // var assetName = 'Asset A';
       // var assetType = 'building';

       // --- Timestamp parsing ---
       var timestamp = -1;
       if (data.ts != null) {
           timestamp = data.ts;
       } else if (data.timestamp != null) {
           timestamp = new Date(data.timestamp).getTime();
       }
       if (timestamp == -1) {
           timestamp = Date.now();
       }

       // --- Telemetry and attributes ---
       var telemetry = {};

       // Keys from the payload that should be stored as attributes instead of telemetry
       var attributeKeyList = ["serialNumber"];

       // Add the payload keys that match the attribute key list to attributes
       var attributes = {};
       for (var i = 0; i < attributeKeyList.length; i++) {
           var attributeKey = attributeKeyList[i];
           if (data[attributeKey] != null) {
               attributes[attributeKey] = data[attributeKey];
           }
       }

       // Keys to exclude from telemetry (device info, attributes and non-telemetry fields)
       var excludeFromTelemetryList = ["deviceName", "deviceType", "ts", "timestamp"].concat(attributeKeyList);

       // Parse all remaining JSON fields as telemetry
       toFlatMap(data, telemetry, excludeFromTelemetryList);

       // Result object with device attributes/telemetry data
       var result = {
          deviceName: deviceName,
          deviceType: deviceType,
       // customerName: customerName,
       // groupName: groupName,
       // assetName: assetName,
       // assetType: assetType,
       };

       // Add attributes to the result only if at least one matching key was found
       if (Object.keys(attributes).length > 0) {
          result.attributes = attributes;
       }

       result.telemetry = {
          ts: timestamp,
          values: telemetry
       };

       /** Helper functions **/

       function decodeToString(payload) {
          return String.fromCharCode.apply(String, payload);
       }

       function decodeToJson(payload) {
          var str = decodeToString(payload);
          return JSON.parse(str);
       }

       function toFlatMap(obj, result, excludeList, prefix) {
           prefix = prefix || '';
           for (var key in obj) {
               if (excludeList.indexOf(key) !== -1) continue;
               var value = obj[key];
               var fullKey = prefix ? prefix + '.' + key : key;
               if (typeof value === 'object' && value !== null && !Array.isArray(value)) {
                   toFlatMap(value, result, excludeList, fullKey);
               } else {
                   result[fullKey] = value;
               }
           }
       }

       return result;
       ```
     </TabItem>
   </Tabs>

   **To adapt:**
   - **Device name in a message attribute** — read it from `metadata`, for example `var deviceName = metadata.deviceId;`.
   - **Device name in another field** — replace `data.deviceName`, for example with `data.id`.
   - **Other attributes** — add keys to `attributeKeyList`, for example `"firmwareVersion"`.
   - **Assets instead of devices** — uncomment `assetName` and `assetType`, and use them in the result instead of `deviceName` and `deviceType`.
   - **Customer or group** — uncomment `customerName` or `groupName` and add it to the result.
6. Click **Test decoder function** and check the result (see **[Test the Decoder](#test-the-decoder)**).
7. Click **Add**.
</Steps>

<h4>Decoder Inputs</h4>

The decoder signature is `function decoder(payload, metadata): object | object[]`.

| Variable | Type | Content |
|----------|------|---------|
| `payload` | byte array | The message data. |
| `metadata` | `{[key: string]: string}` | `integrationName`, `pubSubMsgId` (the message ID assigned by Pub/Sub), every message attribute as a key, and the key–value pairs from the integration's **Metadata** field. A message attribute overrides a **Metadata** pair with the same key. |

Built-in helpers:

| Function | Result |
|----------|--------|
| `decodeToJson(payload)` | Parses the bytes as JSON and returns an object. |
| `decodeToString(payload)` | Converts the bytes to a UTF-8 string. |
| `toFlatMap(obj, excludeKeys, flatNested)` | TBEL only. Returns a flat key–value map of `obj`, skipping `excludeKeys`. With `flatNested` set to `true`, nested objects become dot-separated keys. The JavaScript template defines its own `toFlatMap(obj, result, excludeList)`, which writes into `result`. |

For field renaming, nested values, and non-JSON payloads, see <DocLink product={props.product} path="user-guide/integrations/uplink-data-converter/#common-scripting-patterns" target="_blank">Common scripting patterns</DocLink>.

### Create the Integration

The integration has no downlink, so the wizard skips the downlink converter step.

<Steps>
1. Go to **Integrations &#8702; Integrations** and click **+ Add integration**.
2. **Basic settings:**
   - **Integration type** — select **Pub/Sub**.
   - **Name** — keep the default `Pub/Sub integration` or enter your own.
   - **Enable integration** and **Allow create devices or assets** — keep both on, so the device is created on its first uplink.
   - Click **Next**.
3. **Uplink data converter:**
   - Click **Select existing** and choose `Pub/Sub Uplink Converter`.
   - Alternatively, click **Create new** to write a decoder here.
   - Click **Next**.
4. **Connection:**
   - **Project ID** — enter your project ID, for example `tb-pubsub-integration`.
   - **Subscription ID** — enter `tb-uplink-sub`.
   - **Service Account key file** — click **Browse file** and select the key file, or click **Use Secret storage** and select a stored secret.
   - Leave the other parameters at their defaults. See **[Connection Settings](#connection-settings)** for details.
5. Click **Add**.
</Steps>

#### Connection Settings

| Parameter | Description |
|-----------|-------------|
| **Project ID** | ID of the Google Cloud project with the subscription. |
| **Subscription ID** | Pull subscription to receive messages from. It must exist before the integration starts. |
| **Service Account key file** | JSON key of a service account with the **Pub/Sub Subscriber** role on the subscription. |
| **Execute remotely** | Runs the integration as a separate process outside the ThingsBoard cluster, for example in a network with restricted internet access. ThingsBoard generates an **Integration key** and **Integration secret** for it. See <DocLink product={props.product} path="user-guide/integrations/remote" target="_blank">Remote Integration</DocLink>. |
| **Description** | In **Advanced settings**. Free-text description. |
| **Metadata** | In **Advanced settings**. Key–value pairs added to the `metadata` of every message from this integration. |

The integration does not offer **Check connection**: check the integration status after you add it.

## Configure Downlink

The integration does not send data to Pub/Sub. To publish ThingsBoard data to a topic — for example, a command for a device or an event for a cloud function — add a <DocLink product={props.product} path="reference/rule-engine/nodes/external/gcp-pubsub" target="_blank">GCP Pub/Sub node</DocLink> to a rule chain. The node publishes the message data as is, and it works without the integration.

<Steps>

2. In **New principals**, enter the service account email, for example `tb-pubsub@tb-pubsub-integration.iam.gserviceaccount.com`.
3. In **Assign roles**, select **Pub/Sub Publisher** and click **Save**.
</Steps>

### Configure the Root Rule Chain

<Steps>
1. Go to **Data processing &#8702; Rule chains** and open the **Root Rule Chain**.
2. From the **External** section, drag a **gcp pubsub** node onto the canvas.
3. Set the node fields:
   - **Name** — for example, `Publish to Pub/Sub`.
   - **GCP project ID** — your project ID, for example `tb-pubsub-integration`.
   - **Topic name** — `tb-downlink`.
   - **GCP service account key file** — the key file of the service account.
   - **Message attributes** — optional. Values can use `${metadataKey}` for a message metadata value and `$[messageKey]` for a message data value, for example `deviceName` = `${deviceName}`.
   - Click **Add**.
4. Connect the **message type switch** node to the **gcp pubsub** node with the **Attributes Updated** relation.
5. Click **Apply changes**.
</Steps>

On success, the node adds the `messageId` returned by Pub/Sub to the message metadata. On failure, it routes the message through the **Failure** relation with the reason in `metadata.error`.

## Troubleshooting

| Symptom | Cause | Fix |
|---------|-------|-----|
| Integration does not start | The key file is not a valid service account key. | Create a new JSON key and upload it. |
| No uplinks arrive | Wrong **Project ID** or **Subscription ID**, messages go to another topic, or the subscription uses push delivery or has expired. | Copy both IDs from the Google Cloud console and publish to the subscription's topic. Set **Delivery type** to **Pull**. Recreate an expired subscription. |
| Same, with correct settings | The service account lacks the **Pub/Sub Subscriber** role, is disabled, or the Cloud Pub/Sub API is disabled. | Grant the role, enable the account, and enable the API. |
| Converter error; the message is gone | The data is not valid JSON, or the decoder fails on it. The integration has already acknowledged the message. | Check **In** and **Error** in the converter events, fix the decoder, and publish again. |
| Device not created | `deviceName` is empty, or **Allow create devices or assets** is off. | Check **Out** in the converter events and the integration settings. |
| Node routes to **Failure** with `PERMISSION_DENIED` | The node's service account lacks **Pub/Sub Publisher** on the topic. | Grant the role on `tb-downlink`. |
| Node has no events | The rule chain does not reach the **gcp pubsub** node. | Check the **Attributes Updated** relation and turn on debug mode for the node. |

To read debug events, open the integration or converter, click **Events**, and select an event: **In** is the received data, **Out** is the converter result, and **Error** holds the error text.

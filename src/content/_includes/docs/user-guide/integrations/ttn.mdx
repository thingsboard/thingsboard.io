The Things Stack Community Integration connects ThingsBoard to <a href="https://www.thethingsnetwork.org/" target="_blank" rel="noopener noreferrer nofollow"><strong>The Things Network (TTN)</strong></a>, the public community LoRaWAN network that runs on The Things Stack. ThingsBoard connects to the MQTT server of your The Things Stack application as an MQTT client, subscribes to the uplinks of its devices, and passes each one to an **uplink data converter**, which turns it into telemetry and attributes. For downlink, ThingsBoard publishes messages to the downlink topic of the device on the same connection.

Use The Things Stack Community Integration when:
- Your LoRaWAN devices are registered in an application on The Things Network, for example on the `eu1`, `nam1`, or `au1` cluster.
- You want ThingsBoard to create a device for every end device of the application, with no extra setup per device.
- You need to send downlinks from ThingsBoard to those devices, for example when a shared attribute changes.

For a private The Things Industries deployment, use the <DocLink product={props.product} path="user-guide/integrations/tti" target="_blank">The Things Stack Industries integration</DocLink> instead.

## Architecture

1. **Connect and subscribe.** The integration connects to the MQTT server of your cluster, for example `eu1.cloud.thethings.network:8883`, with the application ID and an API key, and subscribes to `v3/+/devices/+/up`.
2. **Receive data.** A device sends an uplink through a gateway. The Things Stack publishes it as a JSON message to the uplink topic of the device.
3. **Decode the payload.** The uplink converter takes the device payload and the network details out of the message, such as the DevEUI, the frame port, and the signal quality. The decoder turns the payload into telemetry and attributes. If **Allow create devices or assets** is on, ThingsBoard creates the device on its first uplink.
4. **Send a downlink (optional).** The Rule Engine passes a message to the integration. The downlink converter encodes it, and ThingsBoard publishes it right away to `v3/{application ID}@ttn/devices/{device ID}/down/push`. The Things Stack queues it and sends it to the device.

## Prepare The Things Stack

In The Things Stack, devices belong to an **application**. The integration reads the uplinks of every device in one application, and authenticates with an API key of that application.

Here you create the application, its API key, and a test end device. Open the console of the cluster you use, for example **Europe 1** (`eu1`), and keep the cluster ID: you need it for the integration.

<Steps>

## Set Up The Things Stack Community Integration

Create the uplink converter, then the integration with the MQTT credentials of your application.

### Create the Uplink Data Converter

The Things Stack Community Integration uses the Typed uplink converter. ThingsBoard selects it for this integration type, and you cannot change it later. The converter takes the device payload and the network details out of The Things Stack message, then runs your decoder on the payload only. The device name, profile, and label come from patterns in the converter settings, not from the decoder. See <DocLink product={props.product} path="user-guide/integrations/uplink-data-converter/#typed-uplink-converter" target="_blank">Typed uplink converter</DocLink>.

Write the decoder yourself as below, or take a ready-made one for your device model from the **[Library](#use-the-converters-library)**.

<Steps>
1. Go to **Integrations &#8702; Data converters** and click **+ Add data converter &#8702; Create new converter**.
2. **Converter type** — keep **Uplink**.
3. **Integration type** — select **The Things Stack Community**.
4. Keep **Create new** selected.
5. **Name** — enter a name, for example `TTN Uplink Converter`.
6. **Main decoding configuration:**
   - **Entity type** — keep **Device**.
   - **Device name** — keep `Device $eui`. `$eui` is replaced with the DevEUI from the message, so the example device is named `Device 70B3D57ED80054FE`. You can use any key from **[Decoder Inputs](#decoder-inputs)** as `$key`, for example `$deviceId`.
   - The editor holds the default decoder: the body of `function payloadDecoder(payload, metadata)`. Keep it. It reads a serial number, battery level, temperature, and saturation from fixed byte positions. Use the **TBEL / JS** toggle to switch to JavaScript.

        * Decodes the incoming payload and returns a structured object containing telemetry data and attributes.

           // Initialize the output object with empty attributes and telemetry for clarity.
           var result = { attributes: {}, telemetry: {}};

           // Detect input type and normalize to byte array
           var bytes;

           if (metadata.payloadFormat == 'JSON') {
               // payloadFormat is 'JSON' when The Things Network payload formatters are configured on the application or device level.
               // In that case, decoded_payload is a JSON object produced by your formatter.
               // This template assumes the formatter returns { "bytes": [...] } with the raw byte array.
               // If your formatter returns pre-decoded values in a different structure,
               // update this section to extract the values directly from 'parsed' instead.
               var parsed = decodeToJson(input);
               if (parsed.bytes == null) {
                   throw new Error("Payload formatter output does not contain a 'bytes' field. " +
                       "Update this decoder to match your formatter's output structure.");
               }
               bytes = parsed.bytes;
           } else {
               // payloadFormat is 'BINARY' when no payload formatter is configured — raw bytes from frm_payload are passed directly.
               bytes = input;
           }

           // Decode serial number (SN) from the first 4 bytes of the payload.
           // Press '?' icon in the top right corner to learn more about built in helper functions and capabilities.
           result.attributes.sn = parseBytesToInt(bytes, 0, 4);

           // Extract the timestamp from metadata (represented in milliseconds).
           var timestamp = metadata.ts; // ts is the timestamp parsed from the incoming message's time, or returns the current time if it cannot be parsed.

           // Combine the timestamp with decoded values and add it to the telemetry.
           result.telemetry = {

                   battery: parseBytesToInt(bytes, 4, 1),
                   // Decode temperature from the 6th and 7th bytes of the payload (divided by 100).
                   temperature: parseBytesToInt(bytes, 5, 2) / 100.0,
                   // Decode saturation from the 8th byte of the payload.
                   saturation: parseBytesToInt(bytes, 7, 1)
               }

           return result;

       function decodeToJson(payload) {
           return JSON.parse(String.fromCharCode.apply(String, payload));

       /**
        * Parse a slice of bytes from an array into an integer (big-endian).
        *
        * @param {number[]} input - The array of bytes.
        * @param {number} offset - The starting index.
        * @param {number} length - The number of bytes to convert.
        * @returns {number} - The resulting integer.
        */
       function parseBytesToInt(input, offset, length) {
         var result = 0;
         for (var i = offset; i < offset + length; i++) {

   The decoder expects this byte layout:

   | Bytes | Key | Stored as | Value |
   |-------|-----|-----------|-------|
   | 0–3 | `sn` | attribute | Serial number |
   | 4 | `battery` | telemetry | Battery level |
   | 5–6 | `temperature` | telemetry | Raw value ÷ 100 |
   | 7 | `saturation` | telemetry | Saturation |
7. **Advanced decoding parameters** — keep the defaults:
   - **Device profile name** — `$applicationId`. The device gets a profile named after the application, for example `my-thingsboard`.
   - **Device label** — `$deviceId`. The device label is the end device ID, for example `thermostat-a`. The downlink in this guide reads it.
   - **Customer name** and **Device group name** — empty.
   - **Telemetry** — `fCnt`, `data`, `decoded`, `latitude`, `longitude`, `altitude`, `rssi`, `snr`, and `channel`.
   - **Attributes** — `eui`, `devAddr`, `fPort`, `bandwidth`, `spreadingFactor`, `codeRate`, `frequency`, `brandId`, `modelId`, `hardwareVersion`, `firmwareVersion`, `attributes`, and `tenantId`.
   - **Update only keys list** — the same keys as **Attributes**. They are stored only when their value changes.

   The **Telemetry** and **Attributes** lists add network keys from **[Decoder Inputs](#decoder-inputs)** to the decoder output. They do not filter it: every key the decoder returns is stored. A key that the message does not carry, or that the decoder already returns, is skipped.
8. Click **Test payload decoder** and check the result (see **[Test the Decoder](#test-the-decoder)**).
9. Click **Add**.
</Steps>

**To adapt:**
- **Byte layout** — change the offset and length in each `parseBytesToInt()` call, and rename or add keys to match your device.
- **Payload formatter** — if The Things Stack decodes the payload, `metadata.payloadFormat` is `JSON` and `payload` holds the formatter result. Read the values from `parsed` instead of `parsed.bytes`, for example `values: { temperature: parsed.temperature }`.
- **Device name** — change the **Device name** pattern, for example to `$deviceId`, or set `result.name` in the decoder.
- **Network keys** — remove keys from **Telemetry** or **Attributes** that you do not need, for example `data`, which stores the raw payload as a Base64 string.

<h4 id="decoder-inputs">Decoder Inputs</h4>

The Things Stack publishes each uplink as a JSON message. This one comes from the example device, with the payload `00 BC 61 4E 5F 09 29 50`:

```json
{
  "end_device_ids": {
    "device_id": "thermostat-a",
    "application_ids": {
      "application_id": "my-thingsboard"
    },
    "dev_eui": "70B3D57ED80054FE",
    "dev_addr": "260B1234"
  },
  "correlation_ids": ["as:up:01JB8Y2P3Q4R5S6T7V8W9X0YZA"],
  "received_at": "2026-10-22T09:15:30.512Z",
  "uplink_message": {
    "f_port": 1,
    "f_cnt": 12,
    "frm_payload": "ALxhTl8JKVA=",
    "rx_metadata": [
      {
        "gateway_ids": {
          "gateway_id": "my-gateway"
        },
        "rssi": -62,
        "channel_rssi": -62,
        "snr": 9.5
      }
    ],
    "settings": {
      "data_rate": {
        "lora": {
          "bandwidth": 125000,
          "spreading_factor": 7
        }
      },
      "frequency": "868100000"
    },
    "received_at": "2026-10-22T09:15:30.498Z"
  }
}
```

The converter passes the decoder two variables:

| Variable | Type | Content |
|----------|------|---------|
| `payload` | byte array | The device payload. Without a payload formatter, the Base64-decoded `uplink_message.frm_payload`. With a formatter, the JSON of `uplink_message.decoded_payload`. Empty if the message has neither. |
| `metadata` | object | The network keys below, plus `payloadFormat`, `ts`, `integrationName`, the MQTT `topic`, and the key–value pairs from the integration's **Metadata** field. Integration keys replace network keys with the same name. |

Network keys that the converter reads from the message. A key is missing if its field is missing or `null`:

| Key | Source field | Example |
|-----|--------------|---------|
| `deviceId` | `end_device_ids.device_id` | `thermostat-a` |
| `applicationId` | `end_device_ids.application_ids.application_id` | `my-thingsboard` |
| `eui` | `end_device_ids.dev_eui` | `70B3D57ED80054FE` |
| `joinEui` | `end_device_ids.join_eui` | — |
| `devAddr` | `end_device_ids.dev_addr` | `260B1234` |
| `fPort` | `uplink_message.f_port` | `1` |
| `fCnt` | `uplink_message.f_cnt` | `12` |
| `data` | `uplink_message.frm_payload` | `ALxhTl8JKVA=` |
| `decoded` | `uplink_message.decoded_payload` | — |
| `rssi`, `snr` | The `rx_metadata` entry with the highest `rssi` | `-62`, `9.5` |
| `bandwidth` | `uplink_message.settings.data_rate.lora.bandwidth` | `125000` |
| `spreadingFactor` | `uplink_message.settings.data_rate.lora.spreading_factor` | `7` |
| `frequency` | `uplink_message.settings.frequency` | `868100000` |
| `latitude`, `longitude`, `altitude` | `uplink_message.locations.user` | — |
| `brandId`, `modelId`, `hardwareVersion`, `firmwareVersion` | `uplink_message.version_ids` | — |
| `tenantId`, `netId`, `clusterId` | `uplink_message.network_ids` | — |
| `receivedAt`, `uplinkMessageReceivedAt` | `received_at`, `uplink_message.received_at` | `2026-10-22T09:15:30.512Z` |
| `simulated` | `simulated` | `true` for console simulations |

The converter also reads `correlationIds`, `rxMetadata`, `sessionKeyId`, `codeRate`, `dataRateIndex`, `consumedAirtime`, `attributes`, and the other fields of `uplink_message`. Check the **Metadata** of a converter event for the full list.

- `payloadFormat` — `BINARY` when `payload` holds the raw bytes, `JSON` when it holds the formatter result.
- `ts` — the time of `uplink_message.received_at` in milliseconds, for example `1792660530498`. If it is missing, `received_at`, and if that is missing too, the current time.

## Configure Downlink

ThingsBoard publishes each downlink right away to the downlink topic of the device, with QoS `1`. Nothing is queued in ThingsBoard. The Things Stack adds the downlink to the device queue (`/down/push`) and sends it in a receive window after the next uplink of the device.

The downlink converter turns a Rule Engine message into a The Things Stack downlink message and returns the end device ID for the topic. In this guide, a change of a shared attribute sends the changed attributes to the device as JSON. For the full encoder reference, see <DocLink product={props.product} path="user-guide/integrations/downlink-data-converter" target="_blank">Downlink data converter</DocLink>.

### Create and Assign the Downlink Converter

<Steps>
1. Open the integration in **Integrations &#8702; Integrations** and click **Toggle edit mode** (pencil icon).
2. In the **Downlink data converter** field, click **Create new**.
3. Enter a name, for example `TTN Downlink Converter`.
4. **Main encoding configuration** opens in TBEL with a generic encoder that builds an MQTT `topic` from the device name, not the message that The Things Stack needs. Replace it with the encoder below. For JavaScript, use the **TBEL / JS** toggle and the **JavaScript** tab.
5. To record downlink events, click the debug button next to the name, select **All messages**, and click **Apply**.
6. Click **Add**.
7. Click **Apply changes**.
</Steps>

Encoder used in this guide. It encodes the message as JSON, puts it in Base64 into `frm_payload`, and sends it on the port of the last uplink. The rule chain adds the end device ID to the metadata as `devId`, and the `fPort` client attribute as `cs_fPort`.

<Tabs>
<TabItem label="TBEL (Recommended)">

```js
/** Encoder **/

// End device ID in The Things Stack, for example thermostat-a.
// The rule chain adds it to the metadata from the device label.
var devId = metadata.devId;
if (devId == null || devId == "") {
    raiseError("Missing required metadata field: devId");
}

// LoRaWAN port: the fPort client attribute, stored from the last uplink.
if (metadata.cs_fPort == null) {
    raiseError("Missing required metadata field: cs_fPort");
}
var fPort = parseInt("" + metadata.cs_fPort);
if (fPort < 1 || fPort > 223) {
    raiseError("Invalid LoRaWAN port. Expected a value from 1 to 223.");
}

// The message as JSON, for example {"powerState":"on"}, in Base64.
var frmPayload = bytesToBase64(stringToBytes(JSON.stringify(msg)));

var data = {
    downlinks: [
        {
            f_port: fPort,
            frm_payload: frmPayload,
            confirmed: false,
            priority: "NORMAL"
        }
    ]
};

return {
    contentType: "JSON",
    data: JSON.stringify(data),
    metadata: {
        // Replaces ${devId} in the downlink topic pattern.
        devId: devId
    }
};
```

</TabItem>
<TabItem label="JavaScript">

```js
/** Encoder **/

// UTF-8 string to Base64.
function utf8ToBase64(value) {
    var binary = encodeURIComponent(value).replace(/%([0-9A-F]{2})/g, function (match, hex) {
        return String.fromCharCode(parseInt(hex, 16));
    });
    return btoa(binary);
}

// End device ID in The Things Stack, for example thermostat-a.
// The rule chain adds it to the metadata from the device label.
var devId = metadata.devId;
if (devId === undefined || devId === null || devId === '') {
    throw new Error('Missing required metadata field: devId');
}

// LoRaWAN port: the fPort client attribute, stored from the last uplink.
if (metadata.cs_fPort === undefined || metadata.cs_fPort === null) {
    throw new Error('Missing required metadata field: cs_fPort');
}
var fPort = parseInt('' + metadata.cs_fPort, 10);
if (isNaN(fPort) || fPort < 1 || fPort > 223) {
    throw new Error('Invalid LoRaWAN port. Expected a value from 1 to 223.');
}

// The message as JSON, for example {"powerState":"on"}, in Base64.
var frmPayload = utf8ToBase64(JSON.stringify(msg));

var data = {
    downlinks: [
        {
            f_port: fPort,
            frm_payload: frmPayload,
            confirmed: false,
            priority: 'NORMAL'
        }
    ]
};

return {
    contentType: 'JSON',
    data: JSON.stringify(data),
    metadata: {
        // Replaces ${devId} in the downlink topic pattern.
        devId: String(devId)
    }
};
```

</TabItem>
</Tabs>

To check the encoder, click **Test encoder function**. Replace the **Message** with `{"powerState": "on"}`, add `devId` = `thermostat-a` and `cs_fPort` = `1` to **Metadata**, and click **Test**. The **Output** panel shows:

```json
{
  "contentType": "JSON",
  "data": "{\"downlinks\":[{\"f_port\":1,\"frm_payload\":\"eyJwb3dlclN0YXRlIjoib24ifQ==\",\"confirmed\":false,\"priority\":\"NORMAL\"}]}",
  "metadata": {
    "devId": "thermostat-a"
  }
}
```

The integration reads these fields from the encoder result:

| Field | Description |
|-------|-------------|
| `contentType` | `JSON`, `TEXT`, or `BINARY`. `JSON` and `TEXT` publish `data` as UTF-8 text. `BINARY` decodes `data` from Base64 first. |
| `data` | The MQTT message, published as is. For The Things Stack, a `downlinks` array whose entries hold `f_port`, `frm_payload` (the device payload in Base64), and optionally `confirmed` and `priority`. See the <a href="https://www.thethingsindustries.com/docs/integrations/other-integrations/mqtt/" target="_blank" rel="noopener noreferrer nofollow"><strong>The Things Stack MQTT server</strong></a> docs. An empty `data` sends nothing. |
| `metadata.devId` | Replaces `${devId}` in **Downlink topic pattern**. Without it, the topic keeps the text `${devId}`, and the downlink does not reach the device. Every other `metadata` key replaces its own `${key}`. |

To set a fixed port, replace `fPort` with a number, for example `f_port: 2`. To send only one key, replace `JSON.stringify(msg)` with `JSON.stringify({ powerState: msg.powerState })`. For a device that expects bytes, build them instead of JSON, and encode them with `bytesToBase64`.

### Configure the Root Rule Chain

The encoder needs the end device ID and the port. Add them to the metadata, then pass the message to the integration.

<Steps>
1. Go to **Data processing &#8702; Rule chains** and open the **Root Rule Chain**.
2. From the **Enrichment** section, drag an **originator attributes** node onto the canvas:
   - **Name** — for example `Add fPort`.
   - **Client attributes** — `fPort`. The node adds it to the metadata as `cs_fPort`.
   - **Add originator attributes to** — keep **Metadata**.
   - Click **Add**.
3. From the **Enrichment** section, drag an **originator fields** node onto the canvas:
   - **Name** — for example `Add Device ID`.
   - Under **Originator fields mapping**, set **Source field** to `Label` and **Target key** to `devId`.
   - **Add mapped originator fields to** — keep **Metadata**.
   - Click **Add**.
4. From the **Action** section, drag an **integration downlink** node onto the canvas:
   - **Name** — for example `Downlink to TTN`.
   - **Integration** — select `The Things Stack Community integration`.
   - Click **Add**.
5. Connect the **message type switch** node to `Add fPort` with the **Attributes Updated** relation.
6. Connect `Add fPort` to `Add Device ID` with the **Success** relation.
7. Connect `Add Device ID` to `Downlink to TTN` with the **Success** relation.
8. Click **Apply changes**.
</Steps>

Use only **Attributes Updated**. The integration stores client attributes with every uplink, so a **Post attributes** relation would send a downlink after every uplink.

## Troubleshooting

| Symptom | Cause | Fix |
|---------|-------|-----|
| No events on the integration **Events** tab | Debug mode is off, or the integration is disabled. Debug mode records all events only for a limited time after you turn it on. | Turn on **Enable integration** and debug mode. Click **Toggle edit mode** and **Apply changes** to reconnect. |
| `Can't setup TheThingsNetwork integration. Required TheThingsNetwork Application Credentials values are missing!` | **Username** or **Password** is empty. | Enter the username and the API key. |
| `Failed to connect to MQTT broker at eu1.cloud.thethings.network:8883.` | The region or host is wrong, the port does not match **Enable SSL**, or a firewall blocks the connection. | Check the cluster ID of your application in the console address, for example `eu1.cloud.thethings.network`. Use port `8883` with **Enable SSL** on. Allow outbound TCP to the port. |
| `Failed to connect to MQTT broker at ... Result code is: ...`, for example `CONNECTION_REFUSED_NOT_AUTHORIZED` | The server rejected the credentials. The username is not `{application ID}@ttn`, or the API key is wrong, expired, or deleted. | Enter the application ID, not your account name, followed by `@ttn`. Create a new API key and paste it as the **Password**. |
| **Host must be in the public network.** | The custom host is a private or local address, and the platform allows only public hosts. | Use a public address, or run the integration as a <DocLink product={props.product} path="user-guide/integrations/remote" target="_blank">Remote Integration</DocLink>. |
| Connected, but no **Uplink** events | No uplinks reach the application, or the API key lacks the **Read application traffic (uplink and downlink)** right. | Check **Live data** of the application in the console. Check the rights of the API key. |
| Uplink events with status **ERROR** | The decoder failed, for example on a payload shorter than the layout it reads. | Check the **Error** column in the converter events and fix the decoder. |
| `Payload formatter output does not contain a 'bytes' field.` | A payload formatter is set in The Things Stack, and its result has no `bytes` key. | Read the formatter values in the decoder (see **To adapt**), or remove the formatter. |
| Device named `Device $eui` | The message has no `dev_eui`, which is optional for ABP devices. | Set a DevEUI on the end device, or change **Device name** to `Device $deviceId`. |
| Device not created | **Allow create devices or assets** is off. | Turn it on in the integration. |
| No downlink and no error | No downlink converter is assigned, or the rule chain does not route attribute updates. | Assign the converter and check the **Attributes Updated** relation. |
| Downlink converter error `Missing required metadata field: devId` | The device has no label, or the **originator fields** node is missing. | Set **Device label** to `$deviceId` in the uplink converter, or set the label by hand. Connect `Add Device ID` before the **integration downlink** node. |
| Downlink converter error `Missing required metadata field: cs_fPort` | The device has no `fPort` client attribute yet, or the **originator attributes** node is missing. | Send an uplink first: the converter stores `fPort` with every uplink. Connect `Add fPort` after the **message type switch**. |
| **Downlink** event **OK**, but nothing in **Live data** | The topic does not match the device, or the API key lacks the **Write downlink application traffic** right. | Check the topic in the **Downlink** event: it must hold the end device ID. Check the rights of the API key. |
| Downlink in **Live data**, but the device does not react | The device listens on another port, or it is a class A device that has not sent an uplink since. | Set `f_port` to the port your device expects. Wait for the next uplink of the device. |

To read debug events, open the integration or converter, click **Events**, and select an event: **In** is the received data, **Out** is the converter result, and **Error** holds the error text.

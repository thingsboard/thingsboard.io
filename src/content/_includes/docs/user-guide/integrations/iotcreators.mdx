IoT Creators Integration receives device data from the <a href="https://www.iotcreators.com/" target="_blank" rel="noopener noreferrer"><strong>IoT Creators</strong></a> platform, the NB-IoT and LTE-M connectivity service of Deutsche Telekom. IoT Creators sends each uplink to ThingsBoard as an HTTP callback, and an **uplink data converter** transforms it into device data, including telemetry and attributes. In ThingsBoard, the integration type is called **iotcreators.com (T-Mobile &#8211; IoT CDP)**. The integration is uplink-only: to send data to devices, a rule chain calls the IoT Creators API.

Use IoT Creators Integration when:
- Your NB-IoT or LTE-M devices use IoT Creators SIM cards and send their data to the IoT Creators platform.
- One callback URL must serve every device in an IoT Creators project: the converter resolves each device from its IMEI.

## Architecture

1. **Receive data.** The device sends an uplink to the IoT Creators platform. IoT Creators sends it as an HTTP `POST` with a JSON body to the integration endpoint. The body holds a `reports` array; each report carries the device IMEI and the device payload as a hex string.
2. **Decode the payload.** The uplink converter reads each report, sets the device name from the IMEI, and decodes the payload into telemetry and attributes.
3. **Process the message.** ThingsBoard processes the converted data through the Rule Engine. If **Allow create devices or assets** is on, ThingsBoard creates the device on its first uplink.
4. **Respond.** The endpoint answers `200 OK` once the data is processed.

To send data to devices, see **[Downlink to Devices](#downlink-to-devices)**.

## Prepare IoT Creators

Register the device in your IoT Creators project and check the format of the data it sends.

### Register the Device

IoT Creators forwards uplinks only from devices registered in the project. Register the device before it sends data.

<Steps>
1. Log in to the <a href="https://portal.iotcreators.com/login" target="_blank" rel="noopener noreferrer"><strong>IoT Creators portal</strong></a> and open your project, for example **Starterkit**.
2. Click **REGISTER DEVICE**.
3. Enter the device **IMEI**.
4. Select the communication protocol. IoT Creators recommends **UDP** for NB-IoT modules.
5. Confirm the registration.
</Steps>

The device appears in the device list of the project. Its last message and payload stay empty until the device sends its first uplink.

### Uplink Message Format

IoT Creators sends every device uplink to the callback URL as a JSON body. This guide uses the callback for an <a href="https://docs.iotcreators.com/docs/imbuildings-comfort-sensor" target="_blank" rel="noopener noreferrer"><strong>IMBUILDINGS Comfort Sensor</strong></a>, which measures temperature, humidity, CO₂, battery voltage, and presence:

```json
{
  "reports": [
    {
      "serialNumber": "IMEI:866425033313638",
      "timestamp": 1600439712734,
      "subscriptionId": "fa37d89c-a7e2-4f3d-b12f-6002a3642b4c",
      "resourcePath": "uplinkMsg/0/data",
      "value": "0101d880396f026e000158a50a4b121503d301"
    }
  ],
  "registrations": [],
  "deregistrations": [],
  "updates": [],
  "expirations": [],
  "responses": []
}
```

- `reports` — one entry per device uplink. A callback can hold several entries.
- `serialNumber` — the device IMEI with the `IMEI:` prefix.
- `timestamp` — the time IoT Creators received the uplink, in Unix milliseconds.
- `resourcePath` — `uplinkMsg/0/data` for a device uplink.
- `value` — the device payload as a hex string. Its byte layout is defined by the device manufacturer.

The `value` above decodes to `status = 0`, `batteryVoltage = 3.44`, `temperature = 26.35`, `humidity = 46.29`, `co2 = 979`, and `presence = true`. The byte layout is described in the IMBUILDINGS Comfort Sensor documentation.

## Set Up IoT Creators Integration

Create the uplink converter and the integration, then set the integration endpoint as the callback URL of your IoT Creators project.

### Create the Uplink Data Converter

The uplink converter parses the callback body and decodes the hex payload of each report. IoT Creators Integration uses the **Generic** converter: you write the decoder in TBEL or JavaScript. For converter types and the full decoder reference, see <DocLink product={props.product} path="user-guide/integrations/uplink-data-converter/#converter-types" target="_blank">Uplink data converter</DocLink>.

The decoder in this guide maps:

- `serialNumber` without the `IMEI:` prefix &#8702; device name `NB-IoT-<IMEI>`.
- `timestamp` &#8702; telemetry timestamp.
- Bytes of `value` &#8702; telemetry `status`, `batteryVoltage`, `temperature`, `humidity`, `co2`, and `presence`.
- `serialNumber`, `subscriptionId`, and `resourcePath` &#8702; attributes, together with the fixed attribute `model` = `Comfort Sensor`.

<Steps>
1. Go to **Integrations &#8702; Data converters** and click **+ Add data converter &#8702; Create new converter**.
2. **Converter type** — keep **Uplink**.
3. **Integration type** — select **iotcreators.com (T-Mobile &#8211; IoT CDP)**.
4. **Name** — enter a name, for example `IoT Creators Uplink Converter`.
5. **Main decoding configuration** — the editor opens with the generic decoder template, which does not read the `reports` array. Replace it with the decoder below. The editor opens in TBEL; use the **TBEL / JS** toggle to switch to JavaScript.
   <Aside type="tip" title="TBEL">
     Use <DocLink product={props.product} path="user-guide/tbel" target="_blank">TBEL</DocLink> for converter scripts — it runs much faster than JavaScript inside ThingsBoard.
   </Aside>
   <Tabs>
     <TabItem label="TBEL (Recommended)">
       ```js maxLines=15 collapsible
       // Decode an IoT Creators callback
       // payload - array of bytes (the callback body)
       // metadata - key/value object

       /** Decoder **/

       var data = decodeToJson(payload);
       var reports = data.reports != null ? data.reports : [];
       var result = [];

       for (var i = 0; i < reports.size(); i++) {
         var report = reports[i];

         // Decode only device uplinks.
         if (report.resourcePath == "uplinkMsg/0/data" && report.value != null) {
           // The device payload is a hex string.
           var bytes = hexToBytes(report.value);

           // The Comfort Sensor payload is 19 bytes long.
           if (bytes.size() >= 19) {
             // IoT Creators identifies the device by "IMEI:<imei>".
             var serialNumber = "" + report.serialNumber;
             var imei = serialNumber.replace("IMEI:", "");

             var entry = {
               deviceName: "NB-IoT-" + imei,
               deviceType: "NB-IoT sensor",
               attributes: {
                 serialNumber: serialNumber,
                 subscriptionId: report.subscriptionId,
                 resourcePath: report.resourcePath,
                 model: "Comfort Sensor"
               },
               telemetry: {
                 ts: report.timestamp,
                 values: {
                   status: bytes[8] & 0xFF,
                   batteryVoltage: (((bytes[9] & 0xFF) << 8) | (bytes[10] & 0xFF)) / 100.0,
                   temperature: (((bytes[12] & 0xFF) << 8) | (bytes[13] & 0xFF)) / 100.0,
                   humidity: (((bytes[14] & 0xFF) << 8) | (bytes[15] & 0xFF)) / 100.0,
                   co2: ((bytes[16] & 0xFF) << 8) | (bytes[17] & 0xFF),
                   presence: (bytes[18] & 0xFF) == 1
                 }
               }
             };
             result.add(entry);
           }
         }
       }

       /** Helper functions 'decodeToJson' and 'hexToBytes' are already built-in **/

       return result;
       ```
     </TabItem>
     <TabItem label="JavaScript">
       ```js maxLines=15 collapsible
       // Decode an IoT Creators callback
       // payload - array of bytes (the callback body)
       // metadata - key/value object

       /** Decoder **/

       var data = decodeToJson(payload);
       var reports = data.reports || [];
       var result = [];

       for (var i = 0; i < reports.length; i++) {
         var report = reports[i];

         // Decode only device uplinks.
         if (report.resourcePath === "uplinkMsg/0/data" && report.value != null) {
           // The device payload is a hex string.
           var bytes = hexToBytes(report.value);

           // The Comfort Sensor payload is 19 bytes long.
           if (bytes.length >= 19) {
             // IoT Creators identifies the device by "IMEI:<imei>".
             var serialNumber = String(report.serialNumber);
             var imei = serialNumber.replace("IMEI:", "");

             result.push({
               deviceName: "NB-IoT-" + imei,
               deviceType: "NB-IoT sensor",
               attributes: {
                 serialNumber: serialNumber,
                 subscriptionId: report.subscriptionId,
                 resourcePath: report.resourcePath,
                 model: "Comfort Sensor"
               },
               telemetry: {
                 ts: report.timestamp,
                 values: {
                   status: bytes[8],
                   batteryVoltage: ((bytes[9] << 8) | bytes[10]) / 100,
                   temperature: ((bytes[12] << 8) | bytes[13]) / 100,
                   humidity: ((bytes[14] << 8) | bytes[15]) / 100,
                   co2: (bytes[16] << 8) | bytes[17],
                   presence: bytes[18] === 1
                 }
               }
             });
           }
         }
       }

       /** Helper functions **/

       function decodeToString(payload) {
         return String.fromCharCode.apply(String, payload);
       }

       function decodeToJson(payload) {
         return JSON.parse(decodeToString(payload));
       }

       function hexToBytes(hex) {
         var bytes = [];
         for (var j = 0; j < hex.length; j += 2) {
           bytes.push(parseInt(hex.substr(j, 2), 16));
         }
         return bytes;
       }

       return result;
       ```
     </TabItem>
   </Tabs>

   **To adapt:**
   - **Another device** — replace the byte offsets (`8`, `9`–`10`, `12`–`13`, and so on), the `/ 100` scaling, and the `19`-byte length check with the values from your device's payload specification.
   - **Device name** — replace `"NB-IoT-" + imei` to use the bare IMEI or another identifier.
   - **Base64 payload** — if `value` holds Base64 instead of hex, decode it with `base64ToBytesList(report.value)` in TBEL, or `atob()` and `charCodeAt()` in JavaScript.
   - **Timestamp** — remove `ts` to use the time ThingsBoard receives the callback.
   - **Attributes** — add or remove fields in `attributes`. Keep values that change with every uplink in `telemetry`.
6. Click **Test decoder function** and check the result (see **[Test the Decoder](#test-the-decoder)**).
7. Click **Add**.
</Steps>

<h4>Decoder Inputs</h4>

The decoder signature is `function decoder(payload, metadata): object | object[]`.

| Variable | Type | Content |
|----------|------|---------|
| `payload` | byte array | The callback body, as compact JSON. |
| `metadata` | `{[key: string]: string}` | `integrationName` and the key–value pairs from the integration's **Metadata** field. Request headers are not passed. |

Return an array to create data for several devices from one callback. Return an empty array (`[]`) when the callback holds no device uplinks, for example when `reports` is empty.

Built-in helpers:

| Function | Result |
|----------|--------|
| `decodeToJson(payload)` | Parses the bytes as JSON and returns an object. In JavaScript, the decoder above defines it. |
| `hexToBytes(hex)` | TBEL only. Converts a hex string to a list of bytes. Bytes are signed: mask them with `& 0xFF` before you combine them. The JavaScript decoder above defines its own `hexToBytes`, which returns unsigned values. |
| `base64ToBytesList(base64)` | TBEL only. Converts a Base64 string to a list of bytes, like `hexToBytes`. |

For other scripting patterns, see <DocLink product={props.product} path="user-guide/integrations/uplink-data-converter/#common-scripting-patterns" target="_blank">Common scripting patterns</DocLink>.

### Create the Integration

The wizard has no downlink step, because the integration only receives data.

<Steps>
1. Go to **Integrations &#8702; Integrations** and click **+ Add integration**.
2. **Basic settings:**
   - **Integration type** — select **iotcreators.com (T-Mobile &#8211; IoT CDP)**.
   - **Name** — keep the default `iotcreators.com (T-Mobile – IoT CDP) integration` or enter your own.
   - **Enable integration** and **Allow create devices or assets** — keep both on, so the device is created on its first uplink.
   - Click **Next**.
3. **Uplink data converter:**
   - Click **Select existing** and choose `IoT Creators Uplink Converter`.
   - Alternatively, click **Create new** to write a decoder here.
   - Click **Next**.
4. **Connection:**
   - Copy the **HTTP endpoint URL**. You need it for the IoT Creators callback.
   - Leave the other parameters at their defaults. See **[Connection Settings](#connection-settings)** for details.
5. Click **Add**.
</Steps>

#### Connection Settings

| Parameter | Default | Description |
|-----------|---------|-------------|
| **Base URL** | Address of your ThingsBoard server | Used to build the endpoint URL. Example: `https://thingsboard.cloud`. Required. |
| **HTTP endpoint URL** | — | Read-only. Format: `{Base URL}/api/v1/integrations/tmobile_iot_cdp/{integrationKey}`, where `integrationKey` is a UUID assigned at creation. A request with `Content-Type: application/json` is processed as an uplink. A request with `Content-Type: text/plain`, such as a validation request, gets `200 OK` and is not processed. Other content types are rejected. |
| **Execute remotely** | Off | Runs the integration as a separate process outside the ThingsBoard cluster. ThingsBoard generates an **Integration key** and **Integration secret** for it. IoT Creators needs a public endpoint, so the standard setup keeps this off. See <DocLink product={props.product} path="user-guide/integrations/remote" target="_blank">Remote Integration</DocLink>. |
| **Replace response status from 'No-Content' to 'OK'** | Off | In **Advanced settings**. Has no effect on this integration: the endpoint answers every processed callback with `200 OK`, also when the decoder returns no data. |
| **Description** | — | In **Advanced settings**. Free-text description. |
| **Metadata** | — | In **Advanced settings**. Key–value pairs added to the `metadata` of every message from this integration. |

<Aside type="caution">
  The integration has no **Enable security** option. Anyone who knows the endpoint URL can send data to it, so keep the URL secret. If the URL is exposed, delete the integration and create a new one: the new integration gets a new `integrationKey`.
</Aside>

### Set the Callback URL in IoT Creators

The callback URL forwards the uplinks of every device in the project to the integration endpoint. To stop forwarding, set the toggle to off and click **Save**.

<Steps>
1. Sign in to the <a href="https://portal.iotcreators.com/" target="_blank" rel="noopener noreferrer"><strong>IoT Creators portal</strong></a>.
2. Open **Projects**, select your project, and open the **YOUR APPLICATION SERVER** tab.
3. Paste the **HTTP endpoint URL** of the integration into the **CALLBACK URL** field.
4. Set the endpoint toggle to **ON** and click **Save**.
</Steps>

<Aside type="note">
  When you save the callback URL, IoT Creators sends a test `POST` with an empty body and saves the URL only if it gets `200`. ThingsBoard answers an empty `text/plain` request with `200 OK` and does not pass it to the converter.
</Aside>

### Send a Test Uplink

Switch on the registered device and wait for its first uplink. IoT Creators forwards it to the callback URL.

To test without a device, send a callback in the **[Uplink Message Format](#uplink-message-format)** to the endpoint with curl. Replace `$HTTP_ENDPOINT_URL` with the **HTTP endpoint URL** and run:

```bash
curl -v -X POST "$HTTP_ENDPOINT_URL" \
  -H "Content-Type: application/json" \
  -d '{"reports":[{"serialNumber":"IMEI:866425033313638","timestamp":1792660558000,"subscriptionId":"fa37d89c-a7e2-4f3d-b12f-6002a3642b4c","resourcePath":"uplinkMsg/0/data","value":"0101d880396f026e000158a50a4b121503d301"}],"registrations":[],"deregistrations":[],"updates":[],"expirations":[],"responses":[]}'
```

The endpoint returns `200` (`HTTP/2 200` on ThingsBoard Cloud). ThingsBoard stores the telemetry with the time in `timestamp`, in Unix milliseconds. Change it to the current time to see the data as the latest values.

## Downlink to Devices

IoT Creators Integration does not send downlinks. It has no downlink converter, and the wizard has no downlink step. To send data to a device, call the IoT Creators API. It queues the message for the device:

- **Request** — `PUT https://api.scs.iot.telekom.com/m2m/endpoints/{serialNumber}/downlinkMsg/0/data`, where `serialNumber` is the device IMEI with the `IMEI:` prefix, for example `IMEI:866425033313638`.
- **Authentication** — HTTP Basic, with the credentials of your IoT Creators API user. The API user must have a registered application URL.
- **Body** — `{"resourceValue": "<value>"}`, with `Content-Type: application/json`.
- **Response** — `202 Accepted`. IoT Creators queues up to 10 downlinks per device, each up to 512 bytes.

For details, see the <a href="https://docs.iotcreators.com/reference/send-standard-downlink" target="_blank" rel="noopener noreferrer"><strong>IoT Creators API documentation</strong></a>.

### Send a Downlink from the Rule Engine

Call the IoT Creators API from a rule chain with a **rest api call** node. In this example, every change of a shared attribute on the device is sent to it as a downlink. The rule chain keeps only shared attribute updates, reads the device IMEI from the `serialNumber` attribute that the decoder stores, packs the changed attributes into `resourceValue` as JSON, and calls the API.

<Steps>
1. Go to **Data processing &#8702; Rule chains** and open the **Root Rule Chain**.
2. From the **Filter** section, drag a **script** node onto the canvas:
   - **Name** — `Shared attributes only`.
   - Replace the script with `return metadata.scope == 'SHARED_SCOPE';`. Client and server attributes, such as the ones the decoder stores, stay in ThingsBoard.
   - Click **Add**.
3. From the **Enrichment** section, drag an **originator attributes** node onto the canvas:
   - **Name** — `Add IMEI`.
   - **Client attributes** — `serialNumber`. The node adds it to the metadata as `cs_serialNumber`.
   - Click **Add**.
4. From the **Transformation** section, drag a **script** node onto the canvas:
   - **Name** — `Build downlink body`.
   - Replace the script with:

     ```js
     // IoT Creators takes one string per downlink.
     // Send the changed shared attributes as JSON, for example {"temperatureUploadFrequency":60}.
     return {
         msg: { resourceValue: JSON.stringify(msg) },
         metadata: metadata,
         msgType: msgType
     };
     ```

   - Click **Add**.
5. From the **External** section, drag a **rest api call** node onto the canvas:
   - **Name** — `Send to IoT Creators`.
   - **Endpoint URL pattern** — `https://api.scs.iot.telekom.com/m2m/endpoints/${cs_serialNumber}/downlinkMsg/0/data`.
   - **Request method** — **PUT**.
   - **Headers** — `Content-Type` = `application/json`.
   - **Credentials** — set **Credentials type** to **Basic** and enter the username and password of your IoT Creators API user. The default **Anonymous** sends no credentials.
   - Click **Add**.
6. Connect the nodes:
   - **message type switch** &#8702; **Shared attributes only** with the **Attributes Updated** relation.
   - **Shared attributes only** &#8702; **Add IMEI** with the **True** relation.
   - **Add IMEI** &#8702; **Build downlink body** with the **Success** relation.
   - **Build downlink body** &#8702; **Send to IoT Creators** with the **Success** relation.
7. Click **Apply changes**.
</Steps>

To send a downlink, open the device, go to **Attributes**, select **Shared attributes**, and add or update an attribute, for example `temperatureUploadFrequency` = `60`. Turn on **Debug** for **Send to IoT Creators**: on success, its **Events** tab shows an event with the **Success** relation, and IoT Creators answers `202 Accepted`. On failure, the event has the **Failure** relation, and its metadata holds `statusCode`, `status`, `error`, and `error_body` with the response of IoT Creators.

**To adapt:**
- **Raw value instead of JSON** — if the device expects a plain or hex string, send one attribute: replace `JSON.stringify(msg)` with `"" + msg.temperatureUploadFrequency`, and replace the filter script with `return metadata.scope == 'SHARED_SCOPE' && msg.temperatureUploadFrequency != null;`.
- **Size** — IoT Creators accepts up to 512 bytes per downlink. Keep the JSON short, or send fewer attributes at a time.

<Aside type="note">
  NB-IoT and LTE-M devices do not receive downlinks right away. In the PSM and eDRX power-saving modes, a device receives a queued downlink only when it opens a receive window, usually right after its own uplink.
</Aside>

## Troubleshooting

| Symptom | Cause | Fix |
|---------|-------|-----|
| IoT Creators does not save the callback URL | The test request did not get `200`: the URL is wrong, ThingsBoard is not reachable from the internet, or the integration is disabled. | Copy the **HTTP endpoint URL** from the integration again. Check that ThingsBoard is reachable from the internet and that **Enable integration** is on. |
| `400 Bad Request` | Invalid JSON in the body, or an empty body sent as `application/json`. | Check the body syntax. |
| `415 Unsupported Media Type` | The request has no `Content-Type: application/json` header. | Send the body as JSON with that header. |
| `500 Internal Server Error` | The decoder threw an error, for example on a callback it does not expect. Or the integration key in the URL does not exist or belongs to another integration. | Check the **Error** column in the converter's **Events** tab. Copy the **HTTP endpoint URL** from the integration again. |
| No events, but the endpoint returns `200` | The request was sent with `Content-Type: text/plain`. The endpoint treats it as a validation request. | Send uplinks with `Content-Type: application/json`. |
| Downlink: **Failure** with `401 Unauthorized` and `{"msg":"Authentication error","code":1005}` | The **rest api call** node sends no credentials, or the IoT Creators username or password is wrong. | Set **Credentials type** to **Basic** and enter the credentials of your IoT Creators API user. |
| No uplinks from the device | The callback URL is wrong or off, the integration is disabled, or the device is not registered in the project. | Check the **YOUR APPLICATION SERVER** tab in IoT Creators, **Enable integration** in ThingsBoard, and the device list of the project. |
| Uplink with status **OK**, but no device or data | The converter returned an empty array: `reports` is empty, the report has another `resourcePath`, or `value` is shorter than 19 bytes. | Check **In** and **Out** in the converter events. Adapt the filter and the length check to your device. |
| Device not created, and the converter **Out** has data | **Allow create devices or assets** is off. | Open the integration, click **Toggle edit mode** (pencil icon), turn the option on, and click **Apply changes**. |
| Wrong telemetry values | The byte offsets or scaling do not match the device payload. | Compare `value` in the converter's **In** event with the payload specification of your device. |
| Data from several devices arrives in one callback, but only one device is updated | The decoder reads only the first report. | Use the decoder from this guide: it loops over all `reports` and returns one entry per device. |

To read debug events, open the integration or converter, click **Events**, and select an event: **In** is the received data, **Out** is the converter result, and **Error** holds the error text.

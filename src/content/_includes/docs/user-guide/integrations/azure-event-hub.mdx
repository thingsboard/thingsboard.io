Azure Event Hub Integration reads events from an <a href="https://learn.microsoft.com/en-us/azure/event-hubs/event-hubs-about" target="_blank" rel="noopener noreferrer"><strong>Azure Event Hubs</strong></a> event hub, typically the built-in Event Hub-compatible endpoint of <a href="https://azure.microsoft.com/en-us/products/iot-hub" target="_blank" rel="noopener noreferrer"><strong>Azure IoT Hub</strong></a>. An **uplink data converter** transforms each event into device or asset data, including telemetry and attributes. For IoT Hub, ThingsBoard can also send **downlink** cloud-to-device messages to any device in the hub.

Use Azure Event Hub Integration when:
- Your devices already send device-to-cloud messages to Azure IoT Hub, and you want their telemetry in ThingsBoard.
- Your applications publish events to an Azure event hub.
- You need to send commands from ThingsBoard to IoT Hub devices as cloud-to-device messages.

## Architecture

<ImageGallery images={[
  { src: '/src/assets/images/user-guide/integrations/azure-event-hub/azure-event-hub-integration.svg', alt: 'Azure Event Hub integration architecture showing device-to-cloud messages flowing from Azure IoT Hub through the Event Hub-compatible endpoint to ThingsBoard, and cloud-to-device messages flowing back', caption: 'Azure Event Hub integration architecture. Events are read from the Event Hub-compatible endpoint, converted by the uplink data converter, and forwarded to the ThingsBoard Core Service. Downlinks are sent back as cloud-to-device messages.' },
]} />

1. **Receive data.** Devices send device-to-cloud messages to IoT Hub, which routes them to its built-in Event Hub-compatible endpoint. The integration reads every partition of that endpoint as a member of a consumer group.
2. **Decode the payload.** The uplink converter identifies the target device or asset from the payload and extracts attributes and telemetry.
3. **Process the message.** ThingsBoard processes the converted data through the Rule Engine. If **Allow create devices or assets** is enabled, ThingsBoard can create an entity that does not exist yet.
4. **Send downlink data (optional).** The Rule Engine passes a message to the integration. The downlink converter encodes it, and the integration sends it through the IoT Hub service API as a cloud-to-device message to the device in `metadata.deviceId`.

## Set Up Azure Event Hub Integration

Create the uplink converter, assign it to a new Azure Event Hub integration, and send a test message.

   **To adapt:**
   - **Device name in another field** — replace `data.deviceId`, for example with `data.serialNumber`.
   - **Device name of the sender** — for IoT Hub messages, use the Azure Device ID of the sender: `metadata["sysProp:iothub-connection-device-id"]`.

<h4>Decoder Inputs</h4>

The decoder signature is `function decoder(payload, metadata): object | object[]`.

| Variable | Type | Content |
|----------|------|---------|
| `payload` | byte array | The event body. |
| `metadata` | `{[key: string]: string}` | Each system property of the event as `sysProp:<name>`. For IoT Hub messages, this includes `sysProp:iothub-connection-device-id` (the sending device) and `sysProp:iothub-enqueuedtime`. Also `integrationName` and the key–value pairs from the integration's **Metadata** field. Application properties of the event are not passed. |

Built-in helpers:

| Function | Result |
|----------|--------|
| `decodeToJson(payload)` | Parses the bytes as JSON and returns an object. |
| `decodeToString(payload)` | Converts the bytes to a UTF-8 string. |
| `toFlatMap(obj, excludeKeys, flatNested)` | TBEL only. Returns a flat key–value map of `obj`, skipping `excludeKeys`. With `flatNested` set to `true`, nested objects become dot-separated keys. |

For field renaming, nested values, and non-JSON payloads, see <DocLink product={props.product} path="user-guide/integrations/uplink-data-converter/#common-scripting-patterns" target="_blank">Common scripting patterns</DocLink>.

#### Connection Settings

| Parameter | Description |
|-----------|-------------|
| **Connection string** | Event Hubs connection string with `EntityPath`, for example the IoT Hub **Event Hub-compatible endpoint**. Required. |
| **IoT Hub Name** | Name of the IoT hub, without `.azure-devices.net`. Required when a downlink converter is assigned. ThingsBoard combines it with the key from **Connection string** to call the IoT Hub service API. |

| Parameter | Default | Description |

| **Consumer group** | `$Default` | Consumer group the integration reads with. Use a dedicated group when other applications read the same endpoint. |

#### Persistent Checkpoints

A checkpoint records the last event the integration processed in each partition. Without persistent checkpoints, the integration keeps them in memory, and events sent while it is stopped are skipped. With persistent checkpoints, it stores them in an Azure Blob Storage container and processes those events after a restart, as long as the hub still retains them.

<Steps>
1. In the Azure portal, open a storage account, or create one.
2. Go to **Security + networking &#8702; Access keys** and copy the **Connection string** of **key1**.
3. In the integration, turn on **Enable persistent checkpoints**.
4. Paste the connection string into **Storage connection string**.
5. Enter a **Container name**, for example `eventhubcontainer`. The integration creates the container if it does not exist.
</Steps>

## Configure Downlink

ThingsBoard sends a downlink when the Rule Engine routes a message to the integration — for example, after a shared attribute update. The integration sends it through the IoT Hub service API as a cloud-to-device message to the Azure device in `metadata.deviceId`. IoT Hub queues the message until the device receives it or the message expires.

Downlink requires:
- An IoT hub as the event source. A standalone event hub has no cloud-to-device messaging.
- **IoT Hub Name** in the integration.
- A **Connection string** whose policy has **Service connect** permission.

The downlink converter turns a <DocLink product={props.product} path="user-guide/rule-engine" target="_blank">Rule Engine</DocLink> message into the message body. For the full encoder reference, see <DocLink product={props.product} path="user-guide/integrations/downlink-data-converter" target="_blank">Downlink data converter</DocLink>.

### Create and Assign the Downlink Converter

The encoder returns:

- `contentType` — `JSON`, `TEXT`, or `BINARY`.
- `data` — the message body.
- `metadata` — `deviceId`, the Azure Device ID of the target device. Required: without it, the integration skips the message. Every `metadata` key is also added to the message properties, together with `content-type`.

<Steps>
1. Open the integration in **Integrations &#8702; Integrations** and click **Toggle edit mode** (pencil icon).
2. In the **Downlink data converter** field, click **Create new**. The **Downlink** converter type and **Azure Event Hub** integration type are preselected.
3. Enter a name, for example `Azure Event Hub Downlink Converter`.
4. In **Main encoding configuration**, replace the default encoder with the one below.
5. To record downlink events, click the debug icon next to the name, select **All messages**, and click **Apply**.
6. Click **Add**.
7. Enter the **IoT Hub Name**, for example `thingsboard-integration`. The field becomes required once a downlink converter is assigned.
8. Click **Apply changes**.
</Steps>

```js maxLines=15 collapsible
var result = {
  // Payload content type: JSON, TEXT, or BINARY (Base64).
  contentType: 'JSON',
  data: JSON.stringify(msg),
  metadata: {
    // Azure Device ID of the target device.
    // This guide uses the same ID as the ThingsBoard device name.
    deviceId: metadata.deviceName
  }
};

return result;
```

To check the encoder, click **Test encoder function**. **Message type** is already `ATTRIBUTES_UPDATED`. Set **Message** to `{"temperatureUploadFrequency":60}` and **deviceName** in **Metadata** to `8F4A2C6D`, if they differ, then click **Test**. The **Output** shows:

```json
{
  "contentType": "JSON",
  "data": "{\"temperatureUploadFrequency\":60}",
  "metadata": {
    "deviceId": "8F4A2C6D"
  }
}
```

**To adapt:**
- **Another envelope** — build `data` in the structure your device firmware expects, for example `{ "method": "setConfig", "params": msg }`.
- **Different Azure Device IDs** — when ThingsBoard device names differ from Azure Device IDs, store the Azure ID in a device attribute and read it into `metadata` with an enrichment node.
- **Message properties** — add keys to `metadata`, for example `source: 'thingsboard'`. The device receives them as message properties.
- **Other message types** — branch on `msgType`, for example to handle `RPC_CALL_FROM_SERVER_TO_DEVICE` with `msg.method` and `msg.params`. See <DocLink product={props.product} path="reference/rule-engine/message-types" target="_blank">Rule Engine message types</DocLink>.

### Configure the Root Rule Chain

The encoder reads `deviceName` from the message metadata, so the rule chain first adds the device name.

<Steps>
1. Go to **Data processing &#8702; Rule chains** and open the **Root Rule Chain**.
2. From the **Enrichment** section, drag an **originator fields** node onto the canvas.
3. Enter a **Name** (for example, `Retrieve device name`) and map the source fields:
   - **Name &#8702; deviceName**
   - **Add mapped originator fields to &#8702; Metadata**
   - Click **Add**.
4. Connect the **message type switch** node to the **originator fields** node with the **Attributes Updated** relation.
5. From the **Action** section, drag an **integration downlink** node onto the canvas.
6. Enter a **Name** (for example, `Downlink to Azure Event Hub`), select your Azure Event Hub integration, and click **Add**.
7. Connect the **originator fields** node to the **integration downlink** node with the **Success** relation.
8. Click **Apply changes**.
</Steps>

### Test Downlink

<Steps>
1. Go to **Devices & assets &#8702; Devices**, select **8F4A2C6D**, and open the **Attributes** tab.
2. Select **Shared attributes** and click **+**.
3. Set **Key** to `temperatureUploadFrequency`, **Type** to **Integer**, **Value** to `60`, and click **Add**. ThingsBoard sends the downlink.
</Steps>

## Troubleshooting

| Symptom | Cause | Fix |
|---------|-------|-----|
| **Check connection** fails with *"Unable to connect. Check for correct Connection String!"* | Wrong connection string, missing `EntityPath`, wrong **Consumer group**, or blocked port `5671`. | Copy the **Event Hub-compatible endpoint** again. Check that the consumer group exists and that outbound TCP `5671` is open. |
| **Check connection** fails with *"…Check for correct Storage Connection String!"* | Wrong storage connection string. | Copy it again from the storage account's **Access keys** page. |
| No uplinks after a restart | Persistent checkpoints are off, so events sent while the integration was stopped are skipped. | Turn on **[persistent checkpoints](#persistent-checkpoints)**. |
| No uplinks, connection is fine | Messages were sent before the integration started, or another reader takes the partitions in the same consumer group. | Send a new message. Use a dedicated **Consumer group**. |
| Device not created | `deviceName` is empty, or **Allow create devices or assets** is off. | Check **Out** in the converter events and the integration settings. |
| Integration fails to start after a downlink converter is assigned | **IoT Hub Name** is wrong, or the policy lacks **Service connect** permission. | Enter the hub name without `.azure-devices.net`. Select a policy such as `iothubowner` or `service` on **Built-in endpoints** and copy the endpoint again. |
| No downlink is sent | The rule chain does not reach the **integration downlink** node, or the encoder does not set `metadata.deviceId`. | Check the Root Rule Chain wiring. Check **Out** in the downlink converter events for `deviceId`. |
| Downlink sent, the device receives nothing | The Device ID does not exist in the hub, the message expired, or the hub is on the Basic tier. | Compare `deviceId` with the device list. Check **Default TTL** on **Built-in endpoints**. Use the Free or Standard tier. |

To read debug events, open the integration or converter, click **Events**, and select an event: **In** is the received data, **Out** is the converter result, and **Error** holds the error text.

AWS SQS Integration connects ThingsBoard to an <a href="https://aws.amazon.com/sqs/" target="_blank" rel="noopener noreferrer"><strong>Amazon SQS</strong></a> queue. ThingsBoard polls the queue, and an **uplink data converter** transforms each message into device or asset data, including telemetry and attributes. The integration is uplink-only.

Use AWS SQS Integration when:
- Devices, AWS IoT rules, AWS Lambda functions, or backend services already send data to an SQS queue.
- The queue must buffer data while ThingsBoard is unavailable: messages wait in the queue until the integration reads them.
- One queue carries data for many devices: the converter resolves each device from the message body.

1. **Receive data.** A producer sends a message to the queue. The integration requests up to 10 messages at a time.
2. **Decode the payload.** The uplink converter receives the message body, identifies the device or asset, and extracts attributes and telemetry.
3. **Process the message.** ThingsBoard processes the converted data through the Rule Engine. If **Allow create devices or assets** is enabled, ThingsBoard creates an entity that does not exist yet.
4. **Delete the message.** The integration deletes each message from the queue after processing it.

To send data from ThingsBoard to an SQS queue, use the <DocLink product={props.product} path="reference/rule-engine/nodes/external/aws-sqs" target="_blank">aws sqs</DocLink> rule node (see **[Send Data to AWS SQS](#send-data-to-aws-sqs)**).

## Prepare AWS SQS

Create a queue and an IAM user whose access key the integration uses.

### Create a Queue

The SQS console shows only the queues of the selected Region. Check the Region in the top-right corner of the console before you start.

<Steps>
1. Open the <a href="https://console.aws.amazon.com/sqs/" target="_blank" rel="noopener noreferrer"><strong>Amazon SQS console</strong></a>, select a Region, for example `eu-north-1`, and click **Create queue**.
2. Select the queue **Type**. You cannot change it after the queue is created.
   - **Standard** — nearly unlimited throughput, at-least-once delivery, best-effort ordering.
   - **FIFO** — first-in-first-out order and exactly-once processing. The name must end with `.fifo`.
3. Enter a **Name**, for example `ThingsBoard`.
4. Optional: in **Configuration**, set **Receive message wait time** to `20` seconds. The default `0` makes every poll of an empty queue return at once; with `20`, the poll waits for messages, which reduces the number of requests.
5. In **Encryption**, keep **Server-side encryption** enabled with **Amazon SQS key (SSE-SQS)**.
6. Leave **Access policy**, **Redrive allow policy**, **Dead-letter queue**, and **Tags** at their defaults, and click **Create queue**.
7. On the queue page, copy the **URL**, for example `https://sqs.eu-north-1.amazonaws.com/378560561651/ThingsBoard`, and the **ARN** for the IAM policy.
</Steps>

## Set Up AWS SQS Integration

Create the uplink converter, assign it to a new AWS SQS integration, and send a test message.

### Create the Uplink Data Converter

The uplink converter receives each message body as a byte array, resolves the target device, and returns its telemetry and attributes. AWS SQS Integration uses the **Generic** converter: you write the decoder in TBEL or JavaScript. For converter types and the full decoder reference, see <DocLink product={props.product} path="user-guide/integrations/uplink-data-converter/#converter-types" target="_blank">Uplink data converter</DocLink>.

SQS does not define a message format. This guide uses the sample message that the **Test decoder function** dialog provides by default:

```json
{
    "deviceName": "Thermometer",
    "deviceType": "thermostat",
    "serialNumber": "SN-12345",
    "temperature": 25.5
}
```

<Steps>
1. Go to **Integrations &#8702; Data converters** and click **+ Add data converter &#8702; Create new converter**.
2. **Converter type** — keep **Uplink**.
3. **Integration type** — select **AWS SQS**.
4. **Name** — enter a name, for example `AWS SQS Uplink Converter`.
5. **Main decoding configuration** — the editor opens with the default decoder below. Keep it for JSON messages: it takes the device name and type from `deviceName` and `deviceType`, stores `serialNumber` as an attribute, and stores the other fields as telemetry. The timestamp comes from `ts` (Unix milliseconds) or `timestamp` (ISO 8601); without them, the decoder uses the server time. The editor opens in TBEL; use the **TBEL / JS** toggle to switch to JavaScript.
   <Aside type="tip" title="TBEL">
     Use <DocLink product={props.product} path="user-guide/tbel" target="_blank">TBEL</DocLink> for converter scripts — it runs much faster than JavaScript inside ThingsBoard.
   </Aside>
   <Tabs>
     <TabItem label="TBEL (Recommended)">
       ```js maxLines=15 collapsible

       // payload - array of bytes
       // metadata - key/value object

       /** Decoder **/

       // decode payload to JSON
       var data = decodeToJson(payload);

       // --- Device name and type ---
       var deviceName = data.deviceName != null ? data.deviceName : 'Unknown Device';
       var deviceType = data.deviceType != null ? data.deviceType : 'default';
       // var customerName = 'Customer C';
       // var groupName = 'thermostat devices';

       // use assetName and assetType instead of deviceName and deviceType
       // to automatically create assets instead of devices.
       // var assetName = 'Asset A';
       // var assetType = 'building';

       // --- Timestamp parsing ---
       var timestamp = -1;
       if (data.ts != null) {
           timestamp = data.ts;
       } else if (data.timestamp != null) {
           timestamp = new Date(data.timestamp).getTime();
       }
       if (timestamp == -1) {
           timestamp = Date.now();
       }

       // --- Telemetry and attributes ---
       var telemetry = {};

       // Keys from the payload that should be stored as attributes instead of telemetry
       var attributeKeyList = ["serialNumber"];

       // Add the payload keys that match the attribute key list to attributes
       var attributes = {};
       for (var i = 0; i < attributeKeyList.size(); i++) {
           var attributeKey = attributeKeyList[i];
           if (data[attributeKey] != null) {
               attributes[attributeKey] = data[attributeKey];
           }
       }

       // Keys to exclude from telemetry (device info, attributes and non-telemetry fields)
       var excludeFromTelemetryList = ["deviceName", "deviceType", "ts", "timestamp"];
       excludeFromTelemetryList.addAll(attributeKeyList);

       // Parse all remaining JSON fields as telemetry
       telemetry.putAll(toFlatMap(data, excludeFromTelemetryList, true));

       // Result object with device attributes/telemetry data
       var result = {
          deviceName: deviceName,
          deviceType: deviceType,
       // customerName: customerName,
       // groupName: groupName,
       // assetName: assetName,
       // assetType: assetType,
       };

       // Add attributes to the result only if at least one matching key was found
       if (attributes.size() > 0) {
          result.put("attributes", attributes);
       }

       result.put("telemetry", {
          ts: timestamp,
          values: telemetry
       });

       /** Helper functions 'decodeToString', 'decodeToJson' and 'toFlatMap' are already built-in **/

       return result;
       ```

       var data = decodeToJson(payload);

       var attributes = {};

       var excludeFromTelemetryList = ["deviceName", "deviceType", "ts", "timestamp"].concat(attributeKeyList);

       // Parse all remaining JSON fields as telemetry
       toFlatMap(data, telemetry, excludeFromTelemetryList);

       // Result object with device attributes/telemetry data
       var result = {
          deviceName: deviceName,
          deviceType: deviceType,
       // customerName: customerName,
       // groupName: groupName,
       // assetName: assetName,
       // assetType: assetType,
       };

       // Add attributes to the result only if at least one matching key was found
       if (Object.keys(attributes).length > 0) {
          result.attributes = attributes;
       }

       result.telemetry = {
          ts: timestamp,
          values: telemetry
       };

       /** Helper functions **/

       function decodeToString(payload) {
          return String.fromCharCode.apply(String, payload);
       }

       function decodeToJson(payload) {
          var str = decodeToString(payload);
          return JSON.parse(str);
       }

       function toFlatMap(obj, result, excludeList, prefix) {
           prefix = prefix || '';
           for (var key in obj) {
               if (excludeList.indexOf(key) !== -1) continue;
               var value = obj[key];
               var fullKey = prefix ? prefix + '.' + key : key;
               if (typeof value === 'object' && value !== null && !Array.isArray(value)) {
                   toFlatMap(value, result, excludeList, fullKey);
               } else {
                   result[fullKey] = value;
               }
           }
       }

       return result;

<h4>Decoder Inputs</h4>

The decoder signature is `function decoder(payload, metadata): object | object[]`.

| Variable | Type | Content |
|----------|------|---------|
| `payload` | byte array | The message body, as compact JSON. |
| `metadata` | `{[key: string]: string}` | `integrationName` and the key–value pairs from the integration's **Metadata** field. SQS message attributes and the message ID are not passed. |

The message body must be JSON. A body that is a JSON-escaped string, for example `"{\"temperature\":25.5}"`, is unescaped first. The integration parses the body before the decoder runs, so a body that is not JSON never reaches the decoder (see **[How the Integration Reads the Queue](#how-the-integration-reads-the-queue)**).

Built-in helpers:

| Function | Result |
|----------|--------|
| `decodeToJson(payload)` | Parses the bytes as JSON and returns an object. |
| `decodeToString(payload)` | Converts the bytes to a UTF-8 string. |
| `toFlatMap(obj, excludeKeys, flatNested)` | TBEL only. Returns a flat key–value map of `obj`, skipping `excludeKeys`. With `flatNested` set to `true`, nested objects become dot-separated keys. The JavaScript template defines its own `toFlatMap(obj, result, excludeList)`, which writes into `result`. |

For field renaming, nested values, and other scripting patterns, see <DocLink product={props.product} path="user-guide/integrations/uplink-data-converter/#common-scripting-patterns" target="_blank">Common scripting patterns</DocLink>.

### Create the Integration

The wizard has no downlink step, because the integration only reads the queue.

<Steps>
1. Go to **Integrations &#8702; Integrations** and click **+ Add integration**.
2. **Basic settings:**
   - **Integration type** — select **AWS SQS**.
   - **Name** — keep the default `AWS SQS integration` or enter your own.
   - **Enable integration** and **Allow create devices or assets** — keep both on, so the device is created on its first message.
   - Click **Next**.
3. **Uplink data converter:**
   - Click **Select existing** and choose `AWS SQS Uplink Converter`.
   - Alternatively, click **Create new** to write a decoder here.
   - Click **Next**.
4. **Connection:**
   - **SQS Queue URL** — paste the queue URL.
   - **Region** — replace the default `us-west-2` with the Region of the queue, for example `eu-north-1`.
   - **AWS access key Id** and **AWS secret access key** — paste the **Access key** and the **Secret access key** of the IAM user.
   - Leave **Polling period in seconds** at its default `5`. See **[Connection Settings](#connection-settings)** for details.
5. Click **Add**.
</Steps>

#### Connection Settings

| Parameter | Default | Description |
|-----------|---------|-------------|
| **SQS Queue URL** | — | Full queue URL, in the form `https://sqs.{region}.amazonaws.com/{account-id}/{queue-name}`. Required. |
| **Polling period in seconds** | `5` | Pause after a poll that returns no messages. Minimum: `1`. |
| **Region** | `us-west-2` | AWS Region code of the queue. Must match the Region in the queue URL. Required. |
| **AWS access key Id** and **AWS secret access key** | — | Access key of the IAM user. Required. |
| **Execute remotely** | Off | Runs the integration as a separate process outside the ThingsBoard cluster. ThingsBoard generates an **Integration key** and **Integration secret** for it. See <DocLink product={props.product} path="user-guide/integrations/remote" target="_blank">Remote Integration</DocLink>. |
| **Description** | — | In **Advanced settings**. Free-text description. |
| **Metadata** | — | In **Advanced settings**. Key–value pairs added to the `metadata` of every message from this integration. |

#### How the Integration Reads the Queue

- Each poll requests up to 10 messages. While the queue returns messages, the integration polls again right away. After an empty response, it waits **Polling period in seconds**.
- A poll waits for messages as long as the queue's **Receive message wait time** allows. With `0`, it returns at once.
- The integration deletes every message it has received, even when the decoder fails. Failed messages are not retried and do not reach a dead-letter queue. The integration's **Events** tab shows them with status **ERROR**.
- A body that is not JSON stops the processing of the current batch. The integration deletes that message and records an **ERROR** event with a `JsonParseException`; the messages after it in the batch are not processed and return to the queue after its **Visibility timeout** (`30` seconds by default), then arrive with the next poll.

</Tabs>

## Send Data to AWS SQS

AWS SQS Integration has no downlink. To send data from ThingsBoard to SQS, add an **aws sqs** rule node to a rule chain. The node sends the message data as the SQS message body. On success, it adds `messageId`, `requestId`, `messageBodyMd5`, and, when the message has attributes, `messageAttributesMd5` to the message metadata. On failure, it adds `error`. For all parameters, see the <DocLink product={props.product} path="reference/rule-engine/nodes/external/aws-sqs" target="_blank">aws sqs node</DocLink> reference.

This section sends shared attribute updates of the device to a separate queue, `ThingsBoard-downlink`.

<Aside type="caution" title="Use a separate queue">
  Do not send to the queue that the integration reads. Each sent message would come back as an uplink. The integration would also try to decode it as device data.
</Aside>

### Prepare the Queue

<Steps>
1. In the Amazon SQS console, create a **Standard** queue named `ThingsBoard-downlink` with the default settings, as in **[Create a Queue](#create-a-queue)**.
2. Copy its **URL** and **ARN**.

     { src: '/src/assets/images/user-guide/integrations/aws-sqs/aws-sqs-downlink-queue-1.png', alt: 'Queue ThingsBoard-downlink created, Details panel with the ARN arn:aws:sqs:eu-north-1:378560561651:ThingsBoard-downlink and the URL https://sqs.eu-north-1.amazonaws.com/378560561651/ThingsBoard-downlink', caption: 'Copy the URL and ARN of the queue.' },
   ]} />
3. Allow the IAM user to send to the queue. In **IAM &#8702; IAM users**, open `thingsboard-sqs`, select `thingsboard-sqs-policy` on the **Permissions** tab, click **Edit**, and add a second statement with your queue ARN:
   ```json
   {
     "Sid": "AllowThingsBoardSqsPublish",
     "Effect": "Allow",
     "Action": "sqs:SendMessage",
     "Resource": "arn:aws:sqs:eu-north-1:378560561651:ThingsBoard-downlink"
   }
   ```
   Click **Next**, then **Save changes**.

### Configure the Root Rule Chain

The rule chain sends each shared attribute update to the queue. An **originator fields** node adds the device name to the message metadata, and an **aws sqs** node sends the message data as the SQS message body with the device name as a message attribute.

<Steps>
1. Go to **Data processing &#8702; Rule chains** and open the **Root Rule Chain**.
2. From the **Enrichment** section, drag an **originator fields** node onto the canvas. Set:
   - **Name** — `Add Device Name`.
   - **Originator fields mapping** — **Source field** **Name**, **Target key** `deviceName`.
   - **Add mapped originator fields to** — **Metadata**.
   - Click **Add**.
3. From the **External** section, drag an **aws sqs** node onto the canvas. Set:
   - **Name** — `Publish to SQS`.
   - **Queue type** — **Standard**.
   - **Queue URL pattern** — the URL of `ThingsBoard-downlink`. The pattern also accepts `${metadataKey}` and `$[messageKey]` placeholders.
   - **Delay (seconds)** — keep `0`.
   - **Message attributes** — click **Add mapping** and set **Name** to `deviceName` and **Value** to `${deviceName}`.
   - **AWS Access Key ID** and **AWS Secret Access Key** — the access key of `thingsboard-sqs`.
   - **AWS Region** — replace the default `us-east-1` with the Region of the queue, for example `eu-north-1`.
   - Click **Add**.
4. Connect the nodes:
   - **message type switch** &#8702; **Add Device Name** with the **Attributes Updated** relation.
   - **Add Device Name** &#8702; **Publish to SQS** with the **Success** relation.
5. Click **Apply changes**.
</Steps>

## Troubleshooting

| Symptom | Cause | Fix |
|---------|-------|-----|
| **ERROR** events mentioning the queue | Wrong **SQS Queue URL**. | Copy the URL from the queue page again. |
| **ERROR** events with `AccessDenied` | The access key is wrong or inactive, or the policy does not allow `sqs:ReceiveMessage` and `sqs:DeleteMessage` on the queue. | Check the access key and the queue ARN in the policy. For an SSE-KMS queue, allow `kms:Decrypt`. |
| Messages stay in the queue | The integration is disabled, or every poll fails. | Enable the integration and check its **Events** tab for errors. |
| Messages leave the queue, but no device appears | The decoder failed, or the body is not JSON. The integration deleted the messages anyway. | Check the **Error** column in the integration and converter events. Send JSON bodies only. |
| Some messages arrive about 30 seconds late | A message in the same batch had a body that is not JSON. The integration stopped the batch, and the remaining messages came back after the queue's **Visibility timeout**. | Find the **ERROR** event with `JsonParseException` in the integration events and fix the producer so that it sends JSON only. |
| Device not created | `deviceName` is empty or undefined. | Check **Out** in the converter events. |
| Data arrives with a delay | A long **Polling period in seconds** on a mostly empty queue. | Lower the polling period, or set the queue's **Receive message wait time** to `20` seconds. |
| The **aws sqs** node routes messages to **Failure** with `AccessDenied` in `error` | The IAM user has no `sqs:SendMessage` on the target queue. | Add the **[publish statement](#prepare-the-queue)** to the policy. |
| A message attribute holds `${key}` as text | The key is not in the message metadata. | Add the key with an enrichment node, for example **[originator fields](#configure-the-root-rule-chain)**, or use a key that the message already has. |
| Messages consumed by another reader | Another consumer reads the same queue. SQS delivers each message to one consumer only. | Use a dedicated queue for ThingsBoard, or fan out with Amazon SNS to several queues. |

To read debug events, open the integration or converter, click **Events**, and select an event: **In** is the received data, **Out** is the converter result, and **Error** holds the error text.

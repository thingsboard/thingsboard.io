Azure IoT Hub Integration connects ThingsBoard to <a href="https://azure.microsoft.com/en-us/products/iot-hub" target="_blank" rel="noopener noreferrer">**Azure IoT Hub**</a> over MQTT as one registered device. It receives the cloud-to-device messages addressed to that device, and an **uplink data converter** transforms each message into device or asset data, including telemetry and attributes. ThingsBoard can also publish **downlink** messages to the hub as that device.

Use Azure IoT Hub Integration when:
- A backend application sends data to ThingsBoard as cloud-to-device messages through Azure IoT Hub.
- Messages for several ThingsBoard devices arrive through one device identity: the converter sets the target device for each message.
- An Azure-side consumer must receive ThingsBoard data from the hub's built-in events endpoint.

<Aside type="note">
  To read the telemetry that a fleet of Azure IoT Hub devices already sends, use the <DocLink product={props.product} path="user-guide/integrations/azure-event-hub" target="_blank">Azure Event Hub Integration</DocLink> instead. It reads the hub's Event Hub-compatible endpoint, and its downlink sends cloud-to-device messages to any device in the hub.
</Aside>

## Architecture

1. **Receive data.** A backend application, the Azure portal, or the Azure CLI sends a cloud-to-device message to the integration's device identity. The integration is subscribed to `devices/{deviceId}/messages/devicebound/#` and receives it.
2. **Decode the payload.** The uplink converter identifies the target device or asset from the payload and extracts attributes and telemetry.
3. **Process the message.** ThingsBoard processes the converted data through the Rule Engine. If **Allow create devices or assets** is enabled, ThingsBoard can create an entity that does not exist yet.
4. **Send downlink data (optional).** The Rule Engine passes a message to the integration. The downlink converter encodes it, and the integration publishes it to `devices/{deviceId}/messages/events/` as a device-to-cloud message.

<Aside type="caution">
  IoT Hub allows one active connection per device identity. Register a dedicated device for the integration, for example `tb-bridge-01`. If physical hardware connects with the same Device ID, the two connections drop each other.
</Aside>

## Configure Azure IoT Hub

### Create an IoT Hub

<Steps>
1. In the <a href="https://portal.azure.com" target="_blank" rel="noopener noreferrer"><strong>Azure portal</strong></a>, search for **IoT Hub**, open the **IoT Hub** service, and click **+ Create**.
2. On the **Basics** tab, select or create a **Resource group**, enter a globally unique **IoT hub name** (for example, `tb-iot-hub`), choose a **Region**, and select a **Tier**. The Basic tier does not support cloud-to-device messages, so choose the Free or Standard tier.

5. Note the hub hostname `{hub-name}.azure-devices.net`, for example `tb-iot-hub.azure-devices.net`: the integration connects to it. The **Overview** page does not show it. It shows two other hostnames:

</Steps>

## Set Up Azure IoT Hub Integration

Create the uplink converter, assign it to a new Azure IoT Hub integration, and send a test message.

### Create the Uplink Data Converter

The uplink converter receives each message as a byte array plus its topic, resolves the target device, and returns its telemetry and attributes. Azure IoT Hub Integration uses the **Generic** converter: you write the decoder in TBEL or JavaScript. For converter types and the full decoder reference, see <DocLink product={props.product} path="user-guide/integrations/uplink-data-converter/#converter-types" target="_blank">Uplink data converter</DocLink>.

This guide uses the sample payload that ThingsBoard provides for Azure IoT Hub converters:

```json
{
  "deviceId": "8F4A2C6D",
  "deviceType": "Packing machine",
  "temperature": 25.5,
  "pressure": 1013.25,
  "vibration": {
    "x": 0.02,
    "y": 0.03,
    "z": 0.015
  },
  "location": {
    "latitude": 37.7749,
    "longitude": -122.4194,
    "altitude": 10
  },
  "timestamp": "2026-10-14T10:30:00Z",
  "status": "ALARM",
  "alarms": [
    {
      "type": "temperature",
      "severity": "high",
      "message": "Temperature exceeds threshold."
    },
    {
      "type": "vibration",
      "severity": "critical",
      "message": "Excessive vibration detected."
    }
  ],
  "metadata": {
    "version": 1,
    "batteryLevel": 100,
    "batteryStatus": "Charging",
    "manufacturer": "Example corporation"
  }
}
```

<Steps>
1. Go to **Integrations &#8702; Data converters** and click **+ Add data converter &#8702; Create new converter**.
2. **Converter type** — keep **Uplink**.
3. **Integration type** — select **Azure IoT Hub**.
4. **Name** — enter a name, for example `Azure IoT Hub Uplink Converter`.
5. **Main decoding configuration** — the editor opens with the default Azure IoT Hub decoder, which is the decoder below. Keep it, or write your own. It takes the device name from `deviceId` and rejects a message without it, so messages from different senders are not mixed in one device. It takes the device profile from `deviceType`; without it, the device gets the `default` profile. It maps measurements and state to telemetry and static device properties to attributes. It also reads `timestamp`, `location`, and `vibration` when the payload carries them. The editor opens in TBEL; use the **TBEL / JS** toggle to switch to JavaScript.
   <Aside type="tip" title="TBEL">
     Use <DocLink product={props.product} path="user-guide/tbel" target="_blank">TBEL</DocLink> for converter scripts — it runs much faster than JavaScript inside ThingsBoard.
   </Aside>
   <Tabs>
     <TabItem label="TBEL (Recommended)">
       ```js maxLines=15 collapsible
       /** Decoder **/

       // Decode the incoming payload to a JSON object.
       var data = decodeToJson(payload);

       // The device name comes from deviceId. Reject the message if it is missing or empty.
       var deviceName = data.deviceId != null ? data.deviceId.toString().trim() : "";
       if (deviceName.isEmpty()) {
           raiseError("Payload has no deviceId");
       }
       // The device profile comes from deviceType. If it is missing or empty, the "default" profile is used.
       var deviceType = data.deviceType != null ? data.deviceType.toString().trim() : "";
       if (deviceType.isEmpty()) {
           deviceType = "default";
       }

       // Use the ISO 8601 timestamp if provided; otherwise, use the current server time.
       var ts = data.timestamp != null ? new Date(data.timestamp).getTime() : Date.now();

       // Static device properties become attributes.
       var attributes = {};
       if (data.location != null) {
           attributes.latitude = data.location.latitude;
           attributes.longitude = data.location.longitude;
           attributes.altitude = data.location.altitude;
       }
       if (data.metadata != null) {
           attributes.version = data.metadata.version;
           attributes.manufacturer = data.metadata.manufacturer;
       }

       // Measurements and state become telemetry.
       var telemetry = {
           temperature: data.temperature,
           pressure: data.pressure,
           status: data.status,
           receivedAlarms: data.alarms
       };
       if (data.vibration != null) {
           telemetry.vibrationX = data.vibration.x;
           telemetry.vibrationY = data.vibration.y;
           telemetry.vibrationZ = data.vibration.z;
       }
       if (data.metadata != null) {
           telemetry.batteryLevel = data.metadata.batteryLevel;
           telemetry.batteryStatus = data.metadata.batteryStatus;
       }

       // Return the converted uplink message.
       return {
           deviceName: deviceName,
           deviceType: deviceType,
           attributes: attributes,
           telemetry: {
               ts: ts,
               values: telemetry
           }
       };
       ```
     </TabItem>
     <TabItem label="JavaScript">
       ```js maxLines=15 collapsible
       /** Decoder **/

       // Decode the incoming payload to a JSON object.
       var data = decodeToJson(payload);

       // The device name comes from deviceId. Reject the message if it is missing or empty.
       var deviceName = data.deviceId != null ? String(data.deviceId).trim() : "";
       if (!deviceName) {
           throw new Error("Payload has no deviceId");
       }
       // The device profile comes from deviceType. If it is missing or empty, the "default" profile is used.
       var deviceType = data.deviceType != null ? String(data.deviceType).trim() : "";
       if (!deviceType) {
           deviceType = "default";
       }

       // Use the ISO 8601 timestamp if provided; otherwise, use the current server time.
       var ts = data.timestamp != null ? new Date(data.timestamp).getTime() : Date.now();

       // Static device properties become attributes.
       var attributes = {};
       if (data.location != null) {
           attributes.latitude = data.location.latitude;
           attributes.longitude = data.location.longitude;
           attributes.altitude = data.location.altitude;
       }
       if (data.metadata != null) {
           attributes.version = data.metadata.version;
           attributes.manufacturer = data.metadata.manufacturer;
       }

       // Measurements and state become telemetry.
       var telemetry = {
           temperature: data.temperature,
           pressure: data.pressure,
           status: data.status,
           receivedAlarms: data.alarms
       };
       if (data.vibration != null) {
           telemetry.vibrationX = data.vibration.x;
           telemetry.vibrationY = data.vibration.y;
           telemetry.vibrationZ = data.vibration.z;
       }
       if (data.metadata != null) {
           telemetry.batteryLevel = data.metadata.batteryLevel;
           telemetry.batteryStatus = data.metadata.batteryStatus;
       }

       // Build the converted uplink message.
       var result = {
           deviceName: deviceName,
           deviceType: deviceType,
           attributes: attributes,
           telemetry: {
               ts: ts,
               values: telemetry
           }
       };

       /** Helper functions **/

       // Convert the byte array to a string.
       function decodeToString(payload) {
           return String.fromCharCode.apply(String, payload);
       }

       // Convert the byte array to a JSON object.
       function decodeToJson(payload) {
           return JSON.parse(decodeToString(payload));
       }

       // Return the converted uplink message.
       return result;
       ```
     </TabItem>
   </Tabs>

   **To adapt:**
   - **Device name in another field** — replace `data.deviceId`, for example with `data.serialNumber`.
   - **Optional fields** — remove the `location`, `vibration`, `status`, or `alarms` mappings your devices never send.
   - **Other telemetry** — add keys to `telemetry`, for example `humidity: data.humidity`.
   - **Other device properties** — add them to `attributes`, for example `model: data.model`.
   - **Update-only keys** — for Azure IoT Hub, ThingsBoard pre-fills the **Update only keys list** in **Advanced decoding parameters** with `manufacturer`, `receivedAlarms`, `status`, `batteryLevel`, `batteryStatus`, `version`, `latitude`, `longitude`, and `altitude`. These keys are stored only when their value changes. Edit the list to match your keys.
6. Click **Test decoder function** and check the result (see **[Test the Decoder](#test-the-decoder)**).
7. Click **Add**.
</Steps>

<h4>Decoder Inputs</h4>

The decoder signature is `function decoder(payload, metadata): object | object[]`.

| Variable | Type | Content |
|----------|------|---------|
| `payload` | byte array | The message body. |
| `metadata` | `{[key: string]: string}` | `topic` — the topic the message arrived on: `devices/{deviceId}/messages/devicebound/` followed by the message's property bag. Also `integrationName` and the key–value pairs from the integration's **Metadata** field. |

For example, a message sent with the Azure CLI command from **[Send a Test Uplink](#send-a-test-uplink)** arrives with this `topic`:

```text
devices/tb-bridge-01/messages/devicebound/%24.mid=7c1b13d0-7baa-4cfb-a3c4-1bba7bcbc0b7&%24.to=%2Fdevices%2Ftb-bridge-01%2Fmessages%2Fdevicebound&%24.ce=utf-8&iothub-ack=none
```

The part after `devicebound/` is the URL-encoded property bag: `$.mid` is the message ID, `$.to` the destination, `$.ce` the content encoding.

Built-in helpers:

| Function | Result |
|----------|--------|
| `decodeToJson(payload)` | Parses the bytes as JSON and returns an object. |
| `decodeToString(payload)` | Converts the bytes to a UTF-8 string. |
| `toFlatMap(obj, excludeKeys, flatNested)` | TBEL only. Returns a flat key–value map of `obj`, skipping `excludeKeys`. With `flatNested` set to `true`, nested objects become dot-separated keys. |

For field renaming, nested values, and non-JSON payloads, see <DocLink product={props.product} path="user-guide/integrations/uplink-data-converter/#common-scripting-patterns" target="_blank">Common scripting patterns</DocLink>.

### Create the Integration

<Steps>
1. Go to **Integrations &#8702; Integrations** and click **+ Add integration**.
2. **Basic settings:**
   - **Integration type** — select **Azure IoT Hub**.
   - **Name** — keep the default or enter your own.
   - **Enable integration** and **Allow create devices or assets** — keep both on, so the device is created on its first uplink.
   - Click **Next**.
3. **Uplink data converter:**
   - Click **Select existing** and choose `Azure IoT Hub Uplink Converter`.
   - Alternatively, click **Create new** to write a decoder here.
   - Click **Next**.
4. **Downlink data converter:**
   - Click **Skip**. Add a downlink converter later if you need to **[send data to the hub](#configure-downlink)**.
5. **Connection:**
   - **Hostname** — enter the hub hostname, for example `tb-iot-hub.azure-devices.net`.
   - **Device ID** — enter `tb-bridge-01`.
   - **Credentials** — keep **Shared Access Signature** and paste the device's primary key into **SAS Key**.
   - **Topic filters** — replace the default `#` with `devices/tb-bridge-01/messages/devicebound/#` and set **QoS** to **1 - At least once**.
   - **Advanced settings** — set **Max bytes in message** to `131072`. IoT Hub sends cloud-to-device messages up to 64 KB, and with the default `32368` a larger message (the limit includes the topic) is lost without an event.
   - Leave the other parameters at their defaults. See **[Connection Settings](#connection-settings)** for details.
6. Click **Add**.
</Steps>

#### Connection Settings

| Parameter | Description |
|-----------|-------------|
| **Hostname** | Hub hostname, `{hub-name}.azure-devices.net`. Do not use the hostnames from the hub's **Overview** page: the **Service hostname** `{hub-name}.service.azure-devices.net` is for back-end services, and the **Device hostname** `{hub-name}.device.azure-devices.net` works only if you upload DigiCert Global Root G3; see **[Credentials](#credentials)**. |
| **Device ID** | The device identity the integration connects as. It is also the MQTT client ID. |
| **Credentials** | **Shared Access Signature** (default) or **PEM**. See **[Credentials](#credentials)**. |
| **Topic filters** | Subscriptions, each with a **Topic** and **QoS** (`0` or `1`; IoT Hub does not support QoS 2). Default: `#` with QoS `0`. Use `devices/{deviceId}/messages/devicebound/#` — IoT Hub delivers cloud-to-device messages only on this topic. The `#` is required because the hub appends a property bag to the topic. Use QoS `1`: IoT Hub then waits for the integration to acknowledge each message, and reports a message that ThingsBoard did not receive (for example, because ThingsBoard stopped) as not delivered (`Purged`) instead of delivered. With QoS `0`, IoT Hub reports each message as delivered as soon as it sends it. |
| **Execute remotely** | Runs the integration as a separate process outside the ThingsBoard cluster, for example in a network with access to Azure. ThingsBoard generates an **Integration key** and **Integration secret** for it. See <DocLink product={props.product} path="user-guide/integrations/remote" target="_blank">Remote Integration</DocLink>. |

**Advanced settings**

| Parameter | Default | Description |
|-----------|---------|-------------|
| **Protocol version** | MQTT 3.1.1 | The only version available. |
| **Max bytes in message** | `32368` | Maximum size of an incoming message, in bytes (1–256,000,000), including the topic. Set `131072`: IoT Hub sends cloud-to-device messages up to 64 KB, and a message over this limit is lost without an event. |
| **Description** | — | Free-text description. |
| **Metadata** | — | Key–value pairs added to the `metadata` of every message from this integration and to the encoder's `integrationMetadata`. The encoder in this guide reads `deviceId` from it; see **[Create and Assign the Downlink Converter](#create-and-assign-the-downlink-converter)**. |

The integration always connects over TLS on port `8883` with a clean session. IoT Hub delivers only the messages sent after the integration connects: messages sent while it is disabled, restarting, or offline are not delivered. The integration does not offer **Check connection**: check its status after you add it.

#### Credentials

| Type | Fields |
|------|--------|
| **Shared Access Signature** | **SAS Key** — the device's primary or secondary key. ThingsBoard builds a SAS token from it when the integration starts or its settings are saved. The token is valid for one year, so save the integration again before it expires. **CA certificate file** — optional; see below. |
| **PEM** | X.509 authentication. **Certificate file** — the device certificate registered in the hub. **Private key file** — the key for that certificate. **Private key password** — only for an encrypted key. **CA certificate file** — optional; see below. |

Without a **CA certificate file**, the integration verifies the hub with the DigiCert Global Root G2 certificate, which `{hub-name}.azure-devices.net` uses. A **CA certificate file** replaces it. With **Shared Access Signature**, the integration reads only the first certificate in the file, so upload a single root certificate: for example, DigiCert Global Root G3 to connect to the **Device hostname** `{hub-name}.device.azure-devices.net`. For X.509 device registration, see <a href="https://learn.microsoft.com/en-us/azure/iot-hub/authenticate-authorize-x509" target="_blank" rel="noopener noreferrer"><strong>Authenticate identities with X.509 certificates</strong></a>.

## Configure Downlink

ThingsBoard publishes downlinks to the hub when the Rule Engine routes a message to the integration — for example, after a shared attribute update. Downlinks are published with QoS 1 as device-to-cloud messages from the integration's Device ID. They reach the hub's built-in events endpoint, where an Azure-side consumer reads them.

The topic comes from the `topic` value in the downlink converter's output `metadata`. The integration has no fixed downlink topic, so the encoder must set `topic` to `devices/{deviceId}/messages/events/`, with the integration's Device ID. IoT Hub closes the connection when a device publishes to any other topic. The encoder does not receive the **Device ID** field, so this guide adds the **Device ID** to the integration's **Metadata** as `deviceId`, and the encoder builds the topic from it. To identify the ThingsBoard device, put its name in the payload.

The downlink converter turns a <DocLink product={props.product} path="user-guide/rule-engine" target="_blank">Rule Engine</DocLink> message into the published payload. For the full encoder reference, see <DocLink product={props.product} path="user-guide/integrations/downlink-data-converter" target="_blank">Downlink data converter</DocLink>.

### Create and Assign the Downlink Converter

The encoder returns:

- `contentType` — `JSON`, `TEXT`, or `BINARY`.
- `data` — the payload to publish.
- `metadata` — `topic`, the topic to publish to.

The encoder reads:

- `msg`, `msgType`, `metadata` — the Rule Engine message, its type, and its metadata. For RPC commands, `msg.method` and `msg.params` are available.
- `integrationMetadata` — `integrationName` and the key–value pairs from the integration's **Metadata** field. The encoder in this guide reads `deviceId` from it.

<Steps>
1. Open the integration in **Integrations &#8702; Integrations** and click **Toggle edit mode** (pencil icon).
2. In the **Downlink data converter** field, click **Create new**. The **Downlink** converter type and **Azure IoT Hub** integration type are preselected.
3. Enter a name, for example `Azure IoT Hub Downlink Converter`.
4. In **Main encoding configuration**, replace the default encoder with the one below. To use JavaScript, switch the **TBEL / JS** toggle and take the code from the **JavaScript** tab.
5. To record downlink events, click the debug icon next to the name, select **All messages**, and click **Apply**.
6. Click **Add**.
7. In the integration, expand **Advanced settings**. In **Metadata**, click **Add**, enter `deviceId` as the key and the integration's **Device ID** as the value, for example `tb-bridge-01`.
8. Click **Apply changes**.
</Steps>

Encoder used in this guide:

<Tabs>
  <TabItem label="TBEL (Recommended)">
  ```js maxLines=15 collapsible
  /** Encoder **/

  // The rule chain adds the ThingsBoard device name to the metadata.
  // Reject the message if it is missing or empty.
  var deviceName = metadata.deviceName != null ? metadata.deviceName.trim() : "";
  if (deviceName == "") {
    raiseError("Message metadata has no deviceName");
  }

  // The integration Metadata adds the Azure IoT Hub device ID.
  // Reject the message if it is missing or empty.
  var azureDeviceId = integrationMetadata.deviceId != null ? integrationMetadata.deviceId.trim() : "";
  if (azureDeviceId == "") {
    raiseError("Integration metadata has no deviceId");
  }

  // Prepare the downlink payload.
  var data = {
    deviceName: deviceName,
    ts: Date.now()
  };

  // Map Rule Engine messages to commands.
  if (msgType == 'RPC_CALL_FROM_SERVER_TO_DEVICE') {
    // RPC request.
    data.method = msg.method;
    data.params = msg.params;
    data.requestId = metadata.requestId;
  } else if (msgType == 'ATTRIBUTES_UPDATED' || msgType == 'POST_ATTRIBUTES_REQUEST') {
    // Shared attribute update.
    data.method = 'setSharedAttributes';
    data.params = msg;
  } else {
    // Other message types.
    data.method = 'data';
    data.params = msg;
  }

  // Return the encoded downlink payload.
  var result = {
    // Payload content type: JSON, TEXT, or BINARY (Base64).
    contentType: 'JSON',
    data: JSON.stringify(data),
    metadata: {
      // Azure IoT Hub device-to-cloud MQTT topic for this device ID.
      topic: 'devices/' + azureDeviceId + '/messages/events/'
    }
  };

  return result;
  ```
  </TabItem>

**To adapt:**
- **Another envelope** — build `data` in the structure your Azure-side consumer expects.
- **Payload as is** — use `data: JSON.stringify(msg)` and drop the branches.
- **Message properties** — append a URL-encoded property bag to the topic, for example `'devices/' + azureDeviceId + '/messages/events/source=thingsboard'`. IoT Hub routing queries can filter on these properties.
- **Other message types** — add branches for other <DocLink product={props.product} path="reference/rule-engine/message-types" target="_blank">Rule Engine message types</DocLink>.

### Configure the Root Rule Chain

The encoder puts `deviceName` in the payload, so the rule chain first adds the device name to the message metadata.

<Steps>
1. Go to **Data processing &#8702; Rule chains** and open the **Root Rule Chain**.
2. From the **Enrichment** section, drag an **originator fields** node onto the canvas.
3. Enter a **Name** (for example, `Retrieve device name`) and map the source fields:
   - **Name &#8702; deviceName**
   - **Add mapped originator fields to &#8702; Metadata**
   - Click **Add**.
4. Connect the **message type switch** node to the **originator fields** node with the **Attributes Updated** relation.
5. From the **Action** section, drag an **integration downlink** node onto the canvas.
6. Enter a **Name** (for example, `Downlink to Azure IoT Hub`), select your Azure IoT Hub integration, and click **Add**.
7. Connect the **originator fields** node to the **integration downlink** node with the **Success** relation.
8. Click **Apply changes**.
</Steps>

## Troubleshooting

| Symptom | Cause | Fix |
|---------|-------|-----|
| Integration is not connected, error `Failed to connect to MQTT broker at <hostname>:8883.` | Wrong **Hostname**, or the **Service hostname** or **Device hostname** from the hub's **Overview** page is used. | Enter `{hub-name}.azure-devices.net`, or upload DigiCert Global Root G3 to use the **Device hostname**. See **[Create an IoT Hub](#create-an-iot-hub)** and **[Credentials](#credentials)**. |
| Integration is not connected, error `… Result code is: CONNECTION_REFUSED_NOT_AUTHORIZED` | Wrong **Device ID** or **SAS Key**. | Compare both with the device details in the Azure portal. Regenerate the key if unsure. |
| Integration is not connected, error `Failed to connect to MQTT broker at <hostname>:8883.`, from a private network | Outbound port `8883` is blocked. | Open TCP `8883` to `*.azure-devices.net`, or use a <DocLink product={props.product} path="user-guide/integrations/remote" target="_blank">Remote Integration</DocLink>. |
| Some messages never arrive, no event or error | Another client connected with the same Device ID. IoT Hub closes the integration's connection, and messages sent until it reconnects are lost. | Use a dedicated device identity for the integration. To confirm, check the device's connection state in the hub, or look for error `400027 ConnectionForcefullyClosedOnNewConnection` in the IoT Hub logs. |
| Downlink event is OK, but nothing reaches the hub | The encoder's `topic` is not `devices/{deviceId}/messages/events/` with the integration's Device ID. With the encoder from this guide, `deviceId` in the integration's **Metadata** differs from **Device ID**. IoT Hub drops the message and closes the connection; the integration reconnects within seconds and records no error. | Set `deviceId` in **Metadata** to the integration's **Device ID**. |
| No messages received | The topic filter does not match. | Use `devices/{deviceId}/messages/devicebound/#`, ending in `#`. |
| Messages sent while the integration was disabled or offline never arrive | When the integration reconnects with a clean session, IoT Hub discards the messages queued while it was disconnected. | Send the messages again after the integration is connected. |
| Device telemetry never arrives | Devices send device-to-cloud messages, which this integration does not receive. | Use the <DocLink product={props.product} path="user-guide/integrations/azure-event-hub" target="_blank">Azure Event Hub Integration</DocLink>. |
| Device not created, the converter event has the error `Payload has no deviceId` | The message has no `deviceId`, or the value is empty. | Add `deviceId` to the message, or change the decoder to read the device name from another field. |
| Device not created, no converter error | **Allow create devices or assets** is off. | Turn it on in the integration settings. |
| Large messages never arrive, no event | The message, with its topic, exceeds **Max bytes in message**. The integration closes the connection and reconnects, and IoT Hub drops the message (`Purged` in delivery feedback). | Set **Max bytes in message** to `131072` in **Advanced settings**. |
| Downlink produces no event | The rule chain does not reach the **integration downlink** node. | Check the Root Rule Chain wiring and turn on debug mode for its nodes. |
| Downlink not sent, the downlink converter event has the error `Message metadata has no deviceName` | The rule chain does not add the device name to the message metadata. | Add the **originator fields** node with **Name &#8702; deviceName** before the **integration downlink** node. See **[Configure the Root Rule Chain](#configure-the-root-rule-chain)**. |
| Downlink not sent, the downlink converter event has the error `Integration metadata has no deviceId` | The integration's **Metadata** has no `deviceId`. | Add `deviceId` with the integration's **Device ID**. See **[Create and Assign the Downlink Converter](#create-and-assign-the-downlink-converter)**. |
| Downlink sent, nothing in the monitor | The monitor started after the downlink. | Start `az iot hub monitor-events` first, then trigger the downlink. |

To read debug events, open the integration or converter, click **Events**, and select an event: **In** is the received data, **Out** is the converter result, and **Error** holds the error text.

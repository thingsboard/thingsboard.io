CoAP Integration connects ThingsBoard to devices that use the [CoAP protocol](https://tools.ietf.org/html/rfc7252). It exposes a CoAP endpoint, receives device payloads, and transforms them into ThingsBoard telemetry and attributes via an uplink converter.

<DocImage src="/src/assets/images/user-guide/integrations/coap-integration.svg" alt="CoAP Integration architecture diagram — device sends CoAP messages to the ThingsBoard CoAP endpoint, the uplink converter decodes the payload and pushes telemetry and attributes to the platform" />

<Aside type="caution">
The CoAP endpoint is served by the **tb-core** service and must be reachable from the device network. For DTLS modes, additional key store configuration is required — see [CoAP Integration Configuration](#coap-integration-configuration).
</Aside>

## Prerequisites

In this tutorial, device **SN-001** sends temperature and humidity readings to the CoAP Integration at `coap://localhost`. 

The integration accepts three payload types:

<Tabs>
<TabItem label="Text">
```
SN-001,default,temperature,25.7,humidity,69
```
</TabItem>
<TabItem label="JSON">
```json
{
  "deviceName": "SN-001",
  "deviceType": "default",
  "temperature": 25.7,
  "humidity": 69
}
```
</TabItem>
<TabItem label="Binary">
Hex string:
```
\x53\x4e\x2d\x30\x30\x31\x64\x65\x66\x61\x75\x6c\x74\x32\x35\x2e\x37\x36\x39
```

Byte layout:

| Bytes | Hex | Value |
|-------|-----|-------|
| 0–5 | `\x53\x4e\x2d\x30\x30\x31` | Device name: `SN-001` |
| 6–12 | `\x64\x65\x66\x61\x75\x6c\x74` | Device type: `default` |
| 13–16 | `\x32\x35\x2e\x37` | Temperature: `25.7` |
| 17–18 | `\x36\x39` | Humidity: `69` |
</TabItem>
</Tabs>

## Uplink Converter

The uplink converter decodes the CoAP payload and maps it to the ThingsBoard data model. `deviceName` and `deviceType` are required; `attributes` and `telemetry` are optional flat key-value objects. Nested objects are not supported.

<Steps>
1. Go to **Integration center → Data converters** and click **+ Add data converter → Create new converter**.
2. Select type **Uplink** and integration type **CoAP**.
3. Name it **CoAP Uplink Converter**.
4. Enable **Debug mode** to inspect events during initial setup.
5. Paste the decoder script for your payload type (see tabs below) and click **Add**.
</Steps>

:::tip
Use **TBEL** (ThingsBoard Expression Language) for converter scripts — it executes significantly faster than plain JavaScript inside ThingsBoard.
:::

<Tabs>
<TabItem label="Text payload">
<Tabs>
<TabItem label="TBEL (Recommended)">

```js maxLines=25 collapsible
/** Decoder **/

// decode payload to string
var strArray = decodeToString(payload);
var payloadArray = strArray.replaceAll("\"", "").split(',');

var telemetryPayload = {};
for (var i = 2; i < payloadArray.length; i = i + 2) {
    var telemetryKey = payloadArray[i];
    var telemetryValue = parseFloat(payloadArray[i + 1]);
    telemetryPayload[telemetryKey] = telemetryValue;
}

// Result object with device attributes/telemetry data
var result = {
    deviceName: payloadArray[0],
    deviceType: payloadArray[1],
    telemetry: telemetryPayload,
    attributes: {}
};

/** Helper functions 'decodeToString' and 'decodeToJson' are already built-in **/

return result;
```

## CoAP Integration Setup

<Steps>
1. Go to **Integration center → Integrations** and click **+ Add integration**.
2. **Basic settings:** Set **Integration type** to **CoAP** and enter a name (e.g. "CoAP Integration"). Click **Next**.
3. **Uplink data converter:** Select the **CoAP Uplink Converter** created above. Click **Next**.
4. **Connection:** Copy the auto-generated **CoAP endpoint URL** — you will use it to send test messages. Click **Add**.
</Steps>

## CoAP Integration Configuration

CoAP Integration supports three security modes:

| Mode | Description |
|------|-------------|
| **NO SECURE** (default) | Plain CoAP over UDP — no encryption |
| **DTLS** | CoAP over DTLS 1.2 — encrypted |
| **MIXED** | Both plain and DTLS endpoints active simultaneously |

<DocImage src="/src/assets/images/user-guide/integrations/coap/coap-integration-modes-1.png" alt="CoAP Integration security mode selector — NO SECURE, DTLS, and MIXED options" />

For **DTLS** and **MIXED** modes, enable DTLS support in `thingsboard.yml` or set the following environment variables:

```bash
# Enable/disable DTLS 1.2 support
export COAP_DTLS_ENABLED=true
# Default CoAP DTLS bind port
export COAP_DTLS_BIND_PORT=5484
# Path to the key store that holds the SSL certificate
export COAP_DTLS_KEY_STORE=coapserver.jks
# Password used to access the key store
export COAP_DTLS_KEY_STORE_PASSWORD=server_ks_password
# Password used to access the key
export COAP_DTLS_KEY_PASSWORD=server_key_password
# Key alias
export COAP_DTLS_KEY_ALIAS=serveralias
# Skip certificate validity check for client certificates
export TB_COAP_X509_DTLS_SKIP_VALIDITY_CHECK_FOR_CLIENT_CERT=false
```

<Aside type="note">
The values above are defaults. At minimum, update the key store path and credentials before enabling DTLS. See the <a href="/docs/pe/user-guide/coap-over-dtls/">CoAP over DTLS</a> guide for full configuration details.
</Aside>

The endpoint URL is auto-generated from the **Base URL** and the path `/i/$INTEGRATION_ROUTING_KEY`, where the routing key is assigned automatically at integration creation time.

## Send Uplink Message

Once the integration is created, the CoAP server registers the endpoint and waits for incoming data. Send a test message using `coap-client`, replacing `$YOUR_COAP_ENDPOINT_URL` with the URL copied during setup:

<Tabs>
<TabItem label="Text payload">

```bash
echo -e 'SN-001,default,temperature,25.7,humidity,69' | coap-client -m post $YOUR_COAP_ENDPOINT_URL -t text/plain -f-
```

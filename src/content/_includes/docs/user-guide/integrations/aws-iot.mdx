AWS IoT Integration connects ThingsBoard to <a href="https://aws.amazon.com/iot/" target="_blank" rel="noopener noreferrer"><strong>AWS IoT Core</strong></a>, the managed MQTT broker of AWS. ThingsBoard connects as an MQTT client over mutual TLS and subscribes to the topics you configure. An **uplink data converter** transforms each message into device or asset data, including telemetry and attributes. ThingsBoard can also publish **downlink** messages to AWS IoT Core for devices to consume.

Use AWS IoT Integration when:
- Devices already publish to AWS IoT Core and you want their data in ThingsBoard without changing the firmware.
- One subscription must serve many devices: the converter resolves each device from the topic or the payload.
- You need to send commands to devices through AWS IoT Core.

<Aside type="note">
  To read AWS IoT data from a queue or a stream instead, route it with an <a href="https://docs.aws.amazon.com/iot/latest/developerguide/iot-rules.html" target="_blank" rel="noopener noreferrer"><strong>AWS IoT rule</strong></a> and use the <DocLink product={props.product} path="user-guide/integrations/aws-sqs" target="_blank">AWS SQS</DocLink> or <DocLink product={props.product} path="user-guide/integrations/aws-kinesis" target="_blank">AWS Kinesis</DocLink> integration.
</Aside>

1. **Receive data.** A device publishes a message to AWS IoT Core. The integration is subscribed to that topic and receives the message.
2. **Decode the payload.** The uplink converter uses the payload and topic to identify the device or asset and extract attributes and telemetry.
3. **Process the message.** ThingsBoard processes the converted data through the Rule Engine. If **Allow create devices or assets** is enabled, ThingsBoard creates an entity that does not exist yet.
4. **Send downlink data (optional).** The Rule Engine passes a message to the integration. The downlink converter encodes it, and the integration publishes it to AWS IoT Core on the downlink topic.

## Configure AWS IoT

In the <a href="https://console.aws.amazon.com/iot" target="_blank" rel="noopener noreferrer"><strong>AWS IoT console</strong></a>, create a policy, a thing with a certificate, and copy the device data endpoint. ThingsBoard authenticates with the certificate and its private key, and verifies AWS IoT Core with the Amazon Root CA certificate.

### Create a Policy

A policy lists the AWS IoT actions (`Connect`, `Publish`, `Subscribe`, `Receive`) that the certificate may perform. See <a href="https://docs.aws.amazon.com/iot/latest/developerguide/iot-policies.html" target="_blank" rel="noopener noreferrer"><strong>AWS IoT Core policies</strong></a>.

<Steps>
1. Go to **Security &#8702; Policies** and click **Create policy**.
2. Enter a **Policy name**, for example `tb_policy`, and click **JSON** to open the JSON editor.
3. Paste the policy below. Replace `YOUR_REGION` and `YOUR_AWS_ID` with your AWS Region and account ID, for example `eu-west-1` and `111197721064`. The Region also appears in the console URL: `https://eu-west-1.console.aws.amazon.com`.
4. Click **Create**.
</Steps>

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["iot:Publish", "iot:Receive"],
      "Resource": ["arn:aws:iot:YOUR_REGION:YOUR_AWS_ID:topic/*"]
    },
    {
      "Effect": "Allow",
      "Action": ["iot:Subscribe"],
      "Resource": ["arn:aws:iot:YOUR_REGION:YOUR_AWS_ID:topicfilter/*"]
    },
    {
      "Effect": "Allow",
      "Action": ["iot:Connect"],
      "Resource": ["arn:aws:iot:YOUR_REGION:YOUR_AWS_ID:client/*"]
    }
  ]
}
```

<Aside type="tip">
  The policy above allows all topics. In production, limit it to a dedicated namespace: replace `topic/*` with `topic/tb/aws/iot/*` and `topicfilter/*` with `topicfilter/tb/aws/iot/*`.
</Aside>

## Set Up AWS IoT Integration

Create the uplink converter, assign it to a new AWS IoT integration, and publish a test message.

### Create the Uplink Data Converter

The uplink converter receives each MQTT message as a byte array plus its topic, resolves the target device, and returns its telemetry and attributes. AWS IoT Integration uses the **Generic** converter: you write the decoder in TBEL or JavaScript. For converter types and the full decoder reference, see <DocLink product={props.product} path="user-guide/integrations/uplink-data-converter/#converter-types" target="_blank">Uplink data converter</DocLink>.

This guide uses a device that publishes to `tb/aws/iot/sensors/freezer-432`:

```json
{
  "ts": 1791901200000,
  "temperature": 25.3,
  "humidity": 62.8,
  "battery": 78.5,
  "fwVersion": "1.4.2",
  "location": {
    "latitude": 37.7749,
    "longitude": -122.4194
  }
}
```

<Steps>
1. Go to **Integrations &#8702; Data converters** and click **+ Add data converter &#8702; Create new converter**.
2. **Converter type** — keep **Uplink**.
3. **Integration type** — select **AWS IoT**.
4. **Name** — enter a name, for example `AWS IoT Uplink Converter`.
5. **Main decoding configuration** — the editor opens with the default AWS IoT template. Replace it with the decoder below. The decoder takes the device name and type from the last two topic segments (`.../{deviceType}/{deviceName}`), so it works for any topic depth. The editor opens in TBEL; use the **TBEL / JS** toggle to switch to JavaScript.
   <Aside type="tip" title="TBEL">
     Use <DocLink product={props.product} path="user-guide/tbel" target="_blank">TBEL</DocLink> for converter scripts — it runs much faster than JavaScript inside ThingsBoard.
   </Aside>
   <Tabs>
     <TabItem label="TBEL (Recommended)">
       ```js maxLines=15 collapsible
       // Device type and name are the last two topic segments:
       //   tb/aws/iot/sensors/freezer-432
       //              ^^^^^^^ ^^^^^^^^^^
       //              type    name
       var topicParts = metadata.topic.split("/");
       var n = topicParts.length;

       // Fall back to fixed values if the topic is too short.
       var deviceName = n > 0 ? topicParts[n - 1] : "AWS IoT Device";
       var deviceType = n > 1 ? topicParts[n - 2] : "default";

       // Decode the payload to a JSON object.
       var data = decodeToJson(payload);

       // Use the device timestamp if present; otherwise, the server time.
       var ts = data.ts != null ? data.ts : Date.now();

       // Device properties become attributes.
       var attributes = {
           fwVersion: data.fwVersion
       };

       if (data.location != null) {
           attributes.latitude = data.location.latitude;
           attributes.longitude = data.location.longitude;
       }

       // Measurements become telemetry.
       var telemetry = {
           temperature: data.temperature,
           humidity: data.humidity,
           battery: data.battery
       };

       return {
           deviceName: deviceName,
           deviceType: deviceType,
           attributes: attributes,
           telemetry: {
               ts: ts,
               values: telemetry
           }
       };
       ```
     </TabItem>
     <TabItem label="JavaScript">
       ```js maxLines=15 collapsible
       // Device type and name are the last two topic segments:
       //   tb/aws/iot/sensors/freezer-432
       //              ^^^^^^^ ^^^^^^^^^^
       //              type    name
       var topicParts = metadata.topic.split("/");
       var n = topicParts.length;

       // Fall back to fixed values if the topic is too short.
       var deviceName = n > 0 ? topicParts[n - 1] : "AWS IoT Device";
       var deviceType = n > 1 ? topicParts[n - 2] : "default";

       // Decode the payload to a JSON object.
       var data = decodeToJson(payload);

       // Use the device timestamp if present; otherwise, the server time.
       var ts = data.ts != null ? data.ts : Date.now();

       // Device properties become attributes.
       var attributes = {
           fwVersion: data.fwVersion
       };

       if (data.location != null) {
           attributes.latitude = data.location.latitude;
           attributes.longitude = data.location.longitude;
       }

       // Measurements become telemetry.
       var telemetry = {
           temperature: data.temperature,
           humidity: data.humidity,
           battery: data.battery
       };

       var result = {
           deviceName: deviceName,
           deviceType: deviceType,
           attributes: attributes,
           telemetry: {
               ts: ts,
               values: telemetry
           }
       };

       // Convert the byte array to a string.
       function decodeToString(payload) {
           return String.fromCharCode.apply(String, payload);
       }

       // Convert the byte array to a JSON object.
       function decodeToJson(payload) {
           return JSON.parse(decodeToString(payload));
       }

       return result;
       ```
     </TabItem>
   </Tabs>

   **To adapt:**

   - **Other topic structure** — change the indexes in `topicParts[n - 1]` and `topicParts[n - 2]`.
   - **Device name in the payload** — use a payload field instead, for example `data.deviceId`.
   - **Other telemetry** — add or remove keys in `telemetry`, for example `pressure: data.pressure`.
   - **Other device properties** — add them to `attributes`, for example `model: data.model`.
   - **Update-only keys** — in **Advanced decoding parameters**, add keys to the **Update only keys list** to store them only when their value changes, for example `fwVersion`.
6. Click **Test decoder function** and check the result (see **[Test the Decoder](#test-the-decoder)**).
7. Click **Add**.
</Steps>

<h4>Decoder Inputs</h4>

The decoder signature is `function decoder(payload, metadata): object | object[]`.

| Variable | Type | Content |
|----------|------|---------|
| `payload` | byte array | The MQTT message body. |
| `metadata` | `{[key: string]: string}` | `topic` — the topic the message arrived on, for example `tb/aws/iot/sensors/freezer-432`. Also `integrationName` and the key–value pairs from the integration's **Metadata** field. |

With a wildcard topic filter, `topic` holds the actual topic of the message, not the filter.

For field renaming, nested values, and non-JSON payloads, see <DocLink product={props.product} path="user-guide/integrations/uplink-data-converter/#common-scripting-patterns" target="_blank">Common scripting patterns</DocLink>.

### Create the Integration

<Steps>
1. Go to **Integrations &#8702; Integrations** and click **+ Add integration**.
2. **Basic settings:**
   - **Integration type** — select **AWS IoT**.
   - **Name** — enter a name, for example `AWS IoT integration`.
   - **Enable integration** and **Allow create devices or assets** — keep both on, so the device is created on its first uplink.
   - Click **Next**.
3. **Uplink data converter:**
   - Click **Select existing** and choose `AWS IoT Uplink Converter`.
   - Alternatively, click **Create new** to write a decoder here.
   - Click **Next**.
4. **Downlink data converter:**
   - Click **Skip**. Add a downlink converter later if you need to **[send commands to devices](#configure-downlink)**.
5. **Connection:**
   - **AWS IoT Endpoint** — paste the device data endpoint.
   - **CA certificate file**, **Certificate file**, **Private key file** — upload `AmazonRootCA1.pem`, the `*.pem.crt` certificate, and the `*-private.pem.key` key. See **[Credentials](#credentials)**.
   - **Topic filters** — replace the default `#` with `tb/aws/iot/#`.
   - Leave the other parameters at their defaults. See **[Connection Settings](#connection-settings)** for details.
6. Click **Add**.
</Steps>

#### Connection Settings

ThingsBoard always connects to AWS IoT Core on port `8883` over TLS, with a clean session.

| Parameter | Description |
|-----------|-------------|
| **AWS IoT Endpoint** | Device data endpoint, in the form `{prefix}-ats.iot.{region}.amazonaws.com`. Required. |
| **Credentials** | Certificate files for mutual TLS. See **[Credentials](#credentials)**. |
| **Topic filters** | One or more subscriptions, each with a **Topic** and **QoS**. Default: `#` with QoS `0`. Click **Add topic filter** to add more. See **[Topic Filters](#topic-filters)**. |
| **Execute remotely** | Runs the integration as a separate process outside the ThingsBoard cluster. ThingsBoard generates an **Integration key** and **Integration secret** for it. See <DocLink product={props.product} path="user-guide/integrations/remote" target="_blank">Remote Integration</DocLink>. |

**Advanced settings**

| Parameter | Default | Description |
|-----------|---------|-------------|
| **Protocol version** | MQTT 3.1.1 | `MQTT 3.1`, `MQTT 3.1.1`, or `MQTT 5.0`. AWS IoT Core supports 3.1.1 and 5.0. |
| **Client ID** | empty | Empty: an ID is generated. A custom ID must be unique — AWS IoT Core disconnects a client when another one connects with the same ID. |
| **Max bytes in message** | `32368` | Maximum size of an incoming message, in bytes (1–256,000,000). AWS IoT Core itself limits messages to 128 KB. |
| **Connection timeout (sec)** | `10` | Time to wait for AWS IoT Core to accept the connection (1–200). |
| **Downlink topic pattern** | `${topic}` | Topic for downlink messages. Each `${key}` is replaced with the value of `key` from the downlink converter's output `metadata`. |
| **Description** | — | Free-text description. |
| **Metadata** | — | Key–value pairs added to the `metadata` of every message from this integration. |

#### Credentials

AWS IoT Integration supports only certificate (PEM) credentials. Upload each file (**Browse file**) or take it from <DocLink product={props.product} path="user-guide/security/secrets-storage" target="_blank">Secrets storage</DocLink>.

| Field | File |
|-------|------|
| **CA certificate file** | `AmazonRootCA1.pem`. Verifies AWS IoT Core. |
| **Certificate file** | Device certificate, `*.pem.crt`. |
| **Private key file** | Private key, `*-private.pem.key`. |
| **Private key password** | Only for an encrypted key. Keys generated by AWS are not encrypted; leave it empty. |

The certificate must be **Active** and have the policy attached. See <a href="https://docs.aws.amazon.com/iot/latest/developerguide/x509-client-certs.html" target="_blank" rel="noopener noreferrer"><strong>X.509 client certificates</strong></a>.

#### Topic Filters

The integration subscribes to all topic filters when it connects. Subscribe to a dedicated namespace rather than `#`, so the integration receives only ThingsBoard traffic.

| Wildcard | Matches | Example filter | Matching topics |
|----------|---------|----------------|-----------------|
| `+` | One level | `tb/aws/iot/+/freezer-432` | `tb/aws/iot/sensors/freezer-432`, `tb/aws/iot/meters/freezer-432` |
| `#` | All remaining levels; must be last | `tb/aws/iot/#` | `tb/aws/iot/sensors/freezer-432`, `tb/aws/iot/meters/meter-01` |

| QoS | Name | Delivery |
|-----|------|----------|
| `0` | At most once | No acknowledgment. A message may be lost. |
| `1` | At least once | Acknowledged. A message may arrive twice. |

AWS IoT Core does not support QoS 2, so the integration does not offer it. See <a href="https://docs.aws.amazon.com/iot/latest/developerguide/topics.html" target="_blank" rel="noopener noreferrer"><strong>MQTT topics</strong></a>.

## Configure Downlink

ThingsBoard publishes downlinks to AWS IoT Core when the Rule Engine routes a message to the integration — for example, after a shared attribute update. Downlinks are always published with QoS 1. The topic comes from the **Downlink topic pattern**: with the default `${topic}`, it is the `topic` value in the downlink converter's output `metadata`.

The downlink converter turns a <DocLink product={props.product} path="user-guide/rule-engine" target="_blank">Rule Engine</DocLink> message into an MQTT payload. For the full encoder reference, see <DocLink product={props.product} path="user-guide/integrations/downlink-data-converter" target="_blank">Downlink data converter</DocLink>.

### Create and Assign the Downlink Converter

The encoder returns:

- `contentType` — `JSON`, `TEXT`, or `BINARY`.
- `data` — the payload to publish.
- `metadata` — values for the **Downlink topic pattern** placeholders, for example `topic`.

For RPC commands, `msg.method` and `msg.params` are available. `msg.params` is a string — use `parseFloat(msg.params)` or `JSON.parse(msg.params)` to get a number or an object.

<Steps>
1. Open the integration in **Integrations &#8702; Integrations** and click **Toggle edit mode** (pencil icon).
2. In the **Downlink data converter** field, click **Create new**. The **Downlink** converter type and **AWS IoT** integration type are preselected.
3. Enter a name, for example `AWS IoT Downlink Converter`.
4. In **Main encoding configuration**, replace the default encoder with the one below, or write your own.
5. To record downlink events, click the debug icon next to the name, select **All messages**, and click **Apply**.
6. Click **Add**, then **Apply changes**.
</Steps>

Encoder used in this guide (TBEL and JavaScript):

```js
/** Encoder **/
// Publish the ThingsBoard message as JSON to the device command topic.
// metadata.topic is read by the integration when Downlink topic pattern is ${topic}.

var result = {
  // Specify the downlink payload format: JSON, TEXT, or BINARY.
  contentType: "JSON",

  // Serialize the incoming message and use it as the MQTT payload.
  data: JSON.stringify(msg),

  // Build a per-device command topic in the same namespace as the uplink.
  metadata: {
    topic: 'tb/aws/iot/commands/' + metadata['deviceName']
  }
};

return result;
```

**To adapt:**

- **Other payload** — build the object the device expects instead of `msg`, for example `{ "interval": msg.temperatureUploadFrequency }`.
- **Non-JSON payload** — set `contentType` to `TEXT` for a plain string, or `BINARY` with a Base64-encoded string.
- **Other message types** — branch on `msgType` to handle other <DocLink product={props.product} path="reference/rule-engine/message-types" target="_blank">Rule Engine message types</DocLink>.

### Configure the Root Rule Chain

The encoder builds the topic from `deviceName`, so the rule chain first adds the device name to the message metadata.

<Steps>
1. Go to **Data processing &#8702; Rule chains** and open the **Root Rule Chain**.
2. From the **Enrichment** section, drag an **originator fields** node onto the canvas.
3. Enter a **Name** (for example, `Retrieve device name`) and map the source fields:
   - **Name &#8702; deviceName**
   - **Add mapped originator fields to &#8702; Metadata**
   - Click **Add**.
4. Connect the **message type switch** node to the **originator fields** node with the **Attributes Updated** relation.
5. From the **Action** section, drag an **integration downlink** node onto the canvas.
6. Enter a **Name** (for example, `Downlink to AWS IoT integration`), select your AWS IoT integration, and click **Add**.
7. Connect the **originator fields** node to the **integration downlink** node with the **Success** relation.
8. Click **Apply changes**.
</Steps>

### Test Downlink

Subscribe to the command topic, then update a shared attribute to trigger a downlink.

<Steps>
1. In the AWS IoT console, go to **Test &#8702; MQTT test client**, open the **Subscribe to a topic** tab, enter `tb/aws/iot/commands/#`, and click **Subscribe**.
2. In ThingsBoard, go to **Devices & assets &#8702; Devices**, select `freezer-432`, and open the **Attributes** tab.
3. Select **Shared attributes** and click **+**.
4. Set **Key** to `temperatureUploadFrequency`, **Type** to **Integer**, **Value** to `60`, and click **Add**. ThingsBoard publishes the downlink.
</Steps>

## Troubleshooting

| Symptom | Cause | Fix |
|---------|-------|-----|
| Integration is disconnected | Wrong **AWS IoT Endpoint**. | Copy the endpoint again from **Settings &#8702; Device data endpoint**. |
| Same, with correct endpoint | The certificate and private key do not belong together, or the CA file is wrong. | Upload the certificate and key downloaded for the same thing, and `AmazonRootCA1.pem` as the CA file. |
| Same, with correct files | The certificate is inactive or has no policy, or the policy denies `iot:Connect`. | In the AWS IoT console, check that the certificate is **Active** and that the policy is attached and allows `iot:Connect`. |
| Same, on a self-hosted server | Outbound port `8883` is blocked. | Open TCP `8883` to AWS IoT Core, or use a <DocLink product={props.product} path="user-guide/integrations/remote" target="_blank">Remote Integration</DocLink>. |
| Connection keeps dropping | Another client uses the same **Client ID**. | Clear **Client ID** to get a generated one, or make it unique. |
| No messages received | No topic filter matches the published topic, or the policy denies `iot:Subscribe` or `iot:Receive`. | Check the topic filters and the policy resources. `tb/aws/iot/#` matches `tb/aws/iot/sensors/freezer-432`. |
| Decoder error | The test or message has no `topic`, or the payload is not JSON. | Open the converter's **Events** tab and read the **Error** column. In the test dialog, add the `topic` metadata row. |
| Device not created | `deviceName` is empty or undefined. | Check **Out** in the converter events. |
| Large messages missing | The message exceeds **Max bytes in message**. | Raise the limit in **Advanced settings** (AWS IoT Core allows up to 128 KB). |
| Downlink not received | The rule chain does not reach the **integration downlink** node, or the topic differs from the subscription. | Check the Root Rule Chain wiring and the topic in the integration's **Events**. Check that the policy allows `iot:Publish` on that topic. |
| Downlink topic ends in `null` or `undefined` | The message metadata has no `deviceName`. | Add the **originator fields** node before the **integration downlink** node. |

To read debug events, open the integration or converter, click **Events**, and select an event: **In** is the received data, **Out** is the converter result, and **Error** holds the error text.

ThingsBoard OTA (Over-the-Air) updates let you push firmware and software packages to devices remotely. You upload a package once, assign it to a device profile or individual device, and ThingsBoard notifies all affected devices and tracks each one's update progress.

## Firmware vs. Software

ThingsBoard supports two package types — **Firmware** (FOTA) and **Software** (SOTA). The distinction matters mainly for LwM2M devices, which handle the two types through different protocol objects. For MQTT, HTTP, and CoAP devices the update flow is identical regardless of type.

## Uploading a Package

Navigate to **Advanced features &#8702; OTA updates** and click **+ Add package**.  
Required fields:

| Field | Description |
|-------|-------------|
| **Title** | Package name. Title + version must be unique per tenant. |
| **Version** | Package version string. |
| **Device Profile** | Limits this package to compatible devices only. |
| **Type** | Firmware or Software. |
| **Checksum** | Optional. Defaults to SHA-256 if omitted. |

<Aside type="caution">
  A package cannot be deleted while it is assigned to any device or device profile.
</Aside>

## Assigning Updates

### To a Device Profile

<ShowFor product={props.product} show={[Products.CE, Products.PE]}>By default, ThingsBoard sends 100 device notifications per 60 seconds, controlled by `TB_QUEUE_CORE_OTA_PACK_SIZE` and `TB_QUEUE_CORE_OTA_PACK_INTERVAL_MS`. Total rollout time is `(device count / pack size) × pack interval`. With the default settings, a rollout to 1,000 devices takes about (1,000 / 100) × 60 s, or 10 minutes.</ShowFor>

<ShowFor product={props.product} show={[Products.PAAS, Products.PAAS_EU]}>ThingsBoard paces notifications at a fixed rate. For fleets of 1,000 devices or more, a rollout can take several minutes to complete.</ShowFor>

### To an Individual Device

A per-device assignment overrides the profile assignment for that device only.

<ImageGallery images={[{ src: '/src/assets/schemas/assigning-to-device.svg', alt: 'Assigning firmware to an individual device', caption: 'A per-device firmware assignment overrides the profile-level assignment. When the profile is updated later, the device with a direct assignment keeps its own firmware version.' }]} />

<Aside type="note">
  Customers can select available firmware for their devices but cannot upload or manage packages.
</Aside>

## Update Flow

<ImageGallery images={[{ src: '/src/assets/schemas/ota-update-flow.svg', alt: 'OTA update flow diagram', caption: 'ThingsBoard pushes firmware metadata via shared attributes. The device downloads the package, verifies the checksum, applies the update, and reports state transitions back to the platform.' }]} />

States up to **INITIATED** are set by ThingsBoard. All subsequent states are reported by the device firmware.

## Update States

| State | Set by | Meaning |
|-------|--------|---------|
| `QUEUED` | ThingsBoard | Notification waiting to be pushed |
| `INITIATED` | ThingsBoard | Shared attributes updated; device notified |
| `DOWNLOADING` | Device | Download started |
| `DOWNLOADED` | Device | Download complete |
| `VERIFIED` | Device | Checksum passed |
| `UPDATING` | Device | Applying update (device may reboot) |
| `UPDATED` | Device | Update successful |
| `FAILED` | Device | Download, checksum, or apply error |

## Monitoring

ThingsBoard includes built-in **Firmware** and **Software** dashboards (auto-created for new tenants; importable from GitHub for existing ones). They show the update status of every device, historical records, and failure details.

<Aside type="tip">
  See **OTA Dashboards** for import instructions and dashboard customisation.
</Aside>

## Package size limits

<ShowFor product={props.product} show={[Products.CE, Products.PE]}>

- **Upload size** — a single package upload is limited to **16 MB** by default. System administrators can change this limit using the `HTTP_MAX_PAYLOAD_SIZE_LIMIT_CONFIGURATION` environment variable — a semicolon-separated list of `URL pattern=limit in bytes` entries. For example, `/api/otaPackage/**=209715200` allows OTA uploads up to 200 MB.
- **Storage ceiling** — a single package stored in the database cannot exceed **2 GB**, regardless of the upload limit. This ceiling is not configurable.
- **Per-tenant total** — the combined size of all OTA packages per tenant is controlled by the **Maximum sum of data size of all OTA packages** limit in the <DocLink product={props.product} path="user-guide/tenant-profiles">tenant profile</DocLink> (`0` means unlimited, which is the default).

</ShowFor>
<ShowFor product={props.product} show={[Products.PAAS, Products.PAAS_EU]}>

- **Upload size** — a single OTA package upload is limited to **50 MB**.
- **Per-tenant total** — the combined size of all uploaded OTA packages is limited by your subscription plan, from 512 MB on the Free plan up to 4 GB on the Business plan. See <DocLink product={props.product} path="reference/subscriptions/#file-storage-limits">Subscription Plans, File storage limits</DocLink> for the quota on each plan.

ThingsBoard Agent upgrades applications remotely, following the step sequence defined by the application <DocLink product={props.product} path='user-guide/agents/application-profiles#templates'>template</DocLink>. Upgrades support volume backups and roll back automatically when a step fails.

## Upgrade an application

<Steps>
  <ol>
    <li>
      In the agent's **Applications** table, click **Upgrade** on the application row. The **Upgrade Application** wizard opens.
    </li>
    <li>
      If the linked application profile still points at the previous template version, the wizard offers an **Upgrade Profile** step first. Upgrade the profile, or proceed without it.
    </li>
    <li>
      On the **Review Changes** step, compare the new template version with your current Docker Compose configuration. ThingsBoard auto-merges the new images into your configuration and shows both side by side.
    </li>
    <li>
      On the **Configure & Confirm** step, review the upgrade steps and select the volumes to back up before the upgrade, then confirm.
    </li>
    <li>
      Track progress in the **Event progress** dialog or on the **Events** tab.
    </li>
  </ol>
</Steps>

<Aside type="tip">
Back up the volumes that hold your application data. Backups allow automatic rollback if the upgrade fails. After a successful upgrade, the agent keeps the latest backup of each volume and removes older ones.
</Aside>

## Automatic rollback

Before an upgrade or update starts, the agent snapshots the current state of the application. If any step fails:

1. The agent restores the backed-up volumes.
2. The agent recreates the containers from the snapshot, returning the application to its previous version.
3. The event is marked as failed with the error reported by the failing step.

Rollback is idempotent: if the agent restarts mid-rollback, it resumes without repeating completed work.

## ThingsBoard Edge upgrades

For Edge applications, the template defines a multi-step flow that upgrades the Edge database safely:

1. Stop the application.
2. Back up the selected volumes.
3. Update the database service if the new version requires it.
4. Run the ThingsBoard Edge database upgrade job.
5. Start the upgraded application.
6. Clean up old backups after success, keeping the latest one per volume.

### PostgreSQL major version migration

If the new Edge version bumps PostgreSQL to a new major version, the agent migrates the database automatically: it detects the version change from the data volume, backs the volume up, dumps the database with the old version's image, and restores it with the new one. The migration is crash-resumable and rolls back with the rest of the upgrade on failure.

The agent refuses to migrate and fails the upgrade with an actionable error when the change is a downgrade or when the database data directory is bind-mounted from the host instead of a named volume.

## Gateway and generic upgrades

For Gateway and Generic applications, an upgrade applies the new template version's Docker Compose configuration: the agent pulls the new images and recreates the project's containers. Volume backup and automatic rollback work the same way.

## Upgrade a fleet

To upgrade every application that shares an application profile across many agents, use a <DocLink product={props.product} path='user-guide/agents/bulk-actions'>bulk upgrade</DocLink>.

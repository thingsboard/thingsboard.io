**Bulk actions** apply one operation to every application that matches an application profile across a fleet of agents. Use them to restart, update, upgrade, or delete hundreds of deployments with one command: like pushing a new ThingsBoard Edge version to all customer sites at once.

A bulk action targets all applications that match a selected <DocLink product={props.product} path='user-guide/agents/application-profiles'>application profile</DocLink> and whose agent uses the selected <DocLink product={props.product} path='user-guide/agents/agent-profiles'>agent profile</DocLink>.

## Run a bulk action

<Steps>
  <ol>
    <li>
      Go to **Edge management > Profiles > Agent profiles**, open the agent profile, and switch to the **Application profiles & bulk actions** tab.
    </li>
    <li>
      On the application profile row, open the **Bulk actions** menu and select **Bulk Restart**, **Bulk Update**, **Bulk Upgrade**, or **Bulk Delete**.
    </li>
    <li>
      Configure the operation. Depending on the action, select the volumes to back up, the image pull policy, or whether to remove volumes on delete.
    </li>
    <li>
      Review the preview and click **Restart all**, **Update all**, **Upgrade all**, or **Delete all**.
    </li>
  </ol>
</Steps>

<Aside type="danger">
**Bulk Delete** preserves application volumes by default. If you select volume removal, the volumes and all application data are permanently destroyed on every targeted host.
</Aside>

## Preview

Before submission, ThingsBoard evaluates every candidate application and shows the totals: **Total apps**, **Eligible**, and **Skipped**. Applications are skipped with a reason:

- **Template version mismatch:** The application's template version does not match the profile. Upgrade it individually first.
- **Another operation already running:** The application has an event in progress.
- **Event rate limit exceeded:** The tenant's agent event rate limit blocks new events. Retry later.
- **Error while evaluating app:** The application could not be evaluated.

Only eligible applications receive the operation; skipped ones are left untouched.

## Monitor execution

Each targeted application gets its own event, executed and rolled back independently: a failure on one host never affects the others.

- The **Recent bulk actions** panel under the application profile row lists past runs with their status: **Queued**, **In Progress**, **Started**, or **Start Failed**.
- The **Executions** panel summarizes progress as the number of agents reporting success out of the total.
- **Open full details** opens the bulk action details page with the complete list of per-application events, including errors.

## Rate limits

Agent events are rate-limited per tenant and per agent. Large fleets are processed within these limits; applications skipped due to rate limiting can be retried once the limit window passes. A tenant administrator can review the limits in the tenant profile configuration.

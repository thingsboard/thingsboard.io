**ThingsBoard Agent** is a remote Docker container manager for ThingsBoard Professional Edition and ThingsBoard Cloud. The agent runs as a Docker container on a remote host, connects to your ThingsBoard server, and manages Docker Compose applications on that host. You deploy, update, upgrade, and restart these applications from the ThingsBoard UI, monitor their state, and watch live container logs, without SSH access to the machine.

Use the agent to:

- **Install and upgrade ThingsBoard Edge remotely.** Deploy <DocLink product={Products.EDGE_PE} path='installation/agent'>Edge instances</DocLink> on customer sites and push upgrades from the cloud, including automatic database migration, volume backups, and rollback on failure.
- **Deploy and manage IoT Gateways.** <DocLink product={Products.GW} path='installation/agent-installation'>Install gateways</DocLink> on remote machines and keep them updated without manual Docker commands.
- **Run any Docker Compose application.** The Generic application type deploys custom Docker Compose projects: brokers, databases, or your own services.
- **Adopt existing deployments.** If Edge instances, gateways, or other Docker Compose applications already run on a host, the agent discovers and synchronizes them. Existing environments become manageable from ThingsBoard without redeploying anything.
- **Update fleets in bulk.** Restart, update, upgrade, or delete all applications that share an application profile across hundreds of agents with a single <DocLink product={props.product} path='user-guide/agents/bulk-actions'>bulk action</DocLink>.

## How it works

The agent opens an outbound gRPC stream to the ThingsBoard server and authenticates with a routing key and secret. The server sends step-based commands over this stream; the agent executes them against the local Docker Engine and reports acknowledgment, progress, and results for every step.

Every command step is idempotent: completed steps are persisted on the agent, so network retries, reconnects, and agent restarts never re-execute finished work. Operations that change an application are safe too: the agent backs up the selected volumes first, and if any step fails, it rolls the application back to its previous state. See <DocLink product={props.product} path='user-guide/agents/application-actions'>Application actions</DocLink>.

## Key concepts

| Concept | Description |
|---|---|
| <DocLink product={props.product} path='user-guide/agents/installation'>Agent</DocLink> | A ThingsBoard entity that represents one `tb-agent` container running on a remote host. Authenticates with a routing key and secret. |

## Monitoring

A connected agent continuously reports:

- **Status:** Online or Offline, shown in the Agents table.
- **Host metrics:** CPU, memory, and disk usage of the host.
- **Application metrics:** CPU, memory, and volume usage per <DocLink product={props.product} path='user-guide/agents/applications'>application</DocLink> and per container.
- **State:** container states, image digests, and the current Docker Compose configuration of every managed project.
- **Logs:** live container logs, streamed on demand to the <DocLink product={props.product} path='user-guide/agents/applications#view-container-logs'>log viewer</DocLink>.

## Edge and Gateway upgrade tracking

ThingsBoard has native upgrade support for ThingsBoard Edge and IoT Gateway applications. The server periodically syncs application <DocLink product={props.product} path='user-guide/agents/application-profiles#templates'>templates</DocLink> from a public GitHub repository, so new product versions become available for upgrade without a platform update. When a deployed application falls behind the latest template version, ThingsBoard marks it with an **Upgrade available** chip in the **Applications** table, on its application profile, and on the linked ThingsBoard Edge entity. From there, a single <DocLink product={props.product} path='user-guide/agents/application-actions#upgrade-an-application'>upgrade</DocLink> action moves the application to the new version, with volume backups and automatic rollback. A <DocLink product={props.product} path='user-guide/agents/bulk-actions'>bulk upgrade</DocLink> propagates one upgrade to every host that runs the application profile.

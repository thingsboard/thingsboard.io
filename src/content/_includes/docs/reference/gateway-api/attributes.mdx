## Publish Client-Side Attributes

Upload client-side attributes for one or more devices.

**Topic:** `v1/gateway/attributes`

```json
{
  "Device A": {"fw_version": "1.0", "battery": 87},
  "Device B": {"fw_version": "2.1", "battery": 92}
}
```

<ShowFor product={props.product} show={[Products.CE, Products.PE]}>

Replace `GATEWAY_DEVICE_ACCESS_TOKEN` in the commands below with the gateway device's access token, and `$THINGSBOARD_HOST` with your ThingsBoard instance's host.

</ShowFor>

<ShowFor product={props.product} show={[Products.PAAS, Products.PAAS_EU]}>

Replace `GATEWAY_DEVICE_ACCESS_TOKEN` in the commands below with the gateway device's access token.

</ShowFor>

<HostCode product={props.product} lang="bash" code={`mosquitto_pub -h "{MQTT_HOST}" -t "v1/gateway/attributes" -u "GATEWAY_DEVICE_ACCESS_TOKEN" -m '{"Device A":{"fw_version":"1.0","battery":87}}'`} />

## Request Attribute Values

Subscribe to the response topic first, then publish the request.

**Subscribe:** `v1/gateway/attributes/response`

**Publish:** `v1/gateway/attributes/request`

| Field | Required | Description |
|-------|----------|-------------|
| `id` | Yes | Integer request identifier — echoed in the response |
| `device` | Yes | Device name |
| `keys` | Yes | Array of attribute keys to return |
| `client` | Yes | Boolean flag: set to `true` to request client-side attributes, or `false` to request shared attributes |

<Tabs>
<TabItem label="Client">

```json
{
  "id": 1,
  "device": "Device A",
  "keys": ["fw_version", "battery"],
  "client": true
}
```

</TabItem>
<TabItem label="Shared">

```json
{
  "id": 1,
  "device": "Device A",
  "keys": ["state", "level"],
  "client": false
}
```

</TabItem>
</Tabs>

**Example:**

The gateway keeps a single MQTT connection open per device, so use <a href="https://mosquitto.org/man/mosquitto_rr-1.html" target="_blank" rel="noopener noreferrer"><code>mosquitto_rr</code></a>: it subscribes, publishes the request, and waits for the response over that one connection, matching the request/response pattern this API expects.

<ShowFor product={props.product} show={[Products.CE, Products.PE]}>

Replace `GATEWAY_DEVICE_ACCESS_TOKEN` in the commands below with the gateway device's access token, and `$THINGSBOARD_HOST` with your ThingsBoard instance's host.

</ShowFor>

<ShowFor product={props.product} show={[Products.PAAS, Products.PAAS_EU]}>

Replace `GATEWAY_DEVICE_ACCESS_TOKEN` in the commands below with the gateway device's access token.

</ShowFor>

<Tabs>
<TabItem label="Requesting client attributes">

<HostCode product={props.product} lang="bash" code={`mosquitto_rr -d -q 1 -h "{MQTT_HOST}" -p 1883 -t "v1/gateway/attributes/request" -e "v1/gateway/attributes/response" -u "GATEWAY_DEVICE_ACCESS_TOKEN" -m '{"id":1,"device":"Device A","keys":["fw_version","battery"],"client":true}'`} />

</TabItem>
<TabItem label="Requesting shared attributes">

<HostCode product={props.product} lang="bash" code={`mosquitto_rr -d -q 1 -h "{MQTT_HOST}" -p 1883 -t "v1/gateway/attributes/request" -e "v1/gateway/attributes/response" -u "GATEWAY_DEVICE_ACCESS_TOKEN" -m '{"id":1,"device":"Device A","keys":["state","level"],"client":false}'`} />

</TabItem>
</Tabs>

<Aside type="note">
`Device A` must already exist and have the requested attributes (client-side or shared, matching the tab you use) — otherwise the response will not contain any values.
</Aside>

## Subscribe to Shared Attribute Updates

Subscribe to receive push notifications when shared attributes change for any downstream device.

**Topic:** `v1/gateway/attributes` (subscribe)

<HostCode product={props.product} lang="bash" code={`mosquitto_sub -h "{MQTT_HOST}" -t "v1/gateway/attributes" -u "$ACCESS_TOKEN"`} />

ThingsBoard delivers updates in this format:

```json
{
  "device": "Device A",
  "data": {"targetFwVersion": "2.0", "enabled": true}
}
```

The **Alarms table** widget displays a real-time list of alarms for your entities in a tabular format. Each row shows the alarm's originator, type, severity, status, and assignee. The table updates automatically as alarms are created, acknowledged, cleared, or assigned — making it the primary tool for alarm monitoring on ThingsBoard dashboards.

## Adding an Alarms table widget

<Steps>
1. In dashboard edit mode, click the **Add widget** button at the top of the screen, or click the large **Add new widget** icon in the center of the screen.
2. In the widget bundle selection dialog, find and click on **Alarm widgets**.
3. Select the **Alarms table** widget.
4. Configure the data source, filters, and appearance, then click **Add**.
</Steps>

## Configuration

In the "basic" widget editor, the settings are grouped into: **Time window**, **Alarm source**, **Filter**, **Columns**, **Appearance**, **Table buttons**, **Card appearance**, and **Actions**.

### Time window

Set the time range for which alarms are displayed — for example, **Realtime – last 30 days** or a fixed date interval.
A widget can use its own time window or inherit the dashboard's time window value.
Learn more in the <DocLink product={props.product} path="user-guide/time-window/" bold={false} target="_blank">Time Window</DocLink> guide.

### Alarm source

Select the entity or alias that alarms are loaded from.

- **Device** — load alarms from a specific device.
- **Entity alias** — load alarms for a group of entities defined by an <DocLink product={props.product} path="user-guide/aliases" bold={false}>alias</DocLink>. Use this to monitor multiple devices or assets at once.

### Filter

The **Filter** section controls which alarms appear in the table. Multiple criteria can be combined.

| Filter | Description |
|--------|-------------|
| **Alarm status list** | Show only alarms with the selected statuses: **Active**, **Cleared**, **Acknowledged**, **Unacknowledged**. |
| **Alarm severity list** | Show only alarms at the selected severity levels: **Critical**, **Major**, **Minor**, **Warning**, **Indeterminate**. |
| **Alarm type list** | Restrict display to selected alarm types (e.g., *High temperature*, *Device offline*). The list is populated from alarm types present in the system. |
| **Assignee** | Show only alarms assigned to a specific user. |
| **Search propagated alarms** | When enabled, includes alarms propagated from child entities (e.g., a device alarm surfacing on its parent asset). |

### Columns

The **Columns** section defines the alarm fields shown as table columns. The default columns are: **Created time**, **Originator**, **Type**, **Severity**, **Status**, and **Assignee**.

Each column entry has a **key** (the alarm field name) and a **label** (the column header text). Reorder columns by dragging, remove them with the delete icon, and add new ones with **Add column**.

#### Column settings

Click the **gear icon** on a column to open the **Data key configuration** dialog. It has two tabs: **General** and **Advanced**.

**General** — set the field key and the column header label.

**Advanced** — fine-tune column behavior:

| Setting | Description |
|---------|-------------|
| **Custom header title** | Override the column header with a custom label. |
| **Column width** | Fixed width in pixels or percent (`0px` = auto). |
| **Default column visibility** | **Visible** — always shown; **Hidden** — hidden by default; **Hidden in mobile mode** — hidden on small screens. |
| **Column selection in 'Columns to Display'** | **Enabled** — user can toggle this column via the toolbar; **Disabled** — always shown. |
| **Include column in export** | **Always**, **Only if column visible**, or **Never**. |
| **Disable sorting** | Prevents sorting the table by this column. |
| **Use cell style function** | A JavaScript function `f(value, alarm, ctx)` that returns a CSS style object for the cell. |
| **Use cell content function** | A JavaScript function `f(value, alarm, ctx)` that returns custom HTML for the cell. Enable **Use cell content function on export** to also apply it to exported data. |

### Appearance

Set the widget **Card title** and **Card icon** displayed in the widget header.

### Table buttons

**Table buttons** add per-row action controls displayed as icons at the end of each alarm row.

| Button | Description |
|--------|-------------|
| **Display alarm activity** | Opens the alarm activity log — a timeline of lifecycle events (creation, acknowledgment, clearing, comments). |
| **Display alarm details** | Opens the alarm details panel with all metadata: originator, severity, type, status, duration, and assignee. |
| **Allow alarms assignment** | Enables assigning the alarm to a user directly from the row. |
| **Allow alarms acknowledgment** | Adds a one-click acknowledge button to each row. |
| **Allow alarms clear** | Adds a one-click clear button to each row. |

### Card appearance

Controls the widget toolbar and card styling.

- **Show card buttons** — toggle individual toolbar buttons: **Search** (filter rows by text), **Alarm filter** (filter by severity or status), **Columns to display** (show/hide individual columns), **Data export** (download table data), **Fullscreen** (expand the widget).
- **Text color** — sets the color of all text inside the widget.
- **Background color** — sets the widget card background color.

### Actions

The Alarms table supports <DocLink product={props.product} path="user-guide/actions" bold={false}>widget actions</DocLink> on the following sources:

- **Action cell button** — a custom button inside a specific table cell.
- **On cell click** — an action triggered when the user clicks a cell.
- **On row click** — an action triggered when the user clicks a row.
- **Widget header button** — a button added to the widget header bar.

## Alarm row actions

When the widget renders alarms, each row displays inline action buttons on the right side (controlled by the **Table buttons** settings).
- **Activity** — opens the alarm activity log where you can view the lifecycle history and add comments.
- **Details** — opens the alarm details panel with full alarm metadata, the assignee field, and the activity log.
- **Acknowledge** — marks the alarm as acknowledged, indicating that an operator has reviewed it. The alarm remains active until cleared.
- **Clear** — resolves the alarm and removes it from the active alarm list.

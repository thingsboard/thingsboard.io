The **Alarm count** widget displays the total number of alarms that match specific filter criteria — such as status, severity, type, or assignee. It provides a quick numerical summary of alarm conditions and is commonly placed alongside the <DocLink product={props.product} path="reference/widgets/alarm-widgets/alarms-table" bold={false}>Alarms table</DocLink> widget on monitoring dashboards.

## Adding an Alarm count widget

<Steps>
1. In dashboard edit mode, click the **Add widget** button at the top of the screen, or click the large **Add new widget** icon in the center of the screen.
2. In the widget bundle selection dialog, find and click on **Alarm widgets**.
3. Select the **Alarm count** widget.
4. Configure the data source, filters, and appearance, then click **Add**.
</Steps>

## Configuration

The widget is configured in the **Basic** tab of the widget editor. Settings are grouped into: **Datasource**, **Filter**, **Appearance**, **Card appearance**, and **Actions**.

### Datasource

Select the entity or <DocLink product={props.product} path="user-guide/aliases" bold={false}>alias</DocLink> whose alarms will be counted. If no datasource is configured, the widget counts alarms across all entities in the system, filtered by the criteria below.

### Filter

The **Filter** section controls which alarms are included in the count. Multiple criteria can be combined.

| Filter | Description |
|--------|-------------|
| **Alarm status list** | Count only alarms with the selected statuses: **Active**, **Cleared**, **Acknowledged**, **Unacknowledged**. |
| **Alarm severity list** | Count only alarms at the selected severity levels: **Critical**, **Major**, **Minor**, **Warning**, **Indeterminate**. |
| **Alarm type list** | Restrict count to selected alarm types (e.g., *High temperature*, *Device offline*). The list is populated from alarm types present in the system. |
| **Assignee** | Count only alarms assigned to a specific user. |
| **Search propagated alarms** | When enabled, includes alarms propagated from child entities (e.g., a device alarm surfacing on its parent asset). |

<Aside type="tip">
Combine multiple filters — for example, count only **Active**, **Critical** alarms assigned to a specific operator.
</Aside>

### Appearance

Customize how the widget looks on the dashboard.

| Setting | Description |
|---------|-------------|
| **Layout** | **Column** — stacks icon, value, and label vertically. **Row** — places icon and value side by side horizontally. |
| **Auto scale** | Automatically adjusts font sizes to fit the widget area. Useful when resizing the widget. |
| **Label** | Descriptive text shown on the card (e.g., *Total*, *Active*, *Critical*). |
| **Icon** | Icon representing the alarm category, with configurable size and color. |
| **Icon background** | Background color behind the icon. Use to communicate severity at a glance (e.g., red for Critical, orange for Major). |
| **Value** | Configure font and color for the displayed count. |
| **Chevron** | Adds a chevron (**›**) next to the value to indicate the card is clickable — pair with an **On card click** action. |

### Card appearance

| Setting | Description |
|---------|-------------|
| **Background** | Sets the card background color, gradient, or transparency. |
| **Show card buttons** | Toggle **Data export** and **Fullscreen** buttons in the widget header. |
| **Card border radius** | Controls how rounded the card corners are. |

### Actions

The Alarm count widget supports the following action sources:

- **On card click** — triggered when the user clicks anywhere on the widget card. Enable **Chevron** in the appearance settings to provide a visual click indicator.
- **Widget header button** — adds a custom button to the widget header bar.

## Examples

### Active alarms counter

**Scenario:** Display the total number of currently active alarms across all entities in the system.

<Steps>
1. Add the **Alarm count** widget — leave the datasource empty to count alarms across all entities.
2. **Filter:** set **Alarm status** to **Active**.
3. **Appearance:** set the label to *Active*.
4. Click **Add**, resize as needed, and click **Save** to apply.
</Steps>

The widget displays the live count of active alarms and updates automatically as alarm states change.

### Active critical alarms for a device type

**Scenario:** Show the number of active Critical alarms for all devices of type *smart sensor*.

<Aside type="note">
  An <DocLink product={props.product} path="user-guide/device-profiles" bold={false}>alarm rule</DocLink> for the *smart sensor* device profile must be configured before the widget can display any alarms.
</Aside>

<Steps>
1. Add the **Alarm count** widget.
2. **Datasource:** select **Entity alias**, then create or select an alias with **Filter type: Device type** and device type *smart sensor*.
3. **Filter:** set **Alarm status** to **Active** and **Alarm severity** to **Critical**.
4. **Appearance:** set **Layout** to **Row** and the label to *Critical*.
5. Click **Add**, resize as needed, and click **Save** to apply.
</Steps>

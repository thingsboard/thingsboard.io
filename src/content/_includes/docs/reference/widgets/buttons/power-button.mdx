The **Power button** widget controls devices and entities in ThingsBoard. It can execute RPC commands, update attributes, or log time series data, and reflects the current entity state visually through ON/OFF states.

## Adding the widget

<Steps>
1. Open the dashboard in edit mode. Click **Add widget** in the top toolbar, or click the **Add new widget** icon in the center of an empty dashboard.
2. In the widget bundle selection dialog, find and click **Buttons**.
3. Select the **Power button** widget.
4. Configure the datasource, behavior, and appearance, then click **Add**.
</Steps>

## Configuration

The widget configuration dialog has **Basic** and **Advanced** tabs. The **Basic** tab contains: **Target device**, **Behavior**, **Appearance**, **Card appearance**, and **Actions**.

### Target device

Select the <DocLink product={props.product} path="user-guide/widgets/#datasources" bold={false} target="_blank">datasource</DocLink> for the widget:

- **Device** — a specific device.
- **Entity alias** — entities matched by an <DocLink product={props.product} path="user-guide/aliases" bold={false} target="_blank">entity alias</DocLink>.

### Behavior

The **Behavior** section defines how the widget reads and changes device state. It has four sub-sections: **Initial state**, **Power 'On'**, **Power 'Off'**, and **Disabled state**.

#### Initial state

Defines how the widget determines its ON/OFF condition when the dashboard loads.

| Action | Parameters | Result converter | Notes |
|--------|-----------|-----------------|-------|
| **Do nothing** | **Value:** On / Off | — | Static predefined state. |
| **Execute RPC** | **Method:** e.g. `getState` | **None** — 'On' when result matches value; **Function** — `f(data)` → boolean | Advanced settings: RPC timeout (ms), RPC request persistent, Persistent polling interval (ms). |
| **Get attribute** | **Attribute scope:** Any / Client / Server / Shared; **Attribute key:** e.g. `state` | **None** or **Function** | Use for attributes storing device state. |
| **Get time series** | **Time series key:** e.g. `state` | **None** or **Function** | Use when state is stored as telemetry. |
| **Get alarm status** | **Alarm severity:** Critical / Major / Minor / Warning / Indeterminate; **Alarm types:** Any or selected | **None** or **Function** | ON when matching alarm is active. |
| **Get dashboard state id** | — | **None** — 'On' when state id matches value; **Function** — `f(data)` → boolean | Tie button state to dashboard navigation context. |
| **Get dashboard state object** | — | **Function required** — `f(data)` → boolean | React to complex multi-parameter dashboard states. |

#### Power 'On' action

Defines what happens when the user presses the button to turn ON.

| Action | Parameters | Advanced settings |
|--------|-----------|------------------|
| **Execute RPC** | **Method:** e.g. `setState`; **Parameters:** Constant (e.g. `true`) / Function `f(value)` → payload / None | RPC request timeout (ms); RPC request persistent |
| **Set attribute** | **Attribute scope:** Server / Shared; **Attribute key**; **Value:** Constant / Function `f(value)` | — |
| **Add time series** | **Time series key**; **Value:** Constant / Function `f(value)` | — |

#### Power 'Off' action

Mirrors the Power 'On' configuration. The same three action types are available — **Execute RPC**, **Set attribute**, and **Add time series** — with the same parameters, but using a value that represents the OFF state (e.g. `false`, `"OFF"`, `0`).

#### Disabled state

Defines when the button becomes non-clickable. Uses the same action types as **Initial state**. When the configured condition evaluates to `true`, the button renders as disabled and ignores user clicks.

### Appearance

| Setting | Description |
|---------|-------------|
| **Layout** | Button design variant: **Default**, **Simplified**, **Outlined** — each also available as a **Volume** variant (raised effect) and an **Icon** variant (icon only, no text label). |
| **Title** | Text label displayed above the button. |
| **Card icon** | Icon shown next to the title. |
| **Button icon 'On'** | Icon shown on the button in ON state. |
| **Button icon 'Off'** | Icon shown on the button in OFF state. |
| **Power 'On' colors** | **Main** — button fill color in ON state; **Background** — surrounding area color. |
| **Power 'Off' colors** | **Main** — button fill color in OFF state; **Background** — surrounding area color. |
| **Disabled colors** | **Main** — button fill color when disabled; **Background** — surrounding area color. |

### Card appearance

| Setting | Description |
|---------|-------------|
| **Background** | Card background color or image. |
| **Show card buttons** | **Fullscreen** — expand the widget to fullscreen mode. |
| **Card border radius** | Roundness of card corners. |
| **Card padding** | Spacing between the widget content and the card border. |

### Actions

The Power button widget supports the <DocLink product={props.product} path="user-guide/actions#widget-header-button" bold={false} target="_blank">Widget header button</DocLink> action — adds a button to the widget header that triggers a configured action when clicked.

## Example: Power control button for the ventilation relay

**Scenario:** A **Ventilation Relay** device subscribes to shared attribute updates from ThingsBoard. When the shared attribute value changes, the device automatically adjusts its physical relay state.

**Goal:** Add a Power button widget that controls the relay by toggling the value of the shared attribute **powerState**. The widget will:
- read the current `powerState` value (`true` / `false`) from the device,
- display the corresponding ON or OFF state, and
- update the shared attribute when the user presses the button.

- **Attribute scope:** Shared

- **Value:** Constant &#8702; `false` (Boolean)

## Troubleshooting

### Button does not reflect device state

| Cause | Solution |
|-------|----------|
| Incorrect attribute key | Verify the key matches the device attribute exactly. Key names are case-sensitive. |
| Wrong attribute scope | Match the scope to the actual attribute type (Client / Server / Shared). |
| No attribute on device | Open **Devices → Attributes** and confirm the key exists with a value. |
| RPC call fails | Check device connectivity and verify the RPC handler on the device firmware. |

### Button click has no effect

| Cause | Solution |
|-------|----------|
| Device offline | Verify device connectivity and transport configuration. |
| Wrong action type | Confirm the ON/OFF action matches how the device receives commands (RPC vs. attribute vs. time series). |
| RPC timeout | Increase **RPC request timeout** in Advanced settings. |

### Button is stuck in Disabled state

| Cause | Solution |
|-------|----------|
| Disabled condition always evaluates to true | Review the Disabled state configuration — check the action type and result converter logic. |
| Unexpected attribute or telemetry value | Open **Devices → Attributes** or **Latest telemetry** to inspect the actual value. |

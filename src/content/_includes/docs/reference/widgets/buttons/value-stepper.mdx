The **Value stepper** widget lets users increment or decrement a numeric value using two control buttons — left (decrease) and right (increase). Each click can execute an RPC command, update an attribute, or log a time series record. The widget is well-suited for controlling fan speed levels, temperature setpoints, brightness, valve positions, or any numeric device parameter.

## Adding the widget

<Steps>
1. Open the dashboard in edit mode. Click **Add widget** in the top toolbar, or click the **Add new widget** icon in the center of an empty dashboard.
2. In the widget bundle selection dialog, find and click **Buttons**.
3. Select the **Value stepper** widget.
4. Configure the datasource, behavior, and appearance, then click **Add**.
</Steps>

## Configuration

The widget configuration dialog has **Basic** and **Advanced** tabs. The **Basic** tab contains: **Target device**, **Behavior**, **Appearance**, **Button appearance**, **Card appearance**, and **Actions**.

### Target device

Select the <DocLink product={props.product} path="user-guide/widgets/#datasources" bold={false} target="_blank">datasource</DocLink> for the widget:

- **Device** — a specific device.
- **Entity alias** — entities matched by an <DocLink product={props.product} path="user-guide/aliases" bold={false} target="_blank">entity alias</DocLink>.

### Behavior

The **Behavior** section defines how the widget reads and changes device state. It has four sub-sections: **Initial state**, **Left button click**, **Right button click**, and **Disabled state**.

#### Initial state

Determines the numeric value displayed when the dashboard loads.

| Action | Parameters | Result converter | Notes |
|--------|-----------|-----------------|-------|
| **Do nothing** | **Value:** number | — | Static predefined value. |
| **Execute RPC** | **Method:** e.g. `getLevel` | **None** or **Function** `f(data)` → number | Advanced settings: RPC timeout (ms), RPC request persistent. |
| **Get attribute** | **Attribute scope:** Any / Client / Server / Shared; **Attribute key:** e.g. `speed` | **None** or **Function** | Best for persistent setpoint storage. |
| **Get time series** | **Time series key:** e.g. `temperatureSetpoint` | **None** or **Function** | Use when state is frequently reported as telemetry. |
| **Get alarm status** | **Alarm severity:** Critical / Major / Minor / Warning / Indeterminate; **Alarm types:** Any or selected | **None** or **Function** | Special cases: severity-based numeric levels. |
| **Get dashboard state id** | — | **None** or **Function** | Value depends on dashboard navigation context. |
| **Get dashboard state object** | — | **Function required** — `f(data)` → number | Advanced UI workflows with complex state. |

#### Left button click (decrement)

Triggered when the user clicks the left button. Sends the decremented value to the device.

| Action | Parameters | Advanced settings |
|--------|-----------|------------------|
| **Execute RPC** | **Method:** e.g. `setState`; **Parameters:** **Value** (current stepper value) / **Function** `f(value)` → payload / **None** | RPC request timeout (ms); RPC request persistent |
| **Set attribute** | **Attribute scope:** Server / Shared; **Attribute key**; **Value:** Value / **Function** `f(value)` | — |
| **Add time series** | **Time series key**; **Value:** Value / **Function** `f(value)` | — |

<Aside type="tip">
The **Value** parameter option passes the current stepper value directly to the device. Use **Function** `f(value)` to transform the value before sending — for example, to wrap it in a JSON object: `return { "temperature": value };`
</Aside>

#### Right button click (increment)

Mirrors the left button click configuration. The same three action types are available — **Execute RPC**, **Set attribute**, and **Add time series** — but triggered when the user clicks the right button, sending the incremented value.

#### Disabled state

Defines when both buttons become non-clickable. Uses the same action types as **Initial state**. When the configured condition evaluates to `true`, the widget renders as disabled and ignores user clicks.

### Appearance

| Setting | Description |
|---------|-------------|
| **Layout** | Button design variant: **Simplified** — minimal style; **Filled** — filled background; **Volume** — raised/volumetric effect. |
| **Auto scale** | Automatically adjusts font size and element scaling when the widget is resized. |
| **Range** | Allowed numeric limits: **Min** and **Max** values. |
| **Value increment/decrement step** | Step size applied on each button click (e.g., `1`, `5`, `0.5`). |
| **Value** | Font settings (typeface, size, weight), color, and number of decimal places for the displayed value. |
| **Value box background** | Background color behind the numeric display area. |
| **Border** | Border width and color for the value container. |

### Button appearance

The **Button appearance** section has **Left** and **Right** tabs with independent settings for each button.

| Setting | Description |
|---------|-------------|
| **Left / Right button** | Toggle to show or hide the button. |
| **Icon** | Icon displayed on the button (size in px + icon picker). |
| **Power 'On' colors** | **Main** — button fill color in the active state; **Background** — surrounding area color. |
| **Disabled colors** | **Main** — button fill color when disabled; **Background** — surrounding area color. |

### Card appearance

| Setting | Description |

| **Card border radius** | Roundness of card corners. |

### Actions

The Value stepper widget supports the <DocLink product={props.product} path="user-guide/actions#widget-header-button" bold={false} target="_blank">Widget header button</DocLink> action — adds a button to the widget header that triggers a configured action when clicked.

## Example: Temperature setpoint control

**Scenario:** A **Heating Controller** device controls room temperature. The user needs to adjust the **targetTemperature** setpoint within the allowed range of 16–28 °C.
After receiving a new value through an update of the shared **targetTemperature** attribute, the device adjusts its heater accordingly. 
A second shared attribute, **locked** (Boolean), prevents adjustment when set to `true`.

**Goal:** Create a Value stepper widget that:
- reads the initial temperature from the shared attribute **targetTemperature** on dashboard load,
- decrements or increments **targetTemperature** value by updating it accordingly.
- disables both buttons automatically when **locked = true**.

## Troubleshooting

### Widget does not show the correct initial value

| Cause | Solution |
|-------|----------|
| Wrong attribute key | Verify the key matches the device attribute exactly. Key names are case-sensitive. |
| Wrong attribute scope | Match the scope to the actual attribute type (Client / Server / Shared). |
| No attribute on device | Open **Devices → Attributes** and confirm the key exists with a value. |
| RPC call fails | Check device connectivity and verify the RPC handler on the device firmware. |

### Button click has no effect

| Cause | Solution |
|-------|----------|
| Device offline | Verify device connectivity and transport configuration. |
| Wrong RPC method name | Confirm the method name matches the handler implemented on the device firmware. |
| Value out of range | Check that the new value falls within the configured **Min / Max** range. |
| RPC timeout | Increase **RPC request timeout** in Advanced settings. |

### Widget is stuck in Disabled state

| Cause | Solution |
|-------|----------|
| Disabled condition always evaluates to true | Review the Disabled state configuration — check the action type and result converter. |
| Unexpected attribute value | Open **Devices → Attributes** or **Latest telemetry** to inspect the actual value. |

Modbus is a request-response protocol used by PLCs, energy meters, drives, and other industrial equipment. ThingsBoard acts as a **Modbus client** (master): it polls the registers and coils of your devices on a schedule, saves the values as telemetry and attributes, and writes values to the devices on shared attribute updates and RPC commands.

ThingsBoard connects to a device in one of three ways:

- **Modbus TCP:** The device, or a gateway in front of it, listens on a TCP port.
- **RTU over TCP:** A serial-to-Ethernet converter in transparent mode passes RTU frames through a TCP port.
- **Serial port:** An RS-232 or RS-485 line is attached to the machine that runs the Modbus transport.

Available since ThingsBoard **4.4.2**.

<Aside type="note">
The Modbus transport is for devices that the platform can reach directly. To collect data from devices in a remote network and send it to ThingsBoard over MQTT, use the <DocLink product={Products.GW} path="config/modbus">Modbus connector</DocLink> of ThingsBoard IoT Gateway.
</Aside>

## Enable the transport

The Modbus transport is disabled by default. Set the `MODBUS_ENABLED` environment variable to `true` and restart ThingsBoard.

In a microservices deployment, devices are polled by the `tb-modbus-transport` service. If this service is not running, the Modbus transport type is still available in the device profile, but no device is polled.

The Modbus transport is not available on ThingsBoard Cloud.

## Device profile configuration

The device profile defines what to read from and write to the devices, and how often. It does not contain the address of a device, so one profile serves devices on TCP and on serial lines.

<Steps>
1. Go to **Device profiles** and create or edit a profile. Set the transport type to **Modbus**.
2. Set the polling parameters from the table below.
3. Add mappings to the **Timeseries**, **Client attributes**, **Shared attribute updates**, and **RPC** lists.
4. Click **Save**.
</Steps>

| Parameter | Description |
|-----------|-------------|
| **Request timeout, ms** | Time to wait for a response of the device. |
| **Retries** | Number of times a request is sent again after a timeout. |
| **Poll period, ms** | Interval between two readings of the timeseries mappings. Also used for client attributes unless the attributes poll period is set. |
| **Attributes poll period, ms** | Optional interval for the client attribute mappings. |
| **Byte order** | Order of the two bytes inside each register: big endian (default) or little endian. |
| **Word order** | Order of the registers of a value that spans several registers: big endian (default) or little endian. |
| **Send data only on change** | Polled values equal to the previously sent ones are not sent again. |

## Device configuration

The transport configuration of a device defines where the device is reached and its unit id. To set it, open the device details and edit the **Transport configuration** section.

| Parameter | Description |
|-----------|-------------|
| **Connection** | **TCP** or **Serial port**. |
| **Unit id** | Address of the device on the line, also called slave id. |
| **Request timeout, ms** | Optional. Replaces the request timeout of the device profile for this device. |
| **Poll period, ms** | Optional. Replaces the poll period of the device profile for this device. |

### TCP

| Parameter | Description |
|-----------|-------------|
| **Host** | IP address or hostname of the device or of the gateway in front of it. |
| **Port** | TCP port. The standard Modbus port is 502. |
| **Framing** | **Modbus TCP (MBAP)** for devices and gateways that speak Modbus TCP. **RTU over TCP** for a serial gateway in transparent mode that passes RTU frames through. |

The unit id range depends on the framing: from 0 to 255 for Modbus TCP, and from 1 to 247 for RTU over TCP.

<Aside type="caution">
Unit id 0 is valid for a device that speaks Modbus TCP. Some TCP-to-serial gateways forward unit id 0 to every device on the bus as a broadcast. Use it only when the device documentation requires it.
</Aside>

### Serial port

| Parameter | Description |
|-----------|-------------|
| **Serial port** | Device name or path on the machine that runs the Modbus transport, like `/dev/ttyUSB0` or `COM3`. |
| **Baud rate** | Line speed in bits per second. The default is 9600. |
| **Parity** | **None**, **Odd**, or **Even** (default). |
| **Stop bits** | **1** (default) or **2**. Modbus expects two stop bits when parity is None. |
| **RS-485 direction control** | Lets the transport switch the RS-485 transceiver between sending and receiving with the RTS signal. |

The unit id of a serial device is from 1 to 247. Characters always have 8 data bits, as Modbus RTU requires.

<ImageGallery images={[
  { src: '/src/assets/images/reference/modbus-api/modbus-api-device-serial-pe.webp', alt: 'Transport configuration of a device with the Serial port connection: serial port, baud rate, parity, and stop bits', caption: 'Transport configuration of a device connected over a serial port.' },
]} />

With **RS-485 direction control** turned on, four more parameters are available:

| Parameter | Description |
|-----------|-------------|
| **RTS active high** | RTS is driven high while sending. Turned on by default. |
| **Bus termination** | Turns on the termination resistor of the adapter. |
| **Receive while transmitting** | Keeps the receiver on while sending. |
| **Delay before send, ms** and **Delay after send, ms** | Time between switching RTS and the first or the last bit of a frame, from 0 to 100 ms. |

<ImageGallery images={[
  { src: '/src/assets/images/reference/modbus-api/modbus-api-device-serial-rs485-pe.webp', alt: 'Serial port connection with RS-485 direction control turned on and its additional parameters', caption: 'RS-485 direction control parameters of a serial port connection.' },
]} />

<Aside type="note">
RS-485 direction control takes effect on Linux only, and only with a serial driver that supports it. Leave it turned off for RS-232 and for adapters that switch direction automatically, which includes most USB to RS-485 adapters.
</Aside>

Consider the following when you use a serial port:

- The port belongs to one machine. Run a single instance of the Modbus transport on the machine that has the port.
- All devices on one serial port must use the same baud rate, parity, stop bits, and RS-485 settings. A device whose settings differ from the ones already in use on the port is not polled.
- Use a port path that does not change after a reboot or a replug, like `/dev/serial/by-id/...` on Linux.
- The operating system user that runs ThingsBoard needs access to the port. On Linux, add the user to the `dialout` group. In Docker, pass the port to the container with the `--device` option.

## Connections and errors

Devices that share a host and port, or a serial port, share one connection. ThingsBoard sends one request at a time over a connection by default, which is what serial lines and most gateways require.

- **Timeouts:** A request without a response is sent again as many times as the **Retries** parameter allows.
- **Lost connections:** ThingsBoard reconnects automatically. For a serial port, the delay between attempts starts at 500 ms and doubles after each failed attempt up to the value of `MODBUS_SERIAL_MAX_RECONNECT_DELAY_MS`.
- **Error events:** A failure is reported once when it starts, not on every poll. To see it, open the device and go to the **Events** tab with the **Error** event type.

## Transport configuration

The Modbus transport is configured via environment variables. Key parameters:

| Variable | Default | Description |
|----------|---------|-------------|
| `MODBUS_ENABLED` | `false` | Enable or disable the Modbus transport. The standalone `tb-modbus-transport` service has it set to `true`. |
| `MODBUS_MIN_POLL_PERIOD_MS` | `100` | Lower bound for poll periods in device profiles and devices, in milliseconds. |
| `MODBUS_MAX_IN_FLIGHT_PER_ENDPOINT` | `1` | Maximum number of requests in flight per Modbus TCP connection. Always one for RTU over TCP and serial ports. |
| `MODBUS_MAX_QUEUE_SIZE_PER_ENDPOINT` | `1000` | Maximum number of requests waiting to be sent per connection. When the limit is reached, new requests fail immediately. |
| `MODBUS_BLOCK_MERGE_MAX_GAP` | `8` | Maximum gap, in registers or coils, between two mappings that are still merged into one read. |
| `MODBUS_CONNECT_TIMEOUT_MS` | `5000` | Timeout for opening a Modbus TCP connection, in milliseconds. |
| `MODBUS_SERIAL_MAX_RECONNECT_DELAY_MS` | `5000` | Maximum delay between attempts to open a serial port that is missing or busy, in milliseconds. |
| `MODBUS_SCHEDULER_THREAD_POOL_SIZE` | `4` | Number of threads that schedule poll cycles. |
| `MODBUS_RESPONSE_PROCESSING_PARALLELISM_LEVEL` | `4` | Parallelism level of the executor that processes responses. |

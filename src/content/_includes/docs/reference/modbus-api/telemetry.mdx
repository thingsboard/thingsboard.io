To collect telemetry from Modbus devices, add mappings to the **Timeseries** list of the <DocLink product={props.product} path="reference/modbus-api/getting-connected">device profile</DocLink>. ThingsBoard reads the mapped registers and coils every poll period and saves the values as time series data under the mapping keys.

## Mapping fields

Every mapping list of the device profile uses the same fields:

| Field | Description |
|-------|-------------|
| **Key** | Telemetry or attribute key in ThingsBoard, or the RPC method name. Unique within a list. |
| **Type** | Data type of the value. See [Data types](#data-types). |
| **Function code** | Modbus function used to read or write the value. See [Function codes](#function-codes). |
| **Address** | 0-based protocol address, from 0 to 65535. |
| **Count** | Number of registers. Required for the `STRING` and `BYTES` types only. |
| **Bit** | Bit inside a register, from 0 to 15, where 0 is the least significant bit. Required when the `BITS` type is used with a register function code. |
| **Multiplier** | Optional factor for numeric types. A value read from the device is multiplied by it, and a value written to the device is divided by it. |

Addresses are 0-based protocol addresses. Register 40021 in a device manual is function code 3 (holding registers), address 20. Register 30021 is function code 4 (input registers), address 20.

## Function codes

| Function code | Operation | Used in |
|---------------|-----------|---------|
| 1 | Read coils | Timeseries, client attributes, and RPC |
| 2 | Read discrete inputs | Timeseries, client attributes, and RPC |
| 3 | Read holding registers | Timeseries, client attributes, and RPC |
| 4 | Read input registers | Timeseries, client attributes, and RPC |
| 5 | Write single coil | Shared attribute updates and RPC |
| 6 | Write single register | Shared attribute updates and RPC |
| 15 | Write multiple coils | Shared attribute updates and RPC |
| 16 | Write multiple registers | Shared attribute updates and RPC |
| 22 | Mask write register | Shared attribute updates and RPC |

## Data types

| Type | Registers | Value in ThingsBoard |
|------|-----------|----------------------|
| `BITS` | One coil, or one bit of a register | Boolean |
| `INT16`, `UINT16` | 1 | Integer |
| `INT32`, `UINT32` | 2 | Integer |
| `INT64`, `UINT64` | 4 | Integer |
| `FLOAT16` | 1 | Floating point number |
| `FLOAT32` | 2 | Floating point number |
| `FLOAT64` | 4 | Floating point number |
| `STRING` | Set in **Count** | ASCII text. Trailing spaces and zero bytes are removed. |
| `BYTES` | Set in **Count** | Hexadecimal string, like `0102abcd`. |

Coil function codes (1, 2, 5, and 15) work with the `BITS` type only.

## Byte and word order

The **Byte order** and **Word order** parameters of the device profile apply to all mappings of the profile:

- **Byte order:** Order of the two bytes inside each register.
- **Word order:** Order of the registers of a value that spans several registers, like `FLOAT32`.

Both are big endian by default, which is what the Modbus specification defines. Switch the word order to little endian for devices that send the low register first.

## Polling

ThingsBoard reads the timeseries mappings every **Poll period**. The next poll starts when the period has passed after the previous poll has finished, so a slow device is never asked faster than it answers.

- **Merged reads:** Mappings with the same function code and nearby addresses are read with one request. If a device rejects such a request with exception 02 (illegal data address), ThingsBoard reads the mappings of that request one by one from then on.
- **Timestamp:** All values of one poll get the same timestamp.
- **Send data only on change:** With this parameter turned on, a value equal to the previously sent one is not sent again.
- **Minimum period:** A poll period below the value of `MODBUS_MIN_POLL_PERIOD_MS` is raised to it.

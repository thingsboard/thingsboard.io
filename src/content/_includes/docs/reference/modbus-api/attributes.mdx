The Modbus device profile has two lists for attributes: **Client attributes** are read from the device, and **Shared attribute updates** are written to it. Both use the mapping fields described on the <DocLink product={props.product} path="reference/modbus-api/telemetry">Telemetry</DocLink> page.

## Client attributes

To read values that rarely change, like a serial number or a firmware version, add mappings to the **Client attributes** list. ThingsBoard reads them with function codes 1 to 4 and saves the values as client attributes under the mapping keys.

Client attributes are polled with the first period that is set from this list:

1. **Attributes poll period, ms** of the device profile.
2. **Poll period, ms** of the device.
3. **Poll period, ms** of the device profile.

## Shared attribute updates

To write a value to a device when a shared attribute changes, add a mapping to the **Shared attribute updates** list. The mapping key is the **shared attribute name**, and the function code is one of the write codes:

| Function code | Use it to |
|---------------|-----------|
| 5 or 15 | Write a coil. The value is `true`, `false`, `1`, or `0`. |
| 6 | Write one register (`INT16`, `UINT16`, or `FLOAT16`). |
| 16 | Write one or several registers (any numeric type, `STRING`, or `BYTES`). |
| 22 | Set or clear one bit of a holding register without changing its other bits. Requires the `BITS` type and the **Bit** field. |

The value is converted before it is written:

- **Numbers:** The value is divided by the multiplier, if one is set. Integer types round it to the nearest integer. A value outside the range of the type is rejected.
- **`STRING`:** ASCII characters only. The text must fit into the registers set in **Count**.
- **`BYTES`:** A hexadecimal string with exactly two bytes per register.

If the same attribute changes again while the device is busy, only the latest value is written.

A write that fails is reported as an error event of the device. The shared attribute keeps its new value in ThingsBoard.

<Aside type="note">
The same key can be used in both lists. To see the value that the device applied, read the register back with a mapping in the **Client attributes** list.
</Aside>

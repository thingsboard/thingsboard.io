<Aside type="note">
  This node requires **ThingsBoard PE** or **ThingsBoard Cloud**. The node described on this page is the periodic *aggregate latest (deprecated)* variant — it runs on a timer, has no input port, and exposes *Single entity / Group of entities / Relations query* parent selection. The non‑deprecated *aggregate latest* node is event‑driven (triggered by an incoming message and a relations query) and is documented separately.
</Aside>

Use this node to periodically aggregate attribute or time‑series values from child entities and write the result as telemetry on a parent entity — for example, computing the average temperature across all sensors in a building and posting it to the building asset every minute, or counting active devices in a fleet and writing the count to a fleet asset.

The node does not consume incoming messages; it runs on its own schedule.

---

## Concepts

**Parent entity.** The entity on which the aggregated result is written as telemetry.

**Child entity.** A source entity whose attribute or latest time‑series value is read and fed into the aggregator. The set of children is resolved per parent.

**Mapping.** One `(child key → aggregation → parent key)` rule. A node can carry several mappings; each runs independently on each tick.

**Tick.** A periodic internal self‑message scheduled every *Execution period*. On each tick the node resolves the parent set, then for each parent resolves its children, applies all configured mappings and emits one outgoing message per parent on the *Success* branch.

## Configuration

The fields below follow the order of the rule node editor.

### General

| Field | Required | Description |
|-------|----------|-------------|
| **Name** | Yes | Display name of the rule node. |
| **Output message type** | Yes | Type used for outgoing aggregate messages. Defaults to `POST_TELEMETRY_REQUEST`. Selecting a built‑in type fills *Message type value* automatically; selecting *Custom* lets you type any string. |
| **Execution period value / time unit** | Yes | How often the aggregation tick fires. The schedule is anchored at node startup and slides forward by the configured period each tick. |

### Parent entities

Specifies which parent entities receive the aggregation results. Pick one of three modes via the radio button.

| Mode | Behavior |
|------|----------|
| **Single entity** | One specific entity is the only parent. Choose the entity type and the entity itself. The aggregation result is written to that entity. The set of children is resolved by the *Child entities* relations query. |
| **Group of entities** | The configured entity group is treated as a single parent; the aggregation is performed across the group's members and the result is written to the group entity itself. Choose the entity type (e.g. `Device`) and the entity group. No *Child entities* section is shown — the children are the group members. |
| **Relations query** | The parent set is the result of a relations query starting from a configured root entity. Each entity returned becomes its own parent and gets an independent aggregation. The list is re‑resolved on every tick, so newly matched entities start receiving aggregates automatically. The set of children is resolved per parent by the *Child entities* relations query. |

Fields that depend on the selected mode:

- **Type** — entity type for the *Single entity* / *Group of entities* picker.
- **Entity** / **Select entity group** — the actual entity or group to use.
- **Direction**, **Max relation level**, **Relation type filters**, **Root entity** — relations‑query fields that appear when *Relations query* is selected.

### Child entities

Shown only for *Single entity* and *Relations query* parent modes. Configure a relations query that the node runs **per parent** to find that parent's children. For *Group of entities* this section is hidden — the children are the group members.

| Field | Description |
|-------|-------------|
| **Direction** | `From` (children are entities the parent points at) or `To` (children point at the parent). |
| **Max relation level** | How many hops to follow. |
| **Relation type filters** | Limits which relation types are followed and which child entity types are accepted. |

### Aggregate latest mappings

Each row defines one `(source key → aggregation → target key)` rule applied to every child of every parent. Add as many rows as you need.

| Field | Description |
|-------|-------------|
| **Latest telemetry** | When checked, the source is the child's latest time‑series value for the given key; when unchecked, the source is an attribute. |
| **Source telemetry/attribute** | Key name read from each child entity. |
| **Attribute scope** | `CLIENT_SCOPE`, `SHARED_SCOPE`, or `SERVER_SCOPE` — applicable only when aggregating attributes. |
| **Default value** | Numeric value used in place of a missing source on a child. |
| **Aggregation function** | `Minimum`, `Maximum`, `Sum`, `Average`, `Count`, `Count unique`. |
| **Target telemetry** | Key name on the parent entity where the result is written. |
| **Filter entities** | When enabled, applies a JavaScript filter to each child before it is included in the aggregation. |
| **Entity filter** | List of attribute / latest telemetry keys to fetch and a JS function returning `true` / `false`. Fetched values are exposed using scope prefixes: `shared_`, `cs_`, `ss_` (latest telemetry: no prefix). |

### Queue

Optional. Selects a rule engine queue for tick and outgoing messages. If empty, the node uses the `Main` queue.

### Rule node description

Optional free‑text note shown in the rule chain editor. Has no effect on processing.

## Message processing algorithm

1. At each execution tick, resolve the parent set per the *Parent entities* configuration.
2. For each parent, resolve its child entities (relations query, or group members).
3. For each mapping row:
   - read the source key from each child;
   - if the entity filter is enabled, drop children whose JS function returns `false`;
   - apply the aggregation function across the remaining children, substituting the configured default for absent values;
   - place the result under the target key in the outgoing payload.
4. Emit one outgoing message per parent (originated by that parent) on the *Success* branch, with metadata `ts` set to the tick timestamp.
5. If aggregation fails for a parent, an empty failure message is emitted on the *Failure* branch with the failure reason.

---

## Output connections

| Connection | Condition |
|------------|-----------|
| `Success` | One generated message per parent entity carrying the aggregated values. |
| `Failure` | Aggregation failed for a parent entity; the failure message contains the reason. |

---

## Effects on time‑series DB write volume

Each tick emits one outgoing message per parent. The node itself does not write telemetry — the outgoing message must be routed to a Save Time Series node downstream. Total writes per tick ≈ *number of parents* × *number of mappings*. Increasing the parent set (Group, Relations query) directly multiplies that volume; tightening the *Execution period* multiplies it again per unit of time.

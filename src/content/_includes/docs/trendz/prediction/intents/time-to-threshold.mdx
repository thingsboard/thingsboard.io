**Time to Threshold** answers the question a plain forecast leaves open: when. The model forecasts the metric the
same way a <DocLink product={props.product} path="prediction/intents/forecast">Forecast</DocLink> model does, then
reads that forecast with event rules. The moment the forecast first satisfies a rule becomes a predicted event
with a countdown of the remaining time until the crossing, a ThingsBoard alarm whose severity grows as the moment
approaches, and a telemetry key you can put on a dashboard.

The example on this page is a fleet of ten backup generators. Each tank's **fuelLevel** is forecast, and the
countdown runs to the moment it drops below the **10% reserve** — early enough to send a fuel truck before a
generator runs dry.

## When to use it

Use Time to Threshold when you need to know when something happens, not only what the value will be.

| Use case | What Time to Threshold predicts | What you do with it |
|----------|---------------------------------|---------------------|
| **Refill fuel tanks** | When the fuel level of each generator tank drops below its reserve | Send the truck before a tank reaches the reserve |
| **Avoid a peak charge** | When the load of each site goes above the contracted 600 kW | Move heavy jobs out of the hours before the crossing |
| **Replace filters in time** | When the pressure drop across each air filter goes above its limit | Order and replace the filter before the airflow suffers |
| **Plan battery replacement** | When the battery level of each sensor drops below 20% | Replace the batteries on one trip, before devices go offline |
| **Prevent tank overflow** | When the level of each storage tank goes above 90% | Schedule a pickup or stop filling before the tank overflows |

Events are searched only inside the forecast, so the prediction horizon is also how far ahead a crossing can be
found. If you need the value itself rather than the moment, use
<DocLink product={props.product} path="prediction/intents/forecast">Forecast</DocLink>. For a total over a period,
use <DocLink product={props.product} path="prediction/intents/period-total">Period Total</DocLink>, and for a goal
to reach, <DocLink product={props.product} path="prediction/intents/hit-target">Hit Target</DocLink>.

### Predictive alerts and lead time

A classic threshold alarm fires when the live value crosses the limit, often too late to prevent the problem.
Time to Threshold applies the same limit to the forecast, so the alert fires while the value is still on its way
to the limit. This is a predictive alert. The time between the alert and the crossing is your lead time: enough
to send a truck, move a load, or order a part.

Keep your existing threshold alarm in ThingsBoard as a safety net. A forecast can be wrong, and the live alarm
still catches a crossing that comes sooner than predicted.

### Step 4: Define the threshold

The fourth step creates the first event rule — in the example, **Low fuel**, which fires as the forecast **drops
below 10**, the reserve.

<Aside type="tip">
Not sure what to specify? Leave the step empty and build the model without it. Rules can be added at any time in
[Event rules](#event-rules) on the Result tab.
</Aside>

**Rule name** — what the event is called on the Result tab and in the Events tab.

**Threshold condition** — what the countdown counts down to:

| Mode | Behavior |
|------|----------|
| **Simple** | One comparison: **goes above** or **drops below** a **Value**, or an **Attribute** read per item. |
| **Advanced** | Several comparisons combined with AND or OR. |
| **From alarm rule** | Reuses one severity of an existing ThingsBoard alarm rule. |

The Result tab shows the soonest predicted event of one item at a time. Pick the item in the table below the chart;

## Event rules

An event rule turns the forecast into an event. On every refresh, Trendz checks the forecast against the rule's
condition. The first moment the forecast meets the condition is the start of the event, and the moment it stops
meeting it is the end. The time from now to the start is the **time to event**.

<ImageGallery images={[
  {
    src: '/src/assets/images/trendz/prediction/ttt-event.svg',
    alt: 'Diagram: the measured history up to Now, the dashed forecast dropping below the threshold line and rising back, the shaded event between the two crossings, and the time to event from Now to the event start',
    caption: 'Events are searched only inside the prediction horizon.',
  },
]} />

A model can have several rules, such as a warning level and a critical level on the same metric. Each rule can be
switched off without deleting it.

### Open the rule editor

Click **Manage rules** under the Next event card:

<ImageGallery images={[
  {
    src: '/src/assets/images/trendz/prediction/ttt-manage-rules.webp',
    alt: 'Result tab of a Time to Threshold model with the Manage rules button highlighted',
    caption: '<b>Manage rules</b> opens the rule editor.',
  },
]} />

The editor lists the rules on the left and the selected rule on the right. A model built without a rule is
completed here: add the rule and the next refresh checks the existing forecast against it. Nothing is retrained.

<Aside type="note">
**Manage rules** reacts to whatever the model is running:

- A **full model rebuild** — for example after you change the prediction method or another setting on the
  Properties tab — blocks the editor from opening at all.
- A **single item's refresh or retrain** lets you open the editor, but **Save** stays disabled until that item
  finishes.

Both are expected; the editor is fully available again once the run completes.
</Aside>

### Alarm creation

**Alarm creation** raises a ThingsBoard alarm of the **Alarm type** while an event is predicted. The type must be
unique within the profile, because ThingsBoard keeps one active alarm per item and type.

**Severity thresholds** — you define what counts as each severity: how close the event must be for a **Warning**,
a **Major**, or a **Critical**. They are off by default, so turn on the ones you need:

    caption: 'You set the alarm type and how close the event must be for each severity.',

## Events tab

The **Events** tab lists every predicted event of the model, across all items and rules. The chart shows the
selected event on the forecast.

In this example only generator-003 has reached its rule, so the list holds a single **Major** event. A real fleet
usually has many at once, each carrying whichever severity you enabled for the rule — **Warning**, **Minor**,
**Major**, or **Critical**.

|--------|---------|
| **Item** | The device or asset name |
| **Rule** | The rule that found the event |
| **Condition** | The condition of the rule |
| **Event time** | The predicted start of the event |
| **Time to event** | The countdown to the start |
| **Alarm** | The severity of the raised alarm |

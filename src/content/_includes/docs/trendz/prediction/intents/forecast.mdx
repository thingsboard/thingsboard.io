**Forecast** predicts the future values of one metric for every device or asset in a profile. Trendz learns each
item's own history and extends it over a prediction horizon: the next 24 hours, 7 days, 30 days, or a range of
your own. Ten energy meters give ten forecasts, each refreshed as new readings arrive.

    caption: 'Hourly energy of ten retail sites: two weeks measured, seven days forecast.',

]} />

<Aside type="note">
Prediction models created before Trendz 1.16.0 were migrated to this intent: they open as Forecast models,
with the horizon and the training period they were built with.
</Aside>

## When to use it

Use Forecast when you need the predicted values themselves, for each device or asset.

| Use case | What Forecast predicts | What you do with it |
|----------|------------------------|---------------------|
| **Buy electricity** | Hourly consumption of each store for tomorrow | Order the right amount of power a day ahead |
| **Plan production load** | Hourly power use of each production line for next week | Spread heavy jobs so the plant stays under its contracted capacity |
| **Plan parking capacity** | Hourly occupancy of each parking lot for next week | Open overflow lots and set prices before the busy days |

Forecast raises no alarms and has no countdown of its own. To learn when a value crosses a limit, use
<DocLink product={props.product} path="prediction/intents/time-to-threshold">Time to Threshold</DocLink>. For a
total, peak, or average over a period, use <DocLink product={props.product} path="prediction/intents/period-total">Period Total</DocLink>.
To track a goal, use <DocLink product={props.product} path="prediction/intents/hit-target">Hit Target</DocLink>.

## How to create a model

### Step 1: Open the wizard

Two entry points are available on the Prediction models page:

- **Create model** — button in the top-right corner, visible on both tabs.
- **+ Create** — inline button on any profile row of the Profile coverage table. Opens the wizard with that
  profile pre-selected.

**Predicted metric** — pick the telemetry key to forecast and the aggregation applied to it during training:

| Aggregation | Use for |
|-------------|---------|
| **SUM** | Counters such as energy, water, or produced units. |
| **AVG** | Levels such as temperature, pressure, or humidity. |
| **MAX**, **MIN** | Peaks and troughs, for example the highest demand of an hour. |

The aggregation turns every reading inside one bucket into a single value, so it decides what the forecast
actually means.

### Step 3: Configure the forecast

The **Configure forecast** step sets how far ahead the model predicts, how much history it learns from, and how
fine the result is.

**Prediction horizon** — choose how far ahead the model predicts. Pick one of the presets, or **Custom** and
type the number of units to predict:

  {
    src: '/src/assets/images/trendz/prediction/forecast-s3-horizon.webp',

## Forecast result page

The Result tab shows the forecast of one item at a time. Pick the item in the table below the chart; the cards on
the right show the monitoring settings and the data status of the model.

### Forecast chart

The chart draws the selected item: measured history as a solid line and the forecast as a dashed line.

<ImageGallery images={[
  {
    src: '/src/assets/images/trendz/prediction/forecast-chart.webp',
    alt: 'Result tab with the forecast chart highlighted: hourly energy history, the Now marker, the dashed forecast, and a tooltip on a forecast point',
    caption: 'Each forecast point carries its timestamp and value.',
  },
]} />

### Items table

The table under the chart lists every item in the model's scope. Select a row to point the chart at that item.

| Column | Meaning |
|--------|---------|
| **Item** | The device or asset name |
| **Latest telemetry** | The item's last measured value and its time |
| **Latest prediction point** | The last forecast value and how far ahead it lies |
| **Last refresh** | When a refresh last selected this item |
| **Refresh status** | Never, In progress, Success, or Failed |
| **Training** | Training, Trained, Failed, Insufficient data, or Cancelled |

<ImageGallery images={[
  {
    src: '/src/assets/images/trendz/prediction/forecast-items.webp',
    alt: 'Items table with nine trained sites and one site marked Insufficient data',
    caption: 'One site reports a single reading, which is shorter than the horizon, so it stays untrained.',
  },
]} />

**Insufficient data** is a state, not a failure: the item has less history than the horizon and is trained on the
next run that finds enough.

The Anomaly Detection section is organized into three tabs — **Summary**, **Models**, and **Anomalies** —
each providing a different level of visibility into your anomaly detection setup.

## Summary Tab

The **Summary** tab is the default view when you open Anomaly Detection. It gives a fleet-wide picture
of monitoring coverage, detected anomalies, and recent system activity across all your models.

### KPI Cards

Four cards at the top of the page show the most important metrics across all anomaly models:

<ImageGallery images={[
  {
    src: '/src/assets/images/trendz/anomaly/summary-overview.png',
    alt: 'Summary tab with four KPI cards highlighted at the top of the page',
    caption: 'The four KPI cards show fleet-level health at a glance.',
  },
]} />

**Function Monitoring** — shows how well your fleet is covered by anomaly models:

| Segment | Meaning |
|---------|---------|
| Monitored | Items included in at least one active anomaly model |
| Scanned | Items not currently monitored but scanned by a model at least once |
| Not scanned | Items never included in any anomaly model scan |

**Fleet Stability** — shows the health distribution across scanned items:

| Segment | Meaning |
|---------|---------|
| With anomalies | Items where at least one anomaly was detected |
| Healthy | Items that were scanned but no anomalies were found |
| Not scanned | Items never included in any anomaly model scan |

**Deviation Impact** — quantifies the total effect of detected anomalies:

| Metric | Description |
|--------|-------------|
| **Time in Deviation** | Main metric — sum of durations of all detected anomalies across all models |
| **Anomalies** | Total count of detected anomaly events |
| **Scan Runs** | Total number of model scan executions |

**Operational Automation** — shows alarm activity generated by anomaly detection:

| Element | Description |
|---------|-------------|
| **Alarms Escalated** | Total count of ThingsBoard alarms created from anomalies |
| Severity bar | Stacked horizontal bar showing the breakdown by severity: Critical, Major, Minor, Warning |

### Profile Coverage

The **Profile Coverage** table lists every device and asset profile and summarizes anomaly detection
activity across it:

<ImageGallery images={[
  {
    src: '/src/assets/images/trendz/anomaly/summary-profile-coverage.png',
    alt: 'Profile Coverage table showing all profiles with their model and monitoring statistics',
    caption: 'Profile Coverage — one row per profile with aggregated model and anomaly statistics.',
  },
]} />

| Column | Description |
|--------|-------------|
| **Profile** | Profile name and type (Device or Asset) |
| **Items** | Total number of devices or assets in the profile |
| **Models** | Number of anomaly models configured for this profile |
| **Monitoring** | **ON** if at least one model has periodic scanning enabled |
| **Alerts** | **ON** if at least one model has alarm creation enabled |
| **Track Score** | **ON** if at least one model is saving anomaly scores to ThingsBoard |
| **Anomalies** | Total anomaly count detected across all models for this profile |

Each profile row has two action buttons:

- **+ Create** — opens the <DocLink product={props.product} path="anomaly/create">creation wizard</DocLink> with this profile pre-selected.
- **View &gt;** — opens the [Models tab](#models-tab) filtered to show only models for this profile.

Click **All models** in the top-right corner of the Profile Coverage section to open the [Models tab](#models-tab)
with no profile filter applied — showing all models across all profiles.

### System Pulse

The **System Pulse** panel on the right side of the Summary tab shows the status of the last 10
anomaly model scan executions. It gives you a real-time view of whether your models are running
successfully and detecting anomalies as expected.

<ImageGallery images={[
  {
    src: '/src/assets/images/trendz/anomaly/summary-system-pulse.png',
    alt: 'System Pulse panel showing recent scan executions with colored status indicators',
    caption: 'System Pulse — the last 10 scan executions with their status and anomaly count.',
  },
]} />

Each entry in the pulse shows the model name, execution time, and one of four status colors:

| Color | Meaning |
|-------|---------|
| Green | Scan completed successfully — no anomalies found |
| Orange | Scan completed successfully — anomalies were detected |
| Red | Scan failed due to an unexpected error |
| Gray | Scan task was canceled |

Click any entry in the System Pulse to open the full execution details for that scan run.

## Models Tab

The **Models** tab lists all anomaly models across all profiles in a single table. Access it by
clicking the **Models** tab in the top navigation:

<ImageGallery images={[
  {
    src: '/src/assets/images/trendz/anomaly/models-tab-nav.png',
    alt: 'Anomaly Detection page with the Models tab highlighted in the navigation',
    caption: 'Models tab — full list of all anomaly models.',
  },
]} />

Each row in the table shows:

| Column | Description |
|--------|-------------|
| **Name** | Model name and the profile it belongs to |
| **Created** | When the model was created |
| **Status** | **Ready** (trained and operational) or **Failed** (training failed) |
| **Purpose** | The <DocLink product={props.product} path="anomaly/create#step-2-choose-intent">detection intent</DocLink> chosen when the model was created (e.g. Quick Scan, Compare) |
| **Monitoring** | Whether <DocLink product={props.product} path="anomaly/monitoring#set-up-monitoring-refresh">periodic scanning</DocLink> is enabled |
| **Alerts** | Whether <DocLink product={props.product} path="anomaly/monitoring#generate-alarms">alarm creation</DocLink> is enabled |
| **Track Score** | Whether anomaly scores are being <DocLink product={props.product} path="anomaly/monitoring#save-scores-as-telemetry">saved as telemetry</DocLink> |
| **Anomalies** | Total count of detected anomalies |
| **Entities** | Ratio of entities with anomalies to total monitored entities |

Click the **three-dot menu** (⋯) at the end of any model row and select **Delete** to permanently
remove the model and all its detected anomalies:

<ImageGallery images={[
  {

    alt: 'Models table with the three-dot menu open showing a Delete option',

<Aside type="caution">
  Deleting a model is permanent. All detected anomalies, scan history, and configuration for that
  model are removed and cannot be recovered.

## Anomalies Tab

The **Anomalies** tab provides a unified table of every anomaly detected across all your models.
Use it to search, filter, and investigate individual anomaly events without opening each model separately.

<ImageGallery images={[
  {
    src: '/src/assets/images/trendz/anomaly/anomalies-tab-overview.png',
    alt: 'Anomalies tab showing the full list of detected anomalies across all models',
    caption: 'Anomalies tab — all anomalies from all models in one table.',
  },
]} />

Each row in the table shows:

| Column | Description |
|--------|-------------|
| **Time** | Start and end timestamps of the anomaly |
| **Item** | The device or asset on which the anomaly was detected |
| **Duration** | How long the anomalous behavior lasted |
| **Score** | Maximum anomaly score reached during the event |
| **Impact** | Anomaly Score Index — combines score with duration to reflect cumulative impact |
| **Model** | The anomaly model that detected this event |
| **Alarm** | The ThingsBoard alarm raised for this anomaly, if alarm creation is enabled |

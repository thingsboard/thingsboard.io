Trendz provides a guided wizard to create an anomaly model without any manual configuration.
The wizard selects the detection algorithm, segmentation settings, and scoring thresholds automatically
based on your chosen intent and data. For full control over every parameter, use
[Advanced Mode](#advanced-mode) instead.

## Steps to Create

   **Option A — "Create model" button** in the top-right corner of the Anomaly Detection page:

### Step 2: Choose Intent

   The wizard opens on the **"What would you like to detect?"** screen. Choose the detection strategy
   that matches your goal — each option pre-configures the optimal model settings automatically:

   | Intent | Description |
   |--------|-------------|
   | **Quick Scan** *(recommended)* | Fast baseline scan to identify obvious deviations in recent data. Best starting point for most use cases. |
   | **Operational Monitoring** | Continuous alerting for deviations from known seasonal or operational patterns. Uses a rolling window for ongoing detection. |
   | **Comparative Analysis** | Identifies units that behave differently from their peer group. Useful for fleet-wide benchmarking. |
   | **Health Monitoring** | Detects long-term gradual drift in overall system health over time. Uses progressive tracking across longer time ranges. |

### Step 4: Validate Data Readiness

   The **Data Readiness** panel on the right side of the Configure Input Scope screen updates in real time
   as you fill in the entity, items, telemetry keys, and date range. It summarizes what the model will train on:

   | Field | Description |
   |-------|-------------|
   | **Status** | Overall assessment: **Poor**, **Fair**, **Good**, or **Excellent**. |
   | **Entities** | Number of devices or assets selected. |
   | **Telemetry keys** | Number of telemetry keys selected. |
   | **Approximate points** | Estimated total data points available for training. |
   | **Step frequency** | Approximate interval between consecutive data points. |
   | **Time range** | Duration of the selected training period. |

   <ImageGallery images={[
     {
       src: '/src/assets/images/trendz/anomaly/create-scope-readiness.png',
       alt: 'Data Readiness panel showing Excellent status with 3 entities, 1 key, 8k points, 1.0hr step, 3 months',
       caption: 'Data Readiness panel — Excellent status means sufficient data quality for reliable anomaly detection.',
     },
   ]} />

   Aim for a **Good** or **Excellent** status before proceeding. A **Poor** status typically means too few
   data points, too short a time range, or too sparse a telemetry key.

   Once the status is acceptable, click **Next: Configure**.

### Step 5: Choose Sensitivity and Granularity

   The **"Review & Build"** step lets you fine-tune two parameters before the model trains:

   **Sensitivity** — controls how aggressively the model flags anomalies:

   | Option | Behavior |
   |--------|----------|
   | **Strict** | Minimizes false positives. Only flags extreme deviations from the norm. Best when alert fatigue is a concern. |
   | **Balanced** | A balanced approach for most industrial IoT environments. Recommended starting point. |
   | **Don't miss anything** | High recall — flags every potential deviation for expert manual review. Expect more false positives. |

   **Detection Granularity** — the time window the model evaluates data in. Trendz recommends up to 5
   options based on your data's step frequency. Shorter windows catch brief spikes; longer windows are
   better for gradual deviations.

   When satisfied, click **Finish** to start building the model.

The Result tab shows an overview of what the model found during the initial build: key metrics, an activity
heatmap, ranked items by anomaly impact, and a list of top anomalies.

## Advanced Mode

The wizard covers the most common detection scenarios. If you need to configure every parameter manually —
clustering algorithm, distance function, segmentation window type, score thresholds, and limits — use
**Advanced Mode** instead.

To access it, click **Advanced configuration** on the intent selection screen (Step 2).
Full documentation of all parameters is available in
<DocLink product={props.product} path="anomaly/build">Anomaly Model Properties</DocLink>.

## Best Practices

| Situation | Recommendation |
|-----------|----------------|
| **Too many anomalies** | Switch to **Strict** sensitivity. The model is flagging normal variation — tightening the threshold reduces noise. |
| **Too few anomalies** | Switch to **Don't miss anything** or choose a shorter detection granularity. The model may be too conservative for your data patterns. |
| **Selecting telemetry keys** | Only select keys that can physically correlate with each other — for example, vibration and motor temperature on the same pump. Combining unrelated keys (e.g., a pressure sensor and a door contact) produces meaningless segments and degrades model accuracy. |
| **Training data quality** | Ensure the training period covers normal operating conditions. Avoid time ranges that include major outages, commissioning, or maintenance periods, as these skew what the model learns as "normal." |
| **Using Advanced Mode** | Only switch to Advanced Mode if you understand clustering algorithms and segmentation. Misconfiguring clustering parameters can make the model worse than the defaults. |
| **Training data volume** | Aim for at least 3 months of data with regular telemetry readings. Sparse or short datasets produce Poor readiness and unreliable models. |

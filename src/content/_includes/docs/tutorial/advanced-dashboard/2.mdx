Dashboard states let you create a multi-level hierarchy within a single dashboard — think of each state as a separate page scoped to a selected entity. In this lesson, you will add building and office states and wire them together with widget actions.

---

## Step 2.1 Create Dashboard States

<Steps>
1. Open the **Buildings** dashboard in edit mode.
2. Click **Manage dashboard states** in the upper-left corner.
3. Click **+** to add a new state. Set the name to `${entityName}` (dynamic), the ID to `building`, and click **Add**.
4. Add a second state with ID `office` and the same dynamic name.
5. Click **Save**.
</Steps>

---

## Step 2.2 Default State — Navigation to Building

**Map widget — add a tooltip action:**

<Steps>
1. Edit the **OpenStreet Map** widget (pencil icon).
2. Go to the **Actions** tab and click **+**.
3. Set action source to **Tooltip tag action**, name it `building_details`.
4. Set action type to **Navigate to new dashboard state → building**.
5. Update the tooltip HTML to include a `<a href="#" data-action-id="building_details">Details →</a>` tag so users can click through.
6. Save the widget.
</Steps>

**Buildings list widget — add a row-click action:**

<Steps>
1. Edit the **Entities table** widget.
2. Go to **Actions → +**. Set source to **On row click**, type to **Navigate to new dashboard state → building**.
3. Save.
</Steps>

## Step 2.3 Building State

### Background Image

<Steps>
1. Switch to the **building** state.
2. In edit mode, click **Manage layouts → Layout settings**.
3. Set a background image for the building state and save.
</Steps>

### Building Info Card

Add a **Markdown/HTML Card** widget to display building details.

<Steps>
1. Click **Add widget** and select **Markdown/HTML Card** from the **Cards** bundle.
2. Create a new alias named **Selected entity** with filter type **Entity from dashboard state**.
3. Add data keys: `address`, `contactPerson`, `email`, `phone`.
4. In the **Appearance** tab, enable **Use markdown/HTML value function** and write a function that renders the building info in a styled card layout.
5. Disable fullscreen and data export, then click **Add**.
</Steps>

### Map Widget (Building-Focused)

<Steps>
1. Copy the OpenStreet Map widget from the default state and paste it into the **building** state.
2. Edit the pasted widget and change the datasource alias to **Selected entity**.
3. Remove the tooltip action link (no need to navigate deeper from here).
4. Position in the upper-right area.
</Steps>

### Office Attributes

Before adding the offices list, add server-side attributes to **Office A** and **Office B**:

| Key | Type |
|-----|------|
| `floor` | Integer |
| `phone` | String |
| `email` | String |
| `officeManager` | String |
| `address` | String |

### Offices List Widget

<Steps>
1. Add an **Entities table** widget.
2. Create alias **Building offices**: filter type **Asset search query**, enable **Use dashboard state entity as root**, max relation level **1**, relation type **Contains**, asset type **office**.
3. Add data keys: `floor`, `phone`.
4. Set title to **Offices list**. Show only the **Search** button.
5. Add an **On row click** action: **Navigate to new dashboard state → office**.
6. Click **Add** and save.
</Steps>

## Step 2.4 Office State

### Background Image

Set a floor plan image as the background for the **office** state following the same steps as the building state.

### Office Info Card

<Steps>
1. Add a **Markdown/HTML Card** widget with two datasources:
   - **Selected entity** (alias already created) — keys: `floor`, `officeManager`, `phone`, `email`.
   - New alias **Building** with filter type **Relation type**, root from dashboard state, direction **To**, relation **Contains**, entity type **Asset** — key: `address`.
2. Enable the markdown/HTML value function to render a combined info card.
3. Disable fullscreen and data export, then click **Add**.
</Steps>

### Image Map Widget

The Image Map widget lets you place device markers on a floor plan image.

First, add `xCoordinate` and `yCoordinate` attributes (as percentage values, type Double) to each device in Office A and Office B to define their position on the floor plan.

<Steps>
1. Add an **Image Map** widget from the **Maps** bundle.
2. Select the office floor plan image from the gallery.
3. Create alias **Office devices**: filter type **Device search query**, root from dashboard state, max relation level **1**, relation **Contains**.
4. Set `xCoordinate` and `yCoordinate` as the marker position keys.
5. Configure device tooltips to show relevant telemetry keys.
6. Save the widget.
</Steps>

### Office Sensors List

<Steps>
1. Add an **Entities table** widget.
2. Reuse the **Office devices** alias (or create **Office sensors** with the same configuration).
3. Add the entity name column. No telemetry columns yet — you will add those in Lesson 3.
4. Set title to **Office sensors list** and click **Add**.
</Steps>

<DocLink bold={false} product={props.product} path='user-guide/alarms'>Alarms</DocLink> are notifications generated when critical conditions defined in alarm rules are detected. In this lesson, you will configure alarm rules for the air sensor device profile and add an alarm monitoring widget to every dashboard state.

---

## Step 4.1 Create Alarm Rules

Navigate to **Alarms → Alarm rules** and click **+** to open the alarm rule editor.

### High Temperature

<Steps>
1. Set **Alarm type** to `High temperature`, **Entity type** to **Device profile**, and select the `air-sensor` profile.
2. Click **Add argument**: entity type **Current entity**, argument type **Latest telemetry**, key `temperature`. Name it `temperature`.
3. Add a **Critical** create condition: `temperature > 26`.
4. Add a **Major** create condition: `temperature > 24` AND `temperature ≤ 26`.
5. Add a **Clear** condition: `temperature ≤ 24`.
6. Enable **Propagate alarm to related entities**, set relation type to **Contains**.
7. Save the rule.
</Steps>

<Aside type="tip">
Propagation means the alarm will automatically appear on related offices and buildings — you won't need to query devices directly when monitoring at the building level.
</Aside>

### Additional Alarm Rules

Create the following additional rules for the `air-sensor` profile using the same steps:

| Rule | Major condition | Critical condition | Clear condition |
|------|-----------------|--------------------|-----------------|
| Low temperature | `temperature < 20` AND `≥ 18` | `temperature < 18` | `temperature ≥ 20` |
| High humidity | `humidity > 60` AND `≤ 65` | `humidity > 65` | `humidity ≤ 60` |
| Low humidity | `humidity < 40` AND `≥ 35` | `humidity < 35` | `humidity ≥ 40` |
| High CO₂ | `co2 ≥ 490` AND `< 500` | `co2 > 500` | `co2 < 490` |

Enable propagation for all rules.

## Step 4.2 Add Alarm Widget to Air Sensor State

<Steps>
1. Navigate to the **air_sensor** dashboard state and enter edit mode.
2. Click **+ Add widget**, select **Alarms table** from the **Alarm widgets** bundle.
3. Set datasource to the **Selected entity** alias.
4. In **Filter**, check **Active** status only.
5. Remove the **Assignee** column.
6. Set the widget title to **Air sensor alarms**.
7. Enable only **Allow alarms acknowledgment** and **Allow alarms clear** in the table buttons.
8. Disable **Data export**, then click **Add**.
</Steps>

---

## Step 4.3 Propagate Alarm Widget to All States

### Office State

<Steps>
1. Copy the **Air sensor alarms** widget and paste it into the **office** state.
2. Edit the widget and change the datasource alias to **Office sensors** (the device search query alias you created in Lesson 2).
3. Enable the **Search propagated alarms** option.
4. Rename the widget to **Office alarms**.
</Steps>

### Building State

<Steps>
1. Copy the office alarms widget and paste it into the **building** state.
2. Change the datasource alias to **Building offices**.
3. Rename to **Building alarms**.
</Steps>

### Default State

<Steps>
1. Copy the widget into the default (Buildings) state.
2. Change the datasource alias to **Buildings**.
3. Rename to **All alarms**.
</Steps>

Save the dashboard.

---

## Step 4.4 Test Alarm Functionality

<Steps>
1. Go to **Devices** and open **Indoor Air Quality Sensor (SD-001)**.
2. Click **Check connectivity**, select your protocol and OS, and copy the generated command.
3. Modify the temperature value in the command to exceed `26` (Critical threshold).
4. Execute the command in your terminal.
5. Return to the dashboard — the alarm should appear in the **Air sensor alarms** widget.
</Steps>

To acknowledge an alarm, click the acknowledge icon in the widget row and confirm.
To clear it, click the clear icon and confirm.

<Aside type="note">
Propagated alarms will appear not only in the air sensor state but also in the office, building, and default state widgets — demonstrating how alarm propagation works across the entity hierarchy.
</Aside>
